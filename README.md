# 界鉴 JIEJIAN

**开发继续在 Agent 中，权限验证交给界鉴。**

界鉴是面向 AI 辅助开发的轻量权限验证工具。你继续在 Codex、DSH、ZCode 等客户端讨论需求、修改代码；界鉴保留你确认过的权限要求，检查修改后的应用是否仍然满足这些要求，并提供可以回看的结果与证据。

它关注的是实际业务后果：接口返回“没有权限”，不代表后台没有继续生成文件、写入数据或完成其他操作。

## 界鉴能帮你做什么

- **记住要求**：明确谁可以操作谁的资源，哪些结果允许发生、哪些必须禁止。
- **核对修改**：记录真实源码变化，让每批修改对应自己的检查结果。
- **观察后果**：同时检查越权操作与正常业务，结合实际身份、业务结果和证据作出判断。
- **支持修复**：把问题依据带回原来的 Agent 对话；修复后复验原问题，并确认正常功能仍然可用。
- **继续开发**：保留权限、可复用的材料与历史证据，继续下一批修改。

界鉴不要求你另建一套开发任务，也不替代原来的 Agent 对话。

## 用一个示例了解它

官方示例是“协作空间”。项目负责人 Alice 可以导出自己的完整项目包；普通成员 Bob 不可以导出 Alice 的项目包，但仍应能查看日常协作资料。

起始实现先检查权限，再同步导出。随后，预设演练把导出改成后台任务：Bob 虽然收到了 `403`，后台却仍然生成了项目包。界鉴会检查这个真实后果，将它与已确认的权限要求对照，并给出问题证据。

修复时保留后台导出，把权限判断放到创建任务之前。新的检查仍使用原要求，既验证 Bob 的越权导出被阻止，也验证 Alice 的正常导出和 Bob 的日常查看没有被破坏。完成后可以继续修改同一个应用。

预设演练会标明来源；它不表示连接的 Agent 已经替你修改了代码。

## 启动

在 Windows 上进入项目根目录，双击 `start.cmd`，或在 PowerShell 中运行：

```powershell
.\start.cmd
```

首次启动需要联网准备运行环境和浏览器，之后会复用已准备的依赖。启动后按提示打开本地界面，默认地址为 **http://127.0.0.1:8765**。

需要退出时，使用界面右上角菜单中的“退出界鉴”，让本次服务与示例资源完成清理。

## 第一次使用：从示例开始

1. 在首页点击 **启动示例**，确认启动独立的本地示例。
2. 按页面引导采用权限提案，核对允许与禁止的业务，再明确确认。
3. 采用示例提供的测试材料，核对范围后点击 **开始检查**，查看起始实现的结果。
4. 进入 **修改与验证**，展开官方示例演练，体验异步优化后的检查与问题定位。
5. 查看修复依据，应用预设修复或交给已连接的 Agent 修改，再按页面引导复验原题。

准备材料、登记修改都不会自动代表检查通过。示例停止后再次启动会创建新项目，旧检查与证据保留在历史中。

## 使用自己的应用

在首页选择 **接入自己的应用**，选择源码并确认分析范围。受支持的本地 Node 应用可以在 **应用与环境** 中预览并启动；其他 Web 应用先按自身方式启动，再确认地址。

你可以先在原 Agent 对话中确定一条权限约定，让 Agent 通过 MCP 保存为候选。界鉴展示具体例子和支持范围，由你确认正式规则，再列出能复用的材料和仍需准备的部分。Agent 可以协助填写证明来源、读取预检查缺口；读取范围与来源采用仍由你在界面确认。

检查前还需要相应账号、操作演示、目标资源和必要的恢复方式。技术预检查只回答材料是否可用，正式检查才给出权限结论。普通状态变化的完整验证需要可核对的业务发生记录，单看最终状态或 HTTP 状态码不够。

后续使用方式是：

```text
在原 Agent 中确定约定 → 保存候选 → 在界鉴确认规则
→ Agent 协助补齐材料 → 确认必要范围与证明来源 → 首次检查
→ 继续修改代码并登记这一批变化 → 复用有效材料并重新检查
→ 查看结果与证据
→ 将修复依据带回原客户端，继续开发
```

可以从 **Agent 连接与授权** 查看 Codex、DSH、ZCode 的连接指引，并为当前应用选择允许范围。也可以在 **修改与验证** 中手动登记本地修改。权限规则始终需要你明确确认，Agent 不能替你批准。

仓库仅提供官方示例“协作空间”。接入自己的应用时，Agent 可以帮助准备来源配置；通用记录方式的接入条件和操作步骤见[普通应用接入](docs/能力/应用接入/使用普通应用.md)。任意业务 JSON、外部副作用和异步任务不会自动成为可靠证明。

## 看懂检查结果

| 结果 | 含义 |
| --- | --- |
| **验证通过 · PASS** | 本轮已执行范围内的权限要求得到验证。 |
| **发现权限问题 · BLOCK** | 证据确认发生了不应发生的业务后果。 |
| **证据不足 · INCONCLUSIVE** | 当前材料或观察不足，暂时不能作出完整判断。 |

从结果总览选择一项，可以查看实际事实、执行过程和对应证据。普通检查通过不自动等于原题修复成功；修复状态会单独说明。

每次结论只对应当时的权限、源码与观察范围。代码再次修改后，需要新的检查。当前支持范围是明确授权的本地 Web 应用；普通应用的准备成本和运行对应能力取决于已接入的检查与观察方式。
