# 示例应用

本目录只保存官方 Web 示例“协作空间”。示例源码纳入 Git；本机运行数据与验收产物保存在已忽略的 `var/`。

| 示例 | 用途 | 使用入口 |
| --- | --- | --- |
| [协作空间](web/collaboration_space) | 展示完整项目包导出的权限问题、证据不足与原题修复 | 工作台“启动示例” |

## 协作空间

Alice 是项目负责人，Bob 是普通协作成员。Alice 可以导出自己的完整项目交付包；Bob 可以查看日常协作资料，但不能导出 Alice 的完整项目包。

从仓库根运行 `start.cmd`，在工作台启动示例。先核对并确认提供的权限提案，再采用测试材料、执行检查。开发演练从同步导出起点开始，演示异步修改引入的问题与修复：

1. 起始实现先检查权限，再同步导出。
2. 预设的问题修改把入队放在权限检查之前，可能出现接口返回 403、后台仍生成 ZIP。
3. 检查发现问题后，按原题修复并重新检查。
4. 观察来源不可用时，必要证明不足应明确保留，不能假定权限安全。

环境切换与材料准备不产生检查结论。界鉴通过正式执行与观察形成 PASS、BLOCK 或 INCONCLUSIVE；最终 ZIP 是必要证明，审计、任务、队列等保留各自辅助或诊断角色。

协作空间的 `sample.json` 用于官方启动器。每次体验在 `var/runtime/` 内创建独立源码副本和状态，运行修改不写回这里的源码。

## 版本控制与发行

- `samples/`：公开可复现的示例源码和使用说明，可提交到 GitHub。
- `tests/`：自动化测试及 fixture；协议测试驱动只在隔离运行目录生成。
- `var/`：本地数据库、运行副本、日志、截图和验收产物，已由 `.gitignore` 排除。
- full 便携包的构建规则会包含 `samples/`；nosamples 包排除整个目录。个人接入应用只保留在本地运行目录，不进入发行包。

开发与验收边界见[修改官方示例与整链验收](../docs/开发/能力/修改官方示例与整链验收.md)。
