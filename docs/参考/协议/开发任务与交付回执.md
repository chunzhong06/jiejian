# 开发任务与交付回执

> 状态：CURRENT。说明开发任务、交付、回执与精确检查关联。GUI/MCP 共用这些服务；完整版本的客户端与展示验收独立记录。

## 对象与版本

一个应用只能有一个 ACTIVE 任务。任务状态仅 ACTIVE、CLOSED、CANCELLED，结束或取消均不表示安全通过。目标、标题与批准权限的冻结引用保存在追加的 `DevelopmentContext` 中，每份上下文同时代表一次不可变目标修订，不另存重复内容的修订表。

`DevelopmentTask.version` 是所有任务写入的乐观并发版本；`revision` 是目标修订。接收、交付和结束递增 version，不改写目标修订。修改目标或刷新已变更的权限引用追加上下文并递增两个版本，旧接收不能沿用。界鉴只记录已批准权限的引用，任务文字不形成新权限，不自动批准权限。

明确接收由客户端操作形成 `DevelopmentAcceptance`；复制、读取和显示任务不会产生接收。客户端名称用于来源展示，不作为认证凭据。每次调用仍须通过既有 MCP 认证和逐应用授权。

每个任务可包含多个 `DevelopmentDelivery`。第一批相对任务最初源码快照，后续相对上一批快照；每批均保留任务最初快照以供累计对照。真实路径变化由既有受控扫描形成，声明路径只作提示，不代表文件作者身份，也不用于裁剪检查计划。

## 原子写入与恢复

所有写操作携带稳定的 32 位十六进制 operation_id。回执主键为 project/kind/operation_id；请求指纹包含操作内容及预期任务版本。相同键和正文返回原回执，同键异文拒绝。重放先于当前版本、源码或准备状态核对，所以响应丢失后可用原请求恢复，即使后续工作区已变化也不会再次扫描或登记。

变化登记先在事务外形成只读扫描候选，再在 SQLite 写锁下重读权限、任务和源码理解版本。源码理解与快照、Change、影响记录、Delivery、任务版本更新和 SUCCEEDED 回执在同一 Unit of Work 提交。任何一步失败整体回滚；不依赖进程内 RLock 来实现跨进程幂等。

成功响应只返回持久回执，不在提交后同步读取 Workspace。下一步同步失败应单独重读。没有回执仅表示尚无已登记成功事实，不能据此认定请求从未执行或生成新操作键；有界扫描尚在执行时也可能没有成功回执。长时执行必须走现有 Job/lease/fence，不能以此同步事务替代执行队列。

## 持久化与范围

`0008_development_delivery` 从精确合法的 0007 追加五张表：development_tasks、development_contexts、development_acceptances、development_deliveries、development_receipts。既有项目、权限、源码、运行与准备记录原位保留，不按名称或时间补造任务。唯一活动任务使用数据库部分唯一索引约束。重复升级无修改；结构漂移只读拒绝，DDL 失败整笔回滚。

五个独立根记录使用格式 1，并登记公共 Schema。所有读写继续经过严格模型及秘密过滤。开发模块不持有 Verdict，不能将普通 PASS 自动标记为修复成功；正式检查和原题修复仍是各自结论的唯一所有者。运行对应另见[受控运行对应](受控运行对应.md)。

`0009_delivery_check_links` 从精确合法的 0008 追加 `development_check_runs`，在正式 Run/Job 创建事务内保存交付关联。查询交付结果必须通过这条索引和完整发布包，不按最新时间或源码指纹匹配。运行加载的独立格式 1 回执复用 operation 表的 LOAD_RUNTIME 类型，不进入普通交付成功回执 reader。

GUI 的变化登记请求使用格式 2，必须携带 task/context/operation/expected_version；旧无键请求在写入前拒绝。MCP 提供 task_list/show/context/create/accept 与 receipt_show，变化登记返回持久回执，再由 change_show 查看事实。任务修订、结束和取消由 GUI 执行。客户端身份取当前 SDK 请求，无法取得时显示 MCP Agent，不复用上一客户端名称。

浏览器会话存储仅保留操作键及必要的任务/上下文/交付引用；不存正文、草稿或秘密。刷新后查询原键；查询暂未发现成功回执时可以用同键原请求继续，不能偷偷生成新键。切换项目由页面身份隔离。
