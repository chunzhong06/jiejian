# 产物检查协议

> 状态：CURRENT。本文区分已退出的独立产物扫描与当前 CHECK 的发布完整性校验。

## 目的与消费者

原独立 Artifact 扫描器及其请求、扫描结果根模型已退出当前代码。当前 Worker 使用 CHECK 发布校验验证文件清单、路径、大小、摘要与运行关联；这不代表仍提供独立产物扫描或压缩安全检查服务。

## 协议边界

- `CheckPublicationManifest` 绑定项目、Run、Job、attempt、租约与 fencing 身份，以及 request、runtime、result 和 Evidence 文件的摘要与大小。
- `CheckPublisher` 校验当前租约和已形成文件，再发布不可变结果；Reader 独立复核发布完整性。
- `PublicationManifest` 仍由旧运行包 reader 保留，不能用它证明独立扫描器仍存在。
- 发布校验不修改源码或用户目标，不重新决定权限 Verdict。

## 生命周期与数据流

```text
当前 CHECK 的 staging 文件
  → 文件与事实校验、租约及 fencing 核对
  → CheckPublicationManifest / 不可变发布包
  → 数据库记录发布事实
  → CheckResultReader 复核后读取
```

## 失败与安全语义

路径越界、关联错误、摘要不符、文件变化或失效租约不得形成可信发布。发布失败与权限判断分开；Reader 无法确认完整性时不得显示旧的安全结论。证据不足由 Verification 按其三态合同处理，不能靠文件存在补造 PASS。

## 版本规则与 Schema 真源

当前 CHECK 发布清单的 `schema_version` 为字符串 1。字段约束、发布实现与直接测试以：

- `product/protocols/checks/check_publication.py`
- `product/protocols/schemas/runner/check-publication-manifest.schema.json`
- `product/backend/infra/artifacts/checks/`
- `tests/backend/infra/runtime/jobs/publication/`

为准。旧运行包清单见 `product/backend/infra/artifacts/legacy_run_reader.py` 与 `product/protocols/schemas/artifacts/publication-manifest.schema.json`；它只说明该格式仍被读取，不恢复已退出的扫描能力。
