# 报告与格式投影协议

> 状态：CURRENT。本文说明保留的报告格式模型；报告生成、发布及格式投影实现已退出当前代码。

## 目的与消费者

当前保留 `product/protocols/report.py` 中的模型、解析与canonical函数，并由Schema Registry生成格式。独立ReportStore、报告生成工作流及HTML/SARIF/JUnit投影器已退出；当前GUI、CLI、MCP与sample-test使用CHECK结果读取链。保留格式不代表产品能够生成或下载这些报告。

## 先理解：一份语义，多种投影

保留协议将`report.json`定义为报告语义输入，HTML、SARIF与JUnit列为交付格式；当前只保留其格式合同，没有对应生成器。当前GUI/MCP使用CheckResultReader和ResultStory，旧ResultPresentation工作流及其直接测试也已退出。

维护保留模型不能改写Run Verdict、Evidence、Finding或GateResult。若重新实现报告生成与投影，需要另行明确writer、reader与验收，不能从Schema存在推断运行链已经可用。

## 协议边界

- 根文档由 `report_type` 严格区分 `BaseRunReport` 与 `GateRunReport`，不使用可空字段拼成兼容模型；当前由保留解析函数读取，没有ReportStore publication服务。
- `BaseRunReport` 独立呈现 Run/runtime、Artifact 三态、versions、limitations 和有界 diagnosis；`GateRunReport` 引用并复制已验证的 Base 事实，再增加明确的 GateResult。
- diagnosis 只保存授权连续性三态、唯一主断裂、精度、后续 amplifier、固定七项业务故事、已确认下游影响和 Evidence 引用；可选 repair verification 只投影同考题复验三态及其权威引用。二者都不包含完整 Trace，不允许投影器或模型重算位置、精度、影响集合、修复合同或 Verdict。
- 当精度为 `VIOLATION_ONLY` 且 Trace 不能支持具体类型时，diagnosis 的 `breakpoint_type` 为 `null`；投影必须显示当前无法继续定位，不能猜测一个类型填入。
- package manifest 绑定 report、run、报告种类、Base 引用、可选 GateResult、canonical report hash 和固定四格式文件列表。
- HTML、SARIF、JUnit属于保留协议规定的投影文件类型，当前不提供生成实现。
- 报告只能引用已校验 publication 和不可变 Evidence。

## 当前保留范围

```text
保留的 Base/Gate Report 模型与 package manifest
  → 严格解析 / canonical 与摘要函数
  → Schema Registry / 已签入 JSON Schema

当前产品结果：CHECK publication → CheckResultReader → ResultStory / GUI / MCP
```

## 失败与安全语义

保留模型校验有界引用与格式，不能代替当前发布包的文件完整性复核；基础报告不要求Gate。Artifact摘要保留`NOT_REQUESTED`、`COMPLETE`、`INCONCLUSIVE`三态；这些字段不证明当前仍提供扫描或报告派生任务。当前结果缺失、篡改或关联错误的处理见[结果与修复指南](../../能力/结果与变化/修改结果与修复.md)。

## 版本规则与 Schema 真源

Base/Gate Report 当前根 `schema_version` 为字符串 5；report package manifest 是独立根，仍为字符串 1。Report v5 在既有授权连续性、primary/amplifier 和固定七项故事之外，加入可选的权威修复引用与独立复验三态并纳入 canonical；旧 Report 不兼容读取。package manifest 继续绑定当前 report canonical hash，不因被引用根升级而机械改版。字段、hash、canonical、判别联合和严格解析以：

- `product/protocols/report.py`
- `product/protocols/schemas/reports/`

为准。旧开发 Report 和 wire format 不兼容读取。
