# 本地接口使用约定

本页解释调用条件和结果读取方式。完整路由及格式见[接口与协议](接口与协议.md)，精确字段以对应严格模型为准；不要把字段相似的嵌套对象当作独立根文档。

## 控制面与执行面

控制 API 只接受本地回环访问。它核对输入、授权、当前事实和持久任务，不在请求进程直接执行浏览器、高风险目标请求或攻击变异。任务交由 Worker 与隔离 Runner 完成，调用方读取任务和最终发布结果。

## 建立本地会话

1. 从本次服务的实际地址打开根页面；根响应建立本地控制会话。
2. 后续 API 请求携带该会话。Host 必须匹配服务地址，写请求的 Origin 必须与本次服务一致。
3. 前端传输层管理请求和公开错误，不在页面、日志或普通存储中暴露会话值。

本地会话 Cookie 采用 HttpOnly 和 SameSite=Strict，作用路径为 API；不能仅因地址是 localhost 就省略会话或来源检查。更换端口或重启后应使用当前实例的页面和会话。

## 读取、预览、写入、查询

| 阶段 | 示例 | 使用方式 |
| --- | --- | --- |
| 就绪 | `GET /ready` | 等待服务实际可用，不代表材料已就绪 |
| 预览 | `GET /api/projects/{project_id}/check-preview` | 读取执行范围、缺口和当前计划指纹，不执行目标 |
| 提交 | `POST /api/projects/{project_id}/runs` | 提交期望计划指纹和幂等键；写入根格式为 schema_version 2 |
| 查阅 | `GET /api/runs/{run_id}/result-story` | 读取已形成的报告事实；未形成最终结果时不能自行补结论 |

成功 API 以 `schema_version` 与 `data` 包装。外层回执版本、具体请求版本、业务文档版本和数据库修订各有用途，不相互替代。写请求同时核对业务前置条件，HTTP 成功只表示相应操作被接受或完成，仍须读取实际状态。

以提交检查为例，调用方先读取 preview，再以其指纹提交 `expected_plan_fingerprint`、一次性的 `idempotency_key`，需要复验时附带 `change_id`。提交后的 202 表示已接受，最终生命周期和 verdict 另行读取。

`GET /api/projects/{project_id}/readiness` 只投影已有源码分析、地址核验、受控运行记录和证明来源，不进行新的网络探测。`GET /api/projects/{project_id}/activity` 从持久任务返回当前可继续的对象及应用内位置；它不是第二套可写任务状态。

登录通过 `POST /api/test-identities/{identity_id}/preparations` 接收一次 `operation_id`，由 Worker 打开独立窗口。使用 `/preparation-requests/{operation_id}` 精确查回执；已知准备标识时读取 `/api/identity-preparations/{preparation_id}`，显式确认保存或取消。临时资源未收尾时使用该对象的 `/cleanup` 重试精确清理，不能以新登录绕过。

## 回执不确定

请求断开或超时后，使用原操作标识、幂等键或已获得的运行标识查询；不要生成新键重新触发副作用。事实变化导致指纹失配时，先展示新的预览并核对范围，不能静默接受变化。

查询未找到、尚在运行和操作失败分别处理。只有读取到对应终态才能报告完成；服务退出也不能代替执行取消的持久事实。

## 错误与秘密

公开错误给出稳定代码、脱敏消息和可公开上下文，原始异常不直接透出。本地边界拒绝、严格输入错误、业务前置条件失败和执行失败应分别定位。具体状态码核对路由错误映射，不根据文案字符串判断。

秘密只通过受控引用和最小注入进入执行。密码、Cookie、Token、密钥及包含它们的响应不得进入普通请求示例、Evidence、Finding、Report 或日志。
