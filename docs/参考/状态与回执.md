# 状态与回执

状态回答“现在处于哪一步”，结论回答“事实是否符合权限要求”。界面与调用方必须分别读取，不从某一个绿色标签推断全部工作已完成。

## 运行生命周期

| 值 | 含义 | 后续处理 |
| --- | --- | --- |
| `QUEUED` | 已进入等待队列 | 查询原运行，避免重复提交 |
| `RUNNING` | 正在执行 | 展示实际进度，可请求取消 |
| `COMPLETED` | 执行已完成 | 继续读取 verdict、最终化与报告 |
| `FAILED` | 执行失败 | 查看脱敏原因与已形成事实 |
| `CANCELLED` | 已取消 | 保留已发生事实，不显示为通过 |
| `SAFETY_STOPPED` | 触及安全边界而停止 | 解释边界，不改成业务违规 |

## 运行结论

| 值 | 表达 | 范围 |
| --- | --- | --- |
| `PASS` | 符合规则 | 本次冻结范围内的事实支持要求 |
| `BLOCK` | 不符合规则 | 有可信事实与要求冲突 |
| `INCONCLUSIVE` | 证据不足 | 关键身份、关联、观察或对照不足 |

单用例判定值为 `SAFE`、`VULNERABLE`、`INCONCLUSIVE`、`SKIPPED`、`ERROR`。最后两项分别描述未执行和执行错误，不能直接映射成安全或违规；运行聚合由领域验证完成，前端不重新计算 verdict。

## 持久任务与准备

任务使用 `PENDING`、`RUNNING`、`RETRY_WAIT`、`SUCCEEDED`、`FAILED`、`CANCELLED`。任务成功不等于权限通过，例如成功执行的检查可能形成 BLOCK。失败终态也应立即结束轮询，不一直等到超时。

准备状态说明账号、录制、资源、证明和恢复等输入是否可采用；材料齐备只说明可以继续预览。后台读取失败不清空先前已确认事实，当前输入变化后仍须重新核对。

登录准备独立表达 `STARTING`、`WAITING_FOR_LOGIN`、`SAVING`、`CANCELLING` 以及 `PREPARED`、`UNSUPPORTED`、`CANCELLED`、`FAILED`。它们由持久准备记录和原 Job 投影，登录窗口关闭不等于已保存。`cleanup_required` 单独说明临时资源仍需收尾，不能用登录成功或失败代替清理结果。

应用活动入口从服务端查找原登录、录制、检查、运行加载和准备批次。页面刷新后按具体对象标识返回，不能用“最新任务”覆盖用户指定的历史操作。登录同键返回原结果；原任务终止并完成清理后，显式新建一轮才会打开新窗口。

## 写入回执

调用方保存一次动作的标识和预期指纹。确定成功后读取对应新状态；确定拒绝后解释缺口；回执未知时查询原操作。不能把网络异常解释为“未写入”，也不能以重复点击制造第二个任务。

报告、问题和复验保留原来的项目、规则修订、用例与运行关联。结论有效范围包括当时的代码、身份、资源和证明读取边界，历史报告不随当前材料自动更新。

状态声明位于 `product/backend/domain/lifecycle.py`，具体错误位于 `product/backend/domain/errors.py`。完整业务解释见[权限、事实与结论](../产品/检查与复验.md#如何理解结论)。
