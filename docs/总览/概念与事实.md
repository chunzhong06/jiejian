# 概念、身份与事实所有者

> 状态：CURRENT。用于辨认谁拥有事实、谁只做投影，以及相似状态各自证明什么。字段和完整枚举查实际模型与生成参考。

## 先分清五件事

用户确认的权限需求、当前执行材料、一次运行的冻结输入、执行中状态、已经发布的安全结论具有不同生命周期。修改其中一项，不代表其他事实可以随之改写。前端、MCP和解释模型读取权威投影，不能另造READY、任务优先级或Verdict。

## 对象和所有者

| 用户说法与代码概念 | 谁创建/修改 | 保存在哪里、谁读取 | 容易混淆的边界 |
| --- | --- | --- | --- |
| 应用接入：Project、ApplicationUnderstanding | 接入服务建立Project；确认地址、授权扫描及候选审阅更新理解revision | storage/apps；边界、材料、运行和变化服务读取 | 源码识别不代表权限已批准；地址可达不代表受控实例身份成立 |
| 识别候选、规则候选 | 源码分析与RuleCandidateService | 理解记录或rule candidate修订/操作回执；GUI审阅 | Candidate提供建议或实现线索，不是正式Permission |
| 正式角色/动作/权限 | BusinessBoundaryService的LOCAL_GUI提案决定事务 | 业务revision、Proposal、Decision和policy_epoch；Preparation/Check读取 | 人类批准、技术实现binding与真实测试账号分开 |
| TestIdentity测试账号 | 身份工作流绑定正式Actor revision；独立登录准备更新会话元数据 | storage/preparation及SecretStore引用；录制/Runner最小注入 | Actor是业务角色，账号是执行代表；Cookie正文不属于数据库记录 |
| Flow、技术Binding | 人审阅录制与材料预览后形成 | 录制/Flow工件、动作四类binding；准备inspection与检查构建读取 | Binding保存选择和来源；当前可用性由现场核验派生 |
| Preparation、Guidance、PrimaryTask | 准备服务派生缺口；guidance解释当前缺口；Workspace选唯一任务 | 只读投影，不另存页面READY | 材料齐备、可以提交检查、检查通过分别判断 |
| Source revision、scope、preflight、adoption | ProofPreparationService；用户确认读取范围和采用；Worker发布预检查报告 | proof_*聚合、报告工件、准备回执；CHECK冻结有效已采用来源 | 技术USABLE不等于权限PASS；配置、授权、采用不是同一事实 |
| 源码指纹、manifest、runtime instance | 受控源码扫描、运行provider、拥有进程树的控制者 | 快照、加载输入/回执、运行文件；检查前后核验 | 相同源码不等于同一运行实例；Git HEAD不能证明部署对应 |
| Run、Job、attempt、lease、fence | CheckService提交，JobQueue/JobAttempts与Worker维护 | SQLite执行聚合及运行目录；监督者、Runner与读端读取 | Run表示业务检查；Job表示执行责任；fence阻止旧执行者覆盖新事实 |
| Observation、Effect、Trace | Observer与执行适配器采集/归约；Verification消费事实 | 随CheckEvidence发布；结果reader只读 | HTTP403不证明没有副作用；缺失或不完整观察不能推断安全 |
| publication、ResultStory | Worker验证并发布；CheckResultReader/Story读取 | 不可变工件＋数据库收据 | 文件存在不等于发布被接受；故事不重跑Verification |
| task/context/change/delivery | DevelopmentService与真实源码变化服务 | storage/changes；DevelopmentReader及精确check link读取 | Agent声明路径不是实际diff；任务结束不等于安全通过 |
| repair contract/verification | 从原BLOCK及精确NEW Run的完整publication派生 | 当前修复reader，保持历史输入与正常回归标准 | 普通未关联PASS不能证明原题已修复 |

## 状态应从哪里读

| 问题 | 所属状态与依据 | 不可据此推出 |
| --- | --- | --- |
| 操作是否已被接受 | 对应领域的project/kind/operation_id回执 | 尚未查到回执不能证明未执行，不能换新键试探 |
| 任务是否在执行 | Job生命周期、当前attempt、租约、取消和清理事实 | SUCCEEDED不等于权限PASS；取消请求不等于已清理 |
| 材料现在能否使用 | Preparation、BindingSourceInspector、proof active_sources | 历史绑定存在不等于当前有效 |
| 运行是否与本批源码对应 | 对应provider、实例所有权、manifest、load receipt | 页面能打开、PID相同或Git相同都不足以证明 |
| 当前范围是否满足权限要求 | `product/backend/core/verification/checks.py` 的确定性判断 | LLM、HTTP分类、模型解释、界面颜色不能决定Verdict |
| 修改是否修好原问题 | 原题冻结标准、变化与精确NEW Run关联、全部正常回归 | 关闭功能、降低权限要求或普通PASS不能替代 |
