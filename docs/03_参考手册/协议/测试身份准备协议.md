# 测试身份准备协议

> 状态：CURRENT。本文说明控制面与独立登录浏览器进程之间的非秘密机器边界；字段约束以 `product/protocols/schemas/identity/` 为准。

## 先理解：账号记录不保存登录秘密

TestIdentity 只把项目、正式 BusinessActor 的稳定 ID/revision、endpoint、认证方式和准备状态连接起来。用户在独立 headed BrowserContext 中登录后，Cookie/Token 正文由准备进程直接写入 SecretStore；控制面只接收非秘密元数据与 `secret_ref`。因此数据库中“账号已准备”不等于数据库持有密码或 Cookie。

Recording/Runner 只解析冻结请求需要的精确引用并最小注入。缺账号形成执行代表 gap，不改变 PermissionIntent；秘密写入失败则准备失败，不能把正文降级保存到文件或 API。

## 消费者与生命周期

`IdentityPreparationManager` 生成格式 1 的 `IdentityPreparationRequest`，冻结 preparation、project、TestIdentity 与已确认 `WebTargetScope`。开始及提交前核验同一当前 ACTIVE BusinessActor revision、endpoint、源码来源与账号状态；不从 Candidate 猜主体，也不让账号重置后的旧结果提交。受控身份准备进程只读取一次请求，在独立 headed BrowserContext 中等待用户登录；控制面通过固定 ready/save/cancel 标记表达显式意图，不把密码或页面输入写入协议。

控制 API 为 POST `/api/test-identities/{identity_id}/preparations`、GET `/api/identity-preparations/{preparation_id}` 及 POST 同地址的 `/confirm`、`/cancel`。写请求严格接收格式 1，认证仍由统一 LocalControl 执行；页面状态不能代替 Manager 来源校验。

用户确认保存后，进程返回格式 1 的 `IdentityPreparationResult`。PREPARED 只允许 COOKIE_SESSION 或 BEARER：Cookie 最多 32 个且每项只返回非秘密元数据和独立 `secret_ref`；Bearer 只返回一个引用。UNSUPPORTED、CANCELLED 和 FAILED 不携带登录状态，FAILED 必须提供稳定错误码。

## 安全与恢复

请求只能包含已确认 target 的 origin、host、port、超时、请求数和响应字节预算。浏览器逐跳重新授权，拒绝跨 scope 重定向、WebSocket、下载、流式/压缩未知响应和越界私网访问。Cookie/Token 正文由身份准备进程直接写入共享 SecretStore，不经过 stdout、API、数据库或日志。

写入前先在 `var/runtime/identity-preparations/<preparation_id>/secret-refs.json` 原子记录精确引用计划。正常提交后删除该 journal；进程或服务异常退出时，下次 `ApplicationCore` 启动按 TestIdentity 当前已提交引用判定并精确补偿，不枚举 Credential Manager，不用 PID 或遗留文件判断秘密有效性。诊断日志只保存异常类型、稳定错误码或 OS 错误号，不保存异常正文。

## 失败语义

未知版本、额外字段、ID 关联不一致、消息超预算、混合 Cookie/Bearer、超过 32 个 Cookie、多个 Bearer、无可安全归约状态或 SecretStore 写入失败均 fail closed。身份准备失败不会生成 RecordingEvent、Permission 结论或 Verification 事实；删除/补偿失败保留 journal 或 TestIdentity 元数据供后续重试。

删除账号时先在未提交事务内执行数据库删除检查，数据库约束拒绝不能提前清除登录秘密；秘密清理成功后才提交，清理失败保留元数据供重试。Recording 和动作技术绑定保留录制时的身份 ID 作为历史来源，不用账号外键阻止删除或级联删除历史；新写入必须验证真实身份，账号删除后现场准备检查返回缺失或失效，历史不能继续充当可执行准备。
