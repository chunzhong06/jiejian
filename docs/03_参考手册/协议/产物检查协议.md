# 产物检查协议

> 状态：CURRENT。本文解释已发布或待发布产物的隔离扫描和结果边界。

## 目的与消费者

Artifact 检查由 Worker/发布流程和报告生成消费，用于在结果可见前验证文件清单、路径、大小、压缩和安全规则。

## 协议边界

- `ArtifactCheckRequest` 指定项目、产物、manifest、ruleset 和扫描预算。
- `ArtifactScanResult` 表达扫描状态、verdict、文件/字节计数、findings 和 evidence。
- `ArtifactResultManifest` 绑定文件列表、输入 manifest hash 和结果 hash。
- 扫描在受限目录中完成，不修改源码和用户目标，不越过 publication 边界。

## 生命周期与数据流

```text
staging/发布候选 → ArtifactCheckRequest
  → 隔离扫描（路径、压缩、大小、预算、清理）
  → ArtifactScanResult/ResultManifest
  → Worker 校验 hash
  → publication 或拒绝/隔离
```

## 失败与安全语义

路径越界、压缩炸弹、预算不足、文件变化、规则错误、扫描中断或清理失败不得形成安全通过。证据不完整时返回 INCONCLUSIVE；扫描结果不能反改 Verification Verdict 或 Evidence。

## 版本规则与 Schema 真源

Artifact 三类独立根文档的当前 `schema_version` 均为字符串 1。字段约束和严格模型以：

- `product/protocols/artifacts.py`
- `product/protocols/schemas/artifacts/`

为准。Schema 版本只表示机器格式，旧开发 Artifact/wire format 不兼容读取。
