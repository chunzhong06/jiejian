# 数据格式

## 配置 YAML

| 文件 | 内容 | 真源 |
| --- | --- | --- |
| `project.yaml` | Project slug、目标范围、身份秘密引用、资源、Flow/Contract 相对路径、观察器和 seed。 | `verification/inputs.py`、`domain/verification.py` |
| `flow.yaml` | 有序 HTTP 步骤、身份/资源关系、期望状态和测试 reset。 | `domain/verification.py` 的 `Flow`/`FlowStep` |
| `contract.yaml` | ACTIVE Contract、版本、RuleKind、观察者和严重度。 | `domain/verification.py` 的 `SecurityContract` |

`flow` 和 `contract` 必须是相对 `project.yaml` 所在目录的路径，解析后不得越界。样例因此各自保留完整 bundle，不跨目录共享同名文件。

## 持久执行请求

`<var_dir>/jobs/<job_id>/request.json` 保存 `PersistedExecutionRequestV1`：执行预算和路径无关的项目内容快照。文件使用规范 JSON、SHA-256、临时文件、`fsync` 和原子替换；数据库 `request_hash` 必须与其字节一致。只允许 `env:NAME` 引用，不保存真实秘密。

真源：`backend/src/jiejian/worker/request_store.py`。

## RunnerInputV1 与 RunnerResultV1

RunnerInputV1 加入 run/job/attempt/lease owner/Fencing Token 和完整执行快照；RunnerResultV1 返回结果类型、生命周期、Job state、verdict、reason codes、清理结果、有限错误和工件清单。

- 人类字段协议：[Runner 执行协议 V1](Runner执行协议V1.md)
- 可执行模型：`backend/src/jiejian/protocols/runner_v1.py`
- 机器 Schema：`schemas/runner/runner-input-v1.schema.json`、`runner-result-v1.schema.json`

V1 使用 UTF-8 规范 JSON，拒绝 BOM、重复键、未知字段、未知版本、NaN/Infinity 和超限字节。

## Evidence

Evidence 是内容寻址 JSON，包含 run/case/rule、关系变异、观察、reason codes、verdict、fingerprint 和语义内容哈希。Evidence 正文位于发布工件，SQLite 只保存 Evidence Index。

真源：`domain/verification.py`、`verification/evaluation.py`、`verification/artifacts.py`。

## publication manifest

`publication-manifest.json` 随最终 Run 目录发布，记录 project/run/job/attempt/owner/Fencing Token、租约截止、发布时间、结果哈希和精确文件清单。Worker 必须验证路径、reparse point、字节数和 SHA-256；不同 manifest 不能覆盖同一 Run。

真源：`worker/published_artifacts.py`，决策见[ADR-0007](../03_技术决策/ADR-0007-阶段2工件发布与恢复.md)。

## 数据库记录与索引

SQLite 当前只有五张业务表：`projects`、`runs`、`jobs`、`job_events`、`evidence_index`。它保存公共 ID、状态、时间、租约、事件和文件引用，不保存响应正文、真实秘密或大型 Evidence。

真源：`storage/models.py` 和 `backend/migrations/versions/0001_stage2_storage.py`；事务边界是 `StorageUnitOfWork`。
