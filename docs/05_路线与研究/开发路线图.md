# 界鉴开发路线图

> 状态：CURRENT。本文只说明可验证事实、后续目标和验收边界，不替代当前 Architecture、协议、Schema、migration 或代码。

## 当前可验证产品事实

- 产品是面向 Web Target 的权限安全检查工具。
- GUI、CLI、API 和 Worker 共享 ApplicationCore；高风险目标流量经过 Worker 和隔离 Runner。
- 当前执行链已包含权限意图、覆盖计划、Web HTTP 执行、ExecutionFact/ObservationFact、Evidence、Verification、Finding、Baseline、Gate 和 Report。
- 当前公共协议真源为 `product/protocols`，数据库真源为 `product/backend/migrations`，默认 Windows 入口为 `start.cmd`。
- 当前不提供 CLI_APPLICATION、MCP_AGENT、本地命令执行或 MCP ingress 能力。

## 已完成能力摘要

- Contract、Candidate、Profile、执行快照和权限规则治理已形成共享入口。
- Worker/Runner、Observer、证据发布、结果验证、Finding、回归比较、Gate 和报告已形成统一边界。
- Windows 启动、首次使用、只读项目识别、GUI/CLI/API 入口和本地控制面已形成产品路径。
- 官方 Web 回环 Sample 通过正常 GUI 和公开 CLI 入口提供 fixed、vulnerable、inconclusive 三个 Golden；三种结果都来自真实 Worker/Runner、Evidence publication 与 Verification。
- `samples/web` 已收敛为唯一演示 Target、配置与 Truth 真源；产品不保存被测 Demo 应用或演示特判，复杂关系能力继续由 Core、Coverage 与 Observer 定向测试保护。
- 因果关联、Queue/Blob 观察等技术实验已沉淀长期结论，实验本身不等于生产能力。

## 接下来真正未完成的目标

1. 在当前单代代码与文档上完成一次仓库级自动化回归和一次 Windows 真实启动验收。
2. 验收稳定后再为下一种 Target 或交付形态单独形成决策，不在 Web V1 收口中预建空入口。

## 验收边界

每个目标都必须有可复现的入口、真实代码和测试证据，并保持 PermissionContract、执行快照、Evidence、Verdict、GateResult 和 Report 的边界分离。任何新增目标类型、公共协议、数据库迁移或安全语义都必须单独形成决策和验收。

## 明确不做

- 不把模型服务当作目标执行适配器或安全结论来源；模型服务可以辅助候选生成，但不决定 Verdict、不运行目标请求。
- 不把未来 Target 类型或实验结果写成已实现产品能力；未来扩展另行形成决策和验收。
- 不通过兼容读取猜测旧开发数据库、Profile、Run、Evidence、Artifact、Report 或 wire format。
- 不用路线图替代当前架构，也不把历史过程日志作为长期技术入口。
