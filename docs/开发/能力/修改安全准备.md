# 修改安全准备

> 状态：CURRENT。用于准备投影、四类技术绑定、材料局部更新和恢复。准备齐备不等于可执行，更不等于 PASS。

`PreparationGuidanceService` 只组合 Workspace、Preparation 与证明来源上下文，供 GUI/MCP 共享。全局任务由 Workspace 选择；来源内部的授权、预检查、采用只细分对应主任务。材料原因来自实际 reason_codes，未识别原因保持未知。读取前后的依据改变时返回 NEEDS_REFRESH，不输出混合建议；真实写入仍由原 CAS、授权与回执事务核验。该服务没有持久化 READY、目标请求或结论写入。

## 修改与直接验证

先确定改的是派生需求、来源核验、绑定写入、有限草稿还是展示。来源问题从 `bindings/sources.py` 的 `BindingSourceInspector.reasons` 和 Recording/Flow 向上追；页面缺口从 Preparation / PrimaryTask 向下追，避免在两个方向各建一份准备状态。

```powershell
.\scripts\dev.ps1 test tests/backend/workflows/preparation/materials/test_material_recovery.py
.\scripts\dev.ps1 frontend-test src/features/preparation/materials/MaterialEditor.test.tsx src/features/preparation/PreparationPage.test.tsx
```

按改动选择命令；绑定变化另测幂等、多 owner、来源漂移，需求变化测确定性和身份约束。持久化变化再读[数据库指南](修改数据库.md)，验证等级只由[验证规范](../验证.md#4-模块范围--验证程度)及实际影响决定。

## 必须保持

- 当前服务从正式 Action/Permission revision、账号与技术绑定现场派生状态；不持久化第二份 READY，不修改业务权限。
- DENY 必须有完整合法 ALLOW 对照；并列候选由用户明确选择。缺口不是安全结论，前端不选择身份或任务优先级。
- 材料引用必须匹配项目、动作修订、用途、subject / owner 与受控实例；源码、endpoint 或来源漂移失败关闭，不按名称匹配。
- 材料确认先核对预览基线，绑定与回执在同一写事务中提交；同一 operation_id 只回读同一请求，不能重复写入。
- 草稿只存有限引用和回读标识，不存秘密、任意表单或登录内容。草稿恢复后仍重新读取 Preparation。
- 候选录制审阅完成不自动替换正式绑定；采用须经过影响预览和确认。已有 Run 的冻结输入与证据不改变。
- 普通准备 GET 不运行目标、浏览器或模型；Recovery 不删除历史证据，环境 reset 不冒充动作恢复。

## 按问题读取细节

来源服务内部使用具名 `PreparationFacts` 传递同一事务中读取的规则、源码、账号、资源、运行与依据标识；它只存在于内存，不能被保存为第二套准备状态，也不改变公开配置、回执或指纹输入。

通用记录来源由 `workflows/preparation/proofs/service.py` 管理候选、修订、读取授权、预检查与采用。四张 `proof_*` 表保存来源事实、不可变输入与报告引用；`preparation_receipts` 按项目、操作类别和原操作标识保存回执。报告通过独立 `PROOF_PREFLIGHT` Job/Runner 形成，发布必须匹配当前 attempt/fence/租约；API 不访问目标。技术 USABLE 不表示权限 PASS。

采用前核对正式边界、真实源码、运行实例、账号会话、资源与读取范围。采用把当前修订写入已有 ActionEvidenceBinding；CHECK 格式 5 冻结受控记录来源，不新建准备或判定真源。采用预览同时展示资源集合、状态字段、受保护状态或投影字段。已采用的同一配置在新实例上重新预检查后可复用；来源修订变化须重新确认采用。录制复用核对旧/新运行中的相同通用组件、已批准动作实现和原材料关联；旧 JSON 格式仍能读取历史，新预检查和采用要求重新准备通用来源。

接口与来源支持范围参见[普通应用接入](../../产品/普通应用接入.md)。授权撤销、进程重启、旧报告与异文同键等边界的直接验证为 `test_proof_fail_closed.py`、`test_proof_sources.py` 与 `test_proof_reuse.py`。
