# 阶段 1：安全验证纵切

## 目标

在没有 GUI、浏览器录制、LLM、数据库和 Worker 的前提下，用人工提供的 Flow 与 ACTIVE Contract 完成第一个可复现安全证据闭环。

## 已实现

- 严格加载 project/flow/contract YAML，并限制项目内相对引用。
- 只允许显式授权的 IPv4 字面量、origin 和端口。
- 用固定 seed 生成 IdentitySwap、ResourceSwap 和敏感字段变异。
- HTTP 执行统一受请求数、超时和响应体预算限制。
- 同时观察 HTTP 与 owner API 的资源前后状态。
- 显式 Oracle 输出 SAFE、VULNERABLE 或 INCONCLUSIVE，再聚合为 PASS、BLOCK 或 INCONCLUSIVE。
- Evidence、报告和运行工件使用哈希、脱敏和原子写入。
- CLI 提供 validate、run、report 和 ci，CI 退出码稳定。

## 黄金场景

safe 与 vulnerable 样例拥有相同的业务关系和 Contract。差别是 vulnerable 版本在越权更新时先修改资源，再返回 `403`。owner API 观察能确认副作用，因此系统不会把 `403` 误判为安全。

当前样例路径：

- `samples/fixed_apps/ownership/`
- `samples/vulnerable_apps/ownership/`

## 阶段结果

- safe：`PASS`，CI 退出码 0。
- vulnerable：`BLOCK`，CI 退出码 1。
- 关闭必要 owner observer：`INCONCLUSIVE`，CI 退出码 2。

阶段 2 没有改变这些判定规则，只把执行迁移到持久 Job、Worker 和 Runner。实现阅读顺序见[模块地图](../模块地图.md)。
