缺口只使用四级结论：

- **阻止重构**：现有测试无法可靠阻止安全边界、稳定公共行为、持久兼容或执行隔离回归；本级才允许增加最小测试。
- **应该补充**：当前边界可重构，但后续应在相邻变更中增加证据；本阶段不为此扩展测试。
- **已有覆盖但位置不直观**：行为已有可靠断言，但测试位置或入口不在最直观的能力目录。
- **无需补充**：已有测试和架构约束足以作为重构门槛。

本次审计没有发现“阻止重构”缺口，因此不新增测试、不修改生产实现、不移动测试或样例。

“已有覆盖但位置不直观”只说明证据跨目录分布，不表示测试缺失，也不阻止本轮架构重构；后续触及对应边界时按矩阵中的最小回归集合执行即可。

## 重构使用说明

### 触及 Verification/Execution/Worker/Runner

先运行架构依赖、协议、Verification、安全范围、Worker/Runner、publication/recovery 和相关 e2e 集合；确认目标 I/O 仍只在授权环回样例和显式适配器内发生。

### 触及 Recording/Flow

运行 Recording execution、FlowDraft、浏览器边界和 API 控制面集合；重点检查 identity 隔离、脱敏先于持久化、审阅确认和回放隔离。

### 触及 Contract/Drift/LLM/API/GUI

运行 Contract domain/application/storage、API 工作台、CLI e2e、`ContractPage.test.tsx` 和 `App.test.tsx`；不得用前端或 provider 绕过治理 assessment、人工审阅和项目隔离。

### 触及 Migration/公共协议

运行 migration、storage、request store、Runner protocol 和历史 resolver 集合；旧 Run 必须仍能通过持久执行请求定位执行时 Contract，旧非 LLM Candidate 必须无损读取。
