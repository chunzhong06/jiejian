# 启动、控制与退出怎样协作

> 状态：CURRENT。API/CLI/MCP共享ApplicationCore；独立WorkerContainer只装配对应执行职责。

## 装配与调用

1. start.cmd及受控脚本准备环境与前端资源，serve先核对解释器、运行目录与单控制者锁，再创建ApplicationCore。
2. ApplicationCore显式创建UoW、业务服务和基础设施。无环依赖构造注入；运行provider、变化/原题、交付等使用具名连接，最终validate_connections只校验接线，不执行目标回调。
3. FastAPI挂载当前router及同实例MCP。GUI用本机control session/Origin，MCP用独立Bearer与逐项目权限，CLI只提供当前系统操作。所有业务写入进入对应workflow。
4. CHECK、RECORDING、PROOF_PREFLIGHT经通用Worker分支执行；Node运行加载由专用Runtime Worker持有目标；身份准备有独立受控浏览器进程。各自复用进程树和最小注入边界，不能混为一个任务生命周期。
5. Workspace、History、系统状态读取事实。只读系统状态不代表所有业务已接受，也不能由GUI本地状态替代后端事实。
6. 关闭按当前实现先确认受控录制、身份准备、Worker/运行监督等资源退出，再清理短期秘密与释放数据库资源。失败时保留可定位责任，不把清理异常覆盖主错误。

## 状态与所有权

| 资源 | 创建/所有者 | 读取/使用者 | 退出责任 |
| --- | --- | --- | --- |
| ServeLock与owner token | 当前serve进程 | Worker存活监督、第二实例检查 | 原持有者释放；旧文件不能证明锁仍有效 |
| UoW/Engine | ApplicationCore或WorkerContainer各自创建 | 本进程工作流/Repository | 各组合根确认依赖停止后close |
| MCP配对与项目提升 | agent_access与GUI决定 | transport及每个工具 | 暂停/撤权/重启/关闭清除临时提升 |
| 目标进程树 | 对应Supervisor/Worker | 当前执行者与恢复逻辑 | 只清理已证明归属的树，不接管用户进程 |
| 前端页面状态 | app/shared与具体feature | 用户交互 | 写后回读、陈旧响应隔离；不新增持久业务状态 |

## 失败路径

第二个控制者在创建核心服务前失败；不能共用同VarDir并行写。Worker bootstrap失败先核对是否已claim，采用对应条件事务。失去服务owner token触发持久取消并清理受控树。启动UI动画失败可以降低展示，不覆盖真实ready结果。维护预览、清理运行数据与用户数据重置是不同操作，不因为目录看起来临时就删除。
