# 修改官方示例与整链验收

> 状态：CURRENT。官方Sample通过普通业务边界、Recording、Preparation和当前CHECK链形成真实结果，不能预制Verdict。

## 默认Node展馆故事

首次权限草稿直接在普通候选整理工作面呈现为 Agent 回复，明确标注“示例模拟”，不声称真实 Agent 保存过候选。权限页与候选入口都可继续同一草稿，不经“其他入口”跳回示例页。展示版选择保留四张同级大卡；选择后在当前工作面打开普通完整 Proposal 审阅，仍需人的核对与批准，不自动写入正式权限。真实 Agent 已保存的候选仍按其原引用打开。

默认入口安装`samples/web/digital_gallery`的严格格式2清单。`OfficialSampleManager`只校验和复制这份Node源码，`NodeOfficialSampleExperience`编排普通接入、显式运行加载及材料入口；`NodeRuntimeSetup`、Runtime Worker与现有记录组件拥有目标和运行事实。`sample_workspaces.runtime_kind`明确区分NODE_ESM和旧PYTHON，同一项目不能被两个运行提供方同时认领。

人的展示版下载选择进入普通待审Proposal，随后仍由LOCAL_GUI批准。 同页提供允许下载、仅在线预览、这些都不是、暂不确定四个同级选项。后两项只引导自定义整理或暂缓，不按false解释，也不生成官方提案；自定义要求沿原草稿与人工审阅入口。三项动作是公开预览、公开展示版下载、内部完整包领取。内部包领取会为当前账号建立私有取用权限并交付实际ZIP；访问接口实际核对access_for与visibility。负责人允许这两项后果，评审禁止这两项后果；公开预览与已选择的展示版要求另行检查。合法对照与禁止路径覆盖同一组后果。

五个预设只改真实业务源码：正常起点、错误交付、独立提交开放后再撤回、正确修复、后续公开预览修改。每次修改经普通变化登记和受控加载，再使用原材料核对与完整检查。已发布结论只从关联本批change的Run读取；与历史同源码也不借旧PASS。源码偏离最后预设交付时进入普通开发，不覆盖外部修改。

“使用已提供的测试材料”一次建立并自动登录两个官方虚构账号，按需创建展馆资料，再导入录制、资源与证明来源候选。登录使用原身份准备管理器监督的独立进程：固定账号、已确认的本机地址、原有网络限制和 Windows SecretStore；通过实际登录响应与身份接口核对成功。已有可用账号、录制和资源复用，不重建；有自定义账号或尚未完成的手动登录时，明确提示处理。官方实例生成的 ZIP 和 PDF 通过普通参照输入服务一并导入，新来源直接填写参照引用；已存在的来源配置保持原样，缺文件时补充可选输入。重复准备复用相同文件。用户随后核对文件用途、读取范围、预检查和采用；示例安装不静默批准规则、授权读取或采用文件。业务文件仅在运行数据目录生成，不从源代码中的文件名或摘要推断交付成功。

账号已建立但未登录时，示例材料入口保持可用，并说明会自动登录和准备；原登录浏览器入口保留给手动处理。导入完成后回读准备事实和工作区，再展示证明核对任务。已有录制、资源、恢复和来源候选后，主操作进入具体证明核对；缺少来源时仍可导入候选。界面不将“已提供”解释为证明已获授权或所有材料已齐备。API 不直接执行浏览器；跨进程结果继续使用原账号准备合同，秘密不进入普通回执。超时收口原登录进程，返回有限错误，不重放未知写动作。

启动、重置和停止保留原操作键；查询不重放。Node加载仍使用持久Job和原回执，目标不在API进程启动。退出先取消本项目活动检查、等待回收并核对精确Node进程树，最后清理本项目临时登录状态；旧权限、源码和发布证据保留。新的应用接入仍从空白目录选择开始。

新实现与直接验证入口：`workflows/examples/node_environment.py`、`gallery_recipe.py`、`gallery_materials.py`；`tests/backend/workflows/test_node_official_sample.py`覆盖真实五次实现、两次独立提交、原题VERIFIED和历史不改写。正式GUI与MCP走同一`dev.ps1 sample-test`入口中的`gallery.py`和`gui/gallery.py`。人工体验与真实开发Agent的使用成本另行记录，不能由脚本耗时推算。

人的成本评估单独记录首次准备、代码修改、再次准备、返工和求助时间；区分自主完成与开发者介入。脚本执行时长用于定位系统等待，不能直接换算人的时间节省。只有真实组员使用记录才能支持“降低人的成本”的结论。

唯一最终入口为`dev.ps1 sample-test`。非前端编排由`official.py`保留真实start.cmd、新var、source receipt、解释器身份、端口保护、受控浏览器HttpOnly会话、限时等待、failure.json与精确清理；`current_api.py`编排已冻结配方和公开API。

默认Node顺序为：启动隔离实例、明确展示版含义并批准权限、实际登录与创建虚构资料、取样及采用来源、正常起点检查、错误交付检查、先开放后撤回检查、原题修复检查、后续预览改动检查、证据和唯一历史入口核对、MCP核对、退出与资源清理。完整sample-test只在最终产品验收时执行，局部修改使用直接测试。

每轮从精确change_id的check-preview取得计划指纹，向schema2 runs提交完整Plan。切换条件后若普通 Preparation 仍完整且 CheckPreview 可执行，则复用已有材料，不为 Sample 安装标记重复准备；未知回执先回读；GUI路径只定位本轮新Run用于收口，不再次POST；API专用编排若重取回执也只使用原idempotency_key，不能生成新key重复检查。仅在result_integrity=VALID后读取ResultStory/Evidence/repair-contracts；当前有界check-history、runs列表及精确run_id回读替代旧History，ProjectRepair替代旧Finding修复投影。普通 ResultStory、Evidence、Changes 和 Repair 是唯一分析路径，不保留 Sample 专用展示页；旧 Report/CLI/ResultPresentation 链不恢复，也不标成已验收。

### 同实例 MCP 责任场景

正常 Official 流程在五轮源码实现与历史验收后、退出前运行 `current_mcp.py`；没有第二入口，stop_after_setup 跳过完整检查与此场景。受控 SDK 客户端名为“界鉴验收客户端”，不调用用户 Coding Agent 或付费模型，不声称编写过修复代码。

先读取 MCP paired。已有用户级配对只经当前控制会话 reveal 后在内存复用，不重新 pair/rotate/forget；此前未配对才通过 `/tools` 的真实按钮创建，成功或失败后清理自己新建的配对并回读。凭据是 Windows 用户级资源，不随 var 隔离；token、headers、完整 SDK 异常和凭据响应不得进入日志、截图、报告、配置、剪贴板或持久环境。凭据/账户权限阻塞即停止，不替换 SecretStore 或切换身份重试。

通过 GUI 对唯一 Sample 项目选择并核对 READ/PREPARE/EXECUTE 回执。READ 登记变化与 PREPARE 提交检查各拒绝一次，以前后公开列表证明没有新增状态。默认使用 `jiejian_change_registration_preview` 和 `jiejian_change_register`，不创建或接收人工开发任务。PREPARE 只登记一次“受控验收核对当前修复源码，未修改文件”的声明，claimed_paths 为空，实际变化必须为零，来源包含本客户端；GUI 通过精确 change_id 展示记录及客户端来源，不自动打开本地登记表单。EXECUTE 只提交一次关联该 change_id 的完整普通检查，不携带原题修复引用，不用 HTTP 再提交，也不重发未知 SDK 回执；只回读新增 Run 供失败清理。

新增检查沿既有发布读取核对 PASS、三动作五 Case 与四个来源。它是第六个普通 Run，不能标 VERIFIED，也不能混进原五轮列表；原五轮及原题 VERIFIED 关系保持，summary 单列 MCP 证据及实际总数 6。用户仍在筛选历史页时，后台完成不改变 URL 或输入；实际点击完成提示后进入该精确新 Run，返回仍保留原筛选。确认无活动 Run 后恢复 READ、清理自建配对，再沿既有退出与资源清理。GUI、历史、路径或 MCP 必需记录缺失不能报告验收通过。

validation/competition/all及Portable是保留工具，不属于当前默认闭环，不为默认验收失败追加另一套技术L5。局部开发只跑直接测试/stub；最终前端与公开能力就绪后才运行唯一完整sample-test。

## 环境操作回执与历史

start/stop/reset/resume 接受可选 UUID operation_id；显式 ID 持久绑定一次操作，重复 ID 只回读，不再启停。Node 的 start/reset/resume 先持久受理并返回202，后台完成接入；内部需要等待的调用者仍等待同一操作。已有活动实例上的新 start 保持该实例，停止后的 start 与明确 reset 创建新项目；resume 保留当前项目。省略 ID 表示一次显式新操作，未知回执不得用新键重发。

状态查询可携带 operation_id 精确回读，lightweight 省略完整材料投影及变化记录。阶段依次为核对旧实例、创建项目、提交加载、等待目标、核对连接、整理源码。进度记录各阶段起止时间，界面只显示从同一受理时间计算的总用时。前端确认后立即关闭对话框，以400ms串行读取活动操作；明确成功后才同步完整工作区，隐藏页暂停显示轮询。已结束的旧操作不能混入新项目字段。

工作线程活跃时 reconcile 只回读；服务中断后的未知步骤不自动重放。已有精确项目和受控运行记录时核对原实例，其余保留 UNKNOWN 供处理；这不是跨重启自动恢复整个启动流程。后台关闭先等待环境编排结束，再释放运行所有者和数据库。

体验状态区分 NOT_STARTED、STARTING、RUNNING、STOPPING、STOPPED、FAILED 和 UNKNOWN，并给出 history_project_id、last_error_code、operation_id、operation_state。安装 available 与生命周期分开。服务重启不复活进程，旧 PENDING 只读投影 UNKNOWN；停止确认后为 STOPPED，项目与源码继续保留。连接部分提交失败保留已创建项目索引，清理错误不覆盖首个错误码。

`GET /api/experience/official-sample/history` 从独立持久操作表列出真实记录，默认25、最多100条并返回 has_more；不扫描日志猜历史。测试 `tests/backend/workflows/test_environment_receipts.py` 使用 stub 进程所有者验证重放、重启与局部失败，不替代真实环境验收。

## 示例执行链与结果解读

示例材料通过 GUI 的“一键准备示例材料”集中确认与连续处理，不要求演示者逐个核对四个来源。配方更新当前资源绑定和相应文件候选；手工修改过的非配方内容必须另外核对。预设修改加载新进程后，旧进程内的 Cookie 会话失效，示例同步清除旧登录准备状态，随后由一键准备重新登录；测试不得额外登录来掩盖产品中的旧会话问题。

数字展馆在真实请求入口、身份识别、权限判断、事务完成和响应准备处写入 `records.trace`。事务事件引用实际 operation_id，撤回是独立恢复事件；没有把版本名或预期结论写成事件。Runner 通过普通已采用来源读取并封存，旧运行结果不会补写路径。现有示例实例需要重新加载修改后的源码并重新检查，才能得到新链条。

这与普通 Node 应用共用通道，见[使用普通应用](使用普通应用.md)。示例的业务存储本来就依赖受控 `jiejian:records`；新增 Trace 不是让任意项目自动具备内部过程采集。诊断调用失败不改变业务响应，但界鉴会保留不完整说明。五个真实实现回归同时检查原有 PASS/BLOCK、实际事件发布及可读路径。

检查完成后使用界面的“Agent 协助”复制本轮请求。Agent 经 MCP 读取结果和证据，解释实验，再按用户决定修复与复验；界鉴不会仅因为复制了请求就显示“已发送”。

## 脚本所有权与诊断

`official.py` 只保留场景编排；`harness/state.py` 保存运行状态，`harness/receipt.py` 校验源码回执，`harness/lifecycle.py` 管准备、进程、端口与清理，`clients/http.py` 管 HTTP。`CurrentGui` 由共享 session 和 environment、boundaries、checks、history、mcp 动作组成；`reporting/diagnostics.py` 负责有界公开诊断。validation 下 models、runtime、evaluation、summary、suite 分责，不增加用户入口。

脚本直接测试分别检查 contracts、diagnostics、driver、environment、lifecycle、validation；`_support_sample_test.py` 只存无业务判断的准备与替身。失败记录保留 sample_test 根下的相对调用位置和首个错误，不发布绝对私人路径、响应秘密或完整 SDK 异常。

当前套件与证据范围见[环境与脚本](../../工程/运行与交付/环境与脚本.md#测试职责与本地计划)。算法矩阵的身份必须来自实际记录，恢复必须回读业务状态，进程清理另行核对。
