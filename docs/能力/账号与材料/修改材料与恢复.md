# 修改安全准备

> 状态：CURRENT。用于准备投影、四类技术绑定、材料局部更新和恢复。准备齐备不等于可执行，更不等于 PASS。

`PreparationGuidanceService` 只组合 Workspace、Preparation 与证明来源上下文，供 GUI/MCP 共享。全局任务由 Workspace 选择；来源内部的授权、预检查、采用只细分对应主任务。材料原因来自实际 reason_codes，未识别原因保持未知。读取前后的依据改变时返回 NEEDS_REFRESH，不输出混合建议；真实写入仍由原 CAS、授权与回执事务核验。该服务没有持久化 READY、目标请求或结论写入。

`PreparationSuggestionService` 追加保存五类有限建议。规则未批准时引用精确候选修订及局部角色/动作/结果；同一候选仅保存范围决定或修改其他动作时，相关业务含义未变的建议可以沿当前头续接。批准后必须通过实体引用映射续接原材料操作。旧批准缺映射时明确不可关联，不按名称或顺序猜。新建议根为格式2，增加服务端逐项依赖摘要；格式1仍严格读取。最多50项、10个未决问题、256KiB；依赖必须引用同清单且无环，禁止凭据、任意脚本/请求配置或可用状态。

建议依据`psb_…`覆盖规则、授权源码、账号、资源、执行/证明/恢复绑定、全部录制及来源头和读取范围，用于写入CAS与同次读取一致性。保存需原operation_id、expected_basis_id和更新时的expected_revision：同一写锁核验、追加修订、CAS与回执提交，源码在提交前再核对。读取格式2时分别核对每项的规则、源码、明确材料引用及前置建议；完成其他材料不会使整份建议过期。一项依赖失效仅影响该项及其后继，返回逐项原因与可沿用数量。格式1缺少逐项摘要且整体依据变化时保留待核对，不能倒推历史依据；更新一次后使用格式2。已被新修订替代的记录继续仅供回看。

建议是否适用与材料是否齐备分别展示。实际可用性仍由原登录、录制、Inspector、来源预检查与采用决定。读取仅给出已核验的相对源码位置，其他办法标为假设；不读取额外文件正文。准备进度从Preparation按全部动作汇总，列出已齐备数量、剩余材料类别和规则/合法对照缺口；GUI与MCP共用同一投影。完整检查仍由原计划与提交门槛决定，不根据计数放行。读取不一致时不输出进度，保留重新读取入口。

GUI和MCP共用上述服务。现有`proof-preparation`上下文扩展`suggestion_context`；该前缀下`POST /suggestions`保存、`GET /suggestions/{id}?revision=`读精确修订、`GET /suggestion-receipts/{operation_id}`查原回执。建议读取失败局部降级，不阻断原材料操作。前端“Agent 协助”与“读取建议”并排，内容在原五类材料行内展开；未批准的建议保留在同页等待规则核对，不建立第二套审批或准备状态。返回保留项目、动作、批次、任务及建议修订。

MCP 建议输入错误返回以 `suggestion` 为根的已声明字段路径，不回显输入值。`material.capability` 从 `supported_evidence_capabilities` 选择；`RESOURCE_FIELDS_V1`、`TRANSACTION_HISTORY_V2` 属于来源合同 `source_contract_id`，不能填作能力标识。误填合同应修正字段，不能据此删除原业务结果或断言读取能力不存在。

## 必须保持

- 当前服务从正式 Action/Permission revision、账号与技术绑定现场派生状态；不持久化第二份 READY，不修改业务权限。
- DENY 必须有完整合法 ALLOW 对照；并列候选由用户明确选择。缺口不是安全结论，前端不选择身份或任务优先级。
- 材料引用必须匹配项目、动作修订、用途、subject / owner 与受控实例；源码、endpoint 或来源漂移失败关闭，不按名称匹配。
- 材料确认先核对预览基线，绑定与回执在同一写事务中提交；同一 operation_id 只回读同一请求，不能重复写入。
- 草稿只存有限引用和回读标识，不存秘密、任意表单或登录内容。草稿恢复后仍重新读取 Preparation。
- 候选录制审阅完成不自动替换正式绑定；采用须经过影响预览和确认。已有 Run 的冻结输入与证据不改变。
- 普通准备 GET 不运行目标、浏览器或模型；Recovery 不删除历史证据，环境 reset 不冒充动作恢复。

## 按问题读取细节

GUI确认的材料批次由 `product/backend/workflows/preparation/batches.py` 保存固定计划、逐来源操作键、回执与取消决定。完成步骤立即推进；每轮最多8步、100ms软预算，等待子任务时让出。Worker退出唤醒协调器，2秒读取作为兜底；登录阶段有界观察间隔为200ms。取消在每次写入前重新读取，保存进度不得覆盖已经提交的取消。

官方配方的两个账号分别提交受监督登录进程，最多并行两个；录制、资源与文件按依赖顺序处理。每项证明保存自己的授权、预检查与采用进度，最多两项预检查在途，已完成项保留。旧实例、权限、账号、资源、配置和读取授权变化仍按原合同失效；原样复用依据当前准备事实，不新建登录或预检查任务。批次成功只说明材料准备完成，正式检查仍重新核对条件。

持久批次payload格式2支持逐项进度；旧格式1的终态仍可读取，未结束旧批次以及控制会话变化后的批次停止推进，保留回执让用户重新确认剩余计划。未知写入只回读原操作，不能以新键试探。页面关闭不取消后台批次；取消只停止本批次拥有的子任务，不撤销已采用材料。Worker并发边界见[Worker与Runner](../检查执行/修改Worker与Runner.md)。

来源服务内部使用具名 `PreparationFacts` 传递同一事务中读取的规则、源码、账号、资源、运行与依据标识；它只存在于内存，不能被保存为第二套准备状态，也不改变公开配置、回执或指纹输入。

证明来源的配置、读取授权、独立预检查、采用及复用见[证明来源指南](../证明来源/修改证明来源.md)；完整交换语义见[来源契约](../证明来源/证明来源契约.md)。本页只拥有材料派生、绑定、局部更新与准备建议。
