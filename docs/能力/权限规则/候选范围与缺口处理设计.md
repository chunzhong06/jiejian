# 候选范围与缺口处理设计

> 状态：CURRENT。记录本轮实现的业务约束与使用路线；不表示已完成运行验收。用户要求不运行额外检查，本轮提供生产组件截图供视觉审阅。

## 要解决的问题

源码发现的接口、用户的业务要求和准备步骤曾混在同一候选。数量限制促使 Agent 合并接口；所有未决限制又统一阻止规则审阅，使明确的规则无法进入准备。改动保留原始要求、人的决定、正式批准和完整检查门禁，不将限制声明当作通过证明。

## 范围先行

Agent 通过原候选保存接口一起整理 requirement_sources 与权限；确实无法整理时可以先保存范围。每项记录稳定标识、标题、来源类别、依据原文、Agent解释及权限映射。USER只是来源声明，不当作已获人同意。明确的草稿错误先由Agent修正，真正未明确的业务含义再交给用户。

用户逐项确认纳入本轮、仅用于准备恢复、不属于本轮或暂不确定，记录实际要求、理由及检查窗口/历史/不涉及时间的范围。全部来源都确认为准备或不属本轮且没有权限时，仅记录范围，无需编造权限或生成空提案；这些记录仍会进入之后的范围快照。只有 GUI 可提交决定。权限及必要正常对照必须关联已确认的本轮要求；准备和排除项不能同时作为有效权限。不静默删除旧来源；纠正保留历史。权限映射补齐不使原话确认失效，原文、解释、来源或正式依据变化则重新确认。

新候选根为格式6；旧1～5保持独立reader。纠正建议、辅助说明及局部依赖的具体合同见[修改规则候选](修改规则候选.md)。旧记录没有足够依赖证据时保守复核一次，不补造来源与人的同意。

## 分批保存与完整审阅

merge=true按稳定标识合并角色、动作、权限、来源与情境，未提交项保留；例子按权限标识替换，问题与限制去重并保留。原文改变需完整修订。根文档仍限制1MiB，最多100动作、200权限、400例子、100来源；超过预算明确拒绝，不裁切数据。所有批次在同一候选修订链上，最终只形成完整提案。正常对照、关系及引用校验始终保留，不再只在有情境时检查正常对照。

## 问题分工

next_tasks从当前问题产生USER、AGENT、CAPABILITY处理者。补充请求只要求处理当前问题，已解决决定作为约束附带。范围问题无需编造相反选项；材料问题不要求生成情境；未知写回执只查询原键。MCP仍无范围确认、正式批准和来源采用工具。

## 缺口进入检查准备的条件

真实准备、证明或覆盖缺口仍先经原业务边界核对保存。Agent可在coverage_suggestions预填已核对的权限、HTTP目标入口与证明类型；这些建议没有批准效力。用户另行确认该要求对应的候选权限、HTTP目标入口、需要业务结果证明还是过程记录，以及时间范围。关联绑定问题指纹和人工决定修订；原文、业务实体、权限或人工解释变化均使关联失效。

未列全的关联可先保存为DRAFT，继续阻塞。只有人明确确认关联清单完整，且当前窗口关联有效时才为PLANNED，只允许规则进入提案审阅，不等于条件满足；清单或时间修改后需重新确认完整性。HISTORY、未确认业务含义、缺少关联或失效关联继续阻止提案。真实业务规则仍需正确表达，不能用材料关联替代。

检查预览与提交事务从候选批准映射查找精确Permission修订/hash，与当前Case对应，并核对冻结配置中的TARGET请求方式和完整路径段。SETUP不计作覆盖；同一业务动作的两个接口分别列入关联，一份单TARGET录制不能同时满足两个不同路径。需要独立验证时应保留两个可独立准备的动作及相应正常对照，不用标题合并充当覆盖。

PROCESS_RECORD额外要求受保护状态变化效果具有匹配的受控事务记录来源；最终状态快照不能替代过程记录。原计划仍校验账号、资源关联、证明能力、恢复及合法对照，实际执行仍由Worker/Runner完成，最终结论由Verification形成。任意全历史能力未新增，不能将其降为当前窗口。

缺少映射、Case、TARGET或证明时继续阻塞；可准备的缺口提供材料入口。材料失效或正式规则修订变化后实时重新阻塞，没有手工“标为完成”开关。候选归档不隐藏缺口，继续同一候选链修订；本轮不提供跨候选自动承接或自然语言等价消除。

## 范围冻结与结果

CHECK请求新增格式5，保留既有完整计划算法及证据标准，额外冻结已批准候选修订、人的实际要求、范围分类、时间范围与精确权限引用。预览指纹包含范围快照；提交事务重核，不能以旧预览提交新范围。独立reader校验本轮要求确实关联执行Case，排除项不携带已检查权限。旧请求3/4和旧结果不补写新范围。

检查页展示已确认要求及准备/未纳入内容；结果页只读本轮冻结范围，明确未纳入项没有接受独立验证。保持完整检查，不新增删除缺失Case后的部分检查模式。

## 后续验收场景

- 新项目先保存范围，未经GUI确认的接口不得成为可审阅规则；MCP伪造人的决定被严格输入拒绝。
- 同一要求补合法对照，超过10条分批合入同一候选，不丢旧项、不新增相反业务选项。
- 修改原话、时间范围或正式依据时重新确认；补例子、补权限映射沿用仍有效的范围决定。
- 旧1/2/3记录、已有2/2情境决定、归档记录可读；未知回执不重复写，旧revision和同键异文被拒绝。
- 两个不同TARGET入口，遗漏其中之一或只在SETUP出现时阻塞；准备完整后允许提交，撤销来源或更改规则后再次阻塞。
- 当前过程要求需要过程记录；全历史要求仍阻塞；409不能作为权限拒绝。
- 提交前后范围变化、候选并发修订和原始要求遗漏不能绕过门禁；旧结果不继承新范围。
- 页面审阅覆盖范围待确认、已保存、需要重新确认、检查关联待准备、检查阻塞及历史范围摘要，包含窄屏。
