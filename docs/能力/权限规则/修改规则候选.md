# 修改规则候选

> 状态：CURRENT。原Agent或GUI提交的候选只表达待审意图；人通过提案批准后才产生正式权限。

## 快速找到修改位置

| 任务 | 主位置 | 一起检查 |
| --- | --- | --- |
| 候选上下文、保存、读取和回执 | `product/backend/workflows/business_boundaries/candidates/rule_candidates.py::RuleCandidateService` | 当前basis、期望修订、同键异文；`tests/backend/api/boundaries/test_rule_candidates.py` |
| 候选转提案、沿用与影响预览 | 同服务的propose、_merge、_reuse_prediction | proposals及正式边界服务；不得跳过用户审阅 |

| Agent工具 | `product/backend/api/mcp/server.py` | rule_context/save/show/operation，READ/PREPARE权限与脱敏；`tests/backend/api/system/test_current_mcp.py` |
| GUI展示 | `product/frontend/src/features/boundaries/` | 候选、提案与正式规则分层；同目录组件测试 |

## 修改路线

先读context获得当前正式边界及不透明basis；save验证basis和精确候选修订，保存候选与操作回执；show按修订展示候选和沿用分析；GUI显式propose形成普通提案。之后由[规则与批准](修改规则与批准.md)的唯一决定事务处理，不在候选服务里推进policy_epoch。

来源描述、客户端名称和Agent理由只用于审阅，不等同于认证或事实证明。自然语言模型草稿查[模型服务](../控制面/修改模型服务.md)，它同样不能代替正式批准。

## 失败与验证

同键异文、旧basis、旧revision和边界并发变化均应拒绝，不覆盖新决定。响应未知按project/kind/operation_id查询；找不到回执不能证明未执行。重点核对保存后仍非正式、提案生成不等于批准、重复键幂等、影响预览没有写入。涉及格式再验证严格reader和Schema，涉及MCP再测授权；不为候选展示改动重跑检查执行。

完整事务关系见[批准协作](批准协作.md)。
