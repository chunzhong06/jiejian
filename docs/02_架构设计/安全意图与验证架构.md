# 安全意图与验证架构

> 状态：CURRENT。当前适用范围：权限契约治理、覆盖生成、执行事实、证据、验证结论和回归门禁。

## 职责

说明安全意图如何被审阅、编译为覆盖计划，如何与真实执行事实和观察事实关联，以及如何形成 Finding、Baseline、Gate 和 Report。

## 非职责

- 不执行目标请求，不定义 Worker/Runner 调度细节。
- 不把 LLM 候选当作安全结论或自动激活契约。
- 不定义协议 JSON 的完整字段表。
- 不把生命周期状态、Verdict 和 GateResult 合并为一个状态。

## 真源

领域代码位于 `product/backend/core`，公共模型和 Schema 位于 `product/protocols`。

## 目的

真实区分“想验证什么”“观察到了什么”“能否形成结论”和“是否通过交付门禁”。

## 组件与边界

- `Requirement` 表达待验证的权限意图。
- `ContractCandidate` 是确定性或 LLM 生成的待审阅建议。
- `PermissionContract`/`ContractVersion` 是唯一可执行安全意图；只有 ACTIVE 版本可进入执行。
- `Coverage` 和 `PermissionMutationPlan` 将契约编译为有界用例、关系和 required observations。
- `ExecutionProjectSnapshot` 与 `PersistedExecutionRequest` 固定 Contract、计划、bindings、指纹和运行预算。
- `ExecutionFact` 表示请求结果事实；`ObservationFact` 表示真实副作用或状态观察事实。
- `Evidence` 保存不可变 Case 快照、事实、观察完整性和有界脱敏证据。
- `Verification` 根据规则和证据形成 Verdict；`Finding` 保存安全发现；`Baseline` 表示历史比较；`Gate` 决定交付门禁；`Report` 只汇总已发布语义事实。
- ownership 和 permissions 使用同一 Permission → Runner → Evidence → Verification → Results 链；复杂关系不建立第二套安全结论路径。

## 关键数据流

```text
安全意图
  → PermissionContract
  → Coverage / PermissionMutationPlan
  → 冻结执行快照
  → ExecutionFact + ObservationFact
  → Evidence
  → Verification
  → Finding
  → Baseline / Gate
  → Report
```

拒绝表面但真实副作用已发生时，形成越权发现并进入 BLOCK；required observation 缺失、不完整或 UNKNOWN 时只能形成 INCONCLUSIVE；完整事实证明规则正确时才可形成 PASS。INVALID 表示结果不能形成安全结论。

## 关键不变量

- Candidate 不能绕过审阅、不能自动激活 Contract、不能进入 Runner。
- ACTIVE ContractVersion 不原地修改；执行使用绑定版本和冻结快照。
- `ExecutionFact` 不携带 HTTP method、path、body 或 URL；HTTP 细节留在 Web binding 和受限观察中。
- Evidence 发布后不可变，Finding/Gate/Report 不反改原始 Verdict。
- Verification Verdict、Job/Run 生命周期和 GateResult 分开保存。
- LLM 只能提出候选或解释，不得决定 Verdict、Finding 或 Gate。
- 产品结果读模型只能从已发布快照、ExecutionFact、ObservationFact、Evidence、Finding 和 Verification 确定性投影可读标签与解释，不得重写 Finding 身份、Occurrence Verdict、Verification Verdict 或 GateResult。

## 失败语义

候选冲突、契约不完整、覆盖缺口、指纹漂移、观察缺失、证据不完整或事实 UNKNOWN 时拒绝给出安全结论，并保留可解释的限制原因。验证失败与执行生命周期失败分别记录，不能用 Job 完成态替代安全 Verdict。

## 安全约束

权限规则、目标范围、身份、动作和 required observation 必须可追溯到同一执行快照。秘密值不进入 Contract、协议、Evidence、日志或报告。结果中的原始观察必须有界并脱敏。

## 兼容与版本

Schema/protocol 版本只描述机器格式；不代表产品代际。未知字段、结构签名、指纹或证据关联不满足要求时严格失败，不按旧开发格式猜测读取。
