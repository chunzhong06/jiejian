# 产品入口与控制面架构

> 状态：CURRENT。当前适用范围：Windows 启动、首次使用、Web GUI、CLI、CI、loopback API 和 Worker 控制面。

## 职责

说明用户或 CI 如何进入产品、如何建立项目和权限规则、如何提交和观察检查，以及入口如何与高风险执行隔离。

## 非职责

- 不直接执行目标请求，不定义 Runner 字段或 Verification 规则。
- 不把页面展示状态当作安全结论。
- 不把 CLI_APPLICATION、MCP_AGENT、MCP ingress 或本地命令执行写成当前产品入口。
- 不复制启动脚本的全部实现细节或前端组件细节。

## 真源

入口真源是根 `README.md`、`start.cmd`、启动脚本、`product/backend/api`、`product/backend/cli`、`product/frontend`、ApplicationCore 和相关测试。

## 目的

真实区分产品使用入口、控制面和目标执行边界。

## 组件与边界

- `start.cmd` 是正式产品入口，使用 uv 私有 Python、已安装 Wheel、Chromium 和预构建前端 `dist`；正式运行不调用 Conda、Node、pnpm、TypeScript 或 Vite，也不创建 `node_modules`。
- `scripts/dev.ps1` 是仓库开发入口，负责 Conda Python 基线与 frozen uv 精确同步，并提供 bootstrap、sync、update、start、test 和 shell；只有 update 可以修改 `uv.lock`。
- Web GUI 提供工作台、应用接入、权限规则、开始检查、检查结果、历史变化和高级能力。
- CLI 同时提供面向普通用户的引导工作台、熟练用户命令和 CI 自动化入口；Human、JSON、CI 与内部日志互不混用。
- API 是 loopback 资源、任务、事件和结果控制面，负责严格解析、授权、ApplicationCore 调用和脱敏错误映射。
- API 内部路径统一为 `/api`；SSE 使用持久事件序号恢复，客户端断开后停止数据库轮询和等待。
- Onboarding 只允许目录选择和受限、只读项目识别；不执行目标命令、不联网、不读取源码正文或秘密。
- GUI、CLI 和 API 复用 ApplicationCore 下的应用服务；Worker 使用独立 WorkerContainer，Worker/Runner 才能进入高风险执行链。
- “运行环境”页与 CLI 复用同一缓存维护服务，提供缓存状态、按预算清理、清空可重建缓存和修复运行时；数据重置不进入缓存入口。

## 关键数据流

```text
start.cmd
  → loopback 服务
  → GUI / CLI / CI
  → API 或 CLI 调用 ApplicationCore
  → Project / Contract / Profile / Job
  → Worker / Runner 执行
  → GUI / CLI / Report 读取已发布事实
```

首次使用主路径是：应用接入 → 权限规则 → 开始检查 → 检查结果。结果页必须分别展示执行生命周期、Evidence、Verification Verdict 和 GateResult。

### Windows 启动交互

- 启动准备保持六个有序阶段及其缓存、诊断、迁移、Chromium 和前端构建语义；每个任务只有一个主结果节点，版本、缓存状态和 revision 作为详情。准备完成后，第一层显示“图形界面 / 命令行 / 仅完成环境准备”，命令行第二层显示“引导模式（推荐） / 普通命令行 / 返回”。两层都把“↑ ↓ 选择    Enter 确认”固定显示在选项下方，方向键只重画选项行；RawUI 不可靠时一次性降级为带编号操作说明的选择。
- `RuntimePaths` 把 `VarDir` 固定分成 `data`、`runtime`、`cache`、`logs`、`temp` 和 `test`。数据库、Job、项目、Evidence、报告和工件检查只进入 `data`；可重建工具链、浏览器与锁进入 `runtime`；内容缓存进入 `cache`。旧根部布局不迁移、不双读。运行时和下载不得写入 `product/`、用户 profile 或 `VarDir` 根部。
- 启动器在选择 Python 后必须清除继承的 `PYTHONHOME/PYTHONPATH`、启用 `PYTHONNOUSERSITE`，并核对实际解释器、环境前缀、`sys.path` 与关键依赖来源。主进程把已确认的解释器身份传给 Worker，Worker 启动前再次核对；任一来源漂移都停止运行并展示解释器、Node、pnpm、Playwright、前端依赖和恢复建议。Playwright 浏览器固定进入 `VarDir/runtime/playwright`，不能静默复用用户目录缓存。
- 图形界面继续进入 `serve --open`。引导模式按 ApplicationCore 的真实事实给出下一步，并可完成内置演示检查；普通命令行进入仅对当前子进程生效的 PowerShell，直接调用已经解析的 Python 绝对路径，并继承已确认的 `VarDir` 与 Node/pnpm PATH。退出后不得留下永久 `PATH`、PowerShell profile 或系统环境修改。
- 服务 ready 后启动动画立即结束，终端明确提示网页退出入口与 `Ctrl+C`，并继续持有服务生命周期。GUI 的“退出界鉴”使用带专用控制头的 loopback 请求触发同一 shutdown 链；正常退出依次停止 Worker、受控 Runner/浏览器和 ApplicationCore。系统浏览器页面属于用户进程，不被强制关闭，页面只提示服务已停止后可关闭。
- 自动化调用必须显式选择 GUI、CLI 或 prepare 模式；直接调用 `scripts/start.ps1` 时保持可组合的退出码并立即返回。`start.cmd` 对 PowerShell 的任意非零退出统一保留原始退出码，并在阶段、错误码、主错误、日志和恢复建议输出后等待用户关闭窗口；该兜底也覆盖参数解析和模块加载失败。

### CLI 引导与输出通道

- 引导首页只使用应用、身份、权限规则、业务流程、开始检查和检查结果等产品词。它从 Project、Contract、Execution、Recording 和已发布结果读取状态，不保存独立 Guide Progress，也不重新实现业务规则。
- 内置演示提供权限限制正常、存在权限问题和证据不足三种真实结果，仍通过 onboarding、Worker/Runner、Evidence、Verification 和 publication。真实应用的复杂权限矩阵、关系图和大量流程编辑转入现有图形界面。
- 同一演示变体只在关联 Job/Run 仍处于一致活动态，或已形成可信发布结果时复用；FAILED、CANCELLED、缺失或不一致的旧关联必须停止旧 Target、清理会话秘密并创建新的 Session、Run 和 Job，旧失败记录保留为审计事实。
- Human stdout 只呈现结论、关键事实和下一步，默认隐藏内部 ID、原因代码与复杂结构；`--verbose` 才显示有界技术详情。`--json` stdout 只包含一个机器对象，CI 保持严格机器接口。脱敏结构化日志写入 `VarDir/logs/jiejian.log`，普通 CLI 命令不把 INFO 日志混入 stderr。

### 流程录制产品闭环

普通用户从项目已经登记的 `ExecutionProfile` 中选择一个可读身份，进入有界的有头 Chromium 会话。浏览器准备和人工登录不进入录制事件；用户明确开始后才采集，明确停止后保留事件并生成 `FlowDraft`，取消则丢弃本次录制并进入 `CANCELLED`。产品控制面只提交 `profile_id` 与单一 `identity_id`，不得要求普通用户提供本地 profile 路径、逗号身份列表或 headless 开关。

`STARTING` 表示浏览器准备至等待明确开始的持久生命周期，`RECORDING` 只在开始采集后进入；更细的准备、等待、采集和停止阶段由 attempt 控制事实投影，不扩展持久状态枚举。开始与停止由 API/ApplicationCore 写入当前 attempt 的有界无秘密控制标记，Worker/Runner 消费标记并保持 TargetScope、事件预算、网络预算、脱敏和清理边界。

Worker 在 claim 前发生确定性启动失败时，尚处于 `CREATED` 的 Recording 可直接进入 `FAILED`；该路径保留 `started_at_us` 为空，不伪造 `STARTING`、attempt 或 fencing token 事实。

审阅页以步骤卡片和动态变量为主，允许重命名、删除、合并相邻步骤及确认歧义变量来源，最终动作只有“确认并保存流程”；原始 JSON 只允许放在高级信息中。生成的 Web target/binding 仍进入普通 ExecutionWorkflow、Evidence、Verification 和结果发布链。

状态化 Web 配置继续进入现有页面：普通用户确认目标步骤、允许/拒绝身份、预期安全效果和可信观察器，登录、Cookie、CSRF、OAuth2、动态变量、基线与闭合细节收进高级设置。CLI 只扩展现有引导，不建立第二套向导，也不要求普通用户手写 Runner JSON。

### 结果与权限解释

- 检查结果先回答“谁对什么执行了什么、规则期望什么、表面请求怎样、真实对象是否变化、为何形成该结论”，再展开安全意图、执行事实、观察事实和确定性结论；EvidenceTimeline 位于解释之后，内部标识默认收进高级信息。
- 状态化关系差分结果必须同时说明请求表面、安全效果、ALLOW 控制、基线完整性、时间闭合和最终结论；workflow/twin/effect 指纹只在高级信息展示。
- PASS、BLOCK 和 INCONCLUSIVE 使用同一信息层级。尤其“请求表面被拒绝但真实资源已改变”必须直接显示为越权事实，不能由状态码替代真实观察。
- 用户可见结果只使用已发布执行快照、Evidence、Finding 和 Verification 的确定性投影；展示读模型可以补充可读标签和因果说明，但不得改变 Finding 身份、Occurrence Verdict、Verification Verdict 或 GateResult。
- 权限矩阵使用可筛选热力表表达身份、角色、动作和资源，稳定区分 ALLOW、DENY、未声明与冲突，并支持单元格详情。关系看板的全局模式只展示身份、资源和 OWNS、SAME_TENANT、MEMBER_OF 等业务关系，角色作为身份属性而非独立节点；聚焦具体身份后才过滤相关关系并加入该身份自己的权限边。看板使用确定性的行式布局和响应式纵向布局，不依赖无限画布的缩放或平移；中文含义与原始标识分层展示，状态与关系不能只依赖颜色。
- GUI 与 CLI 的任务文案、按钮、状态和业务含义默认使用中文。品牌、命令、文件格式、代码、协议字段、路径及需要复制或对照的机器值保留原文；已知业务枚举使用“中文含义（原值）”展示，不能通过修改协议数据实现翻译。技术原值集中放在次要文字、高级信息或 `--verbose` 中。

## 关键不变量

- API、GUI 和 CLI 不直接创建 Engine、UnitOfWork、RequestStore 或 Dispatcher。
- API/GUI 不直接向目标发高风险请求。
- loopback 控制面与目标执行进程隔离。
- 用户可见状态不替代机器结果；INCONCLUSIVE 不得显示为安全通过，HTTP 拒绝也不得替代真实状态观察。
- 启动失败、浏览器未打开、运行环境不可用和检查无法开始都应给出可恢复、脱敏的提示。
- 普通用户错误固定展示失败阶段、原因、任务标识、日志位置和下一步，并提供可复制文本；内部堆栈只进入有界脱敏日志。

## 失败语义

启动准备、浏览器、数据库、前端、API 输入、项目识别、Contract/Profile、目标地址或运行环境失败时，入口停止当前动作并保留可诊断日志。控制面断开不等于执行成功或失败；事件序号用于恢复读取。

## 安全约束

默认只监听本机回环地址。Onboarding 的识别预算、目标范围、身份、写操作、reset、重定向、私网和请求预算必须显式确认或由执行边界校验。秘密不进入前端、协议、日志、Evidence 或报告。

## 兼容与版本

当前产品入口只服务 Web Target。CLI 的产品命令以实际 help 和启动输出为准；公共 JSON/Schema 版本不是产品代际。生产协议与当前使用路径都不保留未实现的 CLI_APPLICATION、MCP_AGENT 或 MCP 占位。旧启动模式、旧参数位置和旧路由 alias 不兼容保留。
