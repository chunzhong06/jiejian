# 产品入口与控制面架构

> 状态：CURRENT。当前适用范围：Windows 启动、首次使用、Web GUI、CLI、CI、loopback API 和 Worker 控制面。

## 职责

说明用户或 CI 如何进入产品、如何建立项目和权限规则、如何提交和观察检查，以及入口如何与高风险执行隔离。

## 非职责

- 不直接执行目标请求，不定义 Runner 字段或 Verification 规则。
- 不把页面展示状态当作安全结论。
- 不把 CLI_APPLICATION、MCP_AGENT、MCP ingress 或本地命令执行写成当前产品入口。
- 不复制启动脚本的全部实现细节或前端组件细节。

## 真源

入口真源是根 `README.md`、`start.cmd`、启动脚本、`product/backend/api`、`product/backend/cli`、`product/frontend`、ApplicationCore 和相关测试。

## 目的

真实区分产品使用入口、控制面和目标执行边界。

## 组件与边界

- `start.cmd` 是 Windows 默认双击入口，实际链路为 `start.cmd → scripts/start.ps1 → 准备阶段 → 交互选择`；启动脚本准备 Python 环境、依赖、Chromium、数据库和前端，随后进入图形界面、命令行或仅完成环境准备。
- Web GUI 提供工作台、应用接入、权限规则、开始检查、检查结果、历史变化和高级能力。
- CLI 提供运行、报告和 CI 自动化入口；Human、JSON 和 CI 机器语义分离。
- API 是 loopback 资源、任务、事件和结果控制面，负责严格解析、授权、ApplicationCore 调用和脱敏错误映射。
- API 内部路径统一为 `/api`；SSE 使用持久事件序号恢复，客户端断开后停止数据库轮询和等待。
- Onboarding 只允许目录选择和受限、只读项目识别；不执行目标命令、不联网、不读取源码正文或秘密。
- GUI、CLI、API 和 Worker 复用 ApplicationCore；Worker/Runner 才能进入高风险执行链。

## 关键数据流

```text
start.cmd
  → loopback 服务
  → GUI / CLI / CI
  → API 或 CLI 调用 ApplicationCore
  → Project / Contract / Profile / Job
  → Worker / Runner 执行
  → GUI / CLI / Report 读取已发布事实
```

首次使用主路径是：应用接入 → 权限规则 → 开始检查 → 检查结果。结果页必须分别展示执行生命周期、Evidence、Verification Verdict 和 GateResult。

### Windows 启动交互

- 启动准备保持六个有序阶段及其缓存、诊断、迁移、Chromium 和前端构建语义；准备完成后，交互入口显示“图形界面 / 命令行 / 仅完成环境准备”，用方向键和 Enter 选择。
- 图形界面继续进入 `serve --open`。命令行进入仅对当前子进程生效的已准备 PowerShell，会话内提供项目 CLI 入口、`VarDir` 和常用命令提示；不得永久修改 `PATH`、PowerShell profile 或系统环境变量。
- 自动化调用必须显式选择 GUI、CLI 或 prepare 模式；直接调用 `scripts/start.ps1` 时保持可组合的退出码。只有从 `start.cmd` 双击进入的交互失败才在完整显示阶段、错误码、主错误、日志和恢复建议后等待 Enter。

### 流程录制产品闭环

普通用户从项目已经登记的 `ExecutionProfile` 中选择一个可读身份，进入有界的有头 Chromium 会话。浏览器准备和人工登录不进入录制事件；用户明确开始后才采集，明确停止后保留事件并生成 `FlowDraft`，取消则丢弃本次录制并进入 `CANCELLED`。产品控制面只提交 `profile_id` 与单一 `identity_id`，不得要求普通用户提供本地 profile 路径、逗号身份列表或 headless 开关。

`STARTING` 表示浏览器准备至等待明确开始的持久生命周期，`RECORDING` 只在开始采集后进入；更细的准备、等待、采集和停止阶段由 attempt 控制事实投影，不扩展持久状态枚举。开始与停止由 API/ApplicationCore 写入当前 attempt 的有界无秘密控制标记，Worker/Runner 消费标记并保持 TargetScope、事件预算、网络预算、脱敏和清理边界。

审阅页以步骤卡片和动态变量为主，允许重命名、删除、合并相邻步骤及确认歧义变量来源，最终动作只有“确认并保存流程”；原始 JSON 只允许放在高级信息中。生成的 Web target/binding 仍进入普通 ExecutionWorkflow、Evidence、Verification 和结果发布链。

### 结果与权限解释

- 检查结果先回答“谁对什么执行了什么、规则期望什么、表面请求怎样、真实对象是否变化、为何形成该结论”，再展开安全意图、执行事实、观察事实和确定性结论；EvidenceTimeline 位于解释之后，内部标识默认收进高级信息。
- PASS、BLOCK 和 INCONCLUSIVE 使用同一信息层级。尤其“请求表面被拒绝但真实资源已改变”必须直接显示为越权事实，不能由状态码替代真实观察。
- 用户可见结果只使用已发布执行快照、Evidence、Finding 和 Verification 的确定性投影；展示读模型可以补充可读标签和因果说明，但不得改变 Finding 身份、Occurrence Verdict、Verification Verdict 或 GateResult。
- 权限矩阵使用可筛选热力表表达身份、角色、动作和资源，稳定区分 ALLOW、DENY、未声明与冲突，并支持单元格详情。关系图以身份、角色、资源分组，支持总览、主体聚焦、缩放、平移和自动布局；状态与关系同时使用文字或图例，不能只依赖颜色。

## 关键不变量

- API、GUI 和 CLI 不直接创建 Engine、UnitOfWork、RequestStore 或 Dispatcher。
- API/GUI 不直接向目标发高风险请求。
- loopback 控制面与目标执行进程隔离。
- 用户可见状态不替代机器结果；INCONCLUSIVE 不得显示为安全通过，HTTP 拒绝也不得替代真实状态观察。
- 启动失败、浏览器未打开、运行环境不可用和检查无法开始都应给出可恢复、脱敏的提示。

## 失败语义

启动准备、浏览器、数据库、前端、API 输入、项目识别、Contract/Profile、目标地址或运行环境失败时，入口停止当前动作并保留可诊断日志。控制面断开不等于执行成功或失败；事件序号用于恢复读取。

## 安全约束

默认只监听本机回环地址。Onboarding 的识别预算、目标范围、身份、写操作、reset、重定向、私网和请求预算必须显式确认或由执行边界校验。秘密不进入前端、协议、日志、Evidence 或报告。

## 兼容与版本

当前产品入口只服务 Web Target。CLI 的产品命令以实际 help 和启动输出为准；公共 JSON/Schema 版本不是产品代际。未实现的 CLI_APPLICATION、MCP_AGENT 和 MCP 入口不出现在当前使用路径中。
