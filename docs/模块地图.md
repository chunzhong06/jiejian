## 跨模块主链

```text
Project → Recording / Contract → execution request → Job/Attempt
       → Worker → isolated Runner → Verification → Evidence/staging
       → publication → Storage → Results → CLI/API/GUI
```

关键约束：Execution 不依赖 Recording；Runner 是唯一目标 I/O 进程；Storage 不执行目标；Results 只读；模型服务不改变六阶段或 Verdict 权；所有公开跨进程数据带 `schema_version`。详细协作顺序见[系统架构](01_架构设计/系统架构.md)和[数据流](01_架构设计/数据流.md)。

## 目录深度审查结论

- `backend/src/jiejian` 后的生产文件父目录最大深度为三层；最深路径是 `contracts/analysis/sources/`，三层分别表达 Contract 能力、分析子能力和来源适配器分组。
- `frontend/src` 后的生产文件父目录最大深度为两层；`features/<能力>/` 直接对应六个用户阶段及 Job 进度观察。
- 当前没有超过三层的生产路径，也没有连续单子目录链，因此不存在需要登记的超深例外。
- 单文件能力目录只有在具有独立组合、产品、完整性或进程边界时保留，例如 `application`、`projects`、`results`、`worker` 和各前端能力页面；具体结论由 `tests/architecture/test_dependencies.py` 持续约束。
