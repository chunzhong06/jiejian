# 工作区与权限规范

> 状态：CURRENT。适用范围：界鉴在本地 Git 工作区、Codex 沙箱、Windows 文件权限和 Git 历史操作中的安全边界。

## 1. 本规范负责什么

本文只回答“在哪个工作区操作、什么时候需要额外权限、权限失败怎样处理、Git 历史怎样保护”。任务恢复见[任务执行与恢复](./任务执行与恢复.md)，线程职责和交接见[执行线程协作](./执行线程协作.md)；测试运行身份见[验证与测试](./验证与测试.md)。

## 2. 唯一工作区与写入边界

唯一有效工作区是当前 Git 仓库根。开始写入前必须确认实际仓库根、当前分支、HEAD 和 working tree；不能使用旧副本、同名目录、上级工程目录或历史 checkout 代替当前工作区。

源码、测试和 CURRENT Docs 只写入 Git 工作区中明确授权的路径。运行数据库、缓存、日志、构建物、调查报告和临时探针进入 `var/`；阶段只读调查默认使用 `var/audit/<stage>/`，不把过程材料误提交进源码。

同一工作树同一时间只保留一个主要写入者。并行写入需要独立工作树和提前划清的 Git/文件边界，具体生命周期由协作规范负责。

## 3. 沙箱与权限提升

普通代码、测试和文档修改使用工作区沙箱。只有确实需要访问工作区外的用户级缓存、系统临时目录、Windows 凭据、受保护 Git 元数据或其他外部资源时，才申请范围明确的额外权限。

首次需要写入某类受保护资源时只做一个最小探针，确认：

```text
当前工作区
当前执行身份
目标资源是否可访问
本批真实需要的运行时
失败是否来自权限而不是产品代码
```

探针只能写入明确的临时边界，读回后立即清理。环境没有变化时不机械重复。

权限失败后先做一次事实核对。确认属于沙箱、ACL、用户上下文或外部权限后停止无增量重试；交给用户时提供工作目录、可复制命令、用途、安全影响、预期结果和需要回传的输出。

## 4. Windows ACL 原则

不得自行通过 `takeown`、递归 `icacls /reset`、关闭继承、递归删除未知 SID 或放宽整个仓库 ACL 来解决单个权限失败。

Windows 沙箱可能使用专用组、capability SID、显式允许或显式拒绝规则。无法解析成普通本地账户的 SID 不等于恶意或历史残留。判断异常 ACL 时只核对当前工作区、所有者、继承、显式 ACE、本次沙箱 setup 和失败对象；没有充分证据时停止，不猜测清理命令。

只有确认某个显式 ACE 已不被当前会话或最新沙箱配置使用、并且已保存必要恢复信息后，才允许做最小范围修改。不得通过修改父目录或整个项目 ACL 来绕过受保护文件。

## 5. Git 保护

`.git` 被沙箱限制写入时默认视为保护边界，不通过放宽 ACL 绕过。需要 `git add/commit/merge/rebase/update-ref` 等写操作时，按当前授权方式在允许的 Git 边界执行。

完整 SHA 必须来自 Git 实际输出，不根据短 SHA 人工补齐。

任何会改写已存在历史或正式引用的操作，在执行前必须：

```text
确认预期旧 HEAD / ref
→ 建立名称明确的 recovery / backup ref
→ 明确目标 commit 的 parent / tree / message
→ 验证候选历史和 diff
→ 使用旧值保护、lease 或等价保护移动正式引用
→ 再次读取 Git 事实确认结果
```

副作用结果不明确时先读取当前 ref/commit 状态，不重复执行同一个写操作试探。recovery ref 在全部验证完成前不得删除。

执行线程不得自行 squash、force push 或改写已经稳定的阶段历史；是否整理阶段提交由当前阶段提示词和主线程决定。
