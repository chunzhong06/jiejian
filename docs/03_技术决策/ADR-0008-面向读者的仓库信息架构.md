# ADR-0008：面向读者的仓库信息架构

- 状态：已接受
- 日期：2026-08-09
- 适用范围：文档、测试、样例和机器 Schema 的目录组织

## 背景

阶段 0–2.4 完成后，生产代码已经按 Domain、Verification、Storage、Worker 和 Runner 形成清晰依赖，但辅助目录仍按开发时间和技术类型分散：三份权威文档与英文 ADR 平铺，测试集中在 `unit/integration` 大桶，配对样例使用 safe/vulnerable 名称，机器 Schema 放在通用 `protocols` 目录。作者、队友、老师和评委难以在五分钟内找到适合自己的入口。

此次变更只重组信息，不改变生产行为、Runner V1、数据库 Schema、迁移或门禁规则。

## 决策

### 1. 文档

`docs` 根部长期保留 `项目总览.md`、`架构说明.md`、`模块地图.md` 三份快速入口和 `README.md` 导航。详细内容按读者任务编号：项目介绍、架构设计、开发规范、技术决策、协议定义、开发记录、竞赛资料。

项目设计规范、开发路线图、Runner 协议和 ADR 各保留一个权威文件。旧英文路径不保留 wrapper、转发 stub 或副本。

### 2. 测试

测试按业务职责组织为 `domain`、`runtime`、`verification`、`storage`、`execution`、`e2e` 和 `architecture`。`execution` 再按 protocol、runner、worker 分组。测试行为和断言不因移动改变，只修正依赖文件层级的根路径。

### 3. 样例

配对样例改为：

- `samples/fixed_apps/ownership`
- `samples/vulnerable_apps/ownership`

两套 bundle 都保留 project/flow/contract。即使 Flow/Contract 当前相同，也不跨目录提取，因为项目输入边界禁止相对引用越出 `project.yaml` 所在目录。

### 4. Schema 与可执行协议

Runner 机器 Schema 放入 `schemas/runner`，直接表达其消费者。`backend/src/jiejian/protocols` 保留不变，因为它保存 Pydantic 可执行协议模型、规范 JSON 和安全校验，不是普通说明文档。人类协议位于 `docs/04_协议定义`。

### 5. 兼容边界

旧 docs、tests、samples、schemas 路径都是仓库内部路径，不保留兼容文件。所有代码、测试、文档和导航在同一次变更中迁移到新真源。生产 Python 公共导入 `jiejian.protocols`、`jiejian.storage`、CLI `jiejian` 和 Runner 进程入口不变。

## 影响

优点：不同读者有明确入口；测试和样例路径说明业务意义；机器协议和人类说明不混淆；仓库不存在两份权威真源。

代价：旧内部文件路径立即失效，外部笔记或脚本需要更新；Git 历史中会出现大量重命名，需要以 ADR 编号和文件内容追踪历史。

## 迁移与回滚

迁移必须一次更新 AGENTS、README、三份地图、规范、路线图、ADR、协议、测试路径、样例命令和 Schema 漂移测试。完成后旧目录不存在且引用为零。

若必须回滚，应整体恢复旧目录和全部引用，不得只增加 wrapper 或复制第二份规范。该重组不涉及数据库迁移、运行数据转换或生产代码行为回滚。
