# ADR-0004：按职责组织代码库并冻结模块依赖

- 状态：已接受
- 日期：2026-08-09
- 决策范围：Python 模块布局、内部导入方向、路径迁移和架构回归测试

## 背景

阶段 0、1、2.0、2.1 已形成可运行 CLI 纵切、Runner V1 协议和五表持久化映射。原源码仍将 `config.py`、`engine.py`、`services.py`、`protocols.py` 等不同职责平铺在根包，且 `engine.py` 同时承担纯计划、目标 I/O 和安全判定。阶段号还进入了 `domain/stage1.py` 的长期模块名。该结构没有改变行为，但增加了人工审查成本，也无法从路径直接判断依赖方向。

`config/`、`migrations/`、`schemas/runner/`、`docs/04_协议定义/`、`docs/03_技术决策/`、`samples/`、`scripts/` 和 `tests/` 分别服务运行配置、数据库历史、机器契约、人类协议、决策历史、演示输入、环境入口和行为证据，不属于重复目录，不能以减少文件数量为目标合并。

## 决策

### 1. 根包与职责包

根包只保留以下跨层或产品入口：

- `cli.py`：唯一安装的产品命令入口。
- `errors.py`：全局稳定错误结构。
- `redaction.py`：全局展示与证据脱敏边界。
- `sample_app.py`：保留 `python -m jiejian.sample_app` 的本机样例入口。
- `__init__.py`：包标识，不维护重复版本常量。

其余实现按稳定职责归入：

- `domain/`：纯领域模型、公共 ID 格式、生命周期和状态机。
- `runtime/`：配置、诊断和结构化日志。
- `verification/`：输入、授权、计划、HTTP 执行、判定、产物和同步编排。
- `protocols/`：Runner V1 进程协议。
- `storage/`：SQLite、ORM 映射、具体 Repository 和 UnitOfWork。

### 2. 验证流水线 DAG

`verification/` 的依赖方向固定为：

```text
inputs -> safety -> planning -> http -> evaluation -> artifacts
                         \          /
                          pipeline
```

`pipeline.py` 只连接这些节点并维持 `RunService` 的现有同步语义。计划、目标 I/O 和判定不得再次合并为单一 `engine.py`。CLI、未来 API 和 Worker 都是调用方，不得复制判定规则。

### 3. 跨包依赖

- `domain/` 不依赖 SQLAlchemy、Alembic、httpx、Typer、runtime、storage 或 verification。
- `protocols/` 只依赖纯领域模型和全局错误，不依赖 runtime、storage、CLI 或 verification 流水线。
- `storage/` 可以依赖领域枚举、公共 ID 格式、协议工件约束和全局错误，但不得调用 verification pipeline。
- `verification/` 可以依赖 domain、errors、redaction 和 httpx，不依赖 storage。
- `runtime/` 可以依赖 errors 和 redaction，不包含领域判定。
- `cli.py` 负责组合 runtime 与 verification；ORM Session 不得越出 storage。

架构测试通过 AST 检查上述禁止边、验证 `verification/` 无环、确认旧平铺模块不存在，并确认 `jiejian.cli:main` 是唯一安装脚本。

### 4. 内部路径迁移

| 旧路径 | 新路径 |
| --- | --- |
| `jiejian.config` | `jiejian.runtime.config` |
| `jiejian.doctor` | `jiejian.runtime.diagnostics` |
| `jiejian.logging` | `jiejian.runtime.logging` |
| `jiejian.domain.models` | `jiejian.domain.lifecycle` |
| `jiejian.domain.stage1` | `jiejian.domain.verification` |
| `jiejian.inputs` | `jiejian.verification.inputs` |
| `jiejian.safety` | `jiejian.verification.safety` |
| `jiejian.engine` | `jiejian.verification.planning`、`http`、`evaluation` |
| `jiejian.artifacts` | `jiejian.verification.artifacts` |
| `jiejian.services` | `jiejian.verification.pipeline` |
| `jiejian.protocols` 单文件 | `jiejian.protocols.runner_v1` 包实现 |

旧路径是仓库内部实现路径，不保留兼容 wrapper。保留的稳定公共面只有安装命令 `jiejian`、`from jiejian.protocols import ...`、`jiejian.storage` 和 `python -m jiejian.sample_app`。`domain/__init__.py` 只导出当前生命周期与状态机公共符号。

### 5. 不变边界

本决策不改变 CLI 命令、参数、输出或退出码，不改变 Runner V1 字段和签入 Schema，不改变 Alembic revision、五表结构、`jiejian.storage` 公共 API、阶段 1 判定、安全范围或工件格式，也不实现阶段 2.2 及后续能力。

## 后果

正面后果：

- 路径直接表达职责，人工审查可以按 DAG 逐层阅读。
- 计划、外部 I/O 和判定可独立测试，循环依赖由测试阻止。
- 阶段号不再固化在长期领域模块名中。
- 协议和存储的稳定公共导入保持不变。

代价：

- 旧内部 Python 导入路径立即失效，仓库内测试和调用点必须同批迁移。
- `protocols/__init__.py` 需要维护明确的稳定导出清单。
- 新增模块前必须判断它是否拥有独立职责，不能以目录整齐为由拆出薄包装。

## 迁移与回滚

迁移必须作为一个整体更新源码、测试、文档和导入路径，不允许新旧模块并存。若需要回滚，应整体恢复旧目录、旧导入和对应测试；不得只添加兼容 wrapper 形成两套实现路径。数据库文件、迁移 revision、协议 JSON 和已生成工件不受此次路径迁移影响，无需数据迁移。
