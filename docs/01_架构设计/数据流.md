# 数据流

本页只解释 Project、Recording、Contract、Run、Evidence、Result 的跨模块流转；字段级定义见[数据格式](../04_协议定义/数据格式.md)和根部[公共 Schema](../../schemas/README.md)。

## 主链

1. **Project 输入**：Projects/Verification 读取同一自包含 bundle，校验目标范围、身份、资源、Flow、Contract 相对路径和观察器。
2. **Recording / Contract**：Recording 通过独立浏览器边界生成脱敏 FlowDraft；Contracts 从显式 YAML、Requirement、Flow 或受限候选生成可审阅版本。只有确认/激活后的事实进入执行。
3. **Run 请求**：ApplicationContext 将 Project、Flow、ACTIVE Contract、预算、seed 和秘密引用冻结为路径无关 request snapshot；真实秘密只保留 `env:NAME` 引用。
4. **Job / Attempt**：Execution 以幂等键创建 Run/Job。Worker 原子 claim，增加 attempt、租约和 fencing token。
5. **Runner 执行**：Worker 构造 RunnerInputV1，隔离 Runner 在目标范围和预算内执行基线及关系变异，采集 HTTP 与 owner 观察。
6. **Evidence / Result**：Verification 生成 Observation、Evidence、Verdict 和 RunnerResultV1；结果与工件先写入当前 attempt staging。
7. **可信发布**：Worker 校验关联 ID、attempt、owner、token、路径、字节数和哈希后原子发布完整 Run 目录。
8. **Storage 完成态**：publication 成功后，UnitOfWork 同时提交 Run、Job、连续 Job Event 和 Evidence Index；Results reader 只读已发布内容并派生 Finding/overview/evidence detail。
9. **客户端展示**：CLI、API 和 GUI 展示同一已发布 Result；`report` 再次复验 manifest、DB 完成态和内容哈希。

## 失败和恢复

## 模型服务与状态观察

模型服务设置路径为 profile CRUD → `LLMProfileApplicationService` → 非秘密 `llm_profiles` 配置和外部秘密引用；显式测试连接或候选生成才解析秘密并发送一次有界请求。候选输出仍进入严格校验、assessment、REVIEW/ACTIVE，不能产生 Verdict。启动和普通状态读取不请求模型。`/api/v1/system/status` 只读 API、Worker 和本机浏览器探针，不启动 Chromium、不访问目标。

- 输入/协议错误没有可信 RunnerResult，按稳定错误码处理，不伪装成安全结论。
- 可重试错误进入 `RETRY_WAIT`；租约过期先经过恢复审计，不能直接制造第二次目标副作用。
- 取消要求 Runner 完成清理后才写终态；清理失败按 Recording/Run 当前状态语义报告。
- publication 成功而数据库提交失败时，reconciliation 重校验已发布 manifest 并幂等补齐，不重新发目标请求。
- 旧 token、错误 attempt、孤儿 staging 或篡改后的报告不得覆盖新结果，进入受控失败/quarantine 路径。

## 读取边界

Results 不执行 Verification、不读取可变 YAML 作为历史 Run 真源、不修改 Verdict。历史 Run 优先使用经 hash 校验的执行请求快照；Storage migration 和历史工件读取保持向后兼容。完整协议和哈希规则见 [Runner 执行协议 V1](../04_协议定义/Runner执行协议V1.md)、[ADR-0006](../03_技术决策/ADR-0006-阶段2隔离执行设计.md) 与 [ADR-0007](../03_技术决策/ADR-0007-阶段2工件发布与恢复.md)。
