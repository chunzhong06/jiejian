# 数据流

## 从输入到报告

1. **YAML 输入**：CLI 读取 `project.yaml`，再读取同目录内的 `flow.yaml` 和 `contract.yaml`，完成 Schema、路径和交叉引用校验。
2. **执行请求快照**：路径被移除，TargetScope、Identity、Resource、Flow、ACTIVE Contract、预算和 seed 写入规范 `request.json`。真实秘密仍只保留 `env:NAME` 引用。
3. **Job 与 Run**：提交服务按 `(project_id, operation_type, idempotency_key)` 幂等创建 QUEUED Run、PENDING Job 和首个事件。
4. **claim**：Worker 原子 claim 到时任务，增加 attempt 与 Fencing Token，设置租约并把 Run 推进到 PREFLIGHT。
5. **RunnerInputV1**：Worker 把持久请求加上 run/job/attempt/owner/token 关联和执行预算，构造不可变 Runner 输入。
6. **Runner 执行**：Runner 校验输入，在授权范围和预算内执行基线与关系变异，采集 HTTP 和 owner API 观察。
7. **Evidence 与 RunnerResultV1**：Verification 构建 Evidence、计算哈希并聚合 verdict；Runner 把结果和工件原子写入当前 staging。
8. **可信校验**：Worker 比对 Job、RunnerResult、receipt、attempt、owner、Fencing Token，并校验路径、大小、SHA-256 和精确文件集合。
9. **原子发布**：Worker 写 `publication-manifest.json`，把整个 staging 原子移动到确定性最终 Run 目录。
10. **数据库完成态**：发布成功后，UnitOfWork 同时提交 Run、Job、连续 Job Event 和 Evidence Index。
11. **CLI/report**：CLI 从发布结果和数据库终态展示 `PASS`、`BLOCK` 或 `INCONCLUSIVE`；`report` 再次校验 manifest 和报告哈希。

## 失败如何收敛

- 输入或协议错误：没有可信 RunnerResult，映射为基础设施失败，不伪装成 `INCONCLUSIVE`。
- 可重试错误：Job 进入 RETRY_WAIT，清除租约，Run 保持非终态且 verdict 为空。
- 取消：等待态可直接取消；RUNNING 只记录取消请求，Runner 完成清理后才能写终态。
- 租约过期：只进入恢复审计，不能直接 claim 新尝试。
- 发布后数据库提交失败：reconciliation 重校验已发布 manifest，在当前 token 仍匹配时幂等补齐事务。
- 旧 token 或孤儿目录：不得写完成态，只能进入受控 quarantine。
