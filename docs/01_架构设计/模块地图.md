## 根包入口

| 文件 | 职责 |
| --- | --- |
| `jiejian/__init__.py` | 包标识，发行版本由安装元数据提供。 |
| `jiejian/cli.py` | 唯一安装的 `jiejian` 产品命令入口。 |
| `jiejian/errors.py` | 稳定错误码与脱敏 `JiejianError`。 |
| `jiejian/redaction.py` | 日志、错误、Evidence 和展示的通用脱敏。 |
| `jiejian/sample_app.py` | 只绑定环回地址的 safe/vulnerable 样例服务。 |

## Domain 与 Runtime

| 文件 | 职责 |
| --- | --- |
| `domain/identifiers.py` | Project、Run、Job、Evidence、SHA-256 格式规则。 |
| `domain/lifecycle.py` | Project/Contract/Run/Case/Job 生命周期和独立 verdict。 |
| `domain/state_machines.py` | 领域状态转换和 Contract 修订的唯一入口。 |
| `domain/verification.py` | TargetScope、Identity、Flow、Contract、Mutation、Observation、Evidence 等纯模型。 |
| `runtime/config.py` | 配置模型、来源追踪和覆盖优先级。 |
| `runtime/diagnostics.py` | `doctor` 的本机 Python、配置、SQLite、环回和脱敏检查。 |
| `runtime/logging.py` | 默认脱敏的 JSON 结构化日志。 |

## Verification

依赖顺序是输入 → 授权 → 计划 → HTTP → 观察/判定 → Evidence。执行核心和路径适配器只负责编排。

| 文件 | 职责 |
| --- | --- |
| `verification/inputs.py` | 严格 YAML、项目内相对路径和跨文件校验。 |
| `verification/safety.py` | URL、IPv4、origin、端口和重定向授权。 |
| `verification/planning.py` | 固定 seed 的确定性关系变异计划。 |
| `verification/http.py` | 唯一目标 HTTP 边界及请求/超时/响应体预算。 |
| `verification/evaluation.py` | Oracle、Evidence 构建和门禁聚合。 |
| `verification/execution.py` | 路径无关的不可变快照执行核心，Runner 与路径适配器共用。 |
| `verification/artifacts.py` | Evidence/报告原子写入、哈希和完整性读取。 |
| `verification/pipeline.py` | 把已校验 YAML bundle 适配成执行快照；CLI 不再用它直接发目标请求。 |

## Runner 协议与进程

| 文件 | 职责 |
| --- | --- |
| `protocols/runner_v1.py` | RunnerInputV1、RunnerResultV1、规范 JSON、秘密扫描、大小限制和状态矩阵。 |
| `protocols/__init__.py` | 稳定 `jiejian.protocols` 公共导入面。 |
| `runner/__main__.py` | `python -B -m jiejian.runner` 进程入口。 |
| `runner/execution.py` | 解析 RunnerInputV1、调用 Verification、形成 staging 和 RunnerResultV1。 |

人类协议位于[Runner 执行协议 V1](../04_协议定义/Runner执行协议V1.md)，机器 Schema 位于 [`schemas/runner`](../../schemas/runner/)。

## Storage

| 文件 | 职责 |
| --- | --- |
| `storage/db.py` | SQLite 引擎、PRAGMA、会话工厂和 Alembic upgrade。 |
| `storage/models.py` | 五张业务表的 SQLAlchemy typed declarative 映射。 |
| `storage/repositories.py` | 冻结 record 与具体 Repository，不暴露 ORM row。 |
| `storage/job_control.py` | claim、续租、取消、失败、恢复和发布完成态的原子条件更新。 |
| `storage/unit_of_work.py` | 显式 begin/commit/rollback/close，不公开 Session。 |
| `storage/__init__.py` | 稳定 `jiejian.storage` 公共导入面。 |

首版迁移 [`0001_stage2_storage.py`](../../backend/migrations/versions/0001_stage2_storage.py) 是生产建库真源。

## Worker

| 文件 | 调用者与职责 |
| --- | --- |
| `worker/models.py` | 严格控制 DTO、事件/失败枚举、恢复证明和重试策略。 |
| `worker/events.py` | 连续 Job Event 追加的共享事务边界。 |
| `worker/queue.py` | CLI/未来 API 的幂等提交和请求取消。 |
| `worker/attempts.py` | Worker 循环的 claim、续租、取消完成和尝试失败。 |
| `worker/recovery.py` | 监督层的过期租约扫描和恢复确认。 |
| `worker/request_store.py` | request.json 的严格模型、规范 JSON、哈希与原子文件边界。 |
| `worker/submission.py` | 项目内容快照、Project 元数据与持久 Job 的提交边界。 |
| `worker/process_environment.py` | 固定系统允许列表加当前秘密的最小子进程环境。 |
| `worker/supervisor.py` | 单 Job claim、Runner 监督、续租、取消和可信结果接收。 |
| `worker/published_artifacts.py` | staging、receipt、publication manifest、路径/reparse/哈希校验。 |
| `worker/publication.py` | 原子发布后，用一个 UnitOfWork 写完成态和 Evidence Index。 |
| `worker/reconciliation.py` | 补齐发布后提交失败，隔离旧 token 与孤儿目录。 |
| `worker/dispatch.py` | 启动独立 Worker，并等待发布和数据库终态。 |
| `worker/runtime.py` | `python -B -m jiejian.worker.runtime` 单任务 Worker 进程入口。 |

## 辅助目录

- `config`：默认运行配置，不保存秘密。
- `docs`：根部快速地图与编号详细文档。
- `samples`：fixed/vulnerable 自包含环回样例。
- `schemas/runner`：由 Pydantic 生成并签入的 Runner 机器 Schema。
- `scripts`：Conda 环境创建和导入自检。
- `tests`：按业务职责保存行为证据和架构约束。

## 审查顺序

- 产品与范围：根部三地图 → [项目设计规范](../02_开发规范/项目设计规范.md) → 对应 ADR。
- 安全验证：样例 YAML → `inputs.py` → `safety.py` → `planning.py` → `http.py` → `evaluation.py` → `execution.py`/`artifacts.py` → `tests/verification` 与 `tests/e2e`。
- Runner 协议：人类协议 → `runner_v1.py` → `schemas/runner` → `tests/execution/protocol`。
- 数据库：ADR-0003 → migration → storage models/repositories/UoW → `tests/storage`。
- Job 与隔离：ADR-0005/0006 → queue/attempts/recovery → supervisor/runner → `tests/execution/worker` 与 `runner`。
- 发布恢复：ADR-0007 → published_artifacts → publication → job_control → reconciliation → publication recovery 测试。
- 信息架构：ADR-0008 → [文档导航](../README.md) → [测试规范](../02_开发规范/测试规范.md)。
