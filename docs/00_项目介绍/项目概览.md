# 项目概览

## 背景

Vibe Coding 能快速生成 Web 应用，但生成结果常把“页面看起来拒绝了操作”和“后端真的没有执行操作”混为一谈。传统只看响应码或自由文本提示的检查，难以证明开发者声明的安全意图已经落实。

界鉴面向本地或明确授权的 Web 应用，把安全意图转成可执行契约，通过关系变异和多观察者验证运行行为，并把结论固化为可重复检查的 Evidence。

## 面向谁

- 作者和开发者：在提交或发布前验证所有权、身份和敏感字段边界。
- 队友：按稳定协议开发 Worker、Runner、Verification 和 Storage，而不重复业务规则。
- 老师和评委：沿契约、变异、观察、证据链检查结论来源。
- CI：根据 `PASS`、`BLOCK`、`INCONCLUSIVE` 和稳定退出码执行门禁。

## 当前边界

当前完成阶段 0–2.4：CLI 安全验证纵切、Runner V1 协议、SQLite 五表持久化、Job 控制面、隔离 Runner、原子工件发布与恢复均已实现。

当前唯一安装的产品入口是 CLI `jiejian`。Web GUI、REST API、浏览器录制、LLM 候选、插件和完整多格式报告仍未实现。项目不支持未经授权的公网扫描，也不自动执行不可逆破坏性测试。

## 已实现的最小闭环

配对样例描述 owner、attacker、资源、Flow 和 ACTIVE Contract。系统执行正常基线，再交换身份或资源，比较 HTTP 与 owner API 的前后状态，最终形成 JSON Evidence 和门禁结论。

- 修复样例：越权请求被拒绝且没有副作用，结果为 `PASS`。
- 缺陷样例：接口可能返回 `403`，但资源已经被修改，结果为 `BLOCK`。
- 必要观察者缺失：证据不足，结果为 `INCONCLUSIVE`，不能声称安全。
