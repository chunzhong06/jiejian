# 核心思想

## 1. 安全契约

安全契约把“谁能对什么资源做什么”变成结构化规则。正式门禁只使用 ACTIVE Contract；规则必须说明需要哪些观察者，不能只靠自然语言或 LLM 猜测。

## 2. 关系变异

界鉴不随机拼接大量请求，而是在正常 Flow 上只改变安全关系，例如：

- 把 owner 身份换成 attacker；
- 保持身份不变，把资源换成其他人的资源；
- 修改或删除角色、所有者等敏感字段。

这样可以明确比较“正常关系”和“越权关系”，并保持用例可复现。

## 3. 多观察者

HTTP 响应只是一个观察面。界鉴还从资源所有者视角读取执行前后的真实状态。若响应返回 `403`，但 owner API 观察到资源变化，仍然判定为 `VULNERABLE`。

必要观察面不可用时，系统给出 `INCONCLUSIVE`，不会把“没看见”当作“没有问题”。

## 4. Evidence

Evidence 保存规则、变异、请求摘要、前后观察、原因码和内容哈希。最终结论可以从报告追溯到 Evidence，再追溯到 Contract 和 Flow。真实秘密在进入日志、Evidence 或报告前必须脱敏。

## 5. 门禁和可恢复执行

用例结论聚合为 `PASS`、`BLOCK` 或 `INCONCLUSIVE`。执行由持久 Job、Worker 和隔离 Runner 完成：Runner 负责目标请求，Worker 负责租约、取消、重试和发布，CLI 只负责提交与展示。

Fencing Token 阻止旧 Runner 晚到写入；staging 和原子发布保证半写工件不会成为正式 Evidence；UnitOfWork 保证 Run、Job、事件和索引在同一数据库事务中完成。

详细运行过程见[架构说明](../架构说明.md)，字段级约束见[Runner 执行协议 V1](../04_协议定义/Runner执行协议V1.md)。
