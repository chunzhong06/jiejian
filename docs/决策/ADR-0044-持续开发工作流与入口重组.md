# ADR-0044：持续开发工作流与入口重组

> 状态：已接受。以 2026-10-01 的轻量伴随验证定位为有效决策；原始提议已移入独立历史页。当前行为以产品工作流、入口与导航及协议为准，版本验收状态由本轮验证报告单独记录。

## 2026-10-01 定位修订

用户接受轻量伴随验证定位，并授权落实。原提议中以开发任务、接单、结束为中心的前端方案退役；后台任务/上下文/交付和回执继续用于精确追溯，新增一次登记接口，不再构成日常人工前置。现行行为见产品工作流与导航；历史页旧表仅作设计历史，不应恢复到产品。

沿用 R3 结果页设计语言：减少默认内容，保持页头、表格和详情的一致尺度。参考 VS Code Testing 的就近验证角色、Linear 2026-03-12 的界面降噪设计，以及 Apple Design Awards 2025 Play 对复杂专业操作的组织方式。参考只支持具体取舍，不代表界鉴已获奖或应模仿其业务模型。

参考：https://code.visualstudio.com/docs/debugtest/testing 、https://linear.app/now/behind-the-latest-design-refresh 、https://developer.apple.com/design/awards/2025/ 。本轮不实现原生悬浮窗、IDE 插件或聊天代理。

## 阅读边界

当前可用路由和入口以[入口与导航](../总览/产品入口.md)为准。后台任务、上下文、交付和回执已经实现；历史提议中的五模块与手工创建、接收任务的前端路线已被轻量定位取代，不能据此恢复旧入口或改变权限、验证状态。

原提议中的官方预设演练已经单独实现：同步起点 → 异步优化 → 问题检查 → 修复与原题复验；现行行为以[官方示例指南](../能力/应用接入/修改官方示例.md)为准。历史页保留的是设计输入，并不证明真实 Agent 已按任务合同完成开发。

连接界面已提供 Codex、DeepSeek Harness（DSH）、ZCode 的连接指引和同一 MCP 授权边界。配置生成与真实客户端验收分别记录；DSH/ZCode 未安装时只标记实现与合同验证，不宣称实机联调通过。
