# ADR-0030：契约与执行快照绑定

- 状态：已接受
- 适用范围：当前业务权限、完整 CheckPlan、冻结 request/bundle 与历史结果

## 决策与理由

人确认的业务边界、权限和执行材料具有不同生命周期。提交检查时，CheckService 核对当前 revisions、policy_epoch、实现与源码指纹、准备事实和完整计划；将一次检查需要的事实冻结为 `PersistedExecutionRequestV3` 与 `CheckRuntimeBundle`。Worker/Runner 只消费冻结输入，不重新读取可变页面状态或配置解释旧检查。

所有允许和拒绝用例保留，变化影响不能裁剪完整 Plan。提交幂等键绑定本次请求，回执不明先回读；计划或来源漂移拒绝，不静默重绑。秘密只冻结受控引用，运行时注入最小值。

快照让同一结果始终对应当时的权限、代码与执行条件。代价是材料或源码变化必须重新核对并产生新检查；旧发布内容不能追加证据或随新规则重算。历史代码观察与内容快照是不同事实，不能将当前 Git HEAD 当成历史提交。

## 适用边界

当前生产链是 BusinessBoundary/Permission → Preparation → CheckPlan → request/bundle → CHECK Job → publication。独立 Contract/Profile/Runner 协议和相关 reader 仍可维护，但不再通过旧 SecuritySetupCompiler/ExecutionWorkflow 提交产品检查。
