# 测试与验证

验证的目的，是用足够可信的证据回答本次改动会不会破坏某个行为。先确定受影响的契约，再选择最低可用的验证程度；等级不代表每次都要逐级跑满，也不以用例数量衡量质量。

## 选择程度

| 等级 | 回答的问题 | 适用改动 | 证据限制 |
| --- | --- | --- | --- |
| L1 静态成立 | 文件能否解析、类型和声明能否对上 | 文件移动、签名、资源、文档依赖 | 不能证明业务执行正确 |
| L2 确定性行为 | 给定事实是否得到正确结果，失败边界是否成立 | 判断、归属、选择、控件与读取状态 | 模拟浏览器不能证明真实渲染 |
| L3 相邻集成 | HTTP、事务、持久化和资源生命周期是否协同 | 会话、接口、数据库、清理和装配 | 不覆盖完整用户任务 |
| L4 真实流程 | 独立进程、官方目标和浏览器是否走通 | 执行链、实际页面、复验、启动和退出 | 本地场景不能代表全部目标环境 |
| L5 独立交付 | 分发物离开源码工作区后能否完成任务 | 打包、分发、目标机器适配 | 另行约定平台与任务，工具不自动追加 |

等级描述证据强度和资源成本。一个测试文件可能同时包含不同程度的契约；范围目录提供便于选择的集合，维护者仍须核对本次变化。L1 也可能调用 pytest 执行依赖规则检查，不能只按工具名称判断等级。

## 最小充分原则

1. 写出具体风险，例如“离开准备页后，迟到响应可能覆盖当前项目”，不要只写“前端有改动”。
2. 选择能发现该风险的直接测试，同时覆盖关键失败或拒绝路径。
3. 仅当较低等级无法提供所需证据时，增加实际边界或真实流程。文案更改不自动触发修复全链，判断或关联变化则要核对相应结论。
4. 保留仍有效的结果。修正失败后，只重跑失败项和直接受影响邻域；同一代码状态不重复 L4。
5. 交付时列明实际范围和限制。计划、跳过、语法成立、自动化通过和人工观感分别记录。

例如：调整说明正文先检查链接和当前行为；修改链接检查器则增加有效链接、失效锚点与代码示例等 L2 用例。改变数据库事务选 L3；重写官方示例的验收夹具，则实际运行其负责的 L4 场景。

## 测试所有权

| 位置 | 保护的契约 |
| --- | --- |
| `tests/domain` | 证据闭合、权限结论、录制结构与归属 |
| `tests/application` | 用例前置条件、选择、只读投影和回执 |
| `tests/contracts` | 对外格式、严格 reader、本地 HTTP 边界 |
| `tests/infrastructure` | 真实适配器、存储、观察、任务、发布与结果读取 |
| `tests/integration` | 组合根、数据库与跨所有者生命周期 |
| `tests/architecture` | 层间依赖和源码职责边界 |
| `tests/tooling` | 文档检查、范围选择、等待和验证工具 |
| 前端模块旁的 `*.test.ts`、`*.test.tsx` | 所属页面、实体、读取、导航与控件的可见行为 |
| `tests/runtime` | 独立官方示例的实际业务和浏览器流程 |

目录反映所有者，不强迫一个行为在每层重复测试。保留能发现独立风险的断言；删除镜像实现、固定文件行数和过时交互的断言。

`tests/support/contracts.py` 保存独立于实现的公开能力与授权预期。`support/builders` 按检查、准备、运行、Observer 和假目标等输入职责组织，可跨测试所有者复用；单个模块专用辅助留在该模块内。共享辅助不导入测试用例或其他测试所有者，防止一个目录的重组改变另一组测试的发现和资源清理。

前端测试与 app、pages、entities、shared 的实际所有者相邻；通用 DOM 环境由 `product/frontend/tooling/vitest.setup.ts` 初始化，结果样例由报告模块维护。后端测试按相同能力归属组织：接入归 onboarding，示例归 examples，录制整理归 recording，投影归 workspace。跨能力生命周期与事务保留在 integration。新旧测试按风险合并，不形成两套入口。

重组现有测试时先逐项核对被保护的行为和边界。模块搬家只更新真实导入与夹具归属，不删除原断言；实现变化则重写触发方式和预期，不恢复过时交互。重复用例合并时保留不同角色、资源归属、拒绝、恢复和持久化条件。移除项需能说明为何不再保护现有能力，未能对应的旧测试不能默认为无价值。

## 从哪里执行

`verify --list` 查看范围；指定 `--area` 后默认只展示计划，追加 `--run` 才执行。`--level` 限定本次所需程度，省略时采用所选范围的可用程度；不会因为等级为 L4 自动增加真实目标。

`--all` 只执行所列范围中不带 `level4` 的本地契约；按文件和节点可以继续缩小范围。真实场景必须显式选择 `journey` 或 `repair`，并使用 L4；同时选择两者时只运行包含基础阶段的 repair。L5 由[发布验收](发布.md)另行选择。

详细用法见[执行与排错](测试/执行与排错.md)，资源与断言规则见[夹具与断言](测试/夹具与断言.md)，当前可选集合见[验证范围](../参考/验证范围.md)。

迁移原则和覆盖去向见[体系迁移与取舍](体系迁移与取舍.md)。独立进程测试标为 `level4`，普通执行不会自动启动它们；选定后使用正式入口的 `--run-level4`。跳过、未选择和通过分别报告。
