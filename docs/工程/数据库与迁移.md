# 数据库与迁移

数据库保存当前工作区的业务事实。权限修订、材料绑定、冻结检查、执行任务、证据索引和源码变化分别拥有明确的记录；报告读取当次检查的不可变快照，不用当前配置重写历史结论。

## 完整基线

当前数据库从一份完整基线开始，不再重放过去按功能积累的迁移。基线包含当前使用的表、外键、唯一关系、索引和状态约束。旧合同治理、旧执行配置和旧结果终结表已退出当前结构。

工作区身份由 `workspace_schema` 保存格式名称、代际及结构摘要。Alembic 修订记录同一代际内已经完成的结构变更。产品版本、根文档版本、数据库修订及权限业务修订分别维护，不互相推算。

已退出支持代际的旧库不进入正常启动链，也不提供自动转换。同代已发布的结构可以沿明确的迁移路径升级；未知代际、结构漂移或未知修订只读拒绝并保留原文件。重置运行数据必须是用户明确选择的维护操作。

## 初始化与接纳

控制面调用 `prepare_database`。目标不存在时，先在同一磁盘的临时位置建立完整 ORM 结构，写入工作区身份并登记当前修订。核验成功后，以不覆盖已有文件的原子操作发布到正式地址。中断时不留下可被误认为就绪的正式数据库；并发创建时核验已经发布的文件。

目标已经存在时，先核验格式、代际、修订、完整结构及外键关系。当前结构直接接纳；唯一受支持的发布起点按固定历史 DDL 核验后升级，不猜测或修补结构。空文件不是已经准备好的工作区。

Worker 调用 `require_current_database`，只读核验数据库是否已经准备完成。它不创建或升级结构；接纳后仍通过正常事务保存租约、执行状态和结果。

完整基线迁移保存发布时固定的 DDL，不导入会继续变化的 ORM。它与直接初始化必须生成相同的有效结构。ORM 是当前声明的所有者，基线是一个固定的发布产物，两者通过结构比较验证。

## 所有者与事务

| 模块 | 责任 |
| --- | --- |
| `product/backend/infrastructure/storage/db.py` | SQLite 连接、Session、原子初始化和 Worker 接纳入口 |
| `product/backend/infrastructure/storage/workspace.py` | 工作区身份、当前结构摘要和只读核验 |
| `product/backend/infrastructure/storage/schema.py` | 表、约束及索引的结构比较 |
| `product/backend/infrastructure/storage/orm_registry.py` | 当前业务映射登记 |
| `product/backend/migrations/runtime.py` | 定位迁移资源、解析唯一迁移图及生成配置 |
| `product/backend/migrations/versions` | 完整基线及以后真正发布的结构变更 |

SQLite 使用外键、有限 busy timeout 和 WAL。业务工作单元控制短事务，外部请求和浏览器操作留在 Worker、Runner 中。WAL 允许读写并发，但同一时间仍只有一个写事务，不能用它替代事务划分和冲突处理。

可变任务状态与不可变业务修订分开。租约、fence 和执行进度按生命周期更新；规则、冻结输入、证据和发布引用保留其内容身份。UI 汇总状态由已有事实计算，不作为另一套事实源持久化。

## 后续如何维护

尚未发布的同一结构可以持续完善当前基线。发布后，表、列、索引、约束或持久数据语义确实变化时才创建迁移，并说明支持起点、数据处理、失败恢复和消费者影响。文案、布局、目录移动、内部函数和只读投影不创建数据库迁移。

不要为每次提交机械增加一个文件。相关且必须原子完成的变更放在同一修订；互相独立、有不同部署或恢复条件的变更才分开。已发布修订不得原地改写。结束一个代际的支持后，可以建立新的完整基线，但必须明确存量数据处置，不能只删文件或修改版本表。

基线不支持自动降级。维护升级必须先停止原服务及运行任务，取得 SQLite 写入锁，在同一显式事务中重建约束、复制原行、核验外键并更新工作区身份。失败整笔回滚，不自动创建备份或重置业务表。失败后先回读数据库事实，不通过重复写入试探成功与否。

持久登录准备使用一个完整增量修订：新增登录操作记录、账号认证代次与当前准备所有者，扩展 Job 的唯一目标约束。已发布基线保持不变；已有规则、报告、回执、租约与 fence 原样保留。Worker 仍只读接纳当前结构，不参与迁移。

## 最小充分验证

验证覆盖直接初始化与完整迁移图等价、同代升级保留业务历史、升级中断回滚、重复启动保留业务行、中断不发布半成品、结构或身份漂移只读拒绝、Worker 不初始化，以及生命周期和权限结论的数据库约束。测试发现真实迁移图，不固定文件数量、表数量或最后文件名。

设计参考 [Alembic 从当前结构直接建立数据库](https://alembic.sqlalchemy.org/en/latest/cookbook.html#building-an-up-to-date-database-from-scratch)、[Rails 的结构快照](https://guides.rubyonrails.org/active_record_migrations.html#schema-dumping-and-you)和 [GitLab 的迁移整理](https://docs.gitlab.com/development/database/migration_squashing/)。本项目采用完整基线和明确的支持代际，未引入这些产品的运行框架。SQLite 的并发边界以 [WAL 说明](https://www.sqlite.org/wal.html)为依据。
