# 产品改进方案：持续维护权限验证

## 产品目标与完整使用流程

界鉴帮助开发者把业务访问要求变成可持续使用的验证资产。用户能够明确谁可以对哪些数据执行什么操作，复用账号、流程、资源和证明完成检查；代码或业务标准变化后，沿准确要求和原问题继续验证，并从报告追到实际依据。

完整流程为：接入应用与判断适用性 → 核对权限要求 → 准备当前检查 → 预览并执行 → 阅读结果与证明 → 修复、补查或维护下一次检查。GUI、开发工具和命令行使用同一套领域事实与执行能力；每次接续保留原项目、准确规则、操作修订和报告。

## 整体排查与设计判断

排查保持三条主线。先从现象提炼影响用户完成任务的原因，再决定改动及其所有者；用户指出的例子用于校准这套判断，不作为全部检查范围。

| 主线 | 必须回答的问题 | 落地与核对位置 |
| --- | --- | --- |
| 产品价值与完整流程 | 谁因什么问题使用界鉴？从哪里开始，在哪里做决定，得到什么结果；变化、中断与补查之后如何继续？ | 本方案维护完整主线与验收；产品指南维护实际操作，能力规范维护准确事实和门禁 |
| 统一设计语言 | 一眼能否辨认当前对象、业务结论和下一步？内容归属、阅读轴、主次、空间、状态与动作是否一致？ | [布局与视觉](前端/布局与视觉.md)拥有通用规则，[工作面模式](前端/工作面模式.md)及其任务分册拥有具体组织；[实现](前端/实现.md)拥有共享实现责任 |
| 成熟方案复用与工程根因 | 问题属于业务、封装还是上游？实际版本与官方机制是什么，Issue/PR是否同根因并已进入当前版本？为什么选择这一解法？ | [复用排查](开发.md#根据问题核对复用方式)、[抽象判断](架构.md#从实际变化确定抽象)及[采用依据](设计依据.md#调查与采用的方法)维护方法；一次复现和失败证据保留在所属任务 |

每项改动建立“问题与原因 → 选择理由 → 规范所有者 → 实现所有者 → 可观察结果”的对应。验证分别说明代码契约、实际运行、视觉自查和用户接受；AI完成调查、实施、自查与常规操作，用户集中处理业务信息和实质取舍。具体协同规则见[人机协同的推进方式](任务执行与协作.md#人机协同的推进方式)。

## 设计语言与工作面组织

界鉴采用柔和、有空间层次、围绕当前任务组织的专业工作空间。主题、字体、控件、状态、选择反馈和动效由共享层维护。布局表达当前对象及其关系：集合用于寻找，材料目录用于持续选择，正文用于理解或处理当前事项，右下操作用于推进所属任务。

最终范围覆盖全产品的正式页面、独立任务、对话框和关键状态。共同语言贯穿视觉基础、信息成组、动作归属、选择与展开、状态与恢复、动效与焦点六个方面。按当前对象和判断采用相应组合，每个组合都有共享实现所有者；逐项核对真实消费者后，才记录该工作面已完成迁移。当前实跑范围、接受状态与剩余工作见[当前进展与剩余工作](#当前进展与剩余工作)；具体规则由下列规范维护。

名称、用途与短状态形成完整阅读组；组内关系紧密，组间留白明确。页内选择、展开阅读、前往另一任务及提交命令分别表达。图标说明对象或动作，连续选择项不重复添加前进箭头。新增信息进入所属对象和任务，避免全局概况、重复标题或相同卡片割裂阅读。

具体规范分别由[布局与视觉](前端/布局与视觉.md)、[交互与动效](前端/交互与动效.md)、[工作面模式](前端/工作面模式.md)和[前端实现](前端/实现.md)维护。此前已采纳的任务结构、信息组合及视觉关系继续保留，各轮截图与实测在所属验收记录中留证。

## 接入应用与判断适用性

前端先呈现应用的业务用途、运行环境及当前可验证事实。源码、运行地址、来源和授权分别进入所属工作面；在用户准备材料之前说明选定要求能通过什么事实验证、尚缺什么以及需要用户决定什么。

后端从当前来源、业务要求、证明合同与环境形成具名评估。只读评估不创建权限、不执行目标请求；HTTP反馈、业务提交、资源创建、文件和异步结果按实际证明能力分别解释。域名与目标访问继续遵守受控解析、固定连接、重定向和请求预算边界。

验收检查：已有来源和配置可继续使用；不支持的要求有具体缺项和处理去向；切换应用或环境后不带出其他对象的事实与草稿；读取失败可恢复原内容。

## 核对要求与规则

前端首入展示完整规则集合，选中后在相邻区域阅读当前要求。规则自身的角色、资源关系和适用条件先成组；最近检查属于历史事实，当前材料属于下一次准备，各自提供准确去向。详细编辑、遗漏核对和验证方式评估保留原入口及草稿。

后端继续提供正式规则、候选、遗漏决定、准确修订与检查摘要。业务结论、运行对应和样本覆盖分别读取；同角色的不同账号、不同资源归属和不同条件保持原语义。人工批准由原权限用例承担。

验收检查：首入、筛选、无匹配、显式深链接和失效引用可辨；规则条件完整；最近记录回到自己的 Run；进入准备后保留当前要求，返回恢复选择、筛选和焦点。

## 准备当前检查

业务操作在材料工作区上方切换，左侧选择测试账号、操作流程、测试资源、业务结果证明和恢复方式，右侧只处理当前材料。账号用途、别名、状态和核对动作属于完整记录；准确身份复用保留在测试账号材料内，各操作槽位继续独立定位。

所选规则、必要正常对照、待核对条件及原报告构成本次范围。完整材料影响、准确引用和执行安排可按需阅读。补查直接进入对应材料，保存、核验、采用和执行分别反馈；未核验草稿按项目与检查范围保存，回到同一任务继续处理。

后端沿用当前准备投影、兼容匹配、材料替换预览、授权和回执。前端使用预览附属的同项目、同计划指纹材料事实，读取失败或依据变化时重新核对；账号会话变化只影响相应材料，兼容配置保留。未知写入查询原操作，不另建请求来试探。

验收检查：准确身份和槽位不合并错配；同角色账号仍可区分；切换操作后材料归属正确；必要缺项、所有原因和处理入口齐全；原批次、中断、撤权、失效及未知回执可接续。

## 预览并执行

执行前明确实际规则、账号、数据、操作和正常对照。普通检查、所选场景、保存方案与原题复验共享预览和执行能力，同时保留各自范围；材料处理返回后只重新核对原预览。

后端拥有计划指纹、冻结提交、并发条件和执行生命周期。API进程只组织用例；实际浏览器和目标请求进入Worker及隔离Runner。已有运行与未知提交使用自己的冻结范围，当前页面的选择不能附到另一份Run上。

验收检查：预览变化后旧提交被拒绝；重复提交和未知响应不会产生第二次真实副作用；执行中可离开再返回；取消、失败和报告发布分别具有明确状态与恢复去向。

## 阅读结果与证明

报告先给本次判断、对象与实际样本范围，再读逐项结果。修复复验将原问题和正常功能置于同一比较表，各自保留修改前、当前结果和依据。查看依据在所属结果下展开，深入证明记录时进入独立阅读，返回原结果及焦点。

规则适用条件与实际覆盖分开。实际取得结论的状态和仍需检查的状态集中说明；未查项带着准确要求、目标条件及原报告进入准备。完整适用范围、来源、运行对应和引用保留在所属阅读层级。

后端从冻结报告、实际条件观察、正常对照、修复对应和确定性结论组合读取。历史报告保持原事实，当前配置不补写旧依据；缺失、未知和未执行分别呈现。Agent解读消费准确报告，正式权限结论仍由确定性服务形成。

验收检查：原问题与正常功能逐项对应；实际状态不被规则条件覆盖；证明可追到准确Run、Case和记录；未查项接续后原报告保留；只读归档不开放写入。

## 修复、补查与持续维护

修代码、调整业务标准和补齐样本分别继续原任务。代码修复沿原问题和正常对照复验；标准变化形成新修订；新增无关要求不改变原题范围。保存方案和交付摘要支持再次使用，具名未查项和待审线索各有准确去向。

变化影响以真实依赖和兼容依据解释所需处理。主体、流程、资源、来源与部署分别判断，不能从名称相同或定义差异直接推断全部复用或全部重做。Agent接续保留授权、原任务和已有正式产物，模型完成声明不能替代业务核验。

验收检查：新增要求、规则变化、会话失效、环境更新和仅代码修复得到不同且可解释的处理；部分完成与中断可继续；交付摘要能回到原要求、原问题、准确报告和对应依据。

## 实现职责与依赖

| 工作面 | 前端实施 | 后端依赖与验收重点 |
| --- | --- | --- |
| 规则与详情 | 采用集合、相邻详情、完整信息组和所属动作；整理评估、最近检查与当前准备的归属 | 当前正式规则及摘要读取；核对准确条件、Run、选择、筛选和回程 |
| 当前检查与材料 | 共享当前操作、材料导航和正文组合；接通账号、流程、资源、证明、范围和执行安排 | 原预览、准备投影、身份槽位、替换预览与回执；核对兼容复用、草稿隔离和门禁 |
| 结果与证据 | 共用比较表头，所属结果内读依据，集中解释实际覆盖，保持独立证明阅读和补查接续 | 冻结报告、样本事实、原题对应和正常对照；核对历史不变及准确返回 |
| 其他工作面 | 接入、应用资料、Agent、设置和维护采用相应共享模式，按真实任务保持不同布局 | 各能力原有生命周期和授权；复查受影响消费者及非理想状态 |

既有已采纳工作面作为后续固定参照。实际修改沿完整使用流程连接前后环节，共享变更同时检查直接消费者、深入任务、展开和异常状态。普通实现、校对和验证持续推进；下一次审阅提供新成果及必要对照，影响结果的实质选择交由用户判断。已采纳结构继续保留，当前仍缺的真实验证按下文顺序完成。

## 验证与审阅

实现先核对当前源码、接口、Git和运行事实。共享修改列出直接消费者，按合同选择最小充分的类型、组件与接口验证；稳定后走代表完整任务。保留既有工作树和仍有效的验证证据。

真实界面检查同时比较已采纳样张与最终画面，覆盖亮暗主题、长内容、窄窗、首次与筛选空态、读取失败、等待、冲突、中断和返回。测试记录说明实际验证对象，视觉审阅检查任务整体、层级、完整信息组和动作连续性。

用户通过简短审阅入口逐项查看重点画面、对照和必要交互；全量自查、证据归属及异常排查由实现者完成。用户采纳一项设计后，继续既定实现与验证，下一次审阅围绕新的实质判断。

## 当前进展与剩余工作

截至2026-11-15，官方示例已贯通确认要求、正常起点、错误修改、原题修复和深入查证。真实三段结果为PASS、BLOCK、PASS，原题修复为VERIFIED；当前完整发布包与独立读取结果见[保全清单](../../var/design-closure-20261115/evidence/preserved-chain/manifest.json)。普通SQLite应用也已形成真实模型提问、候选审阅采用与两项正式实验，见[原验收](../../var/design-ordinary-collaboration-20261114/实施与验收.md)。

统一设计语言已落实到正式工作面、共享控件及主要深层状态。归档、证据、准确回程与读取恢复，以及最新的场景辨识、窄窗结论、展开目录与单文件审阅入口均已获用户接受，本轮设计收尾已完成。范围及必要验证见[本轮交付](../../var/design-scenario-final-20261115/实施与验收.md)；阶段状态与具体范围由根[todo](../../todo.md)维护。

## 评委体验与贡献表达

主要贡献通过两个可操作时刻呈现：先把人确认的要求与实际业务后果对应，区分接口响应、事后恢复和权限判断；再沿同一原题验收修改，同时核对正常功能。独立证明可以继续追到具体账号、资源和记录。人机协作说明材料如何被维护和审阅，作为支撑能力，不在主线中强制调用模型。

当前完成事实支持业务核验与修复验收机制的展示。对成熟方案的同任务效果、准备成本和复用收益比较，以及非作者短暂操作后的理解反馈，尚无新的实测数据；保留为独立评价工作，不编造效率或领先数值。演示围绕实际要求、观察结果、原题和正常对照展开，避免用功能数量替代贡献说明。

2026-11-15的[评委复审](../../var/judge-reassessment-20261115/评委复审.md)确认当前完整体验、统一设计语言和示例实证已经成立；后续竞赛表达的重点是核心差异更早可见、复验结论具名说明正常操作，以及原创贡献相对成熟方案的准确对照。这些作为尚未选择实施的建议保留，不回写为本轮设计未完成，也不改变已接受结构。

## 遗留事项与范围边界

原Windows录制窗口控制故障继续沿[窗口控制调查](../../var/window-control-20261114/调查与处置.md)处理。普通页面阅读和点击使用独立创建、退出的浏览器完成；不接入录制浏览器，也不把常规点击反复交给用户。Windows连接收尾的WinError10054及模型受限交互的原因细分仍保留诊断缺口，未记为修复。

早期运行原包、设计基准和过程取证的缺失，按用户决定停止追查，不再作为产品待办或阶段收尾门槛。现存历史资料原样保留，当前实现与验收使用自身准确来源。

历史清单中的复杂来源、长历史、异常恢复和客户端差异，在本次评价中保留其既有证据边界，未运行项保持未验证，本轮不追加邻域实跑。原人类非作者首次使用及收益比较是可选后续；陌生用户／评委视角的产品审阅与真实人类试用分别记录。额外域名、受信HTTPS和便携更新保持独立范围。
