# 性能与读取

性能改动减少同一输入、同一事务和同一次读取中的重复工作。授权、独立文件、持久化提交、并发状态和跨进程输入仍由各自边界接受。界面投影、数据库通知及文件元数据都不能代替这些核验。

## 启动测量

分别记录受控环境准备、数据库准备、完整诊断、服务就绪与打开浏览器；区分构建命中、首次构建、文件系统缓存和交互动画。启动日志中的 `timing` 使用同一面板时钟，阶段事件及就绪事实仍由原所有者决定。不能以已准备的解释器内函数调用代替真实 CLI 冷导入，也不能把无界面服务就绪与完整 GUI 打开混为同一次测量。

终端等待行使用进程内运行空间。按 [Microsoft PowerShell 托管指导](https://learn.microsoft.com/en-us/powershell/scripting/developer/hosting/creating-multiple-runspaces)配对 `BeginInvoke`、`EndInvoke` 和释放；仅传入绘制函数、标签、时钟与停止信号，不加载业务上下文或共享准备事务。阶段切换不重复启动解释器，停止后不遗留写入；不通过跳过身份、数据库或 readiness 核验缩短计数。具体测量回执保留于运行目录，不将某次耗时写成跨机器性能承诺。

局部导入、缓存或动画收尾的收益必须回到同一真实终端、同一实例和同一缓存状态复测，不能以局部变快宣称整个启动已提速。比较 Python 字节码缓存时仍保持内容失效校验及 `-B` 检查；缓存参数不能扩散到 Conda 等其他解释器，首次生成成本与命中成本分别记录。全链收益未成立时保留原策略，不为局部数字增加运行层。

## 记录提交

独立业务记录组件仍在内存 SQLite 中完成事务。持久日志追加压缩页增量；首次保存、页大小变化、变化页超过一半或累计达到检查点周期时追加完整压缩检查点。检查点包含全部业务历史，不删除操作回执和过程事实。

长度、载荷和前序摘要共同形成哈希链。追加后完成 fsync 才确认提交；提交结果不明时组件停止后续读写。恢复验证完整链后依次应用检查点与增量，拒绝损坏、截断、异常页号和超过解压预算的载荷。已有全量快照前缀可以继续读取，追加不改写原前缀。

独占句柄、128 MiB 日志上限、顺序与幂等约束保留。当前仍需序列化内存库并比较页面；减少的是落盘、哈希和同步的数据量。没有实现在线截断或无限容量，避免替换独占文件时出现可写间隙。

受控 Node 宿主在检查请求进入处理器前建立持久 scope。普通请求立即进入处理器；只有实际使用记录 SDK 时才建立持久 scope，读取网页或登录页不再产生无用日志。普通应用的 HTTP、SQLite 和文件调用仍由宿主自动采集。响应结束前等待实际记录提交及 scope 关闭；未等待写入、异常关闭和迟到操作不能补成完整证明。

## 历史与证据

一次报告、故事或修复投影共用私有已验证发布包。键包含实际 Run、Job 和发布回执，嵌套派生读取复用相同接受结果。结束本次操作即释放；消费者不得修改共享包。独立 HTTP 请求仍核对文件、清单、内容身份和关联，不使用 TTL 或 size/mtime 接受旧安全结论。

准确证据片段可随所属文档、索引一次返回，前端继续核对项目、Run、Case、动作、证据和记录引用。不会先读目录再串行读取同一记录，也不把未知记录替换成第一条。

问题历史先按检查涉及的规则身份及修改关联建立索引，再为对应问题构建时间线，避免每个问题重新扫描全部检查和计算用例身份。初次读取仍需验证所用历史发布包；数据持续增长时，这项成本仍与相关历史规模有关，不能把请求内复用描述成常数时间。

## 源码与数据库

源码指纹使用独立有界扫描，不执行 AST、端点或角色语义分析。同次完整分析只计算一份文件摘要，总指纹及文件清单共同消费。相对路径、排序、忽略项、敏感目录、重解析点和字节预算保持原规则；Git 操作、源码修改及提交边界仍重新读取实际内容。

服务进程保留少量空闲 SQLite 连接，每个连接建立时配置外键、busy timeout 和 WAL，归还时回滚未提交事务。连接不跨进程共享；工具和短生命周期进程继续使用 NullPool。当前不新增有限的并发取连接门槛，避免嵌套 UoW 等待自身释放连接；持久事实仍由短事务和数据库约束保护。

任务提交成功后通知本地 Worker。空闲等待从 100ms 逐步退避到 1 秒，其他进程提交仍能被有界轮询发现；活跃执行保留原来的检查节奏。通知不是任务事实，不改变领取、租约、fence、取消或恢复职责。

账号列表批量读取所引用的主体修订，任务列表批量读取上下文，交付列表直接读取有项目归属的说明字段。同一动作材料投影复用本事务中的身份与绑定事实，文件、秘密状态和执行采用仍独立核对；该只读作用域内不执行写入。

报告游标的索引顺序与 `project_id, created_at_us DESC, run_id ASC` 一致，避免同时间记录额外排序。索引变化通过同代事务迁移发布，不原地改写已经发布的修订，也不改业务历史。

环境与接口来源目录在 SQL 中选择每个对象最新修订，精确修订按主键和项目读取。只对实际消费的记录解析完整文档并核对索引归属；历史读取仍接受被请求的历史记录。活动环境保留独立快照，不能用最新配置替代。场景执行前同时核对来源的原修订与当前最新修订，不遍历其他历史，也不降低修订或请求指纹检查。

加载状态的任务与回执须处于同一只读快照，复用 `UoW.begin_read_snapshot`。SQLite legacy SELECT 本身不保证多次读取持续使用同一快照，不能把提交前的任务状态与提交后的回执拼接为存储断裂。已有写事务继续由调用方拥有；读取不提交、不重试执行，也不放宽请求、任务、回执的准确关联校验。

## 协议和低频工作

CHECK reader 接受原始字节后，直接由这次接受的模型形成规范字节进行比较，保留秘密和大小检查。公开编码入口仍重新接受可能被 `model_copy` 或可变成员修改的模型。没有向所有协议机械推广“已验证”标记。

录制拥有者使用追加缓冲，在交付或读取快照时转成元组；顺序、脱敏、事件和字节预算、安全停止预留保持不变。缓存清理预览共用同次文件指纹及数量、大小，真正删除前仍重读变化、归属、路径和占用。版本更新预览与应用面对不同文件状态，继续各自核对。

关系变异规划复用本次合约的邻接索引。断点图保留有界祖先和后继集合，当前 Trace 上限为 512；未为这项低频算法改动因果判断。Observer、Runner 和有状态 Case 的隔离、独立输入接受也保留，不用共享进程或并发执行换取表面速度。

## 普通应用运行与依赖

运行状态页面只读取所属进程身份、监听者和准备阶段，不递归扫描整个依赖树。正式运行引用仍核对实际源码、依赖和构建产物，缓存键不代替文件内容接受。依赖按锁文件、Node 及安装模式复用，安装和清理共用维护锁；副本独立可写，不能让目标改坏其他运行的共享文件。

SQLite 来源在同一只读事务内完成元数据、授权投影及历史接受，读取后关闭连接。历史读取先核对字节预算，不先加载全部历史再判断超限。新测试数据库先在所属临时目录完成复制与结构核验，再发布正式文件；失败清理半成品，可修正声明后重新准备。

## 前端资源和刷新

持续协作等待用户或后台执行时不轮询模型。进程内决定通过提交后通知唤醒原监督者，跨进程 Worker 只在确有未完成工作时观察数据库提交代次；等待结束后先核对目标产物，已经齐全时不额外调用模型。没有有效进展或原操作结果未知时保留任务并停止接续，具体预算见[Agent 协作](能力/Agent协作.md)。

读取钩子共享焦点、在线和可见性恢复监听，同轮通知合并一次。读取仍串行，换键取消，迟到响应不得覆盖新对象。数据库 data_version 只作为提前刷新工作区的提示；活跃任务保留 2 秒读取，空闲工作区保留原来的 10 秒文件重读，返回焦点仍重新读取。显示刷新不会代替提交或证据的安全门禁。

图标使用包提供的独立入口，避免开发及测试导入整个图标总入口。路由懒加载和意图预载保持，不以拆分更多文件或消除体积警告作为性能结论。纯测试文件不参与生产构建身份，但仍同步进受控测试工作区并接受类型及组件验证。

字体保持原 MiSans 可变字重、字形及首次文档选择策略。当前官方包的 WOFF2 为静态字重，完整可变字体仍为 TTF；本轮没有替换成多份静态字重或自行裁剪、转换。构建生成静态 gzip 副本，服务仅对接受该编码且无 Range 的哈希资源选择压缩表示，保留 Vary、独立 ETag、长期缓存与解压后的相同字节。HTML、清单、API 与 MCP 不经过该压缩分支。以后取得可用的官方可变压缩字体时，再核对字符映射、字形、度量和字重轴后替换。主题、布局及已接受动效参数不作为性能牺牲项。

## 工作面所需范围

目录、历史和准确修订分别查询：目录在数据库中挑选最新项，不先载入全部旧文档；历史用稳定游标，详情按准确归属和修订读取。旧的全量接口不能悄悄截断，迁移调用方后再决定兼容范围。

长期协作先测量文档字节、SQL 次数和写锁内读取量，再决定存储拆分；存在性门禁直接查询准确事实，不为判断一项未确认操作展开全部任务。接纳预算须在提交事务内判断，区分任务类别、项目、排队和执行，重复请求先回读，不消耗新配额。取消、回执和只读诊断不受新任务配额限制。连接池限制须先排除嵌套工作单元等待自身，不以收紧池大小代替治理查询和任务增长。

协作读取的本地夹具为128任务、各128条已完成操作，正文合计8,578,048字节；7次暖读取中位约99.5ms/94.4ms，Python峰值分配约31.2MB/0.45MB。当前采用单次查询逐条严格接受并在命中时停止，主要收益是避免同时物化全部任务；时间差不足以推算整机提速。旧任务仍完整读取，暂不拆表或建立第二份状态事实。新委派按8MiB正文预算及已有操作上限接纳，问题最多512项、追加目标最多128项；回答、取消和迟到回执不受新委派预算阻断。测量环境及原始样本只存运行目录。

显式读取请求字节的配置入口在每块到达后执行原有大小预算，超限不再继续缓冲；不信任Content-Length替代实际字节数。普通API实体在框架解析前统一限量，准确参照上传使用自身文件预算，MCP保留SDK接收器且不缓冲GET流；预算与责任见[开发](开发.md)。接收之后的同步服务调用进入既有线程池，保持一次调用、原事务和修订条件；慢存储不应阻塞其他异步请求，中断读取不能返回可供提交的半份内容。

概览只读取接口来源与请求数量；测试目录读取动作和流程修订摘要，不读取流程正文及录制列表。编辑与历史审阅仍读取准确修订。摘要继续接受完整根文档并核对来源时效和采用关系，当前减少的是传输与无用投影，不能表述为已消除数据库解析。

已选检查范围只有一处预览读取，取消全部选择不请求整份预览。提交前继续形成当前冻结计划。证明目录在同一次上下文内复用读取范围集合及每项采用事实；下一次请求和真正采用仍重新核对撤权与当前依据，不设置跨请求授权缓存。

仓储装配按绝对成本和调用占比判断。当前保留显式仓储初始化；一次本地测量不足以支持引入惰性属性和额外缓存。测试准备与服务执行分别计时，共享只读准备的条件见[夹具与断言](测试/夹具与断言.md#只读审阅与写入场景)。

范围裁剪参考 [Microsoft 过度提取反模式](https://learn.microsoft.com/en-us/azure/architecture/antipatterns/extraneous-fetching/)与[频繁小读取反模式](https://learn.microsoft.com/en-us/azure/architecture/antipatterns/chatty-io/)，不据请求数量单独推断性能。

## 验证与适用范围

50条检查历史的23,212字节响应，在7次暖序列化中，直接编码已接受模型中位约10.6ms、再解析同一份JSON约12.5ms，Python峰值约132/205KB。因此准确投影模型直接编码，动态映射才执行输出接受；公开响应声明仍与实际投影对应。这是局部输出成本比较，不代表整页或服务整体提速。

排队接纳计数在独立数据库、无Worker和目标的32/128/1024项等待夹具测得：数据库页已预热、每次新建连接，7次查询中位约4.9/5.5/5.5ms，Python峰值约50/46/46KB；计数只返回三项聚合，不加载任务正文。数据库总文件约1.12/1.21/2.00MB，含固定工作区结构，不能当作单任务大小。该测量用于确认新增接纳检查成本，不代表旧路径提速，也不证明128项是硬件容量。默认预算及拒绝恢复见[执行任务与隔离](能力/执行任务与隔离.md#排队接纳)。

功能测试验证行为和边界，不把机器耗时写成固定通过门槛。代表测量区分连接、计算、字节写入和页面读取；缓存冷暖、样本数量及环境随结果说明。截图可确认内容和布局，不能证明帧率。

最小验证覆盖日志恢复与中断、篡改及越权读取、源码身份一致性、事务回滚和跨线程复用、升级保留与回滚、真实普通应用采集、录制顺序与秘密清理，以及前端换键和恢复刷新。已有有效证据继续使用，只有影响行为的新修改才重跑相邻范围。

设计依据：[SQLite WAL](https://www.sqlite.org/wal.html)、[SQLite 查询规划](https://www.sqlite.org/queryplanner.html)、[SQLAlchemy 连接池](https://docs.sqlalchemy.org/en/20/core/pooling.html)、[FastAPI 同步与异步](https://fastapi.tiangolo.com/async/)、[Web 字体优化](https://web.dev/learn/performance/optimize-web-fonts)、[MiSans 官方下载](https://hyperos.mi.com/font/zh/download/)。采用各自适用的机制，未引入其框架外的新服务。

试运行历史在同一次工作单元中读取每份请求、Job 和报告一次，再统一计算恢复关联；明细与准备缺口复用相同事实组合。只读入口持有一致快照，不跨请求缓存、不截断旧历史。10/20/40 份记录的计数回归要求仓储调用分别为21/41/81次；这是调用工作量，不能换算为页面提速比例。
