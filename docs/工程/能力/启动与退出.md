# 启动与退出

## 启动与退出协作

### 装配与调用

1. start.cmd及受控脚本准备环境与前端资源，serve先核对解释器、运行目录与单控制者锁，再创建ApplicationCore。
2. ApplicationCore显式创建UoW、业务服务和基础设施。无环依赖构造注入；运行provider、变化/原题、交付等使用具名连接，最终validate_connections只校验接线，不执行目标回调。
3. FastAPI挂载当前router及同实例MCP。GUI用本机control session/Origin，MCP用独立Bearer与逐项目权限，CLI只提供当前系统操作。所有业务写入进入对应workflow。
4. CHECK、RECORDING、PROOF_PREFLIGHT经通用Worker分支执行；Node运行加载由专用Runtime Worker持有目标；身份准备有独立受控浏览器进程。各自复用进程树和最小注入边界，不能混为一个任务生命周期。
5. Workspace、History、系统状态读取事实。只读系统状态不代表所有业务已接受，也不能由GUI本地状态替代后端事实。
6. 关闭按当前实现先确认受控录制、身份准备、Worker/运行监督等资源退出，再清理短期秘密与释放数据库资源。失败时保留责任与异常链，未确认进程退出前保留共享资源。

### 状态与所有权

| 资源 | 创建/所有者 | 读取/使用者 | 退出责任 |
| --- | --- | --- | --- |
| ServeLock与owner token | 当前serve进程 | Worker存活监督、第二实例检查 | 原持有者释放；旧文件不能证明锁仍有效 |
| UoW/Engine | ApplicationCore或WorkerContainer各自创建 | 本进程工作流/Repository | 各组合根确认依赖停止后close |
| MCP配对与项目提升 | agent_access与GUI决定 | transport及每个工具 | 暂停/撤权/重启/关闭清除临时提升 |
| 目标进程树 | 对应Supervisor/Worker | 当前执行者与恢复逻辑 | 只清理已证明归属的树，不接管用户进程 |
| 前端页面状态 | app/shared与具体feature | 用户交互 | 写后回读、陈旧响应隔离；不新增持久业务状态 |

### 失败路径

第二个控制者在创建核心服务前失败；不能共用同VarDir并行写。Worker bootstrap失败先核对是否已claim，采用对应条件事务。失去服务owner token触发持久取消并清理受控树。启动UI动画失败可以降低展示，不覆盖真实ready结果。维护预览、清理运行数据与用户数据重置是不同操作，不因为目录看起来临时就删除。

## 控制面与装配

### 当前入口

工作台、权限、准备、测试与结果的控制面合同见[入口与输出](入口与输出.md#控制面与machine输出契约)。本页只维护它们如何进入同一组合根以及关闭资源的责任。
### 组件与边界

- `start.cmd` 是源码仓库的一键产品入口：准备或复用项目专用 Conda `jiejian_env`，由受控 uv 按 `uv.lock` frozen 同步并 editable 指向当前仓库；普通启动不安装或运行 Wheel。
- `scripts/dev.ps1` 是源码运行环境的唯一准备入口，提供 bootstrap、sync、update、prepare、start、cli、test、frontend-test、schema、shell 和独立可选的 package；只有 update 可以修改 `uv.lock`，只有 `schema -Update` 可以更新签入的公共 Schema，package 不参与普通启动。`dev.ps1 start` 只薄转发到 `start.ps1 -Mode Gui`，不自行准备后直接调用 `serve`。
- 前端准备、Node/pnpm、构建缓存和开发工作区只属于源码开发环境，不属于产品控制面；完整规则见[修改开发环境](../开发.md)。
- Web GUI 以工作台为唯一主控入口，变化、权限、测试保留既有导航层级。权限区域承载业务边界写流程，检查准备区域承载身份登录与录制动作。首次建立后可从完整 current 边界调整 Actor、Action、Effect、Permission 与实现线索；前端不传 `write_mode`，服务端规划变更并冻结 Proposal，再由用户查看摘要并批准或拒绝。
- 当前确定性下一步由 `WorkspaceService`、动作准备 inspection 由 `PreparationService` 提供。旧 Guidance/ErrorDiagnosis 及八类旧 AI surface 为 dormant 算法，未注册旧 result/error API。当前三类受限 Assistant 只解释服务端短事实，不能改变准备要求、权限或技术绑定。
- CLI 当前只公开 `serve`、产品版本和系统诊断/维护；应用、变化、检查、结果、历史与 status 命令在当前 暂不公开。Human、Machine JSON 与内部日志互不混用。CLI 不提供 Business Boundary、PermissionIntent 或 Proposal 决定写入。
- API 是固定 `127.0.0.1` 的资源与控制面，负责严格解析、授权、ApplicationCore 调用和脱敏错误映射。所有 HTTP 请求先匹配实际 `Host`；GUI 根页面取得只属于当前服务进程的 HttpOnly、SameSite=Strict control session Cookie，全部 `/api` 请求验证该会话，写请求再要求 `Origin` 与实际界鉴 origin 完全一致。业务边界审批只接受路径中的 `proposal_id`、预期 `proposal_fingerprint` 和原因；审批主体与渠道由服务端固定为 `LOCAL_GUI`，并在同一事务中提交 revision、binding、permission、decision 与 epoch。
- 当前 ApplicationCore 不装配旧 `ProjectPreparationService`，也不注册 `/api/projects/{project_id}/preparation/prepare-safe`。不得重新接回 Candidate、Permission Matrix 或 ActionSafetySetup 链。当前 GET `/api/projects/{project_id}/preparation` 直接调用 `PreparationService.get`；动作级下一步只由 `WorkspaceService` 决定。
- 当前代码变化由 `application/changes/service.py` 的唯一inspection核对源码/权限/映射，ProjectRepair只读组合原题、精确变化与NEW Run；Workspace包含变化、修复和当前结果摘要，不重新计算安全结论或保存页面状态。
- 旧 ProjectRevalidation 与 Delivery Check 不属于当前产品入口；当前 ProjectRepair 只读原题合同和精确关联的已发布复验事实，不回接旧权限表。
- MCP 是同一 FastAPI 进程中精确挂载的 `/mcp` Streamable HTTP 控制入口，复用同一 ApplicationCore 与 shutdown 链，不监听第二个端口，也不单独装配 Worker。首次配对生成的独立 Bearer 只经 SecretStore 精确引用长期保存；以后启动自动恢复 READ。GUI Cookie 和模型 Key 均无效。当前 MCP 提供固定只读工具；GUI 对当前项目临时提升后，PREPARE 可登记变化声明，EXECUTE 可提交或取消完整检查。任何 level 都不能 approve/reject、直接修改权限预期、候选审批状态或自选重验范围。
- 当前 `ResultStory` 消费已发布结果与 Evidence，`ExecutionTrace` 为通用 Breakpoint 提供因果事实；二者不根据页面或事件顺序重算 Verdict。旧 ResultPresentation 不属于当前产品入口。
- API 内部路径统一为 `/api`。当前产品通过状态读取与取消接口管理 CHECK；独立 Job SSE 路由未挂载。其 reader 使用持久事件序号恢复，断开后停止轮询，不能据文件存在声明产品已经开放。
- 应用接入、源码分析、身份、Recording、权限准备和结果解释沿唯一主路径推进，详细边界见[应用接入与检查主流程](../../产品/检查与复验.md#如何理解结论)。
- GUI、CLI 和 API 复用 ApplicationCore。当前通用Worker装配CHECK、RECORDING、PROOF_PREFLIGHT；运行加载使用专用Worker，检查后端通过 preview/submit/status/result-story/evidence API 接入，目标请求进入独立 Runner；前端通过同一控制面提供显式检查、结果、变化登记与原题复验。
- “运行环境”页与 CLI 复用同一 `LocalMaintenanceService`。它按明确类别预览可回收的旧构建、下载与构建缓存、历史日志和运行临时文件；预览形成当前实例内短期有效的固定 `MaintenancePlan`，确认按固定计划和所选条目逐项执行，单项占用、变化或失败不会丢失其他结果。应用、权限配置、数据库、Evidence、报告、凭据、当前会话日志、活跃运行目录、进程锁、当前开发工具、测试活动目录和被引用的官方示例数据受保护。启动后的有界孤儿与日志保留维护失败只进入诊断，不反向撤销已经成立的 ready。

### 关键数据流

```text
start.cmd
  → loopback 服务
  → GUI / CLI / Machine / MCP
  → API、CLI 或 MCP 调用 ApplicationCore
  → Project / ApplicationUnderstanding / Business Boundary / Proposal
  → GUI形成人工业务决定；MCP按项目临时READ/PREPARE/EXECUTE读取事实、登记变化与提交完整检查，不能审批权限

CHECK 与 Recording Worker 均接入服务生命周期；当前 CheckResultReader/CheckStoryBuilder 只读已发布事实，不装配旧 Report/Repair writer。
```

应用接入、业务边界、身份、Recording、动作准备与当前 CHECK的边界统一见[应用接入与检查主流程](../../产品/检查与复验.md#如何理解结论)。控制面只暴露该主流程已有的 ApplicationCore 操作，不建立第二套业务或内部配置入口。

### Windows 启动交互

- 启动准备保持六个有序阶段及其缓存、诊断、迁移、Chromium 和前端构建语义。默认无参数启动在准备完成后直接进入 GUI，不等待方向键或 Enter 选择；`-Mode Cli` 与 `-Mode Prepare` 仍为显式入口。只有主动指定 `-Mode Interactive` 才显示模式菜单。
- `RuntimePaths` 只拥有当前产品 `VarDir` 的 `data`、`runtime`、`cache`、`logs`、`temp` 和 `test`。数据库、项目及保留的 Job/Evidence/报告事实进入 `data`；当前实例前端副本、官方体验与锁进入 `runtime`。Worker 路径由各自的受控Supervisor 使用，状态取本轮实际线程。普通产品缓存只保留 `cache/assistant`；源码开发依赖、工具和构建缓存全部位于 `var/development`，按本地存储计划的明确类别清理，始终保护当前在用构建和产品数据。
- 启动器必须核对受控解释器与关键依赖身份，来源漂移时停止并给出恢复建议；当前 CHECK/RECORDING Worker 与独立 Runner 必须继承同一受控身份。具体 Python、前端工具链和 Playwright 准备规则见[修改开发环境](../开发.md)。
- 图形界面继续进入 `serve --open`。工作台只展示 `WorkspaceView` 中的当前应用、连接状态、唯一 `PrimaryTask`、动作级权限/实现摘要和长期区域状态；不读取 dormant Run 或 Result 伪造最近结果，也不保存线性进度。普通命令行进入仅对当前子进程生效的 PowerShell，调用已解析的 Python 绝对路径并继承当前 `VarDir`。
- readiness 的唯一真源是 Python 对 `/ready` 的精确响应校验：HTTP 200、根版本 1 且 `status=ready`。软等待阈值只产生一次“仍在准备”事件并继续等待，不能被解释为服务已启动或浏览器失败；serve 在 ready 前退出则产生独立启动失败事件。只有 ready 成立后才尝试打开系统浏览器，并分别报告“网页已打开”或“服务已 ready、浏览器未打开”。PowerShell 只展示 Python 产生的稳定状态事件，不自行猜测 readiness。
- 服务 ready 后启动动画立即结束，终端明确提示网页退出入口与 `Ctrl+C`，并继续持有服务生命周期。GUI 的“退出界鉴”复用当前 control session 与精确同源 Origin 触发同一 shutdown 链，不保留静态魔法控制头；正常退出依次停止 Worker、受控 Runner/浏览器和 ApplicationCore。系统浏览器页面属于用户进程，不被强制关闭，页面只提示服务已停止后可关闭。
- ready 前装配 ApplicationCore、MCP/control及通用Worker、运行加载监督生命周期。/ready 不把配置或对象存在视为线程存活；后台维护失败只记录错误，不冒充 Worker 失败或成功。退出先有界停止受控任务和 Supervisor，任一独立进程停止失败时保留共享凭据、数据库和运行目录，确认停止后再释放共享资源。
- 自动化调用可显式指定 GUI、CLI 或 Prepare；省略模式时同样进入 GUI。直接调用 `scripts/start.ps1` 时保持可组合的退出码并立即返回。`start.cmd` 对 PowerShell 的任意非零退出统一保留原始退出码，并在阶段、错误码、主错误、日志和恢复建议输出后等待用户关闭窗口；该兜底也覆盖参数解析和模块加载失败。

### 输出与实例边界

CLI 命令范围和 Human / Machine 输出由[入口与输出](入口与输出.md#cli-human-与-machine)统一维护；启动过程只负责建立资源和通道，不另写一份机器格式。

官方环境入口使用普通 Project/BusinessBoundary/Recording/Preparation 与 CHECK 事实。环境面板仅启动、重置、停止或切换中性条件；项目精确匹配时，可在普通权限页采用已提供提案并 Human Approval，在普通 Preparation 采用材料。分析统一进入普通验证、ResultStory/Evidence、Changes/Repair，不能保存预期 Verdict 或 Sample 专属安全判断。

`serve` 与所有准备创建 ApplicationCore 的普通 CLI 命令复用同一 VarDir 系统锁；同一运行目录已有 GUI 或 CLI 控制者时返回 `WORKSPACE_ALREADY_CONTROLLED`，不会创建第二个 ApplicationCore，也不通过 daemon、IPC 或本机 HTTP 绕过。

### 当前业务边界主流程

当前主流程是接入应用、确认或持续维护业务边界，并从 WorkspaceView 获得动作级待办。普通权限、准备缺口、显式验证与已发布结果、变化登记及原题复验共享同一控制面；官方提供的提案/材料只是可选输入，不形成第二套审批或结果链。完整边界见[应用接入与检查主流程](../../产品/检查与复验.md#如何理解结论)。产品文案默认中文，机器字段和路径保留原文。

### 关键不变量

- API、GUI 和 CLI 不直接创建 Engine、UnitOfWork、RequestStore 或 Dispatcher。
- API/GUI 不直接向目标发高风险请求。
- `127.0.0.1` 控制面与目标执行进程隔离；监听 loopback 不能替代 Host、会话和写请求 Origin 校验。
- MCP Bearer 的 SecretStore 引用、逐 Project 临时提权和 SDK Host/Origin 防护不能由 GUI Cookie、Provider Key 或代理头替代；普通状态不能返回 Bearer 正文，工具白名单不能暴露秘密、源码、请求正文、完整日志、完整 Evidence、shell 或任意 HTTP。
- Agent 变化声明只能携带项目、原因与有界相对路径线索；控制面不得接受 Git 命令、文件正文、diff、权限 ID、Case ID、Effect ID 或 Profile 选择。变化感知的 prepare/run 只接受服务端已经形成的 `change_id`。
- 用户可见状态不替代机器结果；INCONCLUSIVE 不得显示为安全通过，HTTP 拒绝也不得替代真实状态观察。
- 启动失败、浏览器未打开、运行环境不可用和检查无法开始都应给出可恢复、脱敏的提示。
- 普通用户错误固定展示失败阶段、原因、任务标识、日志位置和下一步，并提供可复制文本；内部堆栈只进入有界脱敏日志。

### 失败语义

启动准备、浏览器、数据库、前端、API 输入、项目识别、Contract/Profile、目标地址或运行环境失败时，入口停止当前动作并保留可诊断日志。控制面断开不等于执行成功或失败；事件序号用于恢复读取。

### 安全约束

默认只监听 `127.0.0.1`。控制会话令牌使用 256-bit 随机源且只驻留当前服务内存与 HttpOnly Cookie；MCP 使用另一份至少 256-bit 的长期配对 Bearer，其正文只经 `cred:jiejian/mcp-control/pairing` 进入 SecretStore。两者不能互相替代，MCP Bearer 不写数据库、日志、报告或项目，普通 API 也不返回正文。Onboarding 的识别预算、目标范围、身份、写操作、reset、重定向、私网和请求预算必须显式确认或由执行边界校验。共享 SecretStore 只允许严格命名空间下的精确引用操作；测试账号的 Cookie/Token 正文只进入 Windows Credential Manager，API、数据库、项目文件、协议、日志、Evidence 和报告均不出现正文或可枚举秘密。

Serve 把本次实际、已规范化的控制面 origin 注入 ApplicationCore。应用地址确认在网络探测和持久化前拒绝该 origin；Web Target Guard 在保留的目标请求边界再次拒绝，防止历史冻结配置或绕过控制面的输入让界鉴检查自身。Worker/Runner 只能通过固定最小环境继承该 origin；CLI 未启动 Serve 时没有保留 origin，不使用固定端口猜测控制面地址。

### 兼容与版本

当前产品入口只服务 Web Target。CLI 的产品命令以实际 help 和启动输出为准；公共 JSON/Schema 版本不是产品代际。`/mcp` 只是当前 Web 产品的控制 ingress，生产 Target 协议仍不保留未实现的 CLI_APPLICATION 或 MCP_AGENT。旧启动模式、旧参数位置和旧路由 alias 不兼容保留。
