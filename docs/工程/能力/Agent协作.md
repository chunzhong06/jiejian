# 全产品 Agent 协作

状态：CURRENT。本文定义协作能力及其责任边界；验证范围以实际取得的证据为准。

## 应用环境与接口来源

共享目录增加 `environments.read/save/activate`及`sources.read/preview/accept/candidate/annotate`。环境切换保留本机批准门禁；来源只形成可审阅线索，不批准规则。`sources.preview`接收已经净化并持久化的候选引用，原始含秘密资料只经瞬时HTTP导入入口解析，不能作为协作操作参数写入任务历史。Agent从用户已经提供的净化候选继续差异审阅和场景整理。

无源码应用可读取与准备，代码修改能力仍要求实际源码和读取授权。Agent的工作目录位于var运行区，不能通过无源码配置补造源码或部署身份。GUI、MCP和本机Agent使用相同用例；无需真实付费模型也可完成手工工作流。共享`checks.preview/start`接受明确外部原题命令；执行批准显示原问题、当前范围及未核对的部署声明，不沿源码路径补造加载对应。


## 场景试运行

`flows.trial.preview/start/history/read/cancel`复用GUI的场景试运行用例。预览冻结准确流程修订、环境、真实账号、已有资源及预算；开始和取消必须经本机人工审阅，Agent不能自行批准。获准后由Worker及隔离Runner执行一次，有限步骤反馈只说明HTTP请求与主体核验事实，不产生正式权限结论、不采用场景，也不激活规则。

网络回执未知时按原操作编号读取已有任务，取消与进程恢复不重放受检请求。需要恢复时明确预览并批准原记录的恢复请求；HTTP接受不能证明业务状态恢复。进度入口携带业务操作和准确试运行编号，GUI恢复原修订及选中记录；从记录继续编辑产生新草稿，仍采用的修订保持不变。当前试运行要求唯一末尾受检步骤及已知资源编号；执行中创建后才得到编号的场景继续使用正式检查路径。

## 用户目标与责任

用户交代目标后，协作任务关联接入、业务理解、权限候选、运行、账号、数据、操作、证明、检查、修改、复验及维护。用户处理业务决定、必要授权和安全登录；可信已有配置由系统复用，理解与候选整理交给 Agent，确定性执行和结论由界鉴拥有。手工路径继续可用。

## 事实所有权

协作任务保存目标、执行者、会话引用、必要决定、业务操作引用和恢复位置，不另存可手工修改的材料 READY 或权限结论。DevelopmentTask 继续负责代码交付，Job 继续负责具体后台执行。共享工作区只允许一个 Agent 写入者。

HTTP 与 MCP 调用同一能力目录及用例。目录声明参数、所需权限、可读取的结果和人的决定；禁止任意 HTTP、shell、权限批准和秘密正文。输入在公开边界接受，内部传递已接受对象，不重复逐层解析。未知副作用先查询原操作，不能自动换键重发。

连接、任务接收、模型执行、业务执行和目标完成分别展示。Agent 的完成消息不构成检查通过或修复已验证。当前代码只提供实现线索，不独自决定业务应允许什么。

## 能力覆盖

| 领域 | 协作工作 | 必要的人类决定 |
| --- | --- | --- |
| 接入与业务 | 读取已授权源码、识别运行和业务线索、整理候选 | 目录与访问范围，业务歧义 |
| 权限 | 组织候选、差异、正常功能及要求来源 | 正式业务规则批准 |
| 运行 | 准备启动方案、查询和恢复原操作 | 新增安装、构建和执行范围 |
| 账号 | 复用认证结构、建立实际主体、组织核验 | 登录与秘密输入 |
| 操作与资源 | 复用或保存流程候选、动态关联及恢复方案 | 测试数据操作范围及歧义 |
| 证明 | 组织来源配置、预检查和缺口 | 读取授权和采用 |
| 检查 | 组织批准范围、正常对照、执行和取消 | 尚未授权的执行范围 |
| 结果与修复 | 精确读取证据、解释、登记真实修改、原题复验 | 修改范围及新业务标准 |
| 恢复与维护 | 查询回执、保留完成项、诊断并组织维护计划 | 删除、更新及停止的实际影响 |

## 执行通道

外部 Agent 经 MCP 发起或接续任务。界鉴发起时需要真实执行适配器，负责启动、进度、停止和会话恢复；MCP 配置成功不等于可以控制客户端。优先核验本地 Codex app-server。客户端按实际能力接入，不能假定都支持 ACP、sampling、elicitation 或持久任务。

模型调用只在用户明确启动后执行。界鉴不读取或复制客户端认证文件，本地 Codex 自身沿用其已配置账号。适配器只向子进程传入有限系统环境，不继承目标秘密或环境中的模型 Key；配置和进度不保存原始模型文本或推理。目标请求与浏览器仍通过 Worker/Runner。

客户端的文件和网络限制与界鉴工具授权分别落实。当前适配器限制写入根和网络，并拒绝原生提权请求；它不能保证整个文件系统的读取隔离，也不能把客户端继承的配置视作界鉴授权的一部分。

本地执行器只加载协作上下文、能力说明和具名能力入口。只读权限下仅交付三个读取工具；只读入口在服务端拒绝所有写入和待审能力，并按实际语义声明 MCP 只读属性。准备与执行权限下，受控命令入口复用产品授权和必要审阅，不在客户端再重复要求确认同一网关调用。此委派不包括任意终端、文件提权、任务自批准或其他 MCP 工具。

协议连接必须初始化成功后才开始模型回合。任务只保存工具名称、有限状态和回合结果，不保存参数原文或模型回答；工具被拒绝或失败时保留明确提示，不用“回合已返回”掩盖未完成的读取。只读查询不写入业务操作历史，因此不能靠操作条数判断 Agent 是否读到了报告。

## 工作面与恢复

### 有限接续与完成依据

本机启动可以选择持续推进。一次授权最多 8 个模型回合、30 分钟，等待确认及后台任务也计入这个窗口；单回合模式返回后不自动使用剩余额度。系统另限制该次接续新增的业务操作数量，读取原回执不消耗新增操作额度。

每轮结束后先核对业务产物，再决定结束、等待或继续。等待本机决定时使用提交后的通知唤醒；Worker 是独立进程，确有未完成任务时才观察数据库提交代次。等待结束后产物已齐全时直接收口，不额外调用模型复述结果。没有新产物或新决定时停止接续，不通过不断调用模型轮询进度。模型调用不持有业务写事务。

| 目标 | 结束依据 |
| --- | --- |
| 执行检查 | 本任务提交的检查已完成并形成三态结论；发现违规也可以完成“检查”目标 |
| 检查并修复 | 没有发现违规且本次检查通过，或本任务发现的原问题全部取得完整复验依据 |
| 修复指定问题 | 准确原报告关联的问题已验证，正常功能和原题要求继续成立 |
| 理解指定报告 | 本任务确实读取了指定报告，不以其他报告或模型自述替代 |
| 准备、规则与维护 | 分别核对当前材料、候选审阅结果或已执行维护回执 |

完成依据绑定目标、用途和准确业务引用。用户补充目标后，旧目标的计算结果不能结束新目标；暂停与下一回合领取使用同一个事务写锁。业务操作结果未知时保留原标识并停止接续，不换键重放。服务重启将原执行收为待核对，保留会话和业务回执，重新取得明确启动授权后才调用模型。

### 页面交接与产物审阅

委派示例绑定 RULES、SETUP、CHECK，任务类型始终可见且可调整；检查并修复等目标分别采用原有完成条件。补充目标保留此前目标、对象和操作历史，以本次引用替换当前工作范围；完成计算只使用新目标之后的操作，旧报告读取标记不沿用。暂停任务补充后仍保持暂停。网络回执未知时冻结原输入与操作编号，查询同一幂等回执后再继续。

页面地址只提取已知业务引用及产品内回程。接口流程交接可选的 FLOW 编辑结构，包含动作与修订、流程编号、步骤路径和参数来源；结果判断交接 PROOF 的动作、效果及已选映射。嵌套交接类型不重复 schema_version，旧任务缺失 editor 时按无草稿处理；无 editor 的请求保留既有幂等指纹。交接结构不接受参数值、请求正文、凭据或文件，非法路径保留为待补全。原始表单只在本次浏览器文档内存保留，页面导航可接续，整页刷新或关闭窗口不保证恢复。

流程产物通过 flows.read 和对应 HTTP 入口读取准确 flow_id/revision，并核对项目归属。候选先比较当前草稿与该修订，用户显式带入后才进入核对；同名、同位置且仍为常量的参数可选择沿用本机填写值，形成变化时保存新修订。候选保存不采用、不试运行。协作任务归集流程和证明待审入口，采用之后再根据原业务事实核对；新修订替代本任务旧候选的待审位置，旧修订仍可读。针对某份流程或证明的准备目标只核对其对应产物，不能因其他材料齐备而自动完成。

协作工作面提供当前目标补充、建议回答与自由说明、进行中及全部任务。切换或查看任务不启动模型，已结束任务保留产物；用户可另建目标。接口流程与证明页面使用同一个交接入口所有者，任务页的补充不重新复制整份表单。

### 日常检查范围

协作和手工预览共用保存的规则选择。全部规则表示下次按当时已批准规则重新核对；局部选择保存准确意图、修订和内容身份。旧选择失配时明确列出变化，不自动替换规则或丢弃其中一部分。方案不保存账号就绪、运行状态、证明可用性或历史通过结论；正常对照及原题复验仍由原检查服务决定。

任务工作面显示目标、正在处理的对象、执行者、当前具体动作、必要决定、产物及下一步。目标与任务状态相邻，当前推进动作和最近结果共用工作面。资料与记录按需展开，任务管理和执行方式退后一级；空记录区不展示，已有主报告入口不在资料中重复。对象页面保留，协作入口携带精确项目、规则、检查和修改引用。技术日志按需展开，不把整屏聊天或内部字段表作为默认操作方式。离开页面不取消后台工作；重新打开回到原任务。

必要决定展示准确范围和影响。同一已授权范围复用，发生实质变化才重新确认；业务批准、秘密输入不能由 Agent 的普通回答替代。用户取消后先停止后续动作，再收口所属后台操作；取消请求已收到与实际停止分开显示。

## 当前实现与验证边界

持久任务、共享能力目录、MCP 与本机审阅、具体问题、精确业务回执和产物导航已经接通。任务状态不覆盖 Job 和 Run；最近检查仅读取 Run 的生命周期及结论，详细报告、证据按需加载。任务列表不为每个历史项重新展开报告。

同一普通 Express/SQLite 工单应用通过 MCP 完成接入、三种认证、操作与恢复步骤、独立证明、首检、真实修改和三条规则复验。首检确认两项禁止操作实际成功，修改后两项均按原标准通过，负责人正常操作仍通过。重新对应源码没有改变权限版本；原报告继续读取当时事实。服务重启后保留原任务与回执，应用会话失效则重新核验并沿用认证配置登录。

这组实跑使用当前对话的 Agent 调用真实 MCP，验证业务协作通道。选定范围已贯通 GUI、共享能力目录、冻结执行与报告：自动保留必要正常对照，明确未检查规则，原题复验不能缩小。真实普通应用选择一项禁止规则和正常对照通过，未选规则继续保留；无关账号退出、来源复用与读取撤权另有实际 Worker/Runner 验证。

新增匿名、同租户、跨租户及有限资源状态已经在同一普通应用贯通。六项正式检查确认归档工单仍可修改，其余五项符合规则；登记真实修改、载入后，原题复验通过，正常功能及相关限制保留。匿名没有测试账号，条件来自实际身份和所选 SQLite 字段。报告保留每次条件及原结果，不把界鉴技术路径当作应用自行发送的事件。

本机执行可在已配对的只读权限下解读现有规则和结果，无须先授予材料准备权限。MCP 继续拒绝超出当前级别的业务动作；源码写入还须有本轮明确授权，不能由只读启动附带取得。模型回合与业务完成仍分别显示，实际模型验收独立于协议替身记录。

此前真实本机 Codex 已通过任务上下文、能力说明和只读入口读取指定的六项原题复验报告。第三版进一步在没有专用事件代码的独立 Express/SQLite 应用中，接续同一个任务完成真实检查、源码权限修改、变更登记和加载，以及原题复验。首检形成违规报告，最终报告为 PASS，原题核验为 VERIFIED；任务依据实际产物结束。

本轮实际模型共执行 5 个回合；另有一次建立模型会话前的连接失败，连同它按 6 次保守计入授权预算，未超过 8 回合及原 30 分钟窗口。初始项目、正式规则与材料由本对话预先准备；必要审阅、虚构登录、服务修复重启后的账号和源码对应恢复由验收助手完成，不等同于模型从空目录无人值守完成全部接入。原报告、源代码修改与最终复验均可分别回读，不用替身执行器充当模型验收。

实跑暴露并修正了两项接续问题：工具参数已被本轮纠正后，监督器不再丢弃后来成功提交的业务；问题编号格式错误按公开输入错误返回，工具 Schema 共享准确约束，不能误报为内部记录损坏。原始问题文本和客户端错误正文不进入诊断日志。

## 验证与参考

按最小充分原则，分别验证任务与原操作回执、权限边界、真实后台业务执行、协议适配和两主题工作流。普通应用不得依赖专用事件代码或官方示例配方。协议测试执行器不能冒充真实模型；按用户要求取消真人评估和真实用户项目试用门槛。

采用理由：借鉴 [GitHub 会话管理](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents) 的持续任务与产物关系、[Codex app-server](https://learn.chatgpt.com/docs/app-server) 的会话生命周期、[ACP](https://agentclientprotocol.com/protocol/v1/overview) 的能力协商，以及 [VS Code 权限设计](https://code.visualstudio.com/docs/agents/run/approvals) 对授权与隔离的区分。保留现有确定性业务服务，不引入第二套 Agent 权限判断。
