# 材料与恢复

本页面向维护者，说明能力协作、持久事实、拒绝边界和恢复方式。用户操作从[文档入口](../../README.md)选择；源码定位查[模块索引](../../参考/模块索引.md)。

## 材料与恢复

### 修改与直接验证

先确定改的是派生需求、来源核验、绑定写入、有限草稿还是展示。来源问题从 `bindings/sources.py` 的 `BindingSourceInspector.reasons` 和 Recording/Flow 向上追；页面缺口从 Preparation / PrimaryTask 向下追，避免在两个方向各建一份准备状态。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 test tests/application/preparation/materials/test_material_recovery.py
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 frontend-test src/pages/preparation/materials/MaterialEditor.test.tsx src/shared/lib/useRead.test.tsx
```

按改动选择命令；绑定变化另测幂等、多 owner、来源漂移，需求变化测确定性和身份约束。持久化变化再读[数据库指南](../数据库与迁移.md)，验证等级只由[验证规范](../测试.md)及实际影响决定。

### 必须保持

- 当前服务从正式 Action/Permission revision、账号与技术绑定现场派生状态；不持久化第二份 READY，不修改业务权限。
- DENY 必须有完整合法 ALLOW 对照；并列候选由用户明确选择。缺口不是安全结论，前端不选择身份或任务优先级。
- 材料引用必须匹配项目、动作修订、用途、subject / owner 与受控实例；源码、endpoint 或来源漂移失败关闭，不按名称匹配。
- 材料确认先核对预览基线，绑定与回执在同一写事务中提交；同一 operation_id 只回读同一请求，不能重复写入。
- 草稿只存有限引用和回读标识，不存秘密、任意表单或登录内容。草稿恢复后仍重新读取 Preparation。 材料采用在发送前将原操作标识保存到按项目和材料隔离的会话缓存，刷新后查询原回执。未知、错误关联或服务端写入结果不明时保持待确认；关闭整个会话不保证保留该浏览器缓存，后端持久事实仍通过原标识读取。
- 候选录制审阅完成不自动替换正式绑定；采用须经过影响预览和确认。已有 Run 的冻结输入与证据不改变。
- 普通准备 GET 不运行目标、浏览器或模型；Recovery 不删除历史证据，环境 reset 不冒充动作恢复。

## 材料与恢复契约

### 这是什么

准备服务把正式 BusinessAction revision 和 Permission revisions 翻译成真实身份、动作演示、具体资源、业务结果证明和恢复方式。`ActionAssuranceContract` 与身份需求计划都是确定性派生结果，不持久化为另一套权限规则。DENY 没有合法 ALLOW control 时要求回到权限维护，不能猜测允许身份。

`PreparationService` 每次重读业务事实、账号状态和技术绑定，形成 `SATISFIED / NEEDS_USER / STALE / BLOCKED / NOT_REQUIRED`。材料齐备不等于检查可运行，更不等于 PASS。当前准备只经 PreparationService 与四类动作技术绑定；不恢复旧准备状态机或第二套权限配置。

### 正常修改路线

先确定变化属于派生需求、候选提取、技术事实写入还是现场检查。GET `/api/projects/{project_id}/preparation` 直接调用唯一 `PreparationService.get`，不连接目标、浏览器、模型或写库。Workspace 在原业务边界优先级之后依次处理待审录制、身份、动作演示、具体资源、Effect 证明与恢复；待审录制优先于再次演示，同类按稳定动作/slot/effect 顺序选择，材料齐备后由 Workspace 继续选择检查、复验或结果任务，没有待办时才可为空。权限与业务结果来自已批准的正式 revision；候选只来自真实脱敏事件、请求模板与 Flow 资源位置。唯一且合法的解释可由确定性程序采用，歧义则保留待审，LLM 只能解释。

TARGET 最终化时发布不可变 Flow，再在同一数据库事务保存 Recording 完成态、ActionExecutionBinding 和当前 owner 的 ActionResourceBinding。一个动作可有多个 owner 的资源；重复最终化不能用旧录制覆盖后来已成立的绑定。Flow 已发布但数据库事务失败时只留下内容寻址的孤立文件，重试必须验证相同 hash。

OBSERVATION 在开始前绑定当前动作已有的 effect_id，只能从明确的观察录制形成 ActionEvidenceBinding。REGISTERED_OBSERVER 是已存在受控 descriptor 的窄引用，普通 UI 不暴露，不接受任意 URL、SQL 或脚本。RECOVERY 只为改变状态的动作形成恢复模板；只读动作的恢复直接为 NOT_REQUIRED，不创建假记录。

### 查看已有证明材料

GET `/api/projects/{project_id}/preparation/evidence/{action_id}` 提供当前动作的只读材料说明。它沿用准备服务的检查结果，附上正式业务结果名称、已保存来源和有限能力声明；不列出未绑定来源、不保存绑定、不改变准备状态或执行条件。界面入口位于准备页的“查看证明要求与来源能力”，按业务结果分别阅读。

实现入口为 `product/backend/application/preparation/materials/evidence.py` 与 `PreparationBindingService.describe_evidence`。两次读取之间若动作或绑定发生变化，仅将本次详情标为需要更新；不会把新来源和旧检查状态拼成有效材料。未接入来源查询器与明确找不到来源分别表示未知和不可用；缺少能力声明也保持未知。声明支持观察闭合或资源关联，不代表某轮已经取得对应事实。接口不暴露注册引用、请求模板、凭据或原始响应。

### 完整对照与只读计划

每条 DENY 的完整 protected effects 必须由同 Action/revision、同 owner Actor/revision 的单条 ALLOW 覆盖。只按 subject Actor/revision 是否改变排名，全部等价最佳候选保留；多个最佳候选通过 GUI 的 `POST /api/projects/{project_id}/preparation/allow-control` 选择。请求格式 1 仅包含 deny/selected ALLOW 的完整身份和 expected_selection_fingerprint，服务端在同一事务重读并保存技术绑定，不修改 Permission、Approval 或 policy_epoch。候选或 revision 漂移后旧选择不再生效。

`PermissionBoundaryStatus.allow_control_available` 只表示完整合法候选存在；技术选择、账号 distinct 和 Twin 缺口只由 Preparation 投影。Workspace 的 SELECT_ALLOW_CONTROL 紧随完整 ALLOW 缺口，先于账号准备。

`PreparationService.current_plan` 装配现场检查通过的绑定、身份和精确 descriptor 能力，调用 `product/backend/domain/checks/plan.py` 纯编译器。全部 current Action 保留；每条 ALLOW 有完整回归，每条 DENY 与 resolved ALLOW 形成同 owner/resource/Flow/证明/恢复/source/config 的 Twin。超集 ALLOW 保留完整回归，并为 DENY 整组 effects 生成子集 control；相同 case 可以复用两个角色。

动作的执行、证明与恢复绑定记录采集来源的双身份，不把模板限定在该来源 owner。来源仍须通过当前性检查；参数化请求注入每个 case 冻结的资源，受控 observer 必须支持精确资源关联。不同 owner 的 case 分别保留其资源绑定和证明指纹，不能复用另一个 case 的观察结果。计划可构造不等于真实操作已成功：正常对照必须实际确认业务结果，恢复必须实际确认当前资源回到基线。

注册证明必须由注入的受控 reader 精确返回 descriptor/effect 的三态、closure 与资源关联能力；未装配返回 gap。录制 GET 只有资源形成语义且精确注入 CASE_RESOURCE_ID 才支持 HTTP_RESOURCE_PRESENCE，其他 GET 仅 supporting。`build_execution_request` 在关键 gap 存在时 STATE_PRECONDITION；成功仅构造无秘密的当前格式快照，不提交 CHECK Job 或生成认证会话。

### 来源与失效

四类绑定分别保存 subject_test_identity_id/subject_identity_fingerprint 和 resource_owner_test_identity_id/owner_identity_fingerprint；资源主键按 Action/revision/owner 分组，不要求 owner 等于 subject。四类绑定只持久化被确认的技术事实与指纹。现场检查核对业务 revision、语义和实现指纹、真实确认 endpoint、源码来源、账号、来源 Recording/Draft 与 Flow。账号重新登录不抹去技术来源；账号删除保留历史 ID，但旧绑定不能满足当前准备。业务 revision 变化后旧绑定保留历史，不能迁到新 revision 冒充 current。

新写入先验证动作、effect、账号和来源属于同一项目且 revision 精确；补录必须关联同动作、同版本、同 subject 与 owner 的已完成 TARGET。确认前源码、目标地址或实现漂移时失败关闭，不根据名称重新匹配。

### 不能破坏

- 前端不重算身份匹配、准备完成、stale 或唯一下一步；Workspace 是任务优先级真源。
- HTTP method、risk_hint、模型建议和页面状态不能创造或改变 BusinessEffect、Permission、Verdict。
- 缺身份、资源、观察或恢复只形成准备缺口，不冒充安全结论。
- 现场检查不连接目标、不恢复浏览器、不读取秘密正文、不写“READY=true”。
- Recovery 不删除历史证据；测试环境全量 reset 是独立设施，不能冒充动作恢复。
- 数据库增量升级保留正式业务数据，旧候选录制或安全数据非空时在 DDL 前拒绝；不猜映射、不重置数据库。

### 材料局部更新与恢复

`PreparationMaterialService` 只在现有绑定和 Preparation 投影上提供材料详情、候选、影响预览、确认与回执；不产生另一套 READY 状态。候选来自同一应用、动作修订和用途的已完成录制，复用 `PreparationBindingService.build_recording_bindings` 核对不可变录制、Flow、资源所有者和来源。替换动作录制时同时更新其资源绑定；替换某项结果证明只更新该效果。已有 Run 的冻结输入与证据不改变。

同一身份重新登录不会改变录制来源的身份指纹，模板可在当前身份再次可用后沿用。源码、实现映射或目标地址漂移仍由原 `_source_reasons` 拒绝；不会把旧捕获指纹改写为新捕获，也不自动跨动作修订复用。

受控官方环境的来源指纹同时包含持久登记的运行实例标识；即使再次运行沿用同一端口，旧现场材料也必须重新核对。普通接入应用没有该受控实例标识时，保持原指纹格式与核验方式。此关联只证明材料所属的受控实例，不证明运行代码与某个 Git 提交一致。

确认材料时先取得 UoW 写事务，再比对预览基线；绑定与操作回执一次提交。`operation_id` 重复只回读同一请求的回执，指纹不同则拒绝。保存回执仅证明材料操作完成，不等于准备完整或检查通过。GET 回执可以在页面刷新、控制面重启后恢复，不调用目标。

准备草稿只允许动作/材料引用、候选录制、基线指纹和待回读操作标识。草稿修订实施 compare-and-swap，不保存密码、Cookie、Token、任意表单正文或登录页面内容。草稿仅恢复选择位置，使用前仍须读取当前 Preparation。

直接覆盖：`tests/application/preparation/materials/test_material_recovery.py`；前端 `MaterialEditor.test.tsx` 与 `Preparation.test.tsx`。材料预览/保存均不提交检查。

主动录制替换材料使用服务端计算的有限 Recording context，不伪造全局 PrimaryTask。组合必须来自当前已批准 ALLOW、准确账号槽位和资源所有者；补录仍依赖当前有效的父录制。候选用途与 Recording/Job 在同一事务写入 `preparation_candidate_recordings`；Lifecycle 的人工或自动最终化只验证并保存候选，不改正式准备绑定。刷新后按精确材料范围找回活动候选；最终采用仍调用材料影响预览与确认接口。

录制 API 的 `material_candidate` 默认为 false，旧调用保持原行为；材料详情主动发起的替换录制显式设为 true。局部替换必须保持操作账号和资源所有者，不能仅因 effect 相同就采用另一身份组合的来源。身份或归属变化应先走当前准备任务核对。

### 人工补充材料的写入边界

HTTP 入口接受 `SupplementalDocument` 后直接传入服务，不转回字典再解析。基础内容扫描由该模型拥有，指纹只编码并摘要已接受内容。创建复用已核对的指纹，标签修订形成新内容后重新接受；撤回只追加生命周期修订，保留原内容指纹。预览新取得的已知秘密集合和仓储写入边界仍分别检查。

动作级 `supplemental-materials` 路由由 `SupplementalMaterialService` 统一校验和保存。preview 只读；create 绑定 expected_fingerprint 与 UUID request_id；revisions 仅追加说明，withdraw 追加撤回修订。请求 ID 按项目唯一绑定操作、目标和内容，冲突拒绝。所有项目/动作/修订精确核对，新登记必须匹配当前正式动作修订。

导入根 schema_version=1 仅允许项目/动作/动作修订、标题/来源/可选声明资源及1～100条时间/资源/事件记录，UTF-8 canonical 最多64KiB，拒绝额外字段和典型秘密。格式接受不证明真实性；association_status 仅 USER_DECLARED 或 UNCONFIRMED，usage 固定 SUPPLEMENTAL_ONLY。无路径读取、URL采集或脚本执行入口；材料不进入 MCP、Evidence、准备完整性、Plan 或 Verdict。每次列表及修订历史读取最多100项，显式 limit/has_more，不伪造总量；修订历史用正整数 before_revision 继续读取更早记录。直接测试为 `tests/application/preparation/test_supplemental_materials.py`。

### 准备批次的故障与恢复

异步批次遇到业务错误时保留原错误码和说明；未知异常使用 `PREPARATION_INTERNAL_ERROR`，与材料缺口区分。两者都停止后续步骤，生命周期保持 `BLOCKED`，公开进度通过 `error_code` 表达原因，不产生权限结论。

内部错误在持久批次和运行日志中保存异常类别、模块、函数与行号，不保存原始异常正文、源码行、局部变量或目标返回内容。已完成材料和未确认操作引用保留；再次查询不会重放这些操作。重新准备前仍须按原操作标识确认回执。

批次重启后先核对未确认步骤的原回执，再执行已经持久化的取消意图。取消只收口本批已有任务，不因控制会话变化被撤回；继续创建材料仍须核对当前控制会话并重新确认计划。准备页回读取消结果，内部故障使用错误反馈，业务缺口使用待处理反馈。未知准备响应的查询只读取原批次状态。

## 材料协作

### 正常链与执行位置

1. TestIdentity引用已经批准的Actor revision。身份准备使用独立受控浏览器进程；结果只返回非秘密元数据与受控secret_ref，真实Cookie/Token保存在SecretStore。
2. 用户选择已确认动作和一个已准备账号，Recording服务冻结短期录制输入并进入Recording Worker/Runner。API不直接控制目标浏览器。
3. 用户演示业务动作和必要观察/恢复，再审阅FlowDraft。Flow保存受限步骤和身份/资源slot；它不固定差分账号、资源或整个Observer配置。
4. 录制生命周期从同一次记录产生候选资源、独立观察与恢复。材料服务读取候选，先给预览及受影响范围，用户确认后写入对应动作revision下的四类技术binding。
5. BindingSourceInspector供Preparation、材料读取和检查构建共用，复用调用方事务核验来源。Preparation派生缺口，Guidance解释可采取的动作，Workspace决定全局唯一下一步。
6. CheckRuntimeBuilder冻结当前有效身份、资源、Flow、证明与恢复；Runner按冻结输入执行。补充材料只提供明确用途的受限依据，不能代替真实身份或required观察。

### 事实的归属

| 事实 | writer | reader/下游 | 保存边界 |
| --- | --- | --- | --- |
| 身份与登录 | test_identities/identity preparation | Recording、准备、最小秘密注入 | 身份元数据与SecretStore分开 |
| 录制/Flow | recording lifecycle与人审阅 | 候选提取、binding、Runner | 不把录制自报结果当Verdict |
| 四类binding | preparation bindings/materials | inspector与runtime builder | 保存选择、来源及fingerprint；不存READY |
| 材料草稿/回执 | materials service、preparation_recovery | GUI原操作回读 | 只保存有限引用，不保存秘密或任意表单 |
| 准备建议 | guidance | GUI/MCP | 现场派生，依据变化则NEEDS_REFRESH |

### 失败和恢复

- 会话、源码、endpoint、action revision、运行或录制来源漂移，旧binding由inspection判失效；不修改正式权限。
- 写动作缺少独立可信观察或已确认恢复时保持gap，不能为了产生INCONCLUSIVE反复污染目标。
- 恢复草稿后重读Preparation。材料确认用预览基线和CAS，binding与回执同事务；未知响应只查原操作。
- 录制或身份准备中止时分别走其受控进程清理和精确秘密补偿，不按进程名称清理用户浏览器。
- cleanup失败保留主错误和独立清理信息，不能被界面“完成”覆盖。
