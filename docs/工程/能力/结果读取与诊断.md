# 结果读取与诊断

本页面向维护者，说明能力协作、持久事实、拒绝边界和恢复方式。用户操作从[文档入口](../../README.md)选择；源码定位查[模块索引](../../参考/模块索引.md)。

## 权限断裂诊断

### 当前 CHECK 诊断链

当前输入为冻结 `ExecutionRequest` 的 Case/Twin、`CheckRuntimeBundle` 的独立身份映射以及已发布 `CheckEvidence`。唯一 `product/backend/domain/verification/checks.py` 先形成效果事实与 Verdict；`assess_check_authorization_continuity` 和 `BreakpointLocator.locate_current` 使用这些事实，`CheckStoryBuilder` 将定位写入只读 `ResultStory`。不构造旧 `PermissionContract` 或 `DifferentialExperimentPlan`，不通过 `ResultPresentation` 进入当前结果 API。

Trace 真源是 `product/backend/infrastructure/observers/checks/check_trace.py` 对本 Case 真实审计窗口的显式投影；缺失父节点、跨 Case 引用、冲突或预算不足必须保留 partial。它只消费显式范围、effect_id、父引用和受控来源，不能从请求结果或计划补证。实际账号映射来自独立身份核验；Trace 主体名不能覆盖已核验身份或替未知身份兜底。

受控 Node 记录来源还使用 `managed_trace.py`：应用在实际执行处调用 `records.trace(resource_id, event)`，宿主绑定当前请求，记录服务校验父事件、提交引用与请求/资源归属。Runner 只从已采用的同一记录来源读取当前请求事件，并核对来源身份、generation、nonce 与请求摘要；无事件或未记录响应准备节点时保留 partial。事件通过既有 CheckEvidence 发布，GUI 与 MCP 读取同一证据，不靠示例名称识别或生成路径。

这里的完整表示所记录的请求事件链已闭合，不表示追踪了每个函数、异步任务或外部服务。应用的 ALLOW/DENY 事件是应用执行记录，不是界鉴权限结论；事务引用先由独立记录组件核对，但本通道不从该引用猜 protected effect_id，因此具体断裂仍可能只能到 VIOLATION_ONLY。已有业务事实与 Verdict 不受 Trace 缺失影响。

事件写入命令、写入回执和读取日志分别为版本 1 的独立根文档；嵌套事件不带重复版本。事件在请求闭合时与 scope 一起持久化，在记录组件内部压缩保存，读取限制为 256 KiB；继续保留既有 128 MiB 日志上限。崩溃后未闭合的请求不能恢复成完整路径。

六种断裂类型与 `EXACT / RANGE / VIOLATION_ONLY` 语义保持不变。合法委托必须具有因果祖先 `AUTHORIZATION/ALLOW`、非空显式来源范围、未扩大的委托范围、实际动作和资源被覆盖以及一致凭据来源。缺失/空数组不证明范围；错误授权祖先、跨 Case 引用和无关资源不能证明合法委托。即使委托合法，也不能把独立权威来源已确认的 DENY 禁止效果从 BLOCK 改成 PASS。

修改位置为 `product/backend/domain/verification/continuity.py`、`product/backend/domain/verification/breakpoints/` 与 `product/backend/domain/verification/trace.py`、`product/backend/infrastructure/observers/checks/check_trace.py` 与 `product/backend/application/checks/reading/story.py`。诊断只影响解释，不重算发布 Verdict。检查 `test_check_breakpoints.py`、`test_check_continuity.py` 的直接规则及 `test_check_audit_scope_publication.py` 的真实采集发布链；不得仅用手工 Trace 代替后者。当前 GUI 和 MCP 只消费同一 ResultStory；独立报告格式不属于该产品读取链，CLI 不提供结果命令。

### 诊断边界

结果页用 `ExecutionPath` 展示显式关系，`DiagnosisSummary` 解释已发布精度与缺口，`tracePresentation.ts` 仅承担业务文案翻译。EXACT 只标记服务端 first violation 节点；RANGE 默认展示已发布的起止端点与区间，不补画中间事件，完整节点关系可另切图形或列表。端点未出现在本轮路径时明确缺失，不能按首尾节点替代。VIOLATION_ONLY 与无 Trace 保留已有后果说明，不拼造因果图。

桌面侧栏与图同页共存，窄屏默认列表阅读并用单一抽屉查看证据。节点点击后，客户端重新校验证据文档的 Run、Action、Case、ID 和所选节点的类型、来源、父引用；通过前只显示读取状态。来源、前序关系、独立后果与安全结论分别说明。详情读取失败撤下当前结果；迟到响应不得污染另一项检查。

定位只解释已确认后果，不能因为缺少诊断把 BLOCK 降成 PASS。EXACT、RANGE、VIOLATION_ONLY 必须有相应证据支持；无法证明具体类型时保留 null，不猜文件、函数或行号。主断裂与后续影响分开，影响只沿显式父子因果传播，不按时间、名称或列表顺序补边。

当前执行路径只引用本 Case 真正承载 Trace 的 CheckEvidence。缺失 Trace 时保留事实对照，不能生成示意路径冒充执行证据。实际身份来自独立核验，计划主体、Trace 名称和后端 actor 变化均不能兜底。

独立报告格式仍可由保留的 ResultPresentation/trace/reporting 实现及其直接测试消费；其字段与 canonical 约束见[报告与格式投影协议](../协议与持久化.md)，不能据此恢复旧前端或 CLI/MCP 入口。

## 结果与修复

### 当前 CHECK 结果入口

当前链为 `ExecutionRequest + CheckRuntimeBundle → CHECK Worker/Check Runner → CheckEvidence + CheckRunnerResult → CheckPublisher → CheckResultReader → ResultStory`。唯一判定入口为 `product/backend/domain/verification/checks.py`；发布器重验冻结事实与判定后执行受租约/fencing 保护的文件提升和 SQLite 收据事务。读取只能使用同 Run 的不可变文件、hash 和收据，不重放目标、不调用 Observer、不重算 Verdict。

`product/backend/application/checks/reading/results.py` 提供严格 Reader，`story.py` 提供逐 Case 的权限要求、计划身份、独立核验实际身份、HTTP 表面、效果、ALLOW 对照、定位及 Evidence 引用。UNKNOWN/MISMATCH 的实际身份 ID、标签和 actor 保持空值；不得从计划或 Trace 兜底。辅助来源保留 `SUPPORTING / DIAGNOSIS_REQUIRED`，不替代 `VERDICT_REQUIRED`。失效或篡改发布包隐藏安全结论并拒绝详情；进度只是 staging 外非权威旁路。

当前 API 为 `/api/runs/{run_id}`、其 `/result-story`、`/evidence`、`/evidence/{evidence_id}` 与 `/repair-contracts`；项目 `/runs` 提供历史列表，`/repair` 提供只读原题状态。确定性 Story 与受限 AI 解释分开，禁用 AI 不影响读取。Trace 和 Breakpoint 只解释已确认后果，显式合法委托或缺失诊断不能抹去已确认 BLOCK。

修改公共 Check 根需同步 Python、严格解析、canonical/hash、Schema 和真实发布读取测试。使用 `tests/infrastructure/runtime/jobs/publication/`、`test_check_result_reader.py`、`test_check_published_api.py` 与 `test_check_audit_scope_publication.py` 按受影响范围验证。当前BLOCK Case的 `repair_requirement` 从已发布原题重建，`repair_verification` 由精确关联NEW Run派生，ProjectRepair是唯一项目修复投影；保留的 `ResultPresentation`、报告、Finding/Gate 与修复实现不是当前 CHECK 已完成能力的证明，不把旧路由直接接回当前执行链。

`FactComparison.planned_resource_owner` 单独复制同 Run 冻结 bundle 中的资源所有者，verification_status 固定为 PLANNED；`resource_id` 只是冻结 Case 的技术引用，不发明资源实例名称。计划操作人与计划所有者都不能补填 UNKNOWN/MISMATCH 的实际身份。

`CheckProgressView.current_case` 只在有效 EXECUTING 进度、未完成计数与冻结 Case 总数一致时提供计划考题。Reader 使用 CheckRequestStore 按 request/config hash 读取 staging 外的不可变资产，执行纯输入关联校验，并核对 project、source、plan、policy_epoch、engine_version 和 Job/Run 关联。按执行器的 ALLOW 优先、action_id、case_id 串行顺序定位 completed_cases 所指题目；标签只取冻结 action、身份和 proof。该说明不证明请求已发出、实际身份已验证或效果已出现。说明缺失或资产失效时仅 current_case 为空，原有效阶段/计数保留；原进度 fencing/格式校验失败仍无进度。发布后 current_case 为空，安全结论继续只来自完整性校验后的结果。

Story 的 `repair_comparison` 与 ProjectRepair task 的 `comparison` 复用只读 RepairComparisonRow，分别保留 DENY、SELECTED_ALLOW 与全部 REGRESSION 义务。前后只复制对应已发布 CaseVerdict 和 Evidence 引用；缺失、歧义或上下文不符不猜 after 结果。单行 SAFE 不证明原证据标准仍成立，是否完成原题修复始终读取权威 Repair status。

### 修改当前只读投影

结果显示先说明规则要求、实际操作结果和判断依据。状态文字与业务对象合成完整句，不让用户自行拼接“结果名称＋已发生/未发生”；自定义名称保留原文，未知观察不改成不存在。证据详情使用直述标题，原始字段、原因码和精确引用仍可展开核对。文件比较明确标注参照文件与实际收到；状态变化才使用操作前后。此层只解释已发布事实，不改变Verdict、证据或权限。

`ActionResultStory.proof_coverage` 对应同一已发布 Case 的冻结证明要求与实际证据，界面在单项“事实与证明”中展示必要证明摘要，并在“证据记录”中分开列出辅助材料、观察状态及限制。投影只读取已校验的同 Run request、bundle 和 Evidence；当前注册来源或配置变化不影响历史解释，也不回写发布文件或重新判断 Verdict。没有对应观察时保持 UNKNOWN，未闭合的 ABSENT 不显示为已经确认不存在。引用按 observation 的等级分别收集；一份文档含多种观察时，可以同时出现在必要与辅助引用中，但不能因此提升证明等级。

点击对应记录进入当前 Case 的同页 Evidence 阅读面，桌面与窄屏均不叠加抽屉；返回恢复原入口焦点。详情重新核验 Project、Run、Action、Case 及证据文档 ID；只读取所选proof、阶段或流程节点。辅助材料不能替代必要证明，单项观察状态不能当作整轮安全结论。

`reading/records.py`提供FACT、OUTCOME、OBSERVATION、TRACE的有界索引和单条投影；`record_text.py`翻译冻结方法及已发布原因。六类说明包含规则、实际执行、采集方法、归属、判断理由和证明边界，各自带准确逻辑文件、字段位置、原文摘要及白名单片段。旧Evidence1没有保存的前后值明确缺失；未知原因不猜测解释。GET不运行模型或Verification、不访问应用、不回写历史。

API为`GET /api/runs/{run_id}/evidence/{evidence_id}/records`及其`/{record_id}`详情，均要求project_id和case_id。MCP的`jiejian_evidence_show`在READ项目授权下复用同一reader，record_ref为空时仅返回索引；不开放任意路径、URL或字段指针，也不输出nonce、lease/fence或物理位置。

前端`EvidenceVerification`仅位于证据阅读面；舒适模式只把证据目录限宽居中，紧凑模式允许前两项同样收拢。所有入口复用当前结果组件和`tab/evidence_id/record_id`参数，刷新保留准确对象；错误不退回第一条记录。共享“Agent 协助”可携带同一定位，关闭Agent仍能完整阅读。

`observation_reading.py` 为每条已发布观察生成只读 `reading`：对照、过程记录、业务事实、阶段未完成、能力不支持、读取失败、依据不足及未安排采集分别表达。真实读取/关联/预算缺口优先，不能被“已取得部分记录”掩盖；任务完成和队列窗口为空只解释该来源，不提升为交付物存在或不存在。来源类型取同 Run 冻结配置，GUI 与 MCP 共用此说明。该嵌套读模型不改写 Evidence、公共持久化格式或 Verdict。

证据目录按 observer、effect、proof 与等级分别聚合；默认展示最后一个操作后/最终阶段，不挑最好状态，也不用恢复阶段覆盖发生事实。所有阶段仍可展开，早期缺口在概览中计数提示；返回证据目录展开原来源并恢复入口焦点。未知闭合状态不得写成“仍在运行”；已发布记录不会自行变成确认结果，补足条件须发起新检查。

先确认请求的 project、Run、Case 和 Evidence 引用，再沿发布收据、不可变文件及 hash 回读。同 Run 的索引和完整 Evidence 是不同资源；缺失、篡改、关联不符时拒绝详情并隐藏可见安全结论，不能使用数据库旧 Verdict 或前端缓存兜底。生命周期、结果完整性和 PASS/BLOCK/INCONCLUSIVE 分别表达。

检查模块顶部保留唯一“检查历史”入口，只有一张按Run排列的列表。规则、结论和执行状态是同列表的筛选条件；准确规则使用intent_id/revision/intent_hash三元组，SQL筛选先于分页，同Run匹配Case合并。筛选行只归纳匹配Case的已发布结果，不以整轮PASS替代单条规则证据。深链保留筛选、分页起点和Run/Case/record，返回恢复原位置；无效位置明确提示。

`CheckHistoryService`提供有界规则候选和显式索引维护。`rule_check_index`只存定位与manifest_hash，新结果和索引同发布事务提交；GET不补写索引。旧记录通过`POST /api/projects/{project_id}/check-history/index-maintenance`按原operation_id及checkpoint推进，每批最多100包，开始下一包前核对5秒/64MiB预算。未知响应查同键回执；坏包标不可读，不能声称已完整覆盖或补造Verdict。规则候选、覆盖状态及回执均通过同一路由下的只读端点取得。

检查历史来自 CheckResultReader 的有界查询。默认 limit 25、最大 50，过滤与成对 cursor 语义见[控制面协议](控制面与授权.md)。不能把历史列表为空解释为问题已修复。

ResultStory 只复制已发布事实，使用冻结业务标签解释权限、计划身份、独立核验身份、HTTP、真实效果、合法对照、诊断精度及证据边界。HTTP 拒绝保持中性，缺 Trace 不补图，partial 保持 partial；前端不按文本、数量或颜色重判。Evidence 完整性失败时页面撤下该 Run 的安全结论。受限 AI 解释与确定性故事分离，GET 不调用模型，显式 POST 也不能改变结论、证据、断点或修复要求。

ProjectRepair 从最早已发布 BLOCK 建立问题族，只接受精确原题、源 Run、变化和新 Run 的关联。必须消失的效果、应保留的合法控制、全部历史 SAFE 回归与原证据标准不能被弱化。普通 PASS 不等于原题 VERIFIED；Agent 自述、界面状态和 Sample 条件都不是修复事实。旧发布结果永不回填，新条件通过显式提交形成新 Run。

运行格式6的`repair_evidence_standards`直接比较冻结来源语义：后果和必要级别、合同/原子提交语义、集合与字段映射、受保护投影或期望状态、真实身份核验、资源与所有者、完整闭合要求。文件还保留原参照asset_id/size/hash及完整实体比较方法。source修订、预检查ID、展示标签、读取授权ID和源码引用路径不参与标准等价；其追溯仍保留在各自冻结输入。旧运行格式继续原算法。新Run即使PASS，换文件或换证明标准仍返回REPAIR_STANDARD_CHANGED，不能形成原题VERIFIED。

### 必须保持的边界

- Verification 只依据已形成事实给三态；Reader、Story、GUI、MCP 和模型不重判。
- 当前读取不执行目标、Observer、修复或隐式检查提交。
- 必需证明与支持/诊断来源分开；支持材料不能升级为必需安全事实。
- 独立根版本、嵌套 DTO、数据库 revision 和产品版本各有边界。
- 秘密、原始敏感业务数据和无依据的代码位置不进入结果投影。
- 保留报告格式不证明当前产品已提供报告生成、下载或交付检查。
