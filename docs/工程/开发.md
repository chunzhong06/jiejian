# 开发环境与修改流程

日常使用从仓库根的 `start.cmd` 启动；工程操作统一经 `scripts/dev.ps1`。本页面向需要修改代码、依赖或工具的维护者。使用产品的步骤见[首次检查](../产品/开始使用.md)。

## 环境与输出

工具版本由 `product/config/toolchain.json` 定义，Python 环境由 `environment.yml` 和 `uv.lock` 约束，前端由清单和锁文件约束。开发入口核对指纹，复用有效环境和构建；不要在源码目录安装另一套临时依赖来绕过入口。

运行数据、受控依赖工作区、构建与缓存进入 `var/` 边界。需要独立实例时使用开发入口的 `-VarDir`，并选择与日常实例不同的地址；运行根隔离不能代替目标授权。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 prepare
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 cli --help
```

prepare 完成环境和资源准备；CLI help 用于核对当前可用命令。首次准备可能需要下载依赖，后续按指纹复用。准备失败应从明确失败阶段恢复，不删除用户数据或改写数据库来试探。

## 工程工具的所有者

`scripts/dev.ps1` 调度工程任务，`scripts/start.ps1` 组织源码启动。Python 尚未就绪时，由 PowerShell 引导环境；准备完成后调用统一产品 CLI。服务、Worker 和目标进程的生命周期仍由产品管理。

| 位置 | 职责 |
| --- | --- |
| `scripts/lib` | 调用者环境、编码、位置的保存恢复，以及工程文件摘要和临时目录标记 |
| `scripts/dev` | Python 与 Node 工具链、前端依赖工作区、构建回执和命令调度 |
| `scripts/startup` | 源码启动上下文、回执接纳、阶段事件和终端展示 |
| `scripts/build` | Wheel 钩子、发行组装、启动器编译、包校验和归档发布 |
| `scripts/docs` | 声明参考生成及文档依赖检查 |
| `scripts/quality` | 最小验证范围、执行计划、语法检查和测试回执适配 |
| `scripts/editor` | 正式前端源码的编辑器依赖解析插件及工作区安装 |
| `tests/tooling/editor` | 使用真实 TypeScript Server 验证编辑器解析行为 |

前端的工具解析、工作区同步和产物发布分别维护。有效依赖与构建继续按身份复用，目录拆分不增加安装次数。编辑器验证由 `frontend-test` 调用，产品运行不加载这些开发设施。

源码启动与开发入口共用会话恢复库。终端启动需要读取阶段事件，普通开发命令需要保留完整标准流，两者分别适配输出。产品启动器源码与许可归 `product/launcher/windows`，构建工具只读取这些输入，不再从终端脚本文本提取品牌数据。

## 修改顺序

1. 明确本次交付、边界和完成条件，查看 Git 实态与正在运行的实例，保护已有修改。
2. 从 `docs/llms.txt` 找到任务说明，再沿[模块索引](../参考/模块索引.md)核对当前所有者与直接消费者。
3. 先定义输入、可观察结果及失败行为。写操作同时定义幂等标识、事务和回执查询；公共格式确认 reader 与兼容范围。
4. 在事实所有者处实现，接通接口和使用方；删除代码前核对静态引用、注册、资源和独立 reader。
5. 按[测试与验证](测试.md)选择最小充分范围，修正文档与参考，回读保存后的文件和实际结果。

同一工作树只保留一个主要写入者。不因目录更名保留一套转发实现，也不把单次搜索未命中直接认定为死代码。无关功能和有效验证检查点保持原状。

## 声明与参考

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 schema
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 docs
```

默认只读核对。需要接受当前声明时，在相应命令追加 `-Update`，审阅差异后再执行只读检查。Schema、路由和迁移表可生成；用户任务、原因和恢复步骤由人工编写。

## 代码与交付

Python 检查设置 `PYTHONDONTWRITEBYTECODE=1` 并使用 `-B`，单纯语法检查不导入目标模块。Python 自有文件保留一行职责头；其余注释只解释非显然约束和原因，避免逐行翻译代码。

交付说明变化、原因、实际验证和限制。构建成功不能代表真实流程或独立分发成立。数据库维护见[数据库与迁移](数据库与迁移.md)，完整分发见[发布](发布.md)。
