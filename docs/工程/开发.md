# 开发环境与修改流程

日常使用从仓库根的 `start.cmd` 启动；工程操作统一经 `scripts/dev.ps1`。本页面向需要修改代码、依赖或工具的维护者。使用产品的步骤见[首次检查](../产品/开始使用.md)。

## 环境与输出

工具版本由 `product/config/toolchain.json` 定义，Python 环境由 `scripts/development/environment.yml` 和根目录的 `uv.lock` 约束，前端由清单和锁文件约束。开发入口核对指纹，复用有效环境和构建；不要在源码目录安装另一套临时依赖来绕过入口。

运行数据、受控依赖工作区、构建与缓存进入 `var/` 边界。需要独立实例时使用开发入口的 `-VarDir`，并选择与日常实例不同的地址；运行根隔离不能代替目标授权。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 prepare
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 cli --help
```

prepare 完成环境和资源准备；CLI help 用于核对当前可用命令。首次准备可能需要下载依赖，后续按指纹复用。准备失败应从明确失败阶段恢复，不删除用户数据或改写数据库来试探。

## 工程工具的所有者

`scripts/dev.ps1` 调度工程任务，`scripts/start.ps1` 组织源码启动。Python 尚未就绪时，由 PowerShell 引导环境；准备完成后调用统一产品 CLI。服务、Worker 和目标进程的生命周期仍由产品管理。

| 位置 | 职责 |
| --- | --- |
| `scripts/development` | 工具链、环境与会话、前端工作区、构建回执和命令实现 |
| `scripts/development/startup` | 源码启动上下文、回执接纳、阶段事件和终端展示 |
| `scripts/build` | Wheel 钩子、发行组装、启动器编译、包校验和归档发布 |
| `scripts/docs` | 声明参考生成及文档依赖检查 |
| `scripts/quality` | 最小验证范围、执行计划、语法检查和测试回执适配 |
| `product/frontend/tooling` | Vite 配置、Vitest 初始化和编辑器解析插件；安装接入由开发工作区负责 |
| `tests/tooling/editor` | 使用真实 TypeScript Server 验证编辑器解析行为 |

前端的工具解析、工作区同步和产物发布分别维护。有效依赖与构建继续按身份复用，目录拆分不增加安装次数。编辑器验证由 `frontend-test` 调用，产品运行不加载这些开发设施。

源码启动与开发入口共用会话恢复库。终端启动需要读取阶段事件，普通开发命令需要保留完整标准流，两者分别适配输出。产品启动器源码与许可归 `product/launcher/windows`，构建工具只读取这些输入，不再从终端脚本文本提取品牌数据。

## 从哪个入口开始

| 任务 | 入口 |
| --- | --- |
| 日常打开产品 | 根目录 `start.cmd` |
| 指定端口、运行目录或启动模式 | `scripts/start.ps1` |
| 准备环境、运行测试、生成参考或打包 | `scripts/dev.ps1` 的对应命令 |
| 前端工具的内部配置 | `product/frontend/tooling`，由包命令显式加载 |

`scripts` 只保留这两个 PowerShell 入口，内部实现归入 development、build、docs、quality 四个职责目录。源码启动是开发工具的一部分，展示、回执与产品接入模块集中在 development/startup；共用会话和文件机制直接归 development，不另设跨所有者的 lib 目录。

根目录保留 Python 项目清单、锁文件、编辑器约定、仓库说明和启动入口，它们参与工具自动发现或面向整个仓库。前端保留 package、锁文件、工作区设置、tsconfig 和 HTML 入口；构建、测试和编辑器实现集中在 tooling，不通过额外转发文件维持旧路径。

## 修改顺序

1. 明确本次交付、边界和完成条件，查看 Git 实态与正在运行的实例，保护已有修改。
2. 从 `docs/llms.txt` 找到任务说明，再沿[模块索引](../参考/模块索引.md)核对当前所有者与直接消费者。
3. 先定义输入、可观察结果及失败行为。面向用户或跨进程的可重试写入，按实际副作用设计幂等标识、事务和回执查询；普通内部调用不额外建立这些设施。公共格式确认 reader 与兼容范围。
4. 在事实所有者处实现，接通接口和使用方；删除代码前核对静态引用、注册、资源和独立 reader。
5. 按[测试与验证](测试.md)选择最小充分范围，修正文档与参考，回读保存后的文件和实际结果。

同一工作树只保留一个主要写入者。不因目录更名保留一套转发实现，也不把单次搜索未命中直接认定为死代码。无关功能和有效验证检查点保持原状。

## 按契约实现与校验去重

内部代码依照明确的类型、依赖和状态契约直接工作。必需依赖在装配时连接；普通调用不反复判空、探测属性或猜测返回类型。真正可选的能力明确表达可用与不可用状态。没有实际输入、平台或兼容需求时，不增加备用路径、默认成功、空结果兜底或“以防万一”的通用包装。

异常在能够解释和处理它的边界转换。内部契约被破坏时应暴露故障，不能通过广泛捕获后返回空列表、旧值或普通业务缺口掩盖。资源释放、异步任务收口和脱敏错误映射仍由其所有者负责；保留故障原因，清理异常不能覆盖主错误。

校验按对象、输入版本和调用位置判断是否重复：同一份未改变的输入，已经由所属边界确认后，后续内部调用直接使用该结果。不要把合法模型反复转成 JSON 再解析、在摘要函数里重新执行整套模型校验，或在每层复制相同的关联判断。输入经过修改、重新从外部读取，或可变状态跨过并发窗口时，按新条件核对。

每条规则有一个实际所有者。格式由入口 reader 和模型负责，业务约束由领域或用例负责，写入竞争由事务条件和数据库约束负责，文件读取由对应存储 reader 负责。下游需要同一次读取已确认的模型、字节或摘要时，直接传递现有结果；不为消除重复再建立一套校验注册表、常驻可信缓存或绕过检查的开关。

输入解析、权限授权、秘密与路径边界、租约和 fence、并发提交条件、独立文件读取各有真实职责。它们是否需要重新执行，取决于是否出现新的输入、授权或状态变化。具体边界见[协议与持久化](协议与持久化.md#校验的所有者与有效范围)，已收敛调用链见[架构中的实现分工](架构.md#当前校验与错误处理的收敛项)。

工程验证同样复用有效结果。已有命令内置的检查不在外层再执行一遍；同一代码状态不机械重复比对或逐级跑满测试。新增检查须对应本次变化的实际风险或消费者，遵循[最小充分原则](测试.md#最小充分原则)。

## 声明与参考

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 schema
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 docs
```

默认只读核对。需要接受当前声明时，在相应命令追加 `-Update` 并审阅差异。`docs -Update` 已包含更新后的只读复核，不必紧接着再执行 `docs`；之后又修改文档时再检查。Schema、路由和迁移表可生成；用户任务、原因和恢复步骤由人工编写。

## 代码与交付

Python 检查设置 `PYTHONDONTWRITEBYTECODE=1` 并使用 `-B`，单纯语法检查不导入目标模块。注释按真实职责、接口契约和维护原因组织，长度由理解需要决定，不要求统一文件头或固定密度。先清理失效与重复说明，结构调整后再补充对应注释；许可证、工具指令及参与 Schema、帮助等生成的文档按实际消费者处理。

交付说明变化、原因、实际验证和限制。构建成功不能代表真实流程或独立分发成立。数据库维护见[数据库与迁移](数据库与迁移.md)，完整分发见[发布](发布.md)。
