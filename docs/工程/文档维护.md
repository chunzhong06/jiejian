# 文档维护

文档让读者完成任务并理解结果。正文根据当前产品事实独立编写，前置条件、操作和预期结果应足以复现；设计资料和讨论记录不能成为操作的隐含前提。

## 四类内容分别回答问题

| 内容 | 读者此刻需要什么 | 写法 |
| --- | --- | --- |
| 教程 | 在明确环境中完成一个真实任务 | 给出起点、连贯步骤、可观察结果，尽早获得有效产物 |
| 操作 | 解决已有工作中的具体问题 | 先列前置条件，再给动作、结果和失败后的继续位置 |
| 说明 | 理解关系、原因和取舍 | 用业务例子解释条件与限制，链接必要参考 |
| 工程与参考 | 维护机制或查找精确声明 | 工程解释所有权与边界，参考列格式、接口、状态和源码位置 |

一个页面围绕一个任务。避免按内部模块名要求使用者来回跳转；也不把全部背景塞入每份指南。重复事实保留一个所有者，其他页面给出目的明确的链接。

产品指南集中在 `docs/产品`，以接入、规则、准备、检查、开发工具和本地维护等实际任务组织。短概念在所属任务中解释，首次使用单独提供连续路径，修复演练与检查指南合并；不为内容类型分别维护平行目录。工程文档保留实现者需要的精确约束，生成参考负责定位，两者由文档首页连接到对应任务与验证范围。

## 信息由谁负责

用户动作以真实界面和可执行入口为准；状态含义由领域模型与严格契约负责；事务、资源和调用边界由实际实现负责。遇到冲突应判定产品或文档哪一方需要修正，不能默认源码和旧说明永远正确。

`参考/模块索引.md` 及其源码分册、`参考/接口与协议.md`、`参考/数据库修订.md` 从声明提取；`参考/验证范围.md` 从验证目录生成。它们只负责查阅，不证明接口已经运行、迁移可以处理任意旧库或测试覆盖所有风险。

前端通用布局由[布局与视觉](前端/布局与视觉.md)维护，任务专属分区由[工作面模式](前端/工作面模式.md)维护，采用理由由[前端设计依据](前端/设计依据.md)维护；交互与实现分别拥有状态规则及技术参数。修改时只更新事实所有者，其他位置链接对应小节。控制面按授权连接、入口输出、启动退出分别查阅，产品指南继续按用户任务组织。

历史纠正按[使用历史约定](任务执行与协作.md#使用历史约定)核对适用范围。长期有效知识只增量修订所属事实所有者，保留仍成立的条件与知识；一次任务的授权、进度和证据留在原任务记录或 `var/`。不把单次样例、未接受建议和历史测量写成常驻规则，也不新建平行记忆库。

## 按任务加载上下文

根 AGENTS.md 保留始终适用的授权、硬边界和停止条件；[任务路由](../llms.txt)只说明何时读取、到哪里读取，正文继续由事实所有者维护。人和代理使用同一份知识，不为代理另写一套产品契约。

先根据用户当前目标和将要作出的决定选择入口。同一任务涉及多项契约时合并读取；已经读过、仍在上下文且未变化的内容继续复用。普通任务沿用轻量流程；版本任务的完整提示词、当前卡和账本继续按[任务执行规范](任务执行与协作.md#确定交付范围)读取。

| 入口类型 | 读取范围 | 何时展开 |
| --- | --- | --- |
| 无章节锚点的任务指南或能力契约 | 全文，包括前置条件、失败与恢复 | 任务涉及另一能力或跨模块语义时，补读其所有者 |
| 带章节锚点的解释或操作 | 页首适用前提、目标节及子节；同级或更高标题是结束边界 | 小节明确依赖其他条件、当前问题尚未得到回答，或任务转为实施修改时继续读取 |
| 模块、接口、Schema 与验证参考 | 总索引、对应目录或对象章节、准确源码及直接消费者 | 确认关联后再读取相邻对象；参考不能替代所属工程契约 |

实施源码、脚本或测试修改前读取开发流程和本次受影响的完整契约。涉及授权、秘密、公共格式、持久化、事务、发布或核心生命周期时，必须覆盖对应所有者的完整约束；章节入口只用于定位，不能据此省略其前置与失败条件。文档修改先读取本文；检查工具或生成器变化再按测试规范验证直接行为。

路由保持单层扁平，使用相对 Markdown 链接，章节锚点来自实际标题。单目标直接以触发说明作为链接文字，多目标同行列出且全部必读；保留触发条件与目的地，合并重复的展示标签。触发说明区分解释、实施和恢复，不在每条入口重复规则；跨能力依赖在正文对应位置给出带目的的链接。生成模块分册按源码目录导航，每个文件保留独立标题和源码入口，文件事实只维护一份。读取章节按语义标题结束，不以固定行数裁断；同一主题散落或前提不清时，先修正文结构再缩小读取范围。

恢复时保留目标、裁决、完成范围、未决问题与准确来源；输入变化、未知写入或接受过程不完整时重查相应事实。摘要承担定位作用，已经形成的完整要求与证据继续由原始所有者负责。具体恢复流程见[有效检查点](任务执行与协作.md#从有效检查点继续)。

### 直接读取与复用

`docs read` 从当前路由和实际标题读取，不维护知识副本。重复 `--route` 或 `--ref` 合并读取；保留页首前提和子节，按同级或更高标题停止。`--implement` 将所选章节展开为所属全文并补开发流程；其他受影响所有者与直接消费者仍按上文核对，不把“所选所有者已全文读取”当作影响分析完成。`--source` 接受准确源码路径或唯一后缀，只返回模块索引的证据前提及准确文件声明，不能与实施模式混用。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 docs read --route "仅解释未知写入如何恢复"
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 docs read --route "修改公共格式、秘密处理、事务、回执或发布实现" --implement
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 docs read --source "product/backend/application/checks/reading/comparison.py"
```

默认只返回带来源的正文；按需加 `--json` 取得准确行段、内容摘要及读取回执。正文仍在当前上下文时，可把上一JSON输出存入原任务目录，通过 `--seen` 复用；工具先核对当前文件内容，变化后重新返回。新上下文缺少正文时不使用旧回执跳读。文件缺失、越界、章节无效或超过读取预算时明确失败，不截断后冒充已读。入口实现由 `scripts/docs/reading.py` 和 `scripts/docs/context.py` 负责；任务接续与证据核对见[任务片段](任务执行与协作.md#可检查的接续与证据)。

正文默认每次最多返回6000字符，长结果明确给出已返回位置及 `--cursor`。保留同一组参数继续读取，直到结束；游标绑定完整选择的内容，源变化后拒绝旧游标。分段只控制本次输出量，不裁掉已解锁的契约；未结束前不能将所选全文记为已读。分段JSON不发放可跳读回执，避免把最后一段冒充已读全文；预算可用 `--max-chars` 按调用方能力调整。

## 一次更新的顺序

1. 确认受众、要完成的任务和当前可观察行为。
2. 写明起点与条件，例如已有正式规则、真实账号可登录、运行代码已加载。
3. 按用户实际动作编写，采用界面中的当前名称；每组步骤给出可辨认的结果。
4. 处理关键分支：证据不足、材料失效、操作回执未知和运行环境不可用。
5. 同步相关解释、参考与 `docs/llms.txt`，删除失效入口和重复说明。
6. 运行文档检查，审阅生成差异；只有行为有变化且静态证据不足时才补相应运行验证。

## 重组时迁移知识

目录、格式和写作体系可以重建，仍成立的知识必须有去处。先盘点概念、操作、精确契约、异常恢复与设计理由，再按内容决定保留、合并、改写或移除；旧文件短、路径已变或代码已拆分，都不构成删除理由。

移动与内容修订分别核对，保持来源可追溯。重复段落合并到事实所有者；过时命令和路径替换为当前入口；已停止支持的能力说明移除，但仍在支持的历史 reader、数据库起点及恢复边界保留。生成符号页可由新的精确参考替代，人工解释不能被一份文件索引取代。

这一做法吸收了 [GitLab 的内容类型](https://docs.gitlab.com/development/documentation/topic_types/)和[文档移动流程](https://docs.gitlab.com/development/documentation/workflow/)：概念、任务、参考、排错分别维护，迁移时能够辨认位置变化与语义变化。仓库内部链接统一更新；是否需要外部重定向取决于是否存在已发布站点，不为本地文件建立空壳页面。

[Diátaxis 的应用指导](https://www.diataxis.fr/how-to-use-diataxis/)用于识别读者需要，不要求先搭出四套目录；[GitHub 的概念内容指导](https://docs.github.com/en/contributing/style-guide-and-content-model/concepts-content-type)也允许将短解释保留在所属文章中。这里据此合并小型概念，仍用清楚的小节区分操作步骤与原因，避免演练掩盖日常操作入口。

## 文案与示例

直接说明对象、动作和结果，保留专业含义和适用范围。一个段落处理一个问题；表格用于对照，编号用于必须按顺序执行的步骤。按钮名称、接口标识和错误代码准确，避免随意造词、模糊的“优化完成”和中点分隔。

命令标明从哪里运行、需要什么以及会写入哪里。示例只使用占位标识和公开内容，不包含秘密、真实凭据或用户数据。成功例与失败处理相互配合；没有运行证据时不能声称已实测。

## 检查能证明什么

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 docs
```

该命令只读核对。需要更新静态参考时使用 `docs -Update`，该入口在同一进程内回读已写内容并核对生成预期、路由和链接，无需紧接着再运行同一检查。后续又修改了文档或生成源时，再核对受影响内容。

检查覆盖本地文件、标题锚点、显式引用链接、任务路由和生成参考漂移。任务路由的触发条件与目标必须存在，单链接入口的空说明和断链同样拒绝；所有路由链接的目标限定为仓库文档，章节片段与普通链接同样核对；生成分册的目录导航也参加锚点检查。旧的仓库相对纯路径继续校验。代码块中的示例不当作文档依赖；正文行内明确的源码、脚本和测试路径必须存在，带占位符或通配符的路径只作示例。只处理项目使用的 Markdown 子集，不是通用 Markdown 解析器；外部链接内容、操作可用性和论述正确性仍需人工核验。

路由调整后，用解释、局部修改和跨模块修改等代表任务人工核对：能否找到所有者、是否加载必读前置、何时扩展、是否引入无关工作。静态检查核对路径与锚点，实际漏读、指令遵循和任务结果需结合执行观察；衡量改进时同时记录读取量、定位步骤、必要约束与最终正确性，不以文件字数作为效果结论。

内容组织参考 [GitHub Docs 内容模型](https://docs.github.com/en/contributing/style-guide-and-content-model/about-the-content-model)和 [Django 文档编写规范](https://docs.djangoproject.com/en/dev/internals/contributing/writing-documentation/)。采用任务、前置条件、结果与恢复的组织方法，保留本产品的授权与证据边界。

保留、合并和弃用的依据见[体系迁移与取舍](体系迁移与取舍.md)。


一次审计的证据表、实施流水和测量样本进入 `var/` 运行边界；长期文档只保留当前所有权、兼容责任和采用理由。审计结束后清除其临时文档入口，规范不得依赖运行目录才能理解。生成参考继续由源码生成，不能因其体积大或近期无人工访问而当作废弃审计删除。
