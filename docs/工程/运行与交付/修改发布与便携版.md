# 修改发布与便携版

> 状态：CURRENT。Windows x64 自包含发行；用户从界鉴.exe启动，构建只发生在发布端。

## 入口与交付结构

源码开发仍使用 `start.cmd → scripts/start.ps1 → dev.ps1 prepare`。发布包使用 `界鉴.exe → app/start.ps1 → runtime/python/python.exe → product.backend.cli serve`，复用同一个 ApplicationCore、受控浏览器和安全退出流程。

```text
JieJian-WebV1-<version>-Windows-x64/
├── 界鉴.exe
├── README.txt
├── app/               已安装的产品、前端、start.ps1 和 release.json
├── runtime/           python、node、playwright 与生产依赖
├── samples/           digital_gallery；仅完整版包含
├── docs/              使用说明、版本说明、第三方许可
└── var/               首次启动创建，保存项目、证据、日志与运行数据
```

源码、测试、开发脚本、编译器、设计草稿和依赖锁不复制到发布根。内部 Wheel 只作为构建材料，不作为普通用户的交付物。

## 构建命令

在 Windows x64 仓库根执行：

```powershell
.\scripts\dev.ps1 package
```

前端指纹未变化时复用已有 production build。需要明确重新准备时使用 `package -ForcePrepare`。不要把这个构建命令放进用户启动路径。

原生入口使用 toolchain.json 固定的 MinGW-w64 GCC 15.2.0、x86_64-w64-mingw32 目标。构建器核对版本、目标及 PE 导入表，exe只可依赖 Windows 自带 DLL。构建端可通过 `JIEJIAN_LAUNCHER_COMPILER` 指定 gcc.exe 的绝对路径；未指定时从开发环境查找 gcc.exe。编译器只在构建端使用，不进入发行包。

发布前准备固定 CPython、Node、Chromium，使用 `uv export --frozen --no-dev --no-emit-project` 安装生产依赖，构建并安装非 editable Wheel。Hatch只映射已经生成的前端，不自行构建。

输出固定在 `var/development/release/artifacts/`：

```text
JieJian-WebV1-<version>-Windows-x64.zip
JieJian-WebV1-<version>-Windows-x64-nosamples.zip
SHA256SUMS.txt
```

一个 Base Tree 生成两包；除 `samples/` 外的文件路径和 SHA256 完全一致。无示例版仍包含完整 Python、Node、Chromium、Worker 和产品能力。ZIP 先写临时文件，成功后替换同名输出；SHA256 最后生成，构建开始前不删除原 ZIP。

## 六个阶段

1. 复制固定 CPython 与 Playwright，加入固定 Node。
2. 安装 frozen 生产依赖与内部 Wheel。
3. 把同一 Wheel 的产品和 dist-info 移到 app，生成相对 .pth、原生 exe、说明和发行清单，校验 Base Tree。
4. 生成包含唯一官方示例的完整版 ZIP。
5. 生成无示例版 ZIP。
6. 核对两包产品树一致并写入 SHA256。

构建输出持续显示当前阶段；临时文件只进入 `var/development/release/build`。正式产物保留，不因本次任务结束而清理。确认全部构建进程结束后，可以清理该 build staging；不要连带清理共享 tools、cache 或用户 var。

## 固定启动与运行身份

原生入口从自身位置解析发行根，通过系统 Windows PowerShell 5.1 调用 `app/start.ps1`，没有控制台黑窗。它持有自己的进程树；重复双击同目录 exe 只发送本 Windows 会话的重开事件，由原服务复用 GUI 打开动作。不会启动第二个控制面、杀其他程序或自动改端口。

启动脚本核对格式3/布局3、Node摘要、唯一Chromium、产品与包版本，使用包内Python生成并传播来源指纹。产品与 dist-info 在 `app/`；依赖留在 `runtime/python/Lib/site-packages`。其中只包含相对路径的 `jiejian-app.pth` 让各进程读取同一产品，不使用 PYTHONPATH、editable安装或构建机绝对路径。

启动仅创建 var、执行必要数据库迁移并进入 CLI。不得安装、下载、编译、源码同步或调用 dev.ps1。组件损坏必须报错。数据和缓存只写 var；启动后固定 app/runtime 内容应完全不变。

用户关闭窗口后可以再次双击恢复。正常退出通过产品的退出界鉴入口，释放服务、Worker、受控目标、浏览器、端口和文件锁；原生 Job 只负责异常结束时回收本入口的残留后代。

## 最小验证

先验证目录合同和受控运行身份，再实际构建。真实发布验证使用仓库外中文空格路径，启动真正的 exe；核对 GUI、重复启动、包内组件、完整版一次正常检查、无示例版一次受控 Node 启停及正式退出。比较启动前后的固定 app/runtime 文件，不用模拟进程声称没有重新构建。

```powershell
.\scripts\dev.ps1 test tests/scripts/test_portable.py -m "not l5"
.\scripts\dev.ps1 package
$env:JIEJIAN_RUN_PORTABLE_PROBE = '1'
.\scripts\dev.ps1 test tests/scripts/test_portable.py::test_real_full_and_nosamples_portables_start_outside_repository -s
Remove-Item Env:JIEJIAN_RUN_PORTABLE_PROBE -ErrorAction SilentlyContinue
```

默认端口被用户实例占用时，先报告冲突，不自动结束它。首次有效失败后只修正对应根因并重跑受影响项，不因组装失败运行完整五轮 sample-test。需要无窗口或指定端口时，exe支持 `--no-open` 和 `--port 8766`。
