# 任务执行、恢复与协作

本文说明如何维持已授权工作的范围、恢复点和验收责任。行动门禁与安全边界以根 [AGENTS.md](../../AGENTS.md) 为准；本文不自动授权提交、委派或外部操作。

## 确定交付范围

普通任务明确目标、修改范围、必要验证和交付结果即可，不强制建立执行卡、机器状态或问题账本。任务复杂度不能成为扩大授权的理由，也不能以简化流程省略关键安全边界。

用户指定完整版本、连续卡片或正式接受流程时，先找到该任务的完整提示词、当前卡和账本。完整提示词决定范围，卡片划分当前工作，账本保存裁决与证据；摘要和文件名不能替代正文。资料缺失时明确说明缺口，不根据旧提交名猜测下一步。限定章节按语义标题读取，命中结束边界后停止。

产品版本、公共格式版本、数据库修订与业务规则版本分别演进。普通内部重组不自动产生兼容承诺；既有数据库和独立 reader 的支持责任见[数据库与迁移](数据库与迁移.md)和[协议与持久化](协议与持久化.md)。

## 使用历史约定

引用历史偏好、纠正或方案时，核对原话与当前有效性，保留来源、适用对象与属性、生效条件和用户是否接受。当前明确指令优先，只替换被明确改动的部分；讨论建议不自动成为要求。与当前决定无关的记忆不加载，局部约定只影响对应对象与属性，明确通用且仍有效的约束才控制本次选择。例子中的数值、工具和布局先判断适用条件，不扩展为全局规则。

## 从有效检查点继续

恢复工作时核对最新授权、当前 Git 根目录、分支、HEAD、工作树、已完成范围及验证结果，再由 [任务路由](../llms.txt) 加载缺少的知识。已读且未变化的内容继续复用。上下文压缩不使有效证据自动失效，未知写入、输入变化或不完整的接受过程才需要重查相应边界。

跨轮或交接时，在现有任务记录或接续摘要保留短状态：当前目标与授权、已接受决定及适用范围、完成与未完、下一步与门禁、完整范围和证据的准确入口。完整范围独立于进度保存，不以勾选清单或后来的摘要覆盖；普通任务不为此另建文件。补充纠正只更新受影响部分，新交接按约定顺序等待；暂停、取消或替换以最新明确指令为准。

章节读取与扩展见[按任务加载上下文](文档维护.md#按任务加载上下文)。任务转为实施修改时补齐受影响的完整契约，版本任务的原始范围仍按上文核对。

复杂任务在实施前写清模块职责、交换数据、不可改变的公共语义、先后依赖与直接验证。发现代码、文档和任务要求冲突时，明确冲突及裁决依据，不能静默选择。未失效的工作与验证保持有效，只从第一个失效点及其直接邻域恢复。

需要机器状态时，只记录当前阶段、写入者、基线、接受点和下一门禁；问题原因、方案取舍与证据由账本承载。不要解析叙述性账本来驱动机器状态，也不把临时任务身份和过程日志写入长期产品文档。

## 可检查的接续与证据

确需跨轮恢复或机器核对时，在原任务记录的“完整范围”和“当前状态”节分别使用 `task-scope`、`task-state` 围栏；普通任务不必采用。完整提示词继续保留，能力与检查项的投影由主线程对照原要求确认。工具只读这些显式片段，不解析叙述账本作调度，不创建平行状态库。

两个根片段声明格式身份和版本1，使用准确任务标识。完整字段由实际reader维护，按需用 `docs resume --help` 或 `docs check-task --help` 查询；未知格式、字段及重复键拒绝。完整范围保留能力标识、可观察结果与所需检查，状态中的完成和未完必须恰好覆盖这些标识。原授权及范围以 `{ref, sha256}` 引用，摘要取 `docs read --ref ... --json` 的内容摘要，状态更新不改变完整范围。

历史决定只有对象、属性同时匹配且已接受时才展开来源；不指定对象和属性就不加载历史正文。证据准确对应能力及检查序号，人工接受保留原话与来源。工具不把片段中的完成勾选当作事实。

```powershell
# 路径仅为用法示例，仍使用当前任务原有记录。
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 docs resume --record "var/当前任务/任务记录.md#当前状态" --task "原任务标识" --subject "视觉" --property "配色"
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 docs check-task --record "var/当前任务/任务记录.md#当前状态" --task "原任务标识"
```

`resume` 先核对任务身份、原授权、范围摘要和进度完整性，再返回短状态与必要来源；保留返回的 `scope` 和 `evidence_sources` 作为接续入口，不用缺少来源的文字摘要覆盖。新交接不能代替当前任务，暂停不返回可直接继续的下一步。最新用户指令仍须先写回原记录，Git实态仍按恢复规范核对，工具不从历史内容推导新授权。

`check-task` 从完整范围遍历证据，不相信已勾选进度。自动化证据必须来自既有正式回执，准确节点或文件实际通过，输入身份匹配当前代码、测试、工具与依赖；缺失、跳过、失败、过期和内容变更均保留缺口。人工证据只核对原话存在并展示来源，语义及接受范围由主线程审阅。缺口返回非零；齐备只到 `ready_for_review`，继续遵守原接受门禁，不写回完成状态。完整契约由本文维护，读取实现见 `scripts/docs/task_records.py`。

## 安排协作与交接

仅在当前授权和工具规则允许时委派。架构、安全、公共语义、持久化、核心生命周期、文档治理和最终接受由主线程裁决；前端流程、视觉、导航、交互与产品文案由主线程设计并实现。

可委派的非前端工作须有自包含说明：目标、已接受设计、前置事实、输入输出、责任范围、禁止边界、直接验证、失败上限和交接要求。模型配置与线程生命周期服从当前明确授权，不沿用历史任务的固定值。

共享工作树同一时间只有一个主要写入者。执行方持有写入权时，主线程不并发修改或提前开展下一批；相关输入变化前先收回写入权。等待以任务事件和正式交接为依据，不连续轮询或重复播报未变化状态。

交接报告包含修改摘要与范围、实际验证命令及结果、偏离设计之处、未完成事项和当前 Git 事实。通过文件交接时先完整写入临时文件，再原子发布；交接状态与报告分工，不能只发布“已完成”。交回后停止写入，通知行为仍须符合当前消息授权。

## 处理失败和不确定副作用

先区分产品、测试预期、夹具与环境失败。同一根因初次失败用于建立事实，之后最多两次有证据的局部修正；仍未解决则停止试错，说明最后完成步骤、第一主错误、影响与待决策事项。超出已接受设计的公共语义、安全或持久化问题先裁决再实施。

提交、删除、数据库写入、凭据写入或外部调用结果不明确时，先回读其权威状态，不用重复写入试探。退出、取消和清理分别核对结果；清理失败不能掩盖第一主错误。多阶段操作提供真实阶段与停止条件，不编造进度百分比。

权限失败核对目标、执行身份、失败对象及原因。确认属于沙箱或 ACL 后停止无增量重试，使用工具支持的最小范围授权；不能用递归接管所有权、重置 ACL 或修改父目录权限绕过保护。无法解析的 SID 本身不构成可删除理由。

## 验收与结束

执行方停止、存在提交或单项测试通过，均不等于任务已接受。实施前在现有任务说明或账本中，将约定能力对应到可观察结果与所需证据；普通任务可直接逐项说明，不另建验收台账。收尾时主线程对照完整范围审计差异、当前文档、资源清理和最小充分证据，记录实际对象、输入或代码状态、验证结果与缺口。未实现、未验证、失败、通过和用户已接受分别记录，已有局部接受保持有效，只有约定范围逐项有对应证据才标整体完成。

实际界面、终端和用户任务的体验需要相应运行观察，不能把预置终态当作完整状态转换或用少数页面代替全部关键流程。验证选择见[测试](测试.md)，只补缺失证据和受影响邻域。

提交与推送遵循用户授权，不作为所有任务的强制步骤。用户单纯要求提交、推送时，只完成指定版本更新、暂存、提交和推送，不额外启动测试、审计、打包或多轮远端核验；沿用本轮已有结果，Git 命令成功即可交付。

不自动创建备份分支、归档或恢复引用。强制推送须有明确授权，使用 lease 保护远端并发更新；只有 Git 返回失败或结果不明时，才读取必要事实并处理该失败。正式接受流程需要记录提交时，保留准确 SHA，不能把提交成功等同于产品验收。

接受只覆盖约定范围，范围外问题说明影响并另行处理。一次性执行任务在报告回收、审计和接受后按授权回收；明确要求连续推进时才进入下一阶段，否则交付后停止。
