# 构建与发布验收

发布要证明独立产物能够完成约定任务。源码环境可运行只说明开发装配成立，不能替代解压后的启动与使用验证。

## 准备输入

确认本次版本、目标平台、交付任务和数据升级范围。产品版本来自 `product/backend/__init__.py`；工具版本、依赖锁、包资源和前端声明必须对应本次源码。已有用户修改、运行数据和秘密不进入分发物。

开发入口 `scripts/dev.ps1 package` 组织 `scripts/build` 的装配。输出进入运行边界，输入指纹用于判断复用是否有效。构建前明确必须包含的 CLI、协议、迁移、样例、前端及运行时；移动模块后同步资源声明，不能靠复制旧目录填补遗漏。

## 分发物的结构与身份

Windows Portable 从包根的 `界鉴.exe` 进入，由包内 `app/start.ps1` 按自身位置解析发行根。固定产品位于 `app`，解释器、受控 Chromium 和 Node 位于 `runtime`，可选官方示例位于 `samples`，用户运行数据位于发行根自己的 `var`。

显式更新可以让新发行接续原工作区。启动器将工作区参数或发行实例自己的 `var/launcher/workspace.ini` 绑定传给固定入口，原业务数据不移动。入口合并按工作区的规范位置协调，最终写入所有权仍由服务文件锁决定；绑定不是数据库副本。

源码启动会准备开发依赖；Portable 启动只使用已冻结内容，不安装依赖、不构建前端、不下载浏览器。包不能依赖开发机 PATH、Conda、editable 元数据、源码绝对路径、系统 Node 或用户的浏览器缓存。移动到中文、空格或另一磁盘路径后，仍应通过同一入口定位资源。

原生入口使用 Windows 自带 PowerShell，其子进程只从自身 PSHOME 加载系统模块。不能依赖调用方的 PowerShell 7 模块路径；该环境只在本次进程中设置，不修改系统配置。启动错误保留安全阶段码，不把原始异常和环境全集写入启动提示。

启动器收紧产品 PATH 前，解析当前用户已安装 Codex 的绝对入口，供明确启动的本地 Agent 使用。它不安装客户端、不读取或复制客户端认证文件、不扩大目标 Worker 的环境；客户端不存在时显示真实的不可用状态，仍可使用外部开发工具。

`app/release.json` 保存发行元数据，产品版本与 `product/backend/__init__.py` 及 Wheel 元数据一致。元数据格式、运行布局、产品版本和依赖版本分别有含义，不能互相代替。当前构建器写入格式 3 和运行布局 3，并记录 Node 版本与摘要；运行时须核对实际解释器、浏览器与 Node 的归属和身份。

`full` 与 `nosamples` 使用同一 Base Tree，除 `samples` 外的产品路径和文件摘要应相同。没有示例的包仍提供完整产品；不可创建虚假示例目录、从样例导入产品代码或开放测试开关。Wheel 的前端来自已生成资源，构建钩子将它映射到包内静态目录，不向源码写回 `dist`。

`scripts/build/portable.py` 是发行总入口，由模块分别组装运行环境、编译启动器、生成资源、核验包和发布归档。`scripts/build/hatch_build.py` 只映射已经构建的前端，不准备环境。构建工具通过模块入口运行，不在导入时读取说明模板或启动脚本。

随产品运行的 C 启动器、PowerShell 入口、品牌数据和相关许可由 `product/launcher/windows` 维护。源码终端和发行启动器读取同一品牌数据，构建不依赖终端脚本内部的字符串布局。发行使用说明以[便携版使用](../产品/便携版使用.md)为唯一正文来源，构建时生成 README 和包内说明，不另存一份手工文本。

组件级测试位于 `tests/tooling/launch/test_distribution.py`，证明双包组成、路径保护、构建临时目录和文档资源来源等局部合同；不能代替下方独立分发运行。

## 选择 L5 场景

L5 由交付变化决定，不作为普通提交的默认门槛。先列出目标机器、起点和用户要完成的任务，再选择最小充分场景：启动方式变更关注实际入口和退出；资源装配变更关注独立资源读取；数据库变化关注支持起点与恢复。

## 独立验收

1. 将产物解压到独立位置，使用交付入口启动，避免借用源码目录和开发机绝对路径。
2. 核对数据库准备、当前页面和必要资源；执行约定的独立官方任务。
3. 需要时观察 Worker、Runner、报告与复验，分别核对结论和证据范围。
4. 正常退出后检查服务和本次子进程已释放；再次启动核对应保留的业务数据。
5. 记录实际包身份、平台、动作、结果与未覆盖内容。源码自动化、独立运行和人工观感分别表述。

源码测试通过后，仍须检查分发目录是否包含全部依赖、Schema、迁移与前端资源，且没有项目 `node_modules`、本地数据库、秘密、editable 源码路径和任务临时文件。固定 Node 自带的 npm 及其依赖属于 `runtime/node/node_modules/npm`，随同版本 Node 一起交付并在构建时实际启动核验；不能仅复制 `node.exe`，也不能以这一例外放行其他依赖目录。普通应用依赖仍由 Worker 在所属运行副本安装。启动只写当前发行实例拥有的数据目录，不修改包内解释器和浏览器。

退出使用正式 shutdown 链，核对本次服务、受控子进程、端口和锁均已释放。若无法正常退出，先保留所属实例与资源身份，再有界处理；不能按进程名或固定端口批量结束其他实例。

不默认访问生产目标、使用用户凭据或调用付费接口。验收失败先分类构建、环境、数据和产品，不通过放宽授权或覆盖用户数据库消除错误。

## 升级与恢复

构建完成后生成 `app/update-manifest.json`，覆盖启动器、app 与 runtime 的完整冻结树，记录每项摘要及目标支持的工作区代际、修订与结构摘要。自摘要文件不包含自身，运行数据不入清单。预览拒绝链接、未登记文件、摘要变化、缺失组件及不兼容工作区；目标已有业务库、其他工作区绑定或链接形式的运行目录时也拒绝接续，避免覆盖别的实例。不执行目标程序探测兼容性，摘要不代表发布者签名。

更新操作保存在工作区的 `runtime/updates`。预览、等待退出、启动、就绪与失败共享原操作标识。HTTP 只确认交接并请求原服务退出；原生启动器等待本 Job 结束、释放工作区锁和入口互斥后，才由独立交接进程重新读取目标文件并启动新入口。交接锁防止两个 helper 重放同一操作，服务锁防止两个版本并发写库。

新服务取得锁并启动 Worker 后才把交接标为就绪。目标在就绪前停止时记录失败；用户明确重新打开原程序也会结束未完成交接，不自动重试更新。退出的最终结果由原生入口写入独立回执，网页断连不构成该事实。

更新清单格式 2 分别声明最终工作区身份和 `supported_workspaces`。构建器从固定迁移逐项重建支持起点，读取其代际、修订与结构摘要，不能把当前 ORM 的摘要用于历史结构。目标身份必须包含在支持集合中，同一修订不能重复或混入其他代际。

预览在同一 SQLite 只读事务中核对当前身份、真实结构摘要及外键关系；匹配目标声明的起点即可继续，不要求起点等于目标修订。交接进程在原服务停止后重新核对独立文件与工作区，再启动目标。目标启动层拥有实际事务迁移和失败回滚，Worker 仍只读接纳当前结构。涉及结构变化时，确认区域说明影响和不能自动降级的边界。

清单格式 1 的旧候选程序不具备多起点更新 reader。它们不能通过旧更新入口接纳格式 2；需要明确从新发行入口指定原工作区启动，沿同一数据库接纳与迁移路径继续。产品不篡改旧包或清单来伪装兼容。原更新操作和退出回执继续按各自格式 1 读取。

产品不自动备份、不隐式降级，不兼容时保留原文件。换机器后的凭据接续仍服从 Windows 凭据边界。

## 版本提交与验证记录

源码提交、发行构建和产品验收分别记录。提交时顺延唯一产品版本，不改写历史报告、迁移身份或测试夹具中的示例版本，也不把此前生成的包改名当作新版本。新发行物只能由当前源码重新构建取得；已有候选包的运行证据仍绑定原包身份。

验证说明列出实际环境、支持起点、已完成任务及未覆盖范围。同版本候选发行之间的切换和同代数据库修订升级，不等于正式跨产品版本或跨代迁移验收。用户接受截图与设计时记录审阅结论；完整使用观察还需要实际操作反馈，不能由截图、自动化或开发者自测代替。

1.3.4 已完成 Windows x64 完整包与精简包构建，以及中文路径下正式入口的定向运行。包内前端身份与实际服务内容一致；浅色、雾蓝深色的概览、权限表、应用连接和复验报告可用，窄窗口的协作入口及对话框关闭焦点正常。原协作任务、违规报告和已验证复验结果继续读取，正式退出后启动器与服务端口已释放。本次复用此前普通应用完整业务链与本机模型只读解读的有效证据，没有重新执行目标检查、写入凭据或调用模型；不扩大平台、技术栈与模型自动执行的支持声明。

上述记录对应已验收的 1.3.4 发行物。随后源码中的持续协作、保存检查范围及界面整改尚未重新制作便携包；源码服务验收与截图接受不扩展到旧发行物。正式发行前需要从届时源码重新构建，并定向核对新增数据库修订的装配、支持起点升级、历史报告读取及退出，不重复无变化的完整业务实跑。
