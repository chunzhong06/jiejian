# 文档与测试的迁移取舍

重构改变组织和实现方式，仍成立的知识与回归风险需要继续受到保护。文件能否删除，取决于内容是否有效、是否有消费者、是否有等价承接；文件较旧、目录已变或数量较多都不是删除理由。

## 从成熟体系采用什么

| 依据 | 采用的做法 | 在界鉴中的落实 | 适用边界 |
| --- | --- | --- | --- |
| [GitLab 文档工作流](https://docs.gitlab.com/development/documentation/workflow/) | 区分位置迁移与语义修订 | 先核对知识去向，再改链接、命令、实际所有者和当前行为 | 本地文档没有已发布站点时，不建立空壳重定向页 |
| [GitLab 测试策略](https://docs.gitlab.com/development/testing_guide/testing_strategy/) | 明确责任，先运行相关范围，逐步扩大 | 模块范围与 L1 至 L5 分开选择，保留有效检查点 | 不规定固定测试比例，不为目录整理跑满所有流程 |
| [Sentry 测试指南](https://develop.sentry.dev/development-infrastructure/testing/) | 接口保护角色、跨组织访问与非法输入 | 保留本地会话、跨项目、身份与资源归属、陈旧指纹和非法字段场景 | 不引入其多服务开发环境；数据库、进程和目标按需要建立 |
| [Sentry 前端测试](https://develop.sentry.dev/frontend/using-rtl/) | 从使用场景观察操作结果 | 报告检查精确用例与证据归属；材料检查预览、采用及未知回执恢复 | DOM 模拟不证明真实布局、字体和动态流畅度 |
| [Grafana 端到端组织](https://github.com/grafana/grafana/blob/main/contribute/style-guides/e2e-playwright.md) | 分开页面读取、业务流程和资源设施 | 服务、官方场景、浏览器各有所有者；场景保留独立业务断言 | 不复制多版本插件设施，也不维护多套过时界面驱动 |

## 判断一份测试的去向

先写出它保护的行为，再看测试如何触发。断言仍有效、只因导入变化失败时，更新真实声明位置和夹具依赖；不要恢复生产兼容壳。设计发生变化时，重写触发方式并保留拒绝、持久化、恢复与隔离条件。

| 风险 | 保留或重新组织的位置 | 必须继续回答的问题 |
| --- | --- | --- |
| 权限判断和因果定位 | `tests/domain/checks`、`tests/domain/verification` | 正常功能是否成立，禁止后果是否发生，缺口是否降级，部分路径是否避免虚构定位 |
| 规则和人的决定 | `tests/contracts/http/boundaries`、`tests/application/business_boundaries` | 含义与范围是否独立，Agent 能否伪造批准，旧修订能否覆盖新决定，回执能否重放不同内容 |
| 材料与来源 | `tests/application/preparation`、`tests/contracts/http/preparation` | 只读是否无副作用，采用是否原子，来源变化和撤权能否阻止错误沿用 |
| 身份与资源 | `tests/application/test_identities`、`tests/application/recording` | 操作人、资源所有者和同角色其他账号是否被准确区分 |
| 租约、发布与读取 | `tests/infrastructure/runtime/jobs` | 失去 fence 后能否发布，坏包是否拒绝，历史结果与精确证据是否不被当前状态替换 |
| 数据升级与冻结输入 | `tests/infrastructure/storage`、`tests/contracts/protocols` | 完整基线与直接初始化是否等价，未知结构是否不写，冻结字节与 hash 是否保持原样 |
| 启动与退出 | `tests/tooling/launch`、`tests/integration/bootstrap` | 环境是否恢复，脚本是否保留退出码，停止失败后共享资源是否仍受保护 |
| 前端业务契约 | `product/frontend/src/pages/checks/report/Report.test.tsx`、`product/frontend/src/pages/preparation/materials/MaterialEditor.test.tsx` | 未知用例是否避免退回其他项，跨项目证据是否拒绝，预览是否不隐式采用，未知写入是否回读原操作 |
| 真实协作 | `tests/runtime`及各模块显式 `level4` 场景 | 实际 Worker、Runner、目标、浏览器和清理能否共同完成约定任务 |

共享构造器放在 `tests/support/builders`，只提供前置事实。已支持格式的冻结样本保持原始字节；退出支持的旧格式改为明确拒绝测试，不再维护兼容设施。纯判断不装配数据库，接口使用内存秘密和独立 SQLite，进程场景显式启用。

## 哪些内容可以不保留

- 仅检查旧目录名、转发层、固定行数或组件数量的断言，用真实依赖方向、元数据登记和可观察契约代替。
- 旧页面 DOM、旧选择器和一次机器上的接续检查点，不作为当前界面合同。相关业务风险迁移到当前组件、接口和真实流程；删除旧驱动时一并移除其未复用设施。
- 同一个完整业务过程的重复脚手架合并；不同角色、资源关系、错误原因、回执未知和恢复条件不因合并消失。
- 已退出产品入口的独立 Contract 治理、旧 Finding/Gate writer 和旧报告构建路径，不重新装配为当前执行链。仍有真实 reader 或算法消费者的格式与纯判断继续保留直接测试。
- 已有等价覆盖的纯格式快照和生成页，不为凑数量重复维护；仍须保护未知字段、版本拒绝和语义指纹。

删除或替换时必须核对消费者、独立风险和承接位置。不能以“让测试通过”为理由删除失败断言，也不能把无法解释的旧失败直接列为无价值。

## 验收迁移

先核对路由能找到当前指南、源码和直接测试，再检查静态依赖及完整测试收集。运行只选择改动影响的契约；失败后区分产品、夹具和环境，保留未失效结果。真实流程、独立发行和人工观察分别说明，未执行的高等级场景不能算作通过。

## 一套所有权与入口

首次使用、日常操作、概念和修复演练归入同一套产品任务；较短的解释直接放在规则或检查指南中。工程契约不重复操作步骤，由首页连接其产品含义和验证范围。前端测试紧邻所属实现，共享环境集中维护；后端新旧用例按能力合并，跨模块事务与生命周期保留独立集成验证。

Schema 同步与全计划聚合各保留一个所有者，聚合参数保留双方独立场景。数据库验证覆盖完整基线、原子初始化、重复启动保留业务行和漂移只读拒绝；后续发布迁移再增加对应的数据转换与失败恢复场景。关闭失败时提前释放共享秘密的旧预期已退出当前语义，由停止确认、共享资源保护和失败重试场景承接。不同历史起点或不同授权通道即使代码相似，也不能据此合并为一个理想样例。
