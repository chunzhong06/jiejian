# 规则与修改工作面

用于定义和调整权限要求、审阅提案、理解变化及处理原问题。批准规则、登记修改与正式复验保留各自门禁。共同选择、信息归属与返回规则见[工作面模式](../工作面模式.md)，视觉、交互和实现规则各按原所有者维护。

## 规则集合与详情

规则一行对应一条实际要求，保留各自角色、资源范围、状态条件及结果。右侧集中显示所选规则的含义、检查材料和准确结果入口。搜索或筛选改变可见范围后，详情对应可见对象；完整详情仍保留规则、修改与历史深链接。

规则详情保留必要范围和适用条件，避免再用一个“本条要求”分组逐字重复清楚的规则标题。最近检查的结论与准确阅读入口组成一个单元，阅读入口在本单元末端；当前准备与规则约定、历史样本分别表达。详情的准备动作在详情末端收口，集合级检查在未进入具体对象任务时提供，减少并列的强推进动作。

规则详情一次呈现检查结果、修复与修改、检查历史之一；登记表只属于修复任务。历史展开只增加下面的内容，不改变触发器尺寸或所在列。登记草稿和原题引用不能随切换丢失。

规则详情以规则名称、资源范围和检查结果连续阅读。角色、操作和资源已经包含在标题及范围中，不另用长期侧栏重复；相关材料和最近修改在结果后接续。规则目录仍按列表与当前详情选择，不能把目录选择和独立详情页强制套成相同分栏。

## 提案与规则调整

权限提案审阅先展示按业务操作分组的概览，同一行连接访问要求、资源、业务结果与变更类别，支持跨规则比较。选中后打开共享详情栏，概览收起重复的结果列；关闭后恢复完整比较及原条目的键盘焦点。详情一次呈现一条规则的主体、资源、条件和受保护结果。业务定义与提案来源使用同层分类，切换后保留所选条目。窄窗由概览进入详情，避免两栏挤压或上下重复。调整及停用保留原版本与批准后的对照，缺失依据明确提示；浏览与选择不产生批准，底部确认仍覆盖全部访问规则及业务定义，未知回执继续查询原批准。

调整已有规则时先用完整表格比较全部要求，“调整后的要求”保留可直接操作的允许／禁止选择器；选择规则再切换为左侧索引、右侧当前编辑。两处共用同一草稿，修改行内选择不会触发进入详情。收起恢复整表与同一条目的焦点，草稿继续保留。任务使用完整宽度，右侧只编辑当前规则的访问要求与适用条件。主体、资源和受保护结果成组，当前生效要求与调整值相邻；条件变化保留原条件。窄工作面以规则选择器接续同一编辑正文，选择不清理其他规则草稿，生成提案仍覆盖整份变更。返回保留本地草稿，明确放弃才清理。只读验证评估对应一份编辑快照，生成提案和批准继续分别确认。提案对照标明所依据的原版本与拟生效内容，不能将旧依据称为现在；已批准记录展示本次批准内容。示例中的维护提案仍采用普通审阅接续，首次配方的准备引导只用于本次配方批准。

提案重点概览定位新增、调整与停用，沿用项继续在完整提案中可查，批准范围保持整份提案。

规则编辑目录的业务名称和短要求复用`ObjectIdentity`成组，资源范围与条件变化在下方使用完整项宽。短要求不再单独占一整行；名称较长时依实际宽度换行，不截断业务对象，也不改变编辑草稿和批准范围。

首次编写权限时，每条规则直接以主体、允许或禁止及操作形成对象头，适用条件与受保护结果归该规则内部。角色、操作与规则的编辑沿用原草稿，生成完整提案后再独立审阅和批准。

## 业务边界与验证评估

业务要求的处理方式保持短选择，判断依据与保留的业务要求使用相邻字段组；待确认范围的标题、状态与解释分层，不能在无间距的连续正文中混排。

验证评估围绕当前要求阅读：单项直接显示，多项先从目录选择，再核对这一项的业务结果、正常功能对照与当前准备；窄工作面用要求选择器接续同一正文。原配置及变化后的处理按需深入，准备入口携带这一项的准确引用。材料满足、证明配置与正式检查判断分别表达，内部证明类型译为具体用途。业务边界核对先做处理决定，再看验证安排；处理方式、实际业务含义与判断依据同属一项决定，两段说明并列对齐，未决问题保持可见，原始业务描述退为辅助资料。

## 源码修改与当前接续

代码载入按标题与运行状态、后续说明、末尾操作组织，应用配置作为次要入口，载入动作保持最后。查询与恢复原请求仍分别表达，布局不改变未知回执的处理规则。

源码修复复用现有登记任务：说明与目标、实际文件变化、确认登记依次衔接，返回携带准确原题及修复视角。未提交说明按原题隔离，未知写入按原请求恢复。加载运行、准备材料与复验结果分别由原事实决定。外部应用的原题复验使用独立任务，沿用原数据、正常对照和标准，材料缺口返回准确操作；报告明确其行为观察范围，不替代源码与部署版本核对。

源码修改集合用于比较登记内容、文件变化和当前核对，不把当前就绪状态当成历史检查结论。选择后进入独立记录，先读当前核对与准确下一步，再读历史关联检查，完整文件变化与材料依据按需展开；历史报告与现在的源码、规则和材料分别解释。登记时的业务影响没有准确历史名称时保留修订信息，不用当前同名操作补写。文件路径及完整影响按需展开；当前动作在当前待办区收口，源码已变化先登记现在的修改，规则已变化先核对要求，材料不足先准备，就绪后才提供检查预览；返回恢复原查找、位置与条目焦点。最近记录窗口明确可读范围，准确记录深链独立读取，缺失或失败不切换成另一条记录。

修改依据展开后，关联要求、共用测试账号和各项操作的检查材料各自成组。账号与其余材料使用独立的组标题、说明和表格；业务操作使用贯穿表宽的组头，不能仅将多栏文字拉开。每份材料独立成行，名称、当前安排和处理说明使用稳定列；短状态居中比较，解释正文左对齐。不同材料即使处理方式相同，也不合并成长名称并共用一个状态；全部材料相同的核对方式可以集中说明一次。未命名材料显示其业务类别，处理安排使用“可继续使用”“需要补充”“需要重新核对”“需要你决定”等完整表达。

只有准确账号身份、名称及处理事实均相同才合并共用账号，并列明使用它的操作；相似角色名不能作为合并依据。运行版本仍待核对时，当前任务先由原加载工作面推进，材料准备不再同时作为另一主动作；已发布历史结论持续可读。

## 问题处理与复验

问题详情将“问题与证据”和“处理与复验”作为同一原题的两项工作，登记、加载、补材料与复验保留该问题。问题目录已经占一栏时，修复正文使用剩余完整宽度，不能再套一条长窄说明栏。

问题工作面用目录定位原题，右侧阅读影响、正常对照和复验。比较表保留禁止场景、选定正常场景及保留功能的独立结果，原检查与新检查分别呈现。源码登记、关联修改和复验带准确问题及回程；源码档案属于查阅，不代替问题处理。来源记录与新验证都持续保留。

问题内嵌修复任务由父页拥有问题标题与页签。流程提示使用较轻层级，当前任务与推进操作集中在正文，复验依据退为辅助内容；分组间距大于标题与说明的间距，内嵌任务不重复增加一层正文内缩。尚无修改时不展示空的文件折叠；修改登记后的流程提示进入条件核对，真实复验仍须满足原运行和材料门禁。

问题阅读先说明原操作、数据归属及已确认的业务影响，再比较原检查与准确关联的复验。同一正常用例兼任对照与功能回归时合并展示并保留用途；表内用紧凑的完整身份组，不把每个属性拆成段落。结果已形成而前后对应尚未成立时，保留结果并就近标明对应待核对。单个问题直接阅读，多个问题保留持续选择目录；筛选、历史原题和只读归档继续定位准确对象。

修复任务按真实阶段替换正文，验收依据在同一轴上接续。

官方展馆的预置修复从准确原问题的处理任务进入。先说明本次代码修正及必须保留的正常功能，再在任务右下确认加载；自行修改作为次要方式。加载后回到同一原问题与修改，不提前显示修复通过。未知响应只查询该交付并核对原Run、Case及合同引用；材料准备、原题请求条件与正常对照核验完成后，才阅读正式复验结论。通用应用继续使用实际代码修改及登记，不显示展馆预置动作。

修复内容、验收目标、原题依据与推进动作属于同一任务面。宽工作面以主要内容和较轻依据分栏，依据不能脱离任务堆到页面下方；窄工作面按同一组顺序阅读。切换为自行修改后，该组只显示登记修改的推进动作，避免预置加载与手工登记同时争夺主要位置。当前阶段改变正文，任务归属和动作收口保持稳定。
