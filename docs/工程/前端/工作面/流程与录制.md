# 流程与录制工作面

用于维护接口流程、安排业务场景、浏览器录制、试运行及恢复。保存、采用、真实执行与权限判断分别表达。共同选择、信息归属与返回规则见[工作面模式](../工作面模式.md)，视觉、交互和实现规则各按原所有者维护。

## 新建与维护接口流程

接口流程是可维护资产。新建时顶部进度显示起点、账号与数据、执行请求、核对与使用；存在字段比较时增加“结果核对”，数据变更操作显示“结果与恢复”，没有相应配置时直接核对。已经完成的阶段可以返回，必要输入仍控制推进。请求编辑正文只有执行顺序和当前请求两列；请求方式、路径与参数集中编辑，受检请求用明确状态表示，其他步骤可显式设为受检。编辑面只承担账号、资源、请求、结果依据与恢复配置。保存、试运行和用于检查分别收口；试运行替换为聚焦任务，采用前用短审阅说明准确修订和后果，不再常驻左右分栏。历史归当前流程的记录入口。

阶段进度不与正文的步骤索引并列争夺宽度。起点方式和请求参数分别在所属阶段内选择；动态防伪参数由明确命名的配置对话框加入准备步骤，资源提取、字段比较和恢复接口进入后续阶段。请求参数默认定位已有内容或内建资源取值，空参数说明可跳过，不能让使用者误以为必须逐项补齐。执行步骤选择带末端与编辑分界之间保留独立留白，详情也有自己的阅读内边距。场景核对沿用画布，仅保留事实与操作收口，不铺额外整块背景。

接口流程分开处理新建与维护。新建保留引导和逐步准备；从准确修订进入的已有流程使用可直接切换的账号、请求、结果与恢复、保存与使用分类。保存、采用和执行明确分开；未保存修改不可冒充已保存修订参与试运行。候选先比较，再带入草稿；采用仍由原配置入口确认。

流程候选的结构对照按执行安排、账号与测试数据、结果核对与恢复分组，同一表格保持基准与候选方向稳定。变化概览和范围切换属于同一头部，说明退到对应比较之后；完整结构仍可按需阅读。结构无变化只表达本次可交接字段的比较结果，不推断固定值或请求正文相同。读取失败在原事项重读，带入、保存、采用继续由各自明确动作完成。

## 试运行、采用与恢复

正常取样及恢复沿原记录显示对象与处理。文件已完整取得、文件内容由人确认、测试数据已恢复分别呈现；文件确认勾选放在当前内容区，操作行只保留命令。恢复预览显示原计划的实际恢复账号，恢复完成后说明本次未重复取文件；新参照另行准备。数据或状态更新失败时，旧预览不继续执行。

接口流程的短事实按标签和值阅读，试运行与记录单独成组，修改及采用在区域末尾。试运行历史先核对执行条件，再阅读逐步请求反馈，不为短摘要保留固定半栏。

试运行记录把准确修订、账号与资源、本次操作及数据归属组织为一个紧密对象组；记录时间与提交步骤另成较轻的追溯组。执行账号核对、恢复状态与逐步请求反馈放在当前处理表面，就近接续原恢复任务。接口方法、状态码和字节数按需展开；请求接受只表达执行反馈。恢复记录显示原计划的实际恢复账号和单独恢复步骤，不把原受检请求再次画成已执行。读取失败提供原处重读，未取得当前记录前不允许新预览或确认；不能同时显示“没有记录”。

试运行预览和执行、保存草稿和正式采用各有独立后果。未知执行只查询原记录，活动期间不采用；旧试运行和仍被采用的修订持续可读。从旧记录继续编辑建立新修订，不覆盖旧事实。试运行结束不产生权限结论。

流程采用是独立确认任务：先说明准确修订，再连贯核对账号与数据、实际请求、结果查询及恢复，末尾确认后才更新绑定。试运行准备直接展示本次账号与资源，预览列出实际请求；恢复缺口接续原恢复请求，并保持原执行记录可读。请求接受、业务恢复与正式权限结论分别呈现。

流程概览先解释业务操作、操作账号、使用的数据及其归属，再说明执行安排、独立结果核对与恢复用途。技术路径、方法和配置按需深入，不让用户先翻译接口才能理解任务。当前数据选择与规则要求的状态分别显示；数据标识不能替代实际状态核验。执行确认依据服务冻结的本次选择，恢复确认依据原记录，不能以流程默认账号覆盖实际所选账号。

已有接口流程的核对与试运行分别阅读，采用准确的已保存修订。多条试运行记录使用索引和当前正文，单条直接阅读。

已保存流程把修订用途、账号、资源、执行和恢复事实放在同组；试运行、历史阅读与确认用于检查分别进入对应任务。

## 浏览器录制

当前采集阶段与固定录制对象分区阅读：左侧为业务操作、用途、操作账号及资源所有者，右侧为当前事实和推进动作。等待准备、开始中、采集中、结束中与整理中分别表达；有实际等待时采用共享安静三点，不制造百分比。错误原因紧邻当前处理，失败及取消仍返回原准备核对现场。

审阅阶段保持对象事实的简短横向组，下方左侧按真实顺序阅读步骤与已确认来源，右侧完成业务对象及歧义选择。必要选择已齐备时直接说明可以保存候选，补充录制没有歧义时也有明确的保存收口，不保留空白决定栏。保存候选与材料采用继续分开。

录制取消等次要动作排在当前推进之前；数据选择输入限于合理阅读宽度，操作区在窄工作面完整换行并保持右侧收口。

录制工作面先明确业务操作、用途、操作账号和资源所有者，再说明当前阶段与唯一推进动作。浏览器就绪与正式采集分别表达；结束后按实际顺序阅读前序步骤和本次操作，已确认来源与仍需选择的资源分开。请求方法和路径供按需核对，不取代业务名称。待审阅停止执行轮询；失败、取消、安全停止和完成均使用各自终态与原准备回程。录制失败或取消不会自动撤回目标应用的变化。

采用录制时，将更新的材料与继续保留、需要重核的内容并列。当前确认动作在工作面右下收口，其他取得方式与新建录制入口退出当前确认状态。录制工作面沿父任务的内容轴，不在应用壳另设较窄宽度。

## 业务场景

业务场景目录与当前保存的实验安排并列：正常流程、各项变体及其动作顺序就近阅读，再进入准确修订的编辑或检查范围。选择和浏览只读取，不保存、不运行；读取失败保留所选对象，不拿最新修订或其他场景代替。长场景编辑继续拥有完整任务空间。

场景步骤用一个已准备项选择保持权限、账号与资源的准确绑定，选后分项核对业务操作、操作账号、资源编号、归属和访问要求。资源来源说明随所选来源变化。局部试验集中选择本实验、正常流程至当前步或可用的单独动作，再显式进入预览；整份场景保存独立收口。单独试运行接管正文和操作，返回继续原草稿。

复杂业务场景沿用“业务实验页签 → 左侧节点索引 → 右侧当前节点”的工作面。节点从已准备的操作、账号、资源与准确规则选择；批量资源用统一表格比较资源、操作账号、归属与预期后果，选中后编辑一项，不再增加一层导航。完整正常流程与挑战明确区分；保存、预览、执行分别表达不同后果。长路径可以换行，索引与详情保持独立内边距。

组合业务场景先安排正常操作，再处理需要验证的变化。当前实验、步骤和准确准备项相邻阅读；批量请求设置与局部试验按需展开。正常流程与变化可以分别选择步骤；移除变化保留正常对照，步骤调整保留原协议的依赖处理。历史修订可切换实验和步骤阅读，修改动作保持只读；返回当前修订后才编辑。

## 批量资源与局部试验

同一次批量请求只使用一个业务动作和操作账号。第一项确定该范围，其余项只列相同动作及账号的准确规则；改变第一项后保留其他项原选择并明确指出不匹配，不自动替换账号或批准规则。正式结果沿用同一比较表，展示实验、节点、实际资源、预期效果和实际后果；选中依据后目录收敛为资源与结论，完整内容在相邻详情中阅读。资源编号与实验发生位置同时保留，不能只用重复的动作名称定位批量结果。

单个已有资源动作可沿用原试运行器查看请求反馈，明确不运行前序节点、不提供权限结论。整个业务实验或正常流程的选定前缀另存独立准确范围，再进入统一检查预览及确认；变体保留完整正常对照。原草稿、准确修订与未知保存回执持续保留，不因调试覆盖原场景。目录只读取摘要，编辑时再取得准确正文和准备上下文。
