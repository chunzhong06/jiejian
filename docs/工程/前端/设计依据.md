# 前端设计依据

整体组织以功能与对象关系为起点，历史样例用于辨认用户最后采纳的原则，不作为必须复刻的页面模板。[Apple 分栏指导](https://developer.apple.com/design/human-interface-guidelines/split-views)用于区分层级导航、对象选择和详情阅读，并根据窗口宽度调整；不据此为所有任务强制增加左右栏。[Primer 导航模式](https://primer.style/product/ui-patterns/navigation/)用于区分长期目的地、对象内视图与命令。界鉴据此以稳定分类连接检查方案、操作材料、业务场景和检查记录，具体任务另行保持准确回程。

[Carbon 数据表指导](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)用于跨项比较与原行展开。短业务字段直接在内容表中核对，方案目录直接进入准确内容，长证据不再嵌套窄栏；规则目录和材料索引按持续选择的需要保留。取舍是不同任务需要维护适合自身的结构，共享控件与交互语法继续统一。工作台按当前工作、近期事实与接续对象重新组织，减少重复统计、资料入口和孤立元数据；已采纳的主题、MiSans、控件和动效保持。

## 短任务与浮层连续性

[Apple浮层指导](https://developer.apple.com/design/human-interface-guidelines/popovers/)将浮层限定于少量相关任务，保留来源位置，避免层层叠加，并让关闭与下一次操作连续。界鉴将四处短命令菜单的展开、键盘取消和焦点返回交给共享组件，页面只拥有业务动作；不把连续阅读或复杂编辑迁入菜单，也不自动保存授权或执行决定。内容与基础外观保持，减少不同页面对同一种交互的重复实现。

## 对象归属与形状关系

[Apple布局指导](https://developer.apple.com/design/human-interface-guidelines/layout)用对齐、分组和缩进传达对象关系。界鉴据此让集合标题与创建入口一一对应，总任务标题不挂载其中一个子集合的新增操作；共享`SectionHeading`维护排列，业务对象决定动作归属。空态的首项创建与目录的追加按状态互斥，保留任务收口的右下主操作。

[Apple连续曲率](https://developer.apple.com/documentation/swiftui/roundedcornerstyle/continuous)描述转角曲线，[WWDC25设计系统](https://developer.apple.com/videos/play/wwdc2025/356/)另以同心关系协调圆角与内缩。共享形状层采用保留半径的 Web 连续转角近似，原生 continuous 与 CSS 超椭圆分别表述，不宣称复刻未公开的曲线公式。相邻轮廓按组件角色及真实内缩协调，不将卡片中的所有控件都改为同心形状。[材质指导](https://developer.apple.com/design/human-interface-guidelines/materials)区分控制导航与内容层，支持现有工作面减少冗余底色框的方向；本产品保持既有主题，不向表格和普通表单添加玻璃材质。

[Apple弹簧指导](https://developer.apple.com/videos/play/wwdc2023/10158/)以位置和速度的连续性解释自然反馈；共享选择标记据此采样临界阻尼曲线，快速反向保留当前运动，普通 CSS 缓动不冒充物理弹簧。[SF Symbols 6](https://developer.apple.com/videos/play/wwdc2024/10188/)用 Breathe 表达进行中的活动，界鉴只将透明度和轻微缩放用于真实活动点，保留原图标库。[Chrome 139发布说明](https://developer.chrome.com/release-notes/139)确认 `corner-shape` 已进入该浏览器；跨浏览器仍采用 `@supports` 渐进增强，并核对边框、焦点、裁剪和浮层。具体曲线与回退由[布局与视觉](布局与视觉.md)维护。

设置采用 [Primer 导航模式](https://primer.style/product/ui-patterns/navigation/)的父页与子视图关系：齿轮直接进入独立设置页，开发工具、本地存储、运行与维护作为页内分类。URL记录分类，面包屑保留层级；设置分类统一采用横向导航，避免与全局侧栏叠加，不再通过浮层中转。界鉴服务状态与详细诊断统一在运行维护内容中。代价是占用完整工作面，收益是长内容、维护操作及返回位置可以连续组织。分类指示器与局部内容切换参考 [Carbon 动效指导](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview)区分日常反馈和重点转场，复用项目已经确认的节奏，不照搬品牌参数。

场景核对借鉴 [Postman 请求与响应工作区](https://learning.postman.com/docs/use/send-requests/requests/)中输入与反馈相邻的安排，以及 [Carbon 结构化列表](https://www.carbondesignsystem.com/building-blocks/core/components/structured-list/guidelines)的分组与选择方式。已保存摘要退到辅助区，本次执行和历史记录使用相同工作面切换，历史选中后集中展示有限请求事实。界鉴仍保留独立的人工执行批准与正式采用，试运行不产生权限结论；不照搬Postman的原始响应展示或任意请求能力。页签沿用 [WAI-ARIA 页签模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)的方向键、焦点与面板关联。

## 阅读单元与距离

参考 [Carbon 间距指导](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)以空间表达关联强弱：同组间距较小，不同分区之间再留出层次。参考 [Primer 表单](https://primer.style/product/ui-patterns/forms/)的纵向阅读与相关字段就近原则，在窄弹层、登录摘要、操作摘要和数据对应中采用标签在上、值在下的属性组；不为了减少高度继续嵌套横向小列。

参考 [Atlassian 状态标签](https://atlassian.design/components/lozenge)将状态视为对象的紧凑属性。单对象状态与名称相邻；三个复验结果并列呈现，状态留在各自单元内。材料索引、历史表及数量清单仍以共享列支持比较；表单推进操作保留任务收口。采用的是信息关联原则，复用界鉴统一语义令牌和已认可动效，不引入另一套控件或配色。

## 减少重复填写与重新准备

采用 [GOV.UK 问题页面](https://design-system.service.gov.uk/patterns/question-pages/)中只问必要内容、同一流程不重复询问、带入既有回答的原则。界鉴的配置工作台保留相邻的内容与操作，不照搬一问一页；信息性说明改为选填，影响权限含义、真实身份、授权范围和恢复后果的决定仍由用户明确完成。

参考 [ZAP 认证自动检测](https://www.zaproxy.org/docs/getting-further/authentication/auto-detection/)将可复用认证配置与本次认证结果分开的方式。同应用登录配置可以复用，账号编号、秘密和当前身份不能复制。本实现提供配置模板，不声称已经实现任意应用的认证自动发现。

参考 [Postman 导入定义](https://learning.postman.com/docs/design-apis/specifications/import-a-specification/)使用已有结构形成候选。源码中能够识别的相对数据库路径与简单建表定义可用于带入配置；已有运行设置直接显示摘要。没有建表语句、存在冲突或结构动态生成时保留明确编辑方式，不把静态候选当成数据库事实。

全站按信息所有者检查：应用连接复用目录、运行和数据库对应；权限编写复用识别候选及已批准定义；账号跨动作复用主体与同应用技术设置；操作复用已保存版本；证明复用配置；修改任务复用准确原问题并保留回程；本地维护与开发工具复用当前配置。新证据、变更授权和真实身份核验不沿用旧成功状态。

参考 [GitHub 安全告警详情](https://docs.github.com/en/code-security/concepts/code-scanning/code-scanning-alerts)把问题、状态及关联修改汇集在问题所属位置的方式。界鉴的修复任务以准确原题为核心，登记、载入、材料处理和复验保留连续回程；文件档案退为查阅入口。GitHub 的扫描状态与界鉴的运行时权限结论不同，界鉴仍要求原问题和正常功能的真实新证据。

外部资料用于提出有理由、可验证的选择。以下说明采用了什么、解决什么问题以及付出的代价；资料不能代替本产品的实现和验证。

## 界面如何保持连续

[Atlassian 导航布局](https://atlassian.design/components/navigation-system/layout)区分顶栏工具与侧栏导航。界鉴将开发工具与存储集中在独立设置页，按用户偏好由侧栏左下角的齿轮进入；协作作为独立入口放在“应用与来源”下方，顶栏保留页面上下文、统一刷新、主题与最右侧退出。参考 [Linear Agent](https://linear.app/docs/linear-agent)的明确身份、既有上下文与任务进度，以及 [GitHub Copilot 的上下文入口](https://github.blog/changelog/2026-05-18-ask-questions-in-context-with-copilot-on-web/)减少离开当前工作的成本：协作保留“Agent 协作”文字并直接显示任务状态，初次进入展示可交办的具体工作。代价是侧栏增加一个独立入口，窄窗需要先打开导航；名称与任务状态仍完整保留。界鉴继续用目标面板建立任务、完整工作面承接执行和审阅，不复制通用聊天入口或自动启动模型。

[Carbon 空状态指导](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)强调情境、简短解释和主要下一步。维护页面据此保留实际缺口与可用操作，不用重复介绍、假计数或装饰内容占满空白；内容少时允许工作面自然结束。

[JetBrains 连接现有 Node 进程的配置](https://www.jetbrains.com/help/idea/run-debug-configuration-node-js-remote-debug.html)将附加到已有进程与启动进程区分；[GOV.UK 单选的条件展开](https://design-system.service.gov.uk/components/radios/#conditionally-revealing-a-related-question)则只在选择相关方式后展示字段。应用运行据此在同一区域提供连接现有应用、由界鉴启动两种方式，保留草稿，避免同时铺开地址与启动表单。这里不复制调试器端口设置，也不把方式选择当作执行授权；实例启动后仍由用户明确将其采用为检查目标，代价是多一次有实际对象变更含义的采用操作。

[Primer 表单指导](https://primer.style/product/ui-patterns/forms/)强调关联字段的分组和按需展开，避免为了压缩高度随意分列。权限编写据此将业务定义与草稿预览区分职责，账号及其使用范围、状态、操作保持在同一单元；应用接入将源码、地址和运行设置组织在连续工作面。分列由内容关系和可用宽度决定，窄窗口按阅读顺序重排。

[GOV.UK 跨会话任务模式](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/)用于区分任务名称、当前状态与返回入口。侧栏恢复入口指向服务端保存的具体任务，失败、等待用户和实际执行使用不同反馈；任务详情保留原对象及下一步操作。这里不增加独立任务首页或人工完成勾选，代价是需要持续维护入口与真实生命周期的对应。

[Atlassian 页签的层级与分组](https://atlassian.design/components/tabs/usage)将共用对象信息放在页签之前，各自任务放进对应内容面。规则详情据此将登记修改归入修复工作面，页签下方直接切换内容，保留键盘关系及局部过渡；地址继续保留当前分区，便于返回和分享。[GOV.UK 摘要列表](https://design-system.service.gov.uk/components/summary-list/)强调事实与所属修正入口的关联，检查范围据此将业务摘要与缺口处理并列；不照搬其排版或表单声明，也不以展示合组删改执行缺口。

[Fluent 2 动效](https://fluent2.microsoft.design/motion)与 [Atlassian 动效](https://atlassian.design/foundations/motion/applying-motion/)强调功能、方向和连续性。采用零延迟命中的短悬停、可打断页面交接与分开的局部反馈，不把所有变化设为整页淡入。

[View Transitions](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)用于只捕获工作面；[Carbon 加载模式](https://carbondesignsystem.com/patterns/loading-pattern/)用于已知结构占位；[字体建议](https://web.dev/articles/font-best-practices)用于提前发现字体并控制迟到替换。当前字体选择保留短等待和后备方案，原生过渡保留回退及减少动效路径。参数正确不能保证主观流畅，仍需真实动态观察。

[Primer 页面布局](https://www.primer.style/product/components/page-layout/)用于区分概览、结果导航与依据工作面；[Sentry 问题详情](https://docs.sentry.io/product/issues/issue-details/)提供从问题回到历史与处理上下文的参考。采用稳定列表、局部阅读和渐进披露，不照搬调用栈、人工关闭或版本名决定复发。

[Fluent 2 动效](https://fluent2.microsoft.design/motion/)强调按距离、层级组织运动，[Material 3 动效](https://m3.material.io/styles/motion)区分空间运动与颜色反馈。高频悬停保持即时命中，按下与选中清楚响应，页面和阅读区的位移更容易察觉；只让必要图标和层级关系使用适度回弹，不对文字颜色做过冲。现有浏览器能力可以完成这些行为，无需为统一动效引入新框架。

## 连续使用与本地维护

[web.dev 对交互延迟的分解](https://web.dev/articles/optimize-inp)用于区分事件等待、处理与呈现，不能用 CSS 时长证明跟手，也不能把少量本机样本称为真实用户 INP。[资源加载指导](https://web.dev/learn/performance/optimize-resource-loading)用于安排字体与脚本竞争；保留原字体和文档内稳定选择，以高优先级预载 MiSans，并在首次挂载前最多等待 800ms，同时从日常状态读取移除重复全量核验。

[Docker Desktop 排错入口](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/)用于区分查看状态、诊断与有影响的维护动作。采用按需核对、可预览的白名单摘要与原操作恢复，不建设日志上传或工厂重置。[VS Code 便携模式](https://code.visualstudio.com/docs/setup/portable)用于明确程序与持续数据的边界；本项目选择新发行绑定原工作区，不复制整个业务数据目录。

## 维护状态与稳定展开

[Windows 设置设计指导](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)用分组、说明和所属操作建立清晰关系；[Apple 软件更新设置](https://support.apple.com/en-gb/guide/mac-help/mchla7037245/mac)按更新状态呈现当前任务。这里采用单一更新工作面和分阶段主体，完成后优先返回应用，交接路径退入详情。它们提供信息组织参考，不替代界鉴自身的本地发行核验与工作区保护。

[PatternFly 展开区](https://www.patternfly.org/components/expandable-section/)将触发器与隐藏内容分开。复验行据此固定标题与展开入口，仅展开下方历史。保留已确认的折叠和内容过渡，不以取消动效解决布局跳动。

## 自动采集与业务语义

[OpenTelemetry 的插桩分层](https://opentelemetry.io/docs/concepts/instrumentation/)将库级自动采集与业务语义补充区分开；[Node 零代码指导](https://opentelemetry.io/docs/zero-code/js/)强调在应用加载前启用支持的适配器。界鉴据此在已有受控加载器装配原生 HTTP、SQLite 和文件探针，将请求关联、有限元数据和批量提交作为公共机制，不依赖示例应用手写事件。这是设计原则的采用，当前没有引入 OTel SDK 或声称具备 OTLP 接收与任意 npm 插桩能力。

[Node SQLite API](https://nodejs.org/api/sqlite.html)用于校准语句返回、迭代、异常和事务语义。调用结束不能解释为业务提交成功；只保留技术诊断，业务证明独立采集。[HTTP 语义规范](https://opentelemetry.io/docs/specs/semconv/http/http-spans/)说明 URL、请求头等属性可能含敏感内容，界鉴直接不采集这些值，避免先收集秘密再依赖事后脱敏。

[稳定滚动条空间](https://developer.mozilla.org/en-US/docs/Web/CSS/scrollbar-gutter)用于防止折叠内容触发整页横移；采用根区域的稳定占位，保留现有内容动效，不以取消过渡解决布局问题。

## 既有框架项目的连续检查

[Node 同步模块钩子](https://nodejs.org/api/module.html)和 [npm ci](https://docs.npmjs.com/cli/commands/npm-ci/)用于保留标准模块解析及锁定依赖。输入源码、构建输出和实际依赖分别冻结；默认不运行安装脚本，所选构建脚本需要明确授权。代价是支持范围限于已准入的 Node/npm 组合，不能承诺任意原生驱动。

[better-sqlite3 事务 API](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md#transactionfunction---function)与 [SQLite 触发器](https://sqlite.org/lang_createtrigger.html)用于区分真实提交、事务内部中间值及回滚。触发器投影与业务写入共事务，观察器另核请求、主体、资源及闭合条件；技术调用完成不能代替已提交的业务变化。代价是需要声明普通表、稳定资源键、归属及有限字段。

[Playwright 认证复用](https://playwright.dev/docs/auth)用于按实际主体复用会话；认证配置、会话材料和实际身份核验分别保存。账号失效保留所属槽位与恢复入口，避免可用性排序改变资源归属。[OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.1.html)提供接口候选，导入不执行请求、不采用服务器列表或自动批准权限。可编辑流程与真实录制保留各自来源，统一进入现有执行和复验合同。


## 复杂准备任务的表达

参考 [GOV.UK 多任务办理](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/)与[按钮](https://design-system.service.gov.uk/components/button/)，准备总览按任务显示状态，同一工作面明确主要推进动作。账号采用列表与详情，维护操作退入管理区；复杂操作设置逐步聚焦当前问题。简单任务保留直接操作，不把所有页面强制改成向导。

参考 [Primer 表单](https://primer.style/product/ui-patterns/forms/)与[渐进呈现](https://primer.style/product/ui-patterns/progressive-disclosure/)，相关字段成组，次要配置按选择呈现；保留焦点与原对象，避免展开后让用户重新寻找工作位置。参考 [Postman 请求组织](https://learning.postman.com/docs/use/use-collections/manage-collections/)，接口步骤以业务操作及其执行顺序组织。借鉴任务关系，不照搬 API 工具的全部术语和复杂度。

简化呈现不合并事实责任：源码授权、目标启动、身份确认、来源读取和正式使用仍各有明确后果。界面依次展示需要用户决定的内容，不能用一个“下一步”隐式授权全部操作。

参考 [Ant Design Select](https://ant.design/components/select/) 的统一尺寸、选项留白与键盘能力，以及 [Primer Select](https://primer.style/product/components/select/) 的表单控件一致性，将全站普通单选收敛到共用选择器。复用项目已有 Ant Design 组件，不引入第二套控件库；自由输入、文件上传和直接比较的运行方式仍使用各自语义。

参考 [GOV.UK Task list](https://design-system.service.gov.uk/components/task-list/) 将任务名称与状态组织在同一行，说明保持所属关系。应用接入使用这种阅读结构，继续操作放在清单收口；已有记录、已有配置与当前核对完成分别表达，不为整齐而把不同事实全部标绿。

## 任务主次与复杂规则

参考 [Linear 的界面更新](https://linear.app/now/behind-the-latest-design-refresh)中任务内容优先、导航退后的层级处理，工作面标题减少表面竞争，真实进展直接可读，低频技术回执按需展开。保留已认可的浅色与雾蓝深色主题及交互强调色，不将“更安静”理解为削弱已确认的交互动效。

参考 [Primer ActionList](https://primer.style/product/components/action-list/) 将对象、次要说明与关联操作组织在同一阅读单元；材料账号概览据此从分散卡片收为清单。参考 [Carbon 空状态](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)，筛选无匹配时解释当前范围并提供清除入口，不补介绍文字或虚构内容填满页面。

参考 [Primer DataTable](https://primer.style/product/components/data-table/) 的一行一项记录与独立字段列，将不同条件的权限逐条展示，避免角色矩阵的一格包含多条规则后失去横向对应。保留完整规则含义、结果和可定位的详情，不照搬具体列数。

参考 [Refactoring UI 的信息层级建议](https://refactoringui.com/previews/labels-are-a-last-resort)，让实际内容、归属与结果承担阅读主次，减少重复标签；保留表单所需的明确标签。参考 [Carbon for AI](https://www.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai)，将协作的实际产物放在当前任务之后，回执和技术历史按需读取，不把请求成功说成业务完成。依据 [W3C 非文本对比要求](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)校准自定义焦点轮廓，装饰表面和可交互标记分别判断。

依据 [WAI-ARIA 组合框模式](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)区分输入焦点与浮层中的当前候选，键盘移动时在候选处保留清晰定位。借鉴 [React Aria 的焦点显示原则](https://react-aria.adobe.com/useFocusRing)，让键盘轮廓与鼠标悬停分别呈现，沿用现有输入方式追踪与动效。

参考 [GOV.UK 多任务办理](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/) 的关联动作分组及当前状态、[Carbon 按钮层级](https://www.carbondesignsystem.com/building-blocks/core/components/button/guidelines)的推进与次要操作区分，将协作目标、当前动作和结果合为连续工作面，资料与管理按需展开。界鉴保留独立业务决定和列表行操作，不把“一个主要动作”解释成整页只能存在一个按钮，也不引入重复的用户确认。

参考 [Carbon 全局顶栏](https://www.carbondesignsystem.com/building-blocks/core/components/ui-shell-header/guidelines) 的固定公共入口和 [Primer PageHeader](https://primer.style/product/components/page-header/) 的页面操作归属，将跨页面协作放在侧栏稳定位置，管理当前连接等操作保留在页面标题区。只采用作用范围与稳定位置的区分，不复制其导航数量或具体外观；协作仍绑定当前应用，切换应用不会沿用另一应用的目标草稿。

## 有限自动推进与可复用范围

参考 [GitHub Agent 会话管理](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents)将委派目标、执行进展和可审阅产物区分；参考 [VS Code 审批边界](https://code.visualstudio.com/docs/agents/run/approvals)保留一次任务授权、具体业务审阅与隔离的不同责任。界鉴采用有限回合和时间窗口，不通过无限模型轮询制造持续感；目标完成只读取确定性业务事实。

参考 [Temporal 重试策略](https://docs.temporal.io/encyclopedia/retry-policies)区分流程接续与外部动作重试，未知副作用先查原回执；没有引入 Temporal，也没有自动重放整个检查。依据 [SQLAlchemy 事务边界](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html)，数据库只持有短业务事务，模型执行与等待不持有写锁，本机通知在提交之后发送。

参考 [Playwright 身份复用](https://playwright.dev/docs/auth)及[项目配置](https://playwright.dev/docs/test-projects)中的配置复用与执行隔离：界鉴保存的是日常规则选择，实际身份、资源、证明和运行代码在每次提交时重新核对并冻结。不能把复用理解成复制旧就绪标志、旧结论或绕过正常对照；失效范围需要用户重新选择。

## 选择与复验阅读层级

[GOV.UK 复选框](https://design-system.service.gov.uk/components/checkboxes/)把选项名称与简短提示分开，[Primer 对话框](https://primer.style/product/components/dialog/)聚焦当前决定，[Carbon 数据表](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)将行间比较与补充细节分工。界鉴据此将源码修改授权、执行设置和费用分层，将复验的修改前后保留在共同列中，选中后才展开原检查及证据；检查范围与实际场景并列，快捷复用按需展开。重要缺口、必要正常对照和执行门禁保持可见，不用减少说明来改变授权或结论。

[Carbon 侧栏指导](https://www.carbondesignsystem.com/building-blocks/core/components/ui-shell-left-panel/guidelines)明确避免三级侧栏。界鉴已存在全局导航，设置仅有三个分类，因此采用页内横向分类；客户端属于当前连接配置的选择，使用表单选择项。连接与应用授权按对象分区，去掉重复分类标题、介绍横幅及共用大外框。代价是工具完整列表需要打开选项，收益是减少持续占用的导航列。

[Ant Design按钮](https://ant.design/components/button/)包含两字中文自动加空格的处理，说明短中文标签可以单独校准字间留白；其规则针对按钮，并不要求导航居中。界鉴根据当前侧栏标签集合采用统一文字区居中与小幅字距，保留连续的图标列。这是本项目的局部选择，文字内容和可访问名称均不插入空格。

[Primer渐进展开](https://primer.style/product/ui-patterns/progressive-disclosure/)建议谨慎使用展开并保持上下文，[FormControl](https://primer.style/product/components/form-control/)区分字段名称、可选提示与校验信息。这里将同一连接的维护合并到一个管理区；正常状态不堆同义小字，异常与授权边界仍在当前工作面。客户端、应用和接入服务各自与状态成组，避免为了留白拆散语义。

[Carbon间距指导](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)说明间距能够建立关系、层级及内容分组，无须处处增加图形分隔。开发工具页已有独立工作区外框，卡片内部改由间距组织客户端配置、接入服务和管理入口，应用身份与授权输入也按间距区分；分类保留选中指示线，去掉贯穿整行的轨道。控件边界与键盘焦点继续表达可操作性，不能与装饰性分隔线一起删除。


## 扫描密度与选择连续性

[Carbon结构列表](https://www.carbondesignsystem.com/building-blocks/core/components/structured-list/guidelines)按对象组织可扫描信息，[Primer NavList](https://primer.style/product/components/nav-list/)用容器内的位置和状态表达当前位置。界鉴将业务线索分为角色、操作两个工作区，将场景名称和状态靠近，并将材料导航改为连续侧栏选中带。代价是宽屏需要管理列间关系；窄屏按相同阅读顺序排列，不能靠压缩控件内边距塞入。

[Primer分段控件](https://primer.style/product/components/segmented-control/)适合在少量相关选项间切换，[Carbon动效](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview)区分日常操作与强调性表达。界鉴在高频筛选中采用280ms弹簧基准的连续标记和240ms局部内容交接，不增加循环装饰。持续标记比仅换色多了测量和中断维护成本，收益是选择、位置与阅读内容之间的联系更明确。

[Atlassian行内反馈](https://atlassian.design/components/inline-message/usage/)强调消息的上下文关联。这里借鉴归属原则，将失败放在当前操作附近，使用工作区间距分组；不照搬浮层形式，也不移动需要全局处理的故障。


## 内容量变化与选择颜色

[Carbon Tile](https://www.carbondesignsystem.com/building-blocks/core/components/tile/guidelines)用容器归组相关信息与操作，强调容器适应网格且不靠悬浮阴影建立内容层级。业务动作内容短、各有维护入口时，界鉴采用目录卡片，呈现已有业务效果或采用操作；持续积累的记录仍使用可扫描列表或表格。这里采用的是阅读单元与网格关系，并非要求所有页面改成卡片。

[Primer表单](https://primer.style/product/ui-patterns/forms/)用于理解字段分组和当前决定的关系。环境没有记录时直接配置，有记录时先阅读并显式进入编辑，消除空目录与长表单的失衡；范围设置与操作预览按任务顺序组织，避免为短设置保留整条长侧栏。减少常驻编辑面会增加一次显式编辑动作，换取默认工作面的可读性。

[Primer分段选择](https://primer.style/product/components/segmented-control/guidelines/)强调当前选择及即时应用。界鉴保留连续移动标记，并将分段、索引、范围和目标选择的实心底统一到已有蓝色选择语义；暗色表面用来建立层级，不能冒充选中。线型页签和勾选控件保持自身表达，悬停和焦点不覆盖当前选择。

### 横向分类与简短配置

[Carbon页签](https://www.carbondesignsystem.com/building-blocks/core/components/tabs/guidelines)区分选中、悬停与焦点，并保留窄屏横向滚动。结合用户接受的两级导航参考，界鉴使用轻蓝底色与底部强调线表示当前分类，中性悬停只提示指针位置；保留现有连续移动节奏。采用的是状态分工，不引入游戏配色、纹理或快捷键，也不要求页面新增导航层级。

[Primer表单](https://primer.style/product/ui-patterns/forms/)建议字段按可预测的顺序纵向流动，宽度与预期内容相适应。环境配置只有名称、地址和可选说明，改用受控宽度的单向表单，不再为了填满画布将说明排成第四项字段。进入编辑后暂收起目录，取消恢复目录；保存、切换与核验仍为不同操作。代价是短表单不占满整页，换取稳定的输入路径与清楚的操作收口。


## 持续工作面的重建

采用 [Linear 的界面更新](https://linear.app/now/behind-the-latest-design-refresh)中降低导航竞争、稳定标题和操作位置的关系，将连续目录、主要阅读区和辅助上下文统一组织，沿用已认可的画布和基础风格。借鉴的是视觉层级与可预测位置，没有复制其品牌色或数据模型。目录详情增加一处稳定阅读区，代价是目录宽度需要随内容和窗口调整。

依据 [Primer 导航](https://primer.style/product/ui-patterns/navigation/)区分全局工作、局部分类和具体对象。规则、测试、问题与协作是持续任务，环境与来源是应用资产；同一 URL 的全局定位和准确对象接续具有不同职责，不机械去重。来源、账号与材料沿用相邻索引，状态使用相同选中语义。

依据 [GOV.UK 核对回答](https://design-system.service.gov.uk/patterns/check-answers/)保留已有输入及直接返回修改，接口流程从一次性首次向导改为可接续的工作面；实际输入门禁与独立采用保持原义。依据 [Fluent 2 动效](https://fluent2.microsoft.design/motion)用运动说明对象和状态关系，保留已认可时长、快速反向接续和减少动效支持，取消通用卡片悬浮不削弱选择与展开反馈。

这次重建处理分散大卡片及协作信息同时堆叠的组织，基础主题、排版、圆角、尺寸和动效按原基准统一。正常、空白、读取失败与待确认均使用同一任务结构，错误不清空标题。采用理由不等于运行证据，真实截图、组件测试与执行事实分别记录在运行审阅目录。

依据 [Carbon 间距](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)用内外间距表达关系，连续工作面减少整块辅助底色和重复围合；目录与详情各有阅读内边距。依据 [Microsoft 列表与详情](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/list-details)分配定位与阅读职责，报告展开后精简索引，关闭后恢复摘要；窄窗保持单一阅读面。采用的是关系和密度变化，不照搬平台像素断点或替换现有控件。代价是需要同时维护展开与未展开状态，收益是减少重复阅读和视觉竞争。

依据 [Carbon 通知组件](https://www.carbondesignsystem.com/building-blocks/core/components/notification/code)保持通知与相关动作的归属：轻量动作在所属语义表面上可辨，重试不混用危险操作。依据 [GitLab 渐进披露](https://design.gitlab.com/patterns/progressive-disclosure/)将任务必读事实与低频技术信息分开；证明来源以三个明确分类替代连续折叠，核对结果直接展示。分类增加一次可预测切换，代价是需要保持草稿及当前对象；没有引入新的授权动作、主题或控件库。

参考 [Postman 的请求参数编辑](https://learning.postman.com/docs/use/send-requests/create-requests/parameters)集中请求地址和参数，参考 [Carbon 表单](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)按相关任务组织输入并逐渐呈现。接口流程将顶部阶段进度、执行顺序和当前请求分开；比较依据与恢复接口在有实际配置时进入后续阶段，动态防伪参数用独立对话框配置。代价是复杂操作多一次推进，但普通只读操作跳过无关阶段；本地切换不发送目标请求，草稿、保存和正式采用仍有各自边界。


参考 [VS Code 的显式上下文](https://code.visualstudio.com/docs/chat/copilot-chat-context)让用户核对本次交接对象，参考 [GitHub 会话管理](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents)让补充要求和产物回到原任务。界鉴采用准确业务引用与受限草稿结构，不复制整屏对话；候选比较后再带入，避免模型产物直接覆盖编辑。代价是增加一次审阅，收益是保留人工输入与具体版本；原始参数留在文档内存，因此跨页接续可用，整页刷新前仍需保存。

参考 [Linear Inbox](https://linear.app/docs/inbox)将需要注意的事项与其他更新区分，结合 [GOV.UK 任务列表](https://design-system.service.gov.uk/components/task-list/)的简短任务名称和自由处理顺序，协作工作面以连续待办索引配合单项详情；目标、产物上下文和处理记录各有位置。[Carbon 表单](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)的按需呈现和结构化容器右侧主操作用于回答与确认。这里采用任务分流与阅读关系，不引入另一套配色或徽标；代价是查看历史或其他事项多一次明确切换，收益是当前决定有稳定焦点，草稿继续保留。

参考 [Carbon 页签指导](https://www.carbondesignsystem.com/building-blocks/core/components/tabs/guidelines)区分同一上下文中的分类与内容层级，以现有线型页签作为默认完整外观；参考 [WAI-ARIA 页签模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)保留单一Tab入口、方向键和当前位置关系。内容页签与路由链接只共用外观，不互换语义。界鉴将密度和分隔线归属显式放进公共组件，业务只安排位置，代价是新增变化需要在公共所有者审阅；收益是新页面即使没有专属样式，也保持可用且一致。

参考 [Atlassian 颜色角色](https://atlassian.design/foundations/color)区分选中、信息、警告和结果，参考 [Carbon 通知分类](https://www.carbondesignsystem.com/building-blocks/core/components/notification/guidelines)按实际后果选择反馈等级。界鉴据此将正常等待与风险提示分开，选中导航保留单一强调，正式允许/禁止与实际核验结果分开着色；具体色值由当前已采纳的共享色板维护。按 [WCAG 文字对比说明](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)核对语义文字与自身、选中及悬停背景。代价是风险提示需要明确声明，收益是黄色、红色保留可理解的严重程度，视觉统一不遮蔽真实缺口。

参考 [Atlassian 间距](https://atlassian.design/foundations/spacing/)的语义分组与[Carbon 间距](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)由父布局拥有组间距离的做法：索引条目连续排列，追加操作另成一组；表单字段、章节和列表详情之间使用不同层级的留白。共享索引和追加操作组件维护这些关系，页面只安排任务结构。代价是同屏条目略少，收益是选择与追加、当前内容与后续操作更易辨认；不采用固定空白高度填满画布，也不改变基础配色、字号或动效。

依据 [Carbon 表单分组](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)和 [Ant Design 表单任务拆解](https://ant-design.antgroup.com/docs/spec/research-form)，把操作定义与结果、连接与记录对应组织成相关章节；依据 [Atlassian Form 的章节职责](https://developer.atlassian.com/platform/forge/ui-kit/components/form/)保留明确组名和填写顺序。宽工作面并列的是相关任务组，组内不任意左右跳读；窄工作面自动上下排列。共享布局只管理几何关系，不新增主题、背景或卡片。代价是复杂类型需要较长的纵向阅读，收益是输入随当前类型出现，少量字段不会再被铺成宽横排。

依据 [Apple 搜索框](https://developer.apple.com/design/human-interface-guidelines/search-fields)保留放大镜、明确范围和清除操作；依据 [Apple 分栏](https://developer.apple.com/design/human-interface-guidelines/split-views)让选择与相邻详情保持联系，并允许收起补充区域。界鉴复用现有颜色与字形，统一五处搜索和两处目录详情的实现，不照搬苹果材质或改变查询提交边界。代价是详情被收起后需要再次点击条目，收益是比较目录时能使用完整宽度，展开后不必重复阅读摘要。按 [Apple 排版](https://developer.apple.com/design/human-interface-guidelines/typography)维护图标与文字的共同尺度；沿用 MiSans，计数、时间和进度采用等宽数字，正文和业务名称不改字体。

依据 [Apple 文件管理](https://developer.apple.com/design/human-interface-guidelines/file-management)沿用系统文件浏览器，依据 [Apple 拖放](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop)将反馈附着于实际接收区域，并提供同等可用的选择按钮。来源导入、接口文档与完整参照使用同一文件行；文件信息与操作相邻，错误替换保留原文件。按 [Apple 进度提示](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)只表达真实读取等待，不生成百分比或提前宣称上传完成。代价是需要维护取消、清除和异步互斥，收益是摆脱浏览器默认控件的视觉差异，同时保留明确的业务确认和基础主题。

本地目录参考 [Apple 反馈](https://developer.apple.com/design/human-interface-guidelines/feedback)与[指针设备](https://developer.apple.com/design/human-interface-guidelines/pointing-devices)，使高亮、悬停和实际命中区域对应；参考 [Carbon 表格](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)保留单一键盘入口和渐进详情，参考[空态](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)区分初始无数据和筛选结果。界鉴使用共享按钮结构及反馈节奏，颜色由共享语义角色统一维护。整行入口的反馈底色包含完整四边留白，不能只扩大热区而让文字贴边。

参考 [Apple 分栏容器](https://developer.apple.com/documentation/uikit/uisplitviewcontroller)中选择与详情的分工，以及 [Atlassian 间距](https://atlassian.design/foundations/spacing)通过邻近关系成组的原则，权限提案采用完整概览与按需详情。概览将访问要求、资源、业务结果放在同一行，选中后收起重复结果列，以相邻详情集中解释当前规则。关闭后恢复跨规则比较；窄窗分步阅读，定义和来源另行查阅。原版本对照、整份人工批准和未知回执由原流程负责，不随阅读结构改变。

参考 [Atlassian 框架区域](https://atlassian.design/components/navigation-system/layout)对全局工具、应用导航和正文的分工，以及 [Apple 工具栏](https://developer.apple.com/design/human-interface-guidelines/toolbars)的稳定控制层，界鉴沿用直接展开正文的框架、壳层尺寸和控件位置。按用户已采纳小样将背景延续到整个窗口；固定栏复用同坐标背景，避免局部遮罩和单独铺色产生横向接缝。区域需要区分时使用上下留空的细分隔，保持导航与正文的职责差异。

参考 [Apple 颜色](https://developer.apple.com/design/human-interface-guidelines/color)按用途使用颜色、[暗色模式](https://developer.apple.com/design/human-interface-guidelines/dark-mode)区分基础与抬升表面，以及 [Fluent 颜色体系](https://fluent2.microsoft.design/color/)对中性、品牌和语义色的分工。亮暗主题分别定义柔和蓝灰画布、普通表面、输入与浮层；雾蓝承担动作和选择，灰绿、灰金与灰玫瑰分别承担成功、警告与错误。浅色减少大片纯白与过强边框竞争，深色保留已采纳的蓝灰层次。普通待准备使用中性状态，真实不确定或异常仍明确提示。代价是每种文字都需要同时核对所属、悬停与选中表面；收益是页面和第三方控件共用稳定颜色职责。禁用态保留可读文字，对比度与交互通过真实浏览器核对，不将产品自选色值宣称为 Apple 官方色板。


组件重建参考 [Fluent 排版](https://fluent2.microsoft.design/typography)对角色与层级的区分，保留MiSans，按页面、集合、分组、业务名称、正文、标签和辅助信息分配尺寸。参考 [Apple 按钮](https://developer.apple.com/design/human-interface-guidelines/buttons)用稳定几何表达主次，等待时保留原占位；参考 [WAI 组合框](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)维持焦点、候选与选择的区别。业务页消费同一组件，取舍是需要逐个校准原有小字号覆盖，不能只新增一套变量。

参考 [Apple 弹簧连续性](https://developer.apple.com/videos/play/wwdc2023/10158/)保留选择标记在改向时的位置和速度，参考 [Material 运动](https://m3.material.io/styles/motion/overview/how-it-works)区分空间变化和颜色变化。开关、勾选、菜单、文件拖入、实际复制完成、展开与工作面交接各自表达关系，普通阅读和静止成功状态不循环运动；按 [WAI 减少交互动画](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)停止非必要运动而保留能力。具体Web参数为本产品选择，不声称等同Apple原生组件。


## 设置分组与业务线索编辑

[Carbon 表单指导](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)强调按相关任务分组；[文本输入指导](https://www.carbondesignsystem.com/building-blocks/core/components/text-input/guidelines)明确字段宽度应对应预期内容，不能只为填充空白而拉长。[Apple 设置指导](https://developer.apple.com/design/human-interface-guidelines/settings)用于核对设置组织。界鉴将连接、服务开关和应用授权归回各自对象；业务线索分类后以共享列比较名称、处理决定与来源。短名称和选择器保持适当宽度，来源文件与位置相邻；它们不需要目录加空详情。这里借鉴信息归组与任务关系，不照搬主题或为填满工作面增设统计和说明。

## 复杂工作流的组织依据

- [Carbon 进度指示器](https://www.carbondesignsystem.com/building-blocks/core/components/progress-indicator/guidelines)用于线性多步任务；因此流程新建保留引导，已有流程的局部维护改用自由分类切换，避免将日常修改包装成必须重走的步骤。
- [GitHub 变更审阅](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/reviewing-proposed-changes-in-a-pull-request)强调理解意图、逐项差异和提交审阅的区别；界鉴采用逐项上下文与准确版本对照，保留领域配置的人工采用门槛，不将阅读进度当成权限结论。

检查预览、流程维护及协作产物审阅分别采用适合本任务的结构；主题、字体、控件与共享动效统一维护，界面浏览与后端执行决定保持独立。

## 持续检查的任务说明与入口层级

依据 [Apple 按钮指导](https://developer.apple.com/design/human-interface-guidelines/buttons)减少竞争的显著操作，[工具栏指导](https://developer.apple.com/design/human-interface-guidelines/toolbars)避免过多文字操作并排。工作台只提供最近记录的阅读入口；比较留在完整记录中按需选择，状态用内容表达，不逐行重复按钮和方向图标。取舍是比较多一次进入记录页，收益是用户能明确选择参照范围，概览不承担全部命令。

依据 [Carbon 空态指导](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)说明模块用途、当前情况和具体下一步。界鉴在重复检查处说明保存内容与本次准备的关系，协作入口说明目标与执行确认，材料缺口说明应先完成的依赖；创建入口按数据状态收敛。这里采用情境指引，不把业务名词列表当作说明，也不在每个模块重复完整教程。

参考 [Microsoft 的界面写作指导](https://learn.microsoft.com/en-us/style-guide/top-10-tips-style-voice)，先说明用户要完成的事、必要选择和下一步；用具体的应用地址、账号和材料说明工作，技术编号按需查阅。采用自然、专业的中文，不机械套用英文缩写、口语或固定字数。

参考 [Primer 的渐进披露](https://primer.style/product/ui-patterns/progressive-disclosure/)和[导航指导](https://primer.style/product/ui-patterns/navigation/)，保留当前对象和回程，只展开当前事项需要的依据。关键缺口和执行后果直接呈现，不折叠。参考 [Carbon 按钮层级](https://www.carbondesignsystem.com/building-blocks/core/components/button/guidelines)，同类操作保持共同表达，主要推进、对象导航和普通资料链接各有稳定层级；不为不同页面另造一套控件。

跨轮结果较少而解释较长时，采用 [Carbon 可展开数据表](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)的原行展开机制，将前后事实放在选中结果下方，以可用宽度并列阅读。它解决的是摘要表与窄详情栏高度失衡，不改其他目录的任务组织。取舍是展开内容会将后续行下推，因此一次只展开一项，并保留原行收起、键盘焦点和准确报告回程；主题与选中动效仍由共享控件拥有。

内容密度与工作面合并：参考 [Apple Split views](https://developer.apple.com/design/human-interface-guidelines/split-views) 将层级选择与相关内容相邻呈现，保持当前选择；参考 [Primer PageLayout](https://primer.style/product/components/page-layout/) 使辅助区围绕当前内容安排。依据 [Carbon 可展开表格](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) 在短摘要与长内容之间选择原行展开、侧面阅读或独立任务。界鉴的具体取舍为：地址与源码概览并列，方案和场景目录展示真实保存内容，长比较解释继续整行阅读；半栏是内容关系推导的结果，不是所有页面的固定模板。

## 让一个事项连续完成

参考 [GitHub Pull Request 工作流](https://docs.github.com/en/pull-requests/reference/pull-requests)围绕同一事项衔接修改、检查和审阅，界鉴将问题证据与处理复验放在同一原题下，将方案准备与本次检查放在同一任务中。参考 [Carbon 对话框模式](https://www.carbondesignsystem.com/building-blocks/core/patterns/dialogs)，短决定就地完成，复杂材料继续使用完整工作面；不把所有步骤都装进弹窗。代价是组合层需要明确保存当前范围和嵌套回程，原编辑器仍负责自己的草稿和回执。

后端参考 [Azure CQRS 模式](https://learn.microsoft.com/en-us/azure/architecture/patterns/cqrs)中任务命令与展示读取职责分开的原则，准备建议只是现有事实的范围投影，不引入独立事件存储或页面任务数据库。保存、采用、授权、加载和执行继续各走原用例；页面组合不会获得额外执行权限。

方案材料与修复详情采用 [Carbon 结构化列表](https://www.carbondesignsystem.com/building-blocks/core/components/structured-list/guidelines)中将关联内容分组、便于扫描的原则，以及 [Carbon 间距指导](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)中用组内与组间距离建立层级的方法。材料使用要求与当前材料在可用宽度内并列，复杂任务保持完整正文；流程提示和复验依据降低视觉重量，当前任务与主要动作保持突出。代价是需要按实际容器宽度重排，并分别核对空材料、已有材料和不同修复状态；不照搬其品牌配色、控件或固定列数。

同一原则扩展到准备、业务要求处理、检查过程和协作上下文：通过任务结构及间距区分进展、决定与依据；两段需要对照的内容相邻，复杂诊断退后。分组由父容器维护，避免每个字段自行补边距后在组合工作面重复叠加；代价是需要分别核对嵌入宽度和独立页面，不能用一次桌面截图替代过程状态验证。

## 少量核对项的状态概览

参考 [Fluent List](https://fluent2.microsoft.design/components/web/react/core/list/usage) 对相关内容成组、保持平行阅读结构的指导，以及 [Atlassian Lozenge](https://atlassian.design/components/lozenge) 用紧凑状态表达对象属性的方式。界鉴将状态放在本项名称右侧，以固定间距维持关联；条目按实际宽度排列，以留白区分，沿用现有语义色与徽标。每项保持完整文字，长内容或窄区自然换行，不依赖横线和两端拉开的状态列建立关系。

这一方案适用于运行组件、来源核对、试运行条件和复验范围等少量独立结果。取舍是放弃整列状态对照，换取更明确的单项归属；多字段比较继续使用内容表，大集合继续使用目录。窄区保持原阅读顺序，长文字完整换行，模块的说明与后续动作仍由父工作面维护。


## 全组件动效与工作面编排

采用 [Apple弹簧动画](https://developer.apple.com/videos/play/wwdc2023/10158/)在改向时保留位置与速度；[Fluent动效](https://fluent2.microsoft.design/motion)用于内容分组的层级与短间隔编排；[Carbon动效](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview)用于区分日常反馈和重要完成。参考 [Linear界面整理](https://linear.app/now/behind-the-latest-design-refresh)保持当前任务的视觉重心，不把所有区域赋予同等运动强度。

本次以运动重建为范围，保留当前主题与静态布局。统一控件、原生元素、第三方弹层、列表和业务组合的运动职责，清除逐页覆盖；丰富度来自连续交接、弹性、补位、活动和完成的配合。实现与参数由交互规范和共享代码拥有，来源建议不作为实际验证结果。
