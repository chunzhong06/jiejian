# 前端设计依据

界鉴以自身已确认的主题、MiSans、控件和动效为基线。产品组织主要研究 Linear，Apple 用于校准分组、留白与动态连续性。具体页面先服从真实任务和业务边界；来源提供选择依据，不替代实现和运行验证。

## 参考的职责与优先顺序

[Linear 的整体界面整理](https://linear.app/now/behind-the-latest-design-refresh)用于判断任务重心、辅助导航、视觉重量和边界。深入比较同一产品的集合浏览、详情、编辑及其空、等待、失败状态，避免分别摘取不同产品的单个组件。[项目工作面](https://linear.app/docs/projects)、[视图与预览](https://linear.app/docs/custom-views)和[显示选项](https://linear.app/docs/display-options)用于理解对象、集合、属性和定位工具的分工。界鉴采用这些关系，不复制其品牌配色、信息密度或产品功能。

[Linear Triage](https://linear.app/docs/triage)用于研究输入线索经审阅进入正式工作的关系。持续使用设计据此将业务线索、遗漏核对、候选和正式要求保持可辨，并让本次任务保留自己的范围与回程。代价是维护输入依据、决定及准确关联；验收时核对新增线索、已处理内容和原题接续，具体安排见[持续使用工作面设计](工作面模式.md#持续使用工作面设计)。不复制通用工单系统或为每条线索增加强制全应用阻塞。

[Apple 布局指导](https://developer.apple.com/design/human-interface-guidelines/layout)用于按重要性和自然阅读顺序安排信息，利用对齐、空间和容器表达关联。[反馈指导](https://developer.apple.com/design/human-interface-guidelines/feedback)用于让状态变化和动作后果可辨。平台尺寸、原生控件与材质不直接转为 Web 硬规则；界鉴继续沿用自身画布、输入面与浮层角色。

已采纳的规则进入共用实现后，由实际任务和使用效果持续校准。新的外观建议先检查能否由既有组合表达；确需例外时说明任务差异和影响范围。技术文档、领域产品及无障碍标准用于核对具体行为，不参与每页的品牌外观选择。

参考的广度沿同一产品的完整任务及跨页关系展开，深度进入内容取舍、组件组合和正常、空、长内容、等待、失败、完成与恢复状态。影响任务结构或共同模式的选择，按[调查与采用的方法](../设计依据.md#调查与采用的方法)说明适配理由和代价，再转成受影响工作面的具体验收条件。

## 如何转为具体界面

### frontend-design 的完整采用范围

采用 [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) 的任务出发、明确取舍、实施后批判的方法。它与用于调查软件行为的 reverse-engineer-anything 分工不同。技能入口中的原则须覆盖产品表达、构图、排版、色彩与表面、组件、文案、交互状态和动效；不能将几处样式修正当作完整采用。

界鉴的题材是持续核对业务访问边界：明确谁对哪份资料做什么，以实际业务后果和正常功能对照给出结论。主体验的记忆点是“原要求保持、改变实现、观察后果”的连续关系。界面依此安排重心，普通管理与技术引用安静退后。沿用已选亮B、暗A主题及MiSans，不借迁移方法重新选择品牌配色。

| 维度 | 界鉴的具体决定 | 实现与检查所有者 |
| --- | --- | --- |
| 产品表达 | 当前任务先回答待验证的业务问题；示例中同时保留不变要求与这次修改，准确接续原检查 | 工作台、ExampleLab和正式报告；核对真实旅程及已有结果去向 |
| 构图 | 一处重点，其余内容按依赖阅读；比较并列、目录与详情邻接、编辑独立聚焦，区域不默认平分 | TaskStage、ComparePair、ObjectTable、Inspector与业务工作面 |
| 排版 | 页面标题、任务重点、分区、对象、标签、正文和追溯各有字级；任务重点用24px/32px，窄窗22px；同屏仅当前关键问题采用重点字级 | tokens、Heading/ObjectHeading、UIProvider；实际中文换行、长名与菜单一起核对 |
| 色彩与表面 | 保留画布、侧栏、内容、输入、浮层及选中角色；实际结论使用语义色，普通要求与身份保持中性 | tokens与UIProvider；业务CSS不再派生色板，亮暗整窗检查 |
| 结构标记 | 线条表示真实边界，编号只表示执行顺序；普通要求目录靠名称及选中面定位 | IndexSelection、WorkflowSteps及目录消费者；不按编号装饰所有条目 |
| 控件与状态 | 字段按实际内容选档；选择、命令、导航、展开分别表达；忙碌仍能读出原动作，原元素和几何保持稳定 | Field、Choice、Button、CommandMenu、Tabs、Dialog；键盘、禁用、失效值及窄窗一起检查 |
| 文案与反馈 | 每段只承担一个任务；首层给原因、后果和恢复，诊断编号及封存原文按需阅读；清理本地副本与查询原任务分开 | ErrorNote、Notice、Empty、PendingRecovery及业务回执；不将读取成功称为采用或检查通过 |
| 动效 | 异步新增只同步交接可见性，不给每个区块依次上浮；主动选择、展开、布局补位与重要完成保留各自语义动效 | motionScene、PageSurface和对应交互所有者；减少动态、打断、相同轮询与焦点核对 |

组件审查必须进入其真实使用位置：标题与事实之间的净距离、表格和展开的归属、提示与动作的组合、输入到保存后的回执，均由最终组合判断。已有规则成立时记录保留原因，不为了显示采用技能而给每个组件增加新外观开关。新增规则由共享所有者承担，同时清理被替代的局部覆盖。

实施后分别保留全量静态清单、实际画面与交互证据。清单用于发现遗漏；截图用于判断视觉；测试保护行为与门禁。单次审查须准确说明实际运行的状态，不能把主路由截图扩大为每个深层分支均已重验。

设计按内容取舍、任务组织、视觉表现依次展开：先明确当前对象、必要信息、用户决定、产物和完成去向，再按比较、选择、编辑、阅读或执行选择结构，最后校准共同的标题、控件与动效。信息分区不自动产生卡片、标题、说明和入口；布局与组件应帮助用户辨认任务，必要解释放在对应判断位置。基础统一与结构重建的边界见[布局与视觉](布局与视觉.md#基础统一与布局重建)。

| 任务 | 采用的组织与取舍 |
| --- | --- |
| 继续工作 | 当前任务优先，历史提供接续；不重复全局资料入口和状态统计。自然结束后的空白可以保留。 |
| 持续选择对象 | 目录与准确详情相邻，关闭后回原选择；没有选择价值时直接读内容。目录与比较表保留不同职责。 |
| 跨项比较 | 表外分类标题、共同列和逐行内容建立层级；复杂编辑或长解释在对应项下展开或独立阅读。 |
| 编辑和授权 | 按决定依赖分组，必要后果直接说明；草稿、保存、采用、执行和授权各有真实动作。 |
| 理解检查结果 | 先结论和范围，再解释边界与观察；技术过程按需深入，说明不为填补空位搬到窄侧栏。 |
| 处理待办 | 用对象摘要、时间和原入口区分事项；不将多份提案变成一排同名按钮或多条同质通知。 |
| 等待和恢复 | 保留页面身份与原对象，骨架不生成假状态；未知写入查询原动作，失败保留输入和回程。 |
| 完成并继续 | 说明及操作在所属任务末尾收口，次要命令在前，主要推进在后；不增加重复的完成卡或导航层。 |

共同语言由标题组、对象与状态、目录详情、内容表、字段组、反馈、操作收口维护。页面保留业务组合的自由：长表单、长证据、短确认、后台执行和持续选择不会套成相同列数或固定阶段。

## 组合规范的参考与取舍

[Carbon 按钮指导](https://www.carbondesignsystem.com/building-blocks/core/components/button/guidelines)用于核对动作层级、容器内的操作位置和图标语义：图标应直接关联操作，避免为所有入口重复附加图标。Carbon 按页面、向导和对话框区分位置；界鉴采用自身已确认的所属任务右下收口，具体规则归[布局与视觉](布局与视觉.md#统一设计语言的执行)。不将来源的品牌、全部按钮位置或固定参数整体引入。

[Carbon 折叠指导](https://www.carbondesignsystem.com/building-blocks/core/components/accordion/guidelines)用于以展开状态解释标记方向，[GOV.UK 任务列表](https://design-system.service.gov.uk/components/task-list/)用于研究任务名称、必要提示及状态作为一个可辨认事项的关系。界鉴据此区分选择、展开、命令与导航，并把账号名称和短状态保持成组；保留自身共同控件与事实边界，不照搬政府服务的完成门禁。

判断顺序是当前任务与对象关系、已有共同模式、官方机制与版本证据、实际画面和交互验证。动作位置和记录伸展由本地组合直接决定时，先修正组合；遇到组件真实行为分歧，再按[组件复用与版本适配](#组件复用与版本适配)核对源码、Issue、PR 和复现。来源说明机制，业务语义与视觉采纳分别验收。

[GOV.UK 执行前核对](https://design-system.service.gov.uk/patterns/check-answers/)提供先审阅实际内容、返回修正、明确提交的顺序，适配为检查准备之后的独立执行预览。代价是增加一次明确推进，收益是开始真实业务操作之前能够辨认账号、资源、正常对照与条件。[Carbon 表单组织](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)提供相关输入分组和按相关性披露的依据，适配为登录设置中的身份、登录方式及高级字段对应。界鉴保留自身任务表面、主题、右下动作和受控秘密输入流程。证明三阶段消费原授权、预检查与采用事实，阶段展示不引入新的后台门禁。

2026-11-13 核对 [Postman Collection Runner 官方说明](https://learning.postman.com/docs/tests-and-scripts/running-collections/intro-to-collection-runs/)，采用已保存请求集合、运行前选择和逐请求结果各有职责的组织机制：界鉴先读保存修订，再单独预览和试运行，结果记录保留准确账号、资源与恢复反馈。结合 GOV.UK 的提交前核对机制，把采用流程安排为独立审阅，确认后才更新执行、资源和恢复绑定。代价是保存、试运行、采用各需明确动作；它们对应不同后果，不能合成一个成功状态。保留界鉴自己的主题与组合，不引入 Postman 脚本执行、会话持久化方式或权限判断。账号目录换行与材料首屏误导来自自有组合，修正对应布局和任务组织；未发现需要修改第三方组件行为的依据。

## 动态连续性

[Apple 弹簧动画](https://developer.apple.com/videos/play/wwdc2023/10158/)用于理解改向时的位置和速度连续性；采用界鉴已确认的运动参数及共享实现，不以 CSS 缓动冒充物理弹簧。内容选择、展开、布局补位、真实活动及重要完成按对象关系编排，父区域运动时扣除重复的子入场。

日常反馈立即接受输入，重要完成呈现结果与下一步的连续交接；轮询相同事实保持静止。减少动态效果继续呈现完整状态和操作。动效不决定就绪、执行成功或权限结论，也不通过等待动画拖延实际请求。具体参数和验证归[交互与动效](交互与动效.md)。

## 技术与领域依据的边界

- [WAI-ARIA 模式](https://www.w3.org/WAI/ARIA/apg/patterns/)用于页签、菜单、对话框、组合框及焦点契约；[WCAG](https://www.w3.org/WAI/WCAG22/Understanding/)用于适用的可访问性核对。
- [Ant Design v5 Select](https://5x.ant.design/components/select/)用于已采用控件的行为和浮层适配，不引入其默认主题；[MDN](https://developer.mozilla.org/en-US/docs/Web/CSS)用于浏览器能力、布局和渐进增强。
- 认证复用、接口导入、业务证明、运行加载、Agent 执行、外部工单和工作区维护分别由对应[能力规范](../../llms.txt)拥有。领域产品的做法可以帮助理解任务，不能改变界鉴的独立授权、秘密边界和确定性验证。

历史曾使用其他设计系统核对单项机制。仍成立的任务与行为要求保留在实际所有者中；本文件不再将它们并列为页面外观的备选体系。

## 组件复用与版本适配

2026-11-13 审计核对的基线为 React 19.2.8、Ant Design 5.29.3、rc-dropdown 4.2.1、rc-select 14.16.8。组件交互机制、界鉴主题令牌及任务组合各有所有者：UIProvider 负责令牌映射，Choice/CommandMenu 等共享控件负责受控适配，页面只组织业务。版本升级前重核实际依赖树及调用，不能直接以最新主版本文档推断本地行为。

| 调查点与准确来源 | 本地结论、取舍和维护条件 |
| --- | --- |
| Select 旧缩放宽度问题：[Issue #44354](https://github.com/ant-design/ant-design/issues/44354)、[PR #44378](https://github.com/ant-design/ant-design/pull/44378)与 [5.9.0 发布记录](https://github.com/ant-design/ant-design/blob/5.9.0/CHANGELOG.en-US.md) | 旧问题涉及父级 scale 与浮层容器，PR 通过依赖升级处理并进入5.9.0；当前5.29.3已晚于修复。类似现象先以当前版本检查容器测量、scale/动画和最小复现，不能直接套用旧补丁或认定同根因 |
| 滚动时的弹层行为：[Issue #48103](https://github.com/ant-design/ant-design/issues/48103)及 [v5 Select getPopupContainer](https://5x.ant.design/components/select/) | 上游建议按滚动容器选择挂载位置，旧 v4 行为不能直接当作正确标准。现有 popupParent 在 native dialog 内选对话框、其他情况按现有合同使用 body，有 top layer 原因；保留并按滚动、裁切、缩放、退场和键盘核对，不一律改成 parentElement |
| 可用的语义样式范围：[Select 5.29.3 源码](https://github.com/ant-design/ant-design/blob/5.29.3/components/select/index.tsx) | 此版 classNames/styles 的语义键是 root 与 popup.root，不能假设所有内部 selector/option 都有公开 hook。Choice 已使用公开 popup 钩子，shared controls 中必要的 .ant-* 选择器作为有版本责任的适配保留；页面局部选择器先区分布局和内部覆盖。升级时核对 DOM、选择器及直接消费者，确认公开替代能覆盖后再删除适配 |
| 菜单焦点时序：[rc-dropdown v4.2.1 useAccessibility](https://github.com/react-component/dropdown/blob/v4.2.1/src/hooks/useAccessibility.ts) | 上游自动聚焦使用延迟 raf，本地 CommandMenu 关闭 autoFocus、自持 opening/open/closing 及可取消聚焦，服务于退场和焦点返回。准确版本源码支持保留该接管；定向 Issue 搜索未命中不等于没有同类问题。升级时先核对上游取消与聚焦职责，只有交互等价并通过邻域才退回上游默认 |
| React19 与 AntD5：[5.29.3 React19 说明](https://github.com/ant-design/ant-design/blob/5.29.3/docs/react/v5-for-19.en-US.md) | 官方兼容问题聚焦 Wave 与 Modal/Notification/Message 静态方法。本地主要直接使用 Select、Dropdown、Tooltip 和 ConfigProvider，Button/Dialog 自有；按实际受影响调用评估补丁，不因大版本组合就盲加 patch。独立 icons 6.3.2 与 AntD 内部 icons 5.6.1 的责任需在图标/主题变更时核对，当前未复现故障，不据此强制降级 |

这些结论保留现有设计语言和适配责任，不提出默认升级 AntD6、另换查询框架或删除认可动效。若未来出现必须升级的实际收益，另列受影响 DOM/CSS、公开接口、图标与主题兼容、迁移代价及回退条件，按完整任务验收。

产品任务的后续收敛采用三个理由：集合首入应帮助用户定位总体，准确深链接和回访应保留原选择；业务名称按正文/对象角色阅读，辅助引用才使用元信息角色；报告应显著区分规则适用条件与本次实际样本，并给未查/未决项准确去向。前两项沿 Linear 的任务主次与导航机制，后一项沿 [GOV.UK check answers](https://design-system.service.gov.uk/patterns/check-answers/)的具体修改入口与返回机制；不复制其品牌、固定尺寸或强制线性步骤。具体目标与实施状态见[后续方案](../产品改进方案.md#设计语言与工作面组织)。

## 可用性审视与界鉴规范的关系

本地视频《Claude为什么用着舒服？有人让它用REA拆开自己，找出十几处质感细节》提供作者观察与示意：00:20—02:02的可感知表面层次与少量强调色、02:03—03:17的装饰发丝线与溢出边缘、03:19—04:30的暗色字重与稳定数字、04:31—06:23的反馈与减少动态效果、06:24—07:07的首帧主题及真实布局占位。界鉴据此明确各层表面、暗色光学字重、等距内陷、安静等待与对应任务结构的占位；暖灰品牌、作者固定数值和0.01ms实现不直接成为本产品规定。视频中的参数不当作Claude官方实现事实。

真实字重、稳定数字和首帧主题由tokens、字体资源与主题初始化负责；导航和任务表面的层次由壳层及共享表面负责。按钮采用等距内陷的按压面，骨架按真实任务结构占位，实际等待使用共享活动点。当前要求及实现所有者以本组规范为准。每次迁移继续核对实际消费者、整页亮暗画面与受影响动态。

字体行为分别核对[MDN font-synthesis](https://developer.mozilla.org/en-US/docs/Web/CSS/font-synthesis)与[font-variant-numeric](https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric)；新细节依附现有令牌和组件所有者。以实际运行、首次绘制、按压和主题截图核对采用效果，不能从参考实现的参数直接推出界鉴同样合适。

[尼尔森十大可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)作为通用审视参考，用于寻找理解、操作、反馈和恢复中的问题。竞赛贡献与创新表达决定要传达什么，可用性审视检查能否理解并完成任务，界鉴设计语言规定具体构图、间距、状态、字段尺寸和动作位置。三者共同核对，不把通用原则直接换算成竞赛得分，也不以“符合一致性”为由机械统一所有任务结构。

| 原则 | 界鉴的审视问题 |
| --- | --- |
| 系统状态可见 | 准备、执行、发布结果及当前下一步是否清楚，生命周期与权限判断是否可辨？ |
| 符合现实世界与用户语言 | 是否先回答业务问题，再按需提供SHA、内部引用和技术过程？ |
| 用户控制与自由 | 能否取消、返回和恢复，保留原对象、输入及已完成动作？已发生的业务后果是否准确说明？ |
| 一致性与标准 | 同类对象、动作和状态是否采用共同模式，差异是否来自真实任务？ |
| 预防错误 | 真实操作前是否说明范围和后果，依据已变时是否先重核？ |
| 识别优于记忆 | 跨页仍能辨认具体要求、问题和结果，是否依赖记住“原问题”等模糊指代？ |
| 灵活性与效率 | 首次体验是否明确，深入使用能否继续真实进度并采用已有有效材料？ |
| 美观与简约 | 是否具有明确业务重心，辅助资料是否抢占主要判断和动作？简约是否仍保留必要证据和上下文？ |
| 错误识别、诊断与恢复 | 能否知道哪里失败、已保留什么及从何处继续，回执未知时是否查询原动作？ |
| 帮助与文档 | 必要解释是否就近提供，具体步骤与当前界面是否对应？ |

审视单位是完整任务及其中各状态：集合、详情、编辑、展开、等待、失败、取消、返回和恢复。记录具体画面或交互、影响、违反的原则、根因、修改及核验方式；同一问题可以涉及多项原则，不按原则命中数量评价质量。先处理阻断主线、误解业务结论或诱发错误决定的问题，再处理局部视觉细节。全产品覆盖和本轮实际检查范围分别记录，保留用户已接受结构。

## 设计与完成的核对

本地工程视频讨论中提炼出的职责、依赖与实际变化原则，按下表归入现有所有者，不采用固定目录、层数或抽象数量。原阅读取证文件当前缺失，历史时间定位不作为现行依据；这里维护适用原则及可追溯的工程落点。

| 讨论材料 | 界鉴采用的原则与实现 |
| --- | --- |
| 《5 分钟学会写架构设计》00:54—01:58 | 领域、用例、适配与装配各有所有者；后端继续使用现有端口和组合根，前端由任务外层负责内容轴 |
| 《项目越写越乱？先改目录结构》03:02—06:57 | 按共同变化和内外边界组织；以修改定位、上下文和连带变更评价，不进行与本次问题无关的目录搬迁 |
| 《10分钟学会设计 Agent 架构》02:50—10:28 | 使用本产品领域概念，区分上下文、编排、执行适配和装配；保持原授权与确定性判断门禁，按真实环境增加适配 |
| 《为什么你应该忘掉设计模式？》00:33—02:28 | 共享组合完整承担实际职责；材料、核对和采用共用业务概览，避免页面继续重复决定内部关系 |

职责与依赖方向同时参照 [Hexagonal Architecture](https://alistair.cockburn.us/hexagonal-architecture) 和 [The Clean Architecture](https://blog.cleancoder.com/uncle-bob/2012/08/13/the-clean-architecture.html) 的原始说明，后者并不要求固定四层。Agent 采用 [Building effective agents](https://www.anthropic.com/research/building-effective-agents) 中先用简单机制、依据实际任务评价复杂度的原则，不将其旧版工具示例视为当前 SDK 规范。工程规则归[架构](../架构.md#从实际变化确定抽象)及[开发](../开发.md#根据问题核对复用方式)。

逐页先明确当前对象、必要判断、产物及回程，再决定保留、删除或重组。整页审阅与组件状态检查一起完成，检查父子边界、间距和动态叠加；同一种组合要回查全部使用位置，并记录合理例外。

完整任务从入口走到结果，再核对返回、准确修订、草稿重开和中断恢复。静态覆盖、浏览器实际运行和用户视觉审阅分别记录；源码搜索、构建或测试计数不代替整页设计判断。

审阅逐面核对任务重心、对象与状态归属、信息阅读次序、动作后果和完成接续；静态正常页之外，继续观察展开、警告、忙碌及恢复时这些关系是否成立。发现同类问题时，按[反馈处理方式](../任务执行与协作.md#人机协同的推进方式)回查判断与检查方法。

全面设计、状态检查和完整任务走查由AI完成；用户集中审阅少量代表工作面的前后对比与需要取舍的例外。重点图说明关键变化及其理由，动态变化用原速短视频或实际交互呈现。内部全量截图用于自查和追溯，交付数量服从本轮明确要求；既有接受结果继续有效，不反复转交用户逐页兜底。

方案与组合场景采用 [Carbon Forms](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms) 的相关字段分组、渐进披露和字段宽度原则，并以 [PatternFly Wizard](https://www.patternfly.org/components/wizard/design-guidelines/) 的当前任务焦点与提交前核对检验完整流程。简单配置不增加固定向导；界鉴继续保留本地草稿和返回接续，执行前沿用原明确授权。此处复用的是组织理由，字体、表面和动作几何继续服从界鉴自身语言。

本次问题定位在页面组合与共享表格的最小宽度竞争。通过实际批量展开和尺寸读取确认原因，修正在场景资源模式，不添加第三方组件补丁。共享场景阅读与材料名称按各自共同变化建立所有者；未进行目录层级搬迁，也未改变权限判断或运行协议。这是本地工程视频中“按实际职责与变化组织”的具体采用范围。

本轮在减少动态效果下复现了Select退场浮层长期保留、宽窗关闭后缩窄导致文档溢出。实际DOM仍处于leave-active；仅关闭CSS动画未同步第三方组件生命周期。按[Ant Design 5.29.3关闭动效](https://5x.ant.design/docs/react/customize-theme/#disable-motion)的公开token.motion配置，在UIProvider同步系统偏好；正常动效继续保留。该问题属于本地适配遗漏，未使用无关Issue补丁。真实浏览器重核退场、缩窄及同页继续编辑。

《一眼AI味的页面，毛病就出在4个地方》启发的颜色、字号、字体样式及表面层级检查，用于核对注意力分配，不将示例的暖灰色、固定四档字号和三版方案泛化为界鉴规定。修改详情已按当前状态与下一步优先的结构落地，其他采纳继续有效。

进一步在实际编辑中切换减少动态效果，发现当前任务返回概览。核对安装的antd 5.29.3、[同版本MotionWrapper源码](https://github.com/ant-design/ant-design/blob/5.29.3/components/config-provider/MotionWrapper.tsx)与[关闭动效说明](https://github.com/ant-design/ant-design/blob/5.29.3/docs/react/customize-theme.en-US.md#disable-motion)，定位为首次从开到关时新增Provider改变组件树。相关[Issue 53784](https://github.com/ant-design/ant-design/issues/53784)及已合并的[PR 53902](https://github.com/ant-design/ant-design/pull/53902)处理的是嵌套配置失效，不能视为当前重挂载问题的修复。界鉴在UIProvider初始化时建立稳定动效上下文，再于布局阶段采用系统偏好；实际库的回归测试先复现输入丢失，再验证双向切换、主题及完整任务接续。此适配由UIProvider集中维护，不修改第三方源码。

协作阅读采用[GOV.UK提问模式](https://design-system.service.gov.uk/patterns/question-pages/)对具体问题、必要用途与回答的分工，以及[Details组件](https://design-system.service.gov.uk/components/details/)只容纳补充信息的原则。界鉴将当前业务决定直接显示，将任务指令与工具诊断保留为原文入口；任务产物及场景关系使用真实结构化事实。这里借鉴内容职责，布局、动作位置、表格和主题继续使用界鉴已采纳的设计语言。旧自由文本没有简明说明时不自动截句或推断摘要。


## 选定主题与选择器的正式采用

复杂任务继续采用视频所观察的表面层次与安静等待：应用画布承载对象背景，当前处理使用共用表面，与菜单、弹层的抬升层分开。构图按业务归属分配宽度，不将所有阶段画成并列卡片。尼尔森原则中的状态可见、识别而非回忆、用户控制、预防错误及错误恢复，分别落实为采集阶段、准确对象、返回原任务、失效快照门禁和原操作查询；它们用于检查行为与信息组织，不作为颜色数值来源。

用户选定亮B「暖纸蓝」和暗A「石墨蓝」后，角色进入正式tokens和壳层，业务CSS通过同一字重与表面角色消费。浅色导航与正文保持可感知的明度差，暗色由导航到任务、浮层逐层提高明度。字重校准按真实可变字体实施，不把参考视频的观察数值当成Claude官方规范。

独立样张的原生select没有复用正式Choice，是审阅所见控件脱离规范的直接原因。正式产品沿用Ant Design 5.29.3的[Select机制](https://5x.ant.design/components/select/)，以数值形式的popupMatchSelectWidth分别安排短触发器与候选菜单，保留既有popupParent、失效值、搜索与键盘契约。本次问题来自本地呈现与配置，不新增上游补丁。实际内容宽度检查同时覆盖表单、历史查询、方案选择和开发工具，不能仅检查某个当前显示值。

首屏与失败状态、真实浮层和操作后的焦点分别验证；正式源码、运行画面及用户采纳分别核对。本地临时视频、截图与审查记录已按用户清理授权删除，本页维护继续有效的设计依据及其实现要求。
