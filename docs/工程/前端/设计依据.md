# 前端设计依据

界鉴以自身已确认的主题、MiSans、控件和动效为基线。产品组织主要研究 Linear，Apple 用于校准分组、留白与动态连续性。具体页面先服从真实任务和业务边界；来源提供选择依据，不替代实现和运行验证。

## 参考的职责与优先顺序

[Linear 的整体界面整理](https://linear.app/now/behind-the-latest-design-refresh)用于判断任务重心、辅助导航、视觉重量和边界。深入比较同一产品的集合浏览、详情、编辑及其空、等待、失败状态，避免分别摘取不同产品的单个组件。[项目工作面](https://linear.app/docs/projects)、[视图与预览](https://linear.app/docs/custom-views)和[显示选项](https://linear.app/docs/display-options)用于理解对象、集合、属性和定位工具的分工。界鉴采用这些关系，不复制其品牌配色、信息密度或产品功能。

[Apple 布局指导](https://developer.apple.com/design/human-interface-guidelines/layout)用于按重要性和自然阅读顺序安排信息，利用对齐、空间和容器表达关联。[反馈指导](https://developer.apple.com/design/human-interface-guidelines/feedback)用于让状态变化和动作后果可辨。平台尺寸、原生控件与材质不直接转为 Web 硬规则；界鉴继续沿用自身画布、输入面与浮层角色。

已采纳的规则进入共用实现后，由实际任务和使用效果持续校准。新的外观建议先检查能否由既有组合表达；确需例外时说明任务差异和影响范围。技术文档、领域产品及无障碍标准用于核对具体行为，不参与每页的品牌外观选择。

## 如何转为具体界面

| 任务 | 采用的组织与取舍 |
| --- | --- |
| 继续工作 | 当前任务优先，历史提供接续；不重复全局资料入口和状态统计。自然结束后的空白可以保留。 |
| 持续选择对象 | 目录与准确详情相邻，关闭后回原选择；没有选择价值时直接读内容。目录与比较表保留不同职责。 |
| 跨项比较 | 表外分类标题、共同列和逐行内容建立层级；复杂编辑或长解释在对应项下展开或独立阅读。 |
| 编辑和授权 | 按决定依赖分组，必要后果直接说明；草稿、保存、采用、执行和授权各有真实动作。 |
| 理解检查结果 | 先结论和范围，再解释边界与观察；技术过程按需深入，说明不为填补空位搬到窄侧栏。 |
| 处理待办 | 用对象摘要、时间和原入口区分事项；不将多份提案变成一排同名按钮或多条同质通知。 |
| 等待和恢复 | 保留页面身份与原对象，骨架不生成假状态；未知写入查询原动作，失败保留输入和回程。 |
| 完成并继续 | 说明及操作在所属任务末尾收口，次要命令在前，主要推进在后；不增加重复的完成卡或导航层。 |

共同语言由标题组、对象与状态、目录详情、内容表、字段组、反馈、操作收口维护。页面保留业务组合的自由：长表单、长证据、短确认、后台执行和持续选择不会套成相同列数或固定阶段。

## 动态连续性

[Apple 弹簧动画](https://developer.apple.com/videos/play/wwdc2023/10158/)用于理解改向时的位置和速度连续性；采用界鉴已确认的运动参数及共享实现，不以 CSS 缓动冒充物理弹簧。内容选择、展开、布局补位、真实活动及重要完成按对象关系编排，父区域运动时扣除重复的子入场。

日常反馈立即接受输入，重要完成呈现结果与下一步的连续交接；轮询相同事实保持静止。减少动态效果继续呈现完整状态和操作。动效不决定就绪、执行成功或权限结论，也不通过等待动画拖延实际请求。具体参数和验证归[交互与动效](交互与动效.md)。

## 技术与领域依据的边界

- [WAI-ARIA 模式](https://www.w3.org/WAI/ARIA/apg/patterns/)用于页签、菜单、对话框、组合框及焦点契约；[WCAG](https://www.w3.org/WAI/WCAG22/Understanding/)用于适用的可访问性核对。
- [Ant Design Select](https://ant.design/components/select/)用于已采用控件的行为和浮层适配，不引入其默认主题；[MDN](https://developer.mozilla.org/en-US/docs/Web/CSS)用于浏览器能力、布局和渐进增强。
- 认证复用、接口导入、业务证明、运行加载、Agent 执行、外部工单和工作区维护分别由对应[能力规范](../../llms.txt)拥有。领域产品的做法可以帮助理解任务，不能改变界鉴的独立授权、秘密边界和确定性验证。

历史曾使用其他设计系统核对单项机制。仍成立的任务与行为要求保留在实际所有者中；本文件不再将它们并列为页面外观的备选体系。

## 设计与完成的核对

逐页先明确当前对象、必要判断、产物及回程，再决定保留、删除或重组。整页审阅与组件状态检查一起完成，检查父子边界、间距和动态叠加；同一种组合要回查全部使用位置，并记录合理例外。

完整任务从入口走到结果，再核对返回、准确修订、草稿重开和中断恢复。静态覆盖、浏览器实际运行和用户视觉审阅分别记录；源码搜索、构建或测试计数不代替整页设计判断。
