# 布局与视觉

全量空间复核同时检查普通入口和过程状态：标题与状态、说明与选项、推进与辅助依据应有明确归属；组内距离小于组间距离。短任务使用自然高度与区域末尾操作，长事实按阅读宽度排列，不靠固定高度或无关说明补空白。分栏须在内容所占工作面内仍可阅读，空间不足时按同一顺序换行；内容表与局部索引保留各自结构。

界鉴围绕持续维护的应用、权限要求、测试场景和检查事实组织工作。主内容应先回答“当前对象是什么、需要看什么、可以做什么”。本文维护通用视觉与审查判据，具体组织归[工作面模式](工作面模式.md)，控件行为和节奏归[交互与动效](交互与动效.md)，实现所有权归[实现](实现.md)。

## 基础统一与布局重建

基础设计的目标是统一，布局与信息组织围绕真实任务建立主次。保留MiSans、应用导航及已成立的业务结构；亮暗主题分别建立可感知的表面层次，组件、字号、字重、曲率尺度、密度和反馈由共同规则维护。全前端设计按当前授权推进，主题配色由用户从完整工作面候选中选择；页面不得各自增加一套主题。局部意见仍按其实际对象处理。

## 统一设计语言的执行

设计语言是一套全产品共用、可执行和可检查的风格规范，覆盖视觉基础、信息组合、布局、控件语义和反馈。每个新工作面先确定当前对象、必须理解的事实、用户决定及完成去向，再选择共同模式；“柔和、专业、有层次”等气质描述不能单独作为验收条件。

| 需要作出的决定 | 规范所有者与检查方法 |
| --- | --- |
| 颜色、排版、表面与留白 | 本文维护基础角色和空间关系；核对真实主题与内容，不按页面另定基础参数。 |
| 动作的含义、层级与方向提示 | [交互与动效](交互与动效.md#动作语义与图标)维护选择、展开、命令和导航的表达。 |
| 同类任务使用什么结构 | [工作面模式](工作面模式.md)维护目录详情、材料准备、比较、编辑及证据阅读。 |
| 共同规则由谁实现 | [实现](实现.md#共同模式的实现所有权)维护共享控件、组合模式与页面的职责。 |
| 采用什么成熟机制及为何采用 | [设计依据](设计依据.md#组合规范的参考与取舍)维护来源、适配理由与代价。 |

检查到每一个阅读单元：名称、短状态与必要说明构成对象组；动作按所属任务收口。区域主要推进位于本区域右下，次要动作在前；记录的核对或编辑在记录末端，局部展开与被展开内容相邻。区域末端按内容自然结束，不以固定大高度将正文与操作拉开。同屏有对象详情时，详情推进承担当前重心，集合级推进避免与其重复强调。

成组以语义和阅读距离判断：短状态紧随所属名称，操作可以独立在记录末端；内容表的独立状态列用于跨项比较。复核父容器伸展列是否拆散了原本相关的信息，不能只检查页面总宽和是否溢出。相关信息就近后再决定行高、分区距离及可用宽度，保留仍有作用的留白。

间距按嵌套关系检查：标签与值、同一对象的事实、独立阅读组分别拥有不同距离。标题到所属内容的距离应小于到上一组的距离；同一对象的操作和归属不能被较大空白拆散，历史时间也不能因邻近而被误读为执行核对的一部分。先按内容组成阅读组，再校准组内与组间的节奏；不能给所有字段统一增加外边距，或用新增分隔线代替分组。宽窄窗口都以实际外沿核对，样式中存在gap不足以通过验收。

每次交付同时给出代表画面和规则核对：指出当前对象、主动作、局部动作、状态归属及采用模式；记录需要业务例外的原因。用户审阅聚焦新增的设计取舍，整页和同类消费者的规则执行由实现者先完成。构建、截图、组件测试和用户视觉采纳分别记录，未采纳的样张布局不直接升级为全产品定式。

粗看也应能识别归属：同一对象的标题、状态、事实与命令保持邻近，必要时用完整对象组的边界或内缩区分，不能只依靠仔细逐字阅读。数据行的展开区继续从属于原记录，使用连续位置线、所属对象名称及较轻的子标题，不因跨列展开而获得集合级标题重量。各区域自然结束，不能靠固定等高填满短内容。

任务收口突出当前最重要且可执行的推进，放在最右；状态留在对象或事实附近，编辑与重新核验回到各自管理位置。不能只把主按钮染色，却把它排在多个普通操作左侧；也不能把状态、日常管理和下一步全部堆进右下角。

## 框架与层级

侧栏是应用导航，顶栏是位置与全局工具，正文直接展开当前任务。沿用工作台框架和壳层尺寸；导航、正文画布、独立任务表面与浮层分别拥有背景。两套主题下都能直接辨认侧栏和当前任务，不能仅靠选中项或分隔线区分。顶栏从属于正文画布，不增加独立的强调色带。

浅色主题以低彩度的导航、较亮正文和接近白色的任务及浮层建立层次；深色主题按导航、正文、任务、浮层逐层变亮。四种角色不要求每处都绘制四层，普通段落继续沿正文阅读，只有独立对象与决定才需要围合。整窗共用渐变不再作为基础约束，表面差异由语义角色稳定表达；必要的细边缘作补充。

蓝色等主题强调色服务动作、链接与选择，普通环境表面保持克制。导航选择、分类指示和当前对象按层级分配强调强度；实际结果仍以独立的状态文字、图形与成对语义表面呈现。浮层采用不透明背景和适量层级阴影，避免透出下方的选中与错误颜色。

侧栏沿用既有入口：工作台、权限与覆盖、测试、问题；分隔后的应用与来源管理资料，Agent 协作在其下方独立同级。Agent 使用明确文字和对话图标，当前任务状态属于该入口，不做独立宣传卡。应用切换菜单集中选择、新建和官方示例。设置固定在侧栏左下角，以齿轮和“设置”文字共同呈现，对齐其他导航的图标及文字轴，保留可访问名称和键盘焦点，直接进入独立设置页。顶栏保留上下文、刷新、主题及最右侧退出；设置分类在页内选择。

既有框架使用 224px 侧栏、68px 桌面顶栏及原阅读宽度。布局重建不另行缩改这些基础尺寸。它们服务于本产品的密度，不是通用设计定律；窄窗按内容重排。固定导航的图标与名称分列，名称使用一致的文字中心线；两字中文适当增加字距。此规则不用于正文、动态名称或全部按钮。

标题、对象、状态、辅助说明分配不同视觉重量。页面只有一个主标题；业务对象标题次之，分组标题再次。辅助栏不重复主标题或完整规则。页签属于当前位置，不形成卡片中的第二套主导航。普通页签不播放整页转场。

字体使用真实可用字重，根层关闭浏览器伪粗与伪斜；MiSans的可变字重和既有深色校准由原字体所有者维护。频繁变化的执行数量、进度与预算采用等宽数字，避免轮询时横向抖动；业务正文不机械改成等宽排版。

标题的 HTML 层级与视觉角色独立。可维护集合使用统一的20px/28px/600组合，紧凑分组使用16px/24px/600，辅助分类使用13px/20px/500；语义上从属于业务操作的“业务结果”仍使用集合外观。页面不因 h2/h3 标签不同而另定同类字号，也不将所有 h3 机械放大。字体组合由共享标题预设负责，业务样式只安排空间、位置和适用颜色。

工作台当前任务承担主要阅读重心，使用24–28px、1.5行高和500字重，区别于普通集合标题。任务周围保留自然留白，概况与近期对象退后；不靠加重所有标题或给每个分组铺底色建立层级。

## 表面与颜色

当前采用用户确认的亮B「暖纸蓝」与暗A「石墨蓝」。固定导航、正文画布、任务表面和浮层分别消费 `--navigation-bg`、`--bg`、`--surface` 与 `--surface-elevated`；两主题都须在真实工作面上辨明侧栏与主区。配色选择记录和运行审阅归本轮交付，业务页不保存候选配色或另外铺整窗渐变。

圆角半径与转角曲线分别维护。共享形状层在浏览器支持时对产品控件、表面及 Portal 浮层采用 `superellipse(1.5)`，作为直边平滑进入转角的 Web 近似；普通控件采用约10–12px、菜单16px、对话框20px半径；默认高度44px，紧凑工作区36px，同组等高，颜色由共享语义角色维护。悬停遮罩与宿主使用相同曲线，单选圆点、编号圆与活动点保持圆形，局部连续索引仍为直角选择带。不支持时自然回退普通圆角，不增加 SVG 裁剪或运行时重绘。等距内外轮廓按真实内缩协调，不能将任意子控件机械改成同心形状。

浅色画布低彩度，任务与输入表面接近白色；深色画布与内容面按职责逐层提高明度。普通表面不承担强调，标签比标题更轻，输入保留独立可辨的中性边界。具体主题色从完整亮暗候选中选择，颜色由共享语义角色统一调整，业务样式不另建色板。MiSans保持不变，字号、字重、圆角、控件尺寸和动效按共同体系统一。

画布、内容面、输入面和浮层分别持有背景角色；深色浮层相对内容面提高明度，普通表面减少饱和度。主要动作、链接和选中各有前景角色，选中面的正文和辅助文字使用对应前景；不能只改底色后继续使用原灰字。普通悬停使用中性浅层，持续选中使用主题对应的低彩度选择面及位置标记；选中项悬停使用同色系的明暗变化，保持原位置线。

同一任务中的层次优先通过语义表面、排版与组间留白建立，分隔线只标明真实边界。不因参考质感细节就全局细化输入边界，滚动边缘渐隐仅适用于确有溢出的辅助区域，不能遮挡业务事实或必需操作。

完整颜色角色由 `tokens.css` 唯一维护：主、次、轻量按钮分别消费动作、普通表面及链接色；悬停与按下分别取对应角色。信息使用雾蓝，成功使用灰绿，警告使用灰金，错误使用灰玫瑰，中性等待使用灰蓝。角色、来源和 Agent 身份不额外分配彩虹色；允许、禁止与实际核验结果继续分开表达。

输入边界与装饰分隔线分别校准。正文、辅助文字、占位、禁用文字有独立角色，禁用控件不用整体透明度同时冲淡文字和底色；禁用按钮、输入、选择器和候选均沿用同一颜色职责。菜单、对话框和提示共用浮层角色，组件库按亮暗算法与同一组语义颜色映射，不另派生一套主题。

连续目录使用表格或相接的行；编辑任务、需要独立确认的范围可以围合。固定工作面默认无悬浮阴影，菜单和对话框保留真实层级。不能将每段文字、每条说明都包成相同权重的框。已有留白或表面差异足以表达分组时，减少重复线条。

连续目录、索引与普通配置表单沿用画布，不默认铺满辅助蓝底。选中、输入、语义通知和独立证据面保留各自表面；移除冗余底色不改变主题令牌。目录外层与内部表格只由一处承担边界，页签下分界也只有一个所有者，避免外框套表格、页签下双线。空态和读取失败不再叠加无意义外卡。

选中使用持续的主题选择表面与位置标记；深色主题使用相对明亮的对应表面。悬停仅反馈指针所在对象，不能替代或遮盖选中。键盘焦点独立可辨，禁用与未选中不同。普通辅助底色不能冒充选中底色，状态色不能只靠颜色表达。

左侧局部索引以检查准备的材料目录为样式基准，使用连续行、主题整行选择和左侧位置线，普通行不单独铺底。行高可随内容增长，图标、名称、短状态和方向各有轨道；不按页面重新发明圆角、背景、悬停或选择动画。该规则限定同类局部入口，不将全局侧栏、页签、表单选择和多选框混成一种控件。

有表头、按列比较的内容表，与左侧选择条目、右侧编辑或阅读的局部索引分别维护布局。内容表保留表头列定义、单元格内边距及表格与详情的现有留白；局部索引的整行点击区和选择面延伸到相邻详情的分隔线，文字留白由条目内部承担，不预留空的滚动条槽或额外右侧间隔。真实滚动条和独立证据卡片保留各自空间。两类只共享主题、选择反馈与动效，不互套宽度、列或排列规则。

## 选中与状态的颜色职责

提示表面的状态色与正文前景分别负责。错误、警告、成功和信息提示保留各自低彩度底色，原因、说明、诊断入口与编号使用中性文字角色；读取恢复也不画成危险命令。状态徽标、字段错误和确有破坏后果的命令继续使用原语义前景，不能因提示正文中性而一起取消。亮色使用主文字深色，暗色使用对应浅色，不把“黑色”固化为跨主题色值。

错误的必要标记不能只靠淡底色表达。整页失败采用实色错误标记与成对前景，行内错误以语义边缘标明所属原因；正文、诊断和恢复仍保持可读的中性文字。按实际计算色核对文字至少4.5:1、必要图形与相邻背景至少3:1，并查看原始尺寸截图，避免细线虽达阈值却难以辨认。基础主题不随单个异常页改色。

导航选中、键盘焦点和业务状态分别表达，不在一条短导航中叠加多个强色。全局协作入口的状态作为次要文字：未选中使用辅助文字色，选中沿用选中前景；状态名称保留，不用黄色强调普通待回复。局部连续索引上的短状态文字同样继承选中前景，避免红、绿、黄文字直接铺在浅蓝选中底上；确需保留的结果图标或独立状态徽标继续使用自身形状与成对语义表面。

普通说明和正常待准备默认中性，正常进行与等待业务回复使用信息强调，取得对应结果使用成功色；需防止误操作、未知回执、读取异常和准备条件失效才使用警告，实际失败与错误使用错误色。任务进展不等同权限结论，规则中的允许、禁止和预期结果使用中性文字与明确符号；角色类别和步骤记录的授权决定也不使用成功或失败色。红绿结果色留给实际执行状态与核验结果。不能为了减少彩色而隐藏未知、安全边界或真实失败。

徽标、状态标记和危险命令的语义文字与所属背景成对使用，普通小字按至少4.5:1核对；关键图形和焦点另按适用要求检查。两套主题分别核对，包含真实渐变、悬停、选中和禁用背景。第三方组件的错误、警告、成功、信息色及危险菜单反馈由公共适配接入同一组令牌，不沿用另一套默认色。新的页面布局继续引用已采纳的颜色角色，不随页面调整底色。

## 空间、阅读与对齐

排版是注意力分配。页面标题使用28px，当前任务的关键问题或下一步使用共享任务重点字级24px/32px，窄窗22px；集合标题20px、分组16px、对象15px、正文14px、标签13px、追溯12px保持原角色。同屏避免多处同时使用任务重点字级；解释正文不能因放进通知而自动降为追溯小字。真实代码、技术引用与次要时间仍用元信息字级。浮层通过UIProvider读取同一套角色，不维护独立固定字号。

结构标记承担实际信息：执行步骤与时间顺序可以编号，平级业务要求目录不编号。主体验可突出当前要核对的业务问题，原要求和实现变化就近说明；不要把所有信息都做成同权重标题、相同圆角卡或同色通知。已有主题、字重与有效构图保留，通过真实内容判断例外。

内容决定宽度和高度。短表单使用适合阅读的字段宽度，目录与证据比较使用可用宽度；相关信息之间不能因容器铺满而被拉到远端。内容结束后的页面留白可以保留，禁止用装饰、虚构状态或最小高度填满。左右区域按阅读任务分配，默认顶部对齐，各自自然结束。

记录中的时间、执行结论、名称等独立字段使用约20px横向间隔，行内上下各约18px，标题到首项约16px；名称与所属短状态继续保持紧密关系。边框表格的外沿内缩独立于紧凑单元格密度，桌面与所属面板的24px阅读边线对齐，窄窗再降至16px。不同历史工作面各自拥有布局类名，不能通过加载顺序改变另一页的首行和间距。

同组距离小于分区距离。局部标题到首项通常 12–16px，标签与值约 6px，名称与短状态 8–12px，独立分区约 20–28px。按真实长文字和窗口校准，避免父级 gap、标题 margin 和内边距叠加。

返回导航与紧随的标题组之间统一保留24px，从返回控件组的外沿量到标题组外沿；有眉题时眉题属于该标题组。共享`jj-back-link`持有这项距离，普通独立容器也直接得到该规则。父容器已有行距时，只由该布局所有者声明已占用的距离，共享规则扣除后仍得到相同净间距。不得在材料、源码等页面另写一份返回间距，也不把24px与父级gap重复相加。检查包括普通入口、聚焦任务、加载/失败和窄窗，不只看`TaskSurface`。

已有条目与“添加动作、添加步骤”等追加操作属于不同分组，使用共享 `IndexActions` 保留约 24px 的组间留白，追加操作图标和条目图标沿同一轴线排列。索引行保留足够的垂直内边距，编号、名称和方向之间各自留出空间，长名称自然增高。该规则同步到场景、接口流程、材料、结果和协作的同类索引；数据表、徽标和标签内的紧密关系继续按内容校准，不能把全部小间距机械改成分区间距。

有边界的内容在四边保留完整内边距；桌面工作面通常采用24px，窄窗按内容降至16–20px。目录列与相邻详情分别保留阅读内边距，方法、名称与路径使用同一列轨道，按 DELETE、OPTIONS 等最长方法校准。同层导航的选择带左右采用相同内缩，不能一侧贴边、一侧留空。

悬停或选中后才出现的底色也属于有边界的表面。整块统计与整行入口保留完整四边内边距，不能继承纯文字按钮的零内边距；用网格排列时同时核对内容轨道是否被共享按钮的居中规则收窄。图标按钮以固定热区居中，表格入口按单元格已有内边距核对，不机械叠加第二份留白。

名称、图标和状态共用整行对齐：徽标按中心，纯文字数量按共同基线。标题不携带单侧段落间距，不用固定偏移补偿旧布局。表头与正文共用列定义和内边距；文字列对齐起点、短状态列对齐中心、数值与操作列对齐右边界。长文字允许换行，路径和编号不撑破容器。

状态先归属对象。单对象的短状态紧接名称，可比较目录保留共享状态列；说明留在名称下面。主操作在任务收口，短行内操作就近。不能把全部状态推到最右，也不能将所有内容堆在左侧。窄属性单元优先标签在上、值在下，避免再嵌固定宽键值列。

检查记录摘要以执行结论作为阅读起点，将“符合规则／不符合规则／证据不足”放在检查名称前。它与名称右侧的就绪、连接或保存状态承担不同职责；内容表仍通过独立结果列支持纵向比较，不跟随摘要行改变列顺序。

主推进按钮位于所属任务区域右下角；直接说明和下一步放在同一操作组，不能把说明留在整行远端。整批进度可以独立置于左侧。报告状态图标与标题本行对齐，辅助标题和元数据沿标题文字起点排列。

## 通用审查规则

截图反馈应先还原为任务和关系，再检查同根因的全部消费者。每条规则只有一个事实所有者，不为一次截图或实施批次另写一套规范。

| 检查对象 | 判据 |
| --- | --- |
| 重复入口 | 同对象、同目的地、同一上下文保留一处正文动作。全局导航、准确对象深链接和回程入口各有职责，不按 URL 相同机械删除。空状态承担创建动作时，标题不重复提供同义动作。 |
| 说明与术语 | 使用对象和动作解释当前后果。源码关联、部署版本、地址连通、身份有效、材料就绪、执行结束和权限结论分别表达。避免没有实际任务的“当前业务动作”及装饰流程图。 |
| 核心能力 | Agent 等高价值入口保留名称和真实状态，图标与悬停提示不能独自说明能力。实例和示例归应用切换及明确管理工作面。 |
| 控件一致性 | 同类按钮、选择器、状态、页签、菜单与浮层复用共享实现。业务层只改尺寸、密度和排列，不重写选中色或争夺优先级。 |
| 内外边界 | 文字、选中表面、图标和箭头均有内边距；通知与表格、表单和卡片之间保留独立间距。检查全部四边，不只看是否出现整页横向滚动。 |
| 空白与平衡 | 先调整信息分组、目录和详情比例，再决定宽度；不靠统一缩窄、左右拉开或添加装饰遮盖缺少内容关系的问题。 |
| 标题与嵌套 | 主标题、局部分类和当前对象各承担一个层级。两个独立任务使用并列工作区，避免多层侧栏、卡片、页签套叠。 |
| 对象与创建入口 | 标题命名本区域的对象，创建入口与该对象同组；总任务标题不承接其中一个子集合的新增操作。例如“业务操作—添加操作”“业务结果—添加结果”。子对象保留所属对象的上下文，多条记录下不能串改其他对象。目录追加与空态创建按状态互斥。 |
| 初始、空与失败 | 初始状态说明可以开始的真实任务；筛选空态可恢复。读取失败保留标题、对象、原因及重试，不能让页面退化为孤立横幅，也不能显示默认成功。 |
| 动效 | 选择标记连续移动，局部内容有接续，展开锚点稳定；保留已认可节奏和减少动效支持。等待用户决定不持续旋转，动画不延迟事实或拦截操作。 |
| 证据 | 静态扫描、组件行为、真实浏览器和用户观感分别记录。全路由截图不等于全部业务分支验证，构建通过不等于视觉采纳。 |

审阅覆盖两主题、正常与空/失败、长名称、各类状态、键盘焦点以及代表窄窗口。完整页面用于判断整体层级，局部截图用于核对边界；不得只修用户圈出的几个像素。交付用户审阅时只选本次修改的重点工作面和关键状态，避免重复提供大量全量截图；检查范围与截图数量分别记录。

已有页面标题或分类边界时，空态沿当前内容轴开始；首次创建、正常无待办、筛选无结果和读取失败分别表达。只有需要解释的状态才补说明，不重复正文用途。首次连接直接填写必要字段，部署说明和请求限制按需展开；保存、采用和实际核验分别保留。

对齐核对到可见文字和图标，不能只比较外层盒子。版本、状态和折叠入口共用首行高度，展开正文向下延伸，不参与首行居中。相邻分类同时核对父标题、页签和正文起点，避免各页单独居中造成跳转偏移。

视觉收口同时核对内容取舍：当前对象是否明确、同一事实是否重复、短事实是否被固定分列摊空、主要动作是否就近收口。设计稿本身也按这些判据复核；组件复用、测试通过和没有溢出不能替代这一步。


## 完整组件体系

排版统一使用角色：页面标题28/36/600、集合标题20/28/600、分组标题16/24/600、对象名称15/22/500、阅读正文15/24/400、控件与列表正文14/22/400–500、字段标签13/20/500、元信息12/18/400。字号、行高、字重依次列出；同一对象的选中前后尺寸与字重稳定。标题层级不倒置，真实分组名称不能当成小字元信息。代码和路径用等宽字体，数字计数采用等宽数字。

上述字重是浅色基准。深色主题通过共同角色作光学减重，正文、对象/标签、标题分别以380、480、560作为校准起点，保持真实可变字重；实际中文细笔画、英数和回退字体共同核对后调整。业务样式不得写死500/600来绕过主题角色。决定当前任务的事实和解释使用正文角色，12px元信息留给低频引用、时间和辅助编号。

字色按内容角色设置：任务与对象标题、关键事实使用正文主色；字段标签、修订和辅助说明使用辅助色；链接与选中对象保留交互色。混合标题、事实和说明的父容器不统一设灰。验收同时读取实际字色和查看截图，区分有意的辅助标签与意外继承，不能靠全局覆盖所有标题修正局部问题。

工作面拥有当前任务的命名；嵌入组件提供内容，不重复声明同一任务。已命名集合的空态、进度计数和缺口摘要属于集合内容，独立开始任务与读取失败仍保留必要标题。重新归组时保留完整解释、数量、清单和原入口，不用新增折叠或隐藏重要材料替代组织工作。

组件默认44px舒适高度，紧凑工具区36px；同组控件等高，主次通过样式区分。字段标签、输入、说明成组，相关字段之间24px左右、章节32px左右；窄窗允许内容驱动重排。输入、选择器和按钮的基线一致，连续目录不改成相互悬浮卡片。普通控件10–12px、菜单16px、对话框20px连续曲率，圆点保持正圆。

组件状态分别核对默认、悬浮、按下、焦点、选中、展开、忙碌、只读、禁用、错误和恢复；每种控件只采用自身适用状态。Field统一标签、说明、错误关联和输入尺寸，不改变业务提交或安全判断。组件库映射与原生控件共用角色，页面仅拥有任务、数据、内容和密度选择。

空间分配先检查任务边界：两项配置服务于同一对象且各自较短时，可在同一概览并列；目录与实际正文需要反复往返时，可用列表与相邻详情；两项数据用于逐条比较时保留内容表。长配置、长证据和跨轮比较按需深入或整行展开。分栏必须承载实际内容，不用通用说明、固定最小高度或重复入口填空；不因页面结束有留白就拼入无关模块。窄窗顺序阅读，目录详情一次只显示当前层级，保留返回与选择。

目录分栏随集合规模调整：只有一个对象时直接展示内容与相关准备，不保留无选择价值的半页目录；多个对象时使用目录与当前实际内容。多项变体逐项阅读，大集合说明按需展开，不把全部长正文堆进右栏。


## 独立任务的内容轴与阅读比例

同一任务链中的材料阅读、流程核对和执行确认，共用任务外层规定的内容轴；返回、标题、正文与末尾命令沿该轴接续。宽度由任务外层决定，内部概览不再次限制另一套整页宽度。隐藏的编辑器、旧录制或后台任务不能通过祖先 `:has()` 改变当前画面的宽度。目录、比较表和证据等宽内容按任务保留宽面，不把全部产品强制居中或统一成同一宽度。

章节优先用标题和组间距离区分。分隔线表示明确边界：不同记录的比较、独立提交区域或目录与正文；标题说明与其第一组内容之间不加无条件顶线。相邻组合已有边界时，下一个组合不重复绘线。

审阅以可读正文为默认，保持原始字号或接近原始字号，长内容在图像阅读区域内滚动；整页缩略图只用于概览。对比使用同一倍率，提供原图入口及完整页面，不能把长图完整塞进固定高度导致正文缩成小字。交付时实测呈现倍率，并在真实视口检查，不只核对源 PNG 尺寸。

## 阅读组的宽度与短值列

限宽且居中的阅读组要同时给出可用宽度与最大宽度。位于 flex 或 grid 子项时，仅设置 `max-width` 与自动外边距会使内容按固有宽度收缩；须实际检查标题、正文和操作的共同轴，不能以整页没有横向溢出代替宽度核对。工作台、证明阅读、当前协作事项与运行诊断按各自任务设定阅读宽度，不要求所有页面同宽。

内容表的对象主列保持连续阅读；其余比较字段与各自表头共用水平中心轴，多行适用条件也遵循同一轴，表体垂直居中。原始结构、长请求及JSON前后文本采用明确的阅读型表格，保留段落阅读对齐；窄窗转为逐条记录后按记录组织。短枚举列使用共同的 `jj-table-state`：表头与对应单元格共享水平中心，表体垂直居中。列内选择器的控件本体与所选文字分别居中，箭头保留自己的右侧位置。单元格中的弹性布局、网格或自带宽度的子容器也须按所属列对齐；验收核对真实内容的边界与中心，不能只读取单元格的 `text-align`。长正文、路径、比较内容维持阅读所需的对齐；名称旁状态组继续紧随名称，不改成独立状态列。首末单元格保留24px左右的呼吸空间。

窄窗压缩表格时保留决定所需的事实。权限要求仍可在行内调整时，适用条件须移入该行摘要或保持可见；也可以改为进入完整编辑后作决定。不能隐藏条件列后保留脱离条件的允许/禁止选择器。历史时间等辅助字段与决定性条件分别处理，不按相同的隐藏列规则批量省略。

复杂场景编辑沿用完整任务内容轴，实验切换、步骤目录和当前准备项各有稳定分组。窄窗先显示实验，再显示其编辑工具；批量资源转为逐项阅读，账号、归属与预期均直接可见。页面不能仅以没有横向滚动为验收标准，还要核对表格内部关键字段是否完整，避免局部容器裁掉事实。

## 字段的阅读宽度

输入和选择的宽度表达预期内容长度，并服从所属表单组的共同轴。相同角色、同一纵向组采用相同档位；数字、名称、地址和长说明按真实内容分别处理，不随父容器默认铺满。当前共享Field提供短枚举96px、短输入160px、中等枚举240px、标准400px、长值640px五档，均以实际可用空间为上限。允许／禁止这类两字枚举采用96px紧凑档，表内与详情中的同类控件一致；交付方式等较长固定候选采用240px，不因选项数量少而缩窄长名称选择。选择前核对全部候选，切换不改变控件宽度，控件与选项浮层一起校验。多行说明使用textarea；长URL、路径及协议正文保留适合阅读的长档或专用编辑区。

同组操作准备项和资源来源选择沿用共同宽度，不能一个由整列拉伸、另一个由半列限制。目录筛选与记录表内紧凑编辑按其局部任务组织；需要比较的对应字段保持相同宽度。分组、列宽和控件宽度分别有所有者，页面不能用宽度覆盖重新引入差异。迁移时同时核对真实短值、长值、提示、状态与窄窗；所有正式表单显式采用适合内容的档位，并排查页面私有宽度与共享尺寸的竞争。

## 当前结论与历史时间

业务结果的识别特征来自“要求、实际后果、正式判断”的稳定对应。三个角色使用同一字阶、语义状态和阅读方向，宽区按内容重量分配，窄区按要求到后果再到判断阅读；不通过装饰插画、额外指标或预设绿色结果表达创新。当前操作与具名对象优先，技术过程和历史时间按自身用途退后。

中等宽度的结果组可将要求放左侧，将实际后果与判断在右侧上下相接；判断继续从属于当前观察。真正窄区再按顺序单列，不因略低于三列阈值就把整组长内容堆到左侧，也不为状态保留贯穿正文的空轨道。

当前状态和本次结果先展示业务结论、所属对象及下一步。时间用于区分历史先后、选择记录或判断有效期限时直接展示；当前连接、身份核对、单份报告和当前方案不默认附带时间。准确检查时间保留在记录依据或摘要中，历史列表与记录选择仍显示时间。去掉时间不改变事实的新鲜度：上次核验结果仍明确写“上次核验可达”，不改称实时可用。

标签、结论和原因采用明确字阶：轻量标签说明“这是什么”，主文字给具体业务结论，较轻正文解释原因。两句同样粗细、同样字号的抽象标题与具体值不能连续占用主层级；证明阅读复用对象标题的 caption、title 与 description。左右区域按任务和内容分配宽度，目录占较窄空间，当前编辑和依据占主体；空间合理由完整阅读与动作距离判断。
