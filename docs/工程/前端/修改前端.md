# 修改前端

> 状态：CURRENT。用于现有页面、布局、导航、异步反馈和 API DTO 修改。先读本页；按任务进入下表指向的章节，不加载整套设计历史。

## 快速找到修改位置

前端文件以 `product/frontend/src/` 为根；测试与组件共置。正式测试参数使用 `src/...`。

新接入由应用切换器或入口搜索进入`/application?new=1`，经`app/state/useNewApplication.ts`清空旧应用选择；活动官方示例按明确的新接入动作提交一次停止。停止未知或进行中只回读，确认退出后进入空白目录选择。继续既有应用仍使用普通`/application`上下文。不能把旧应用的权限审阅当成新应用第一步。

`features/checks/CheckProgressPanel.tsx`按服务端状态展示等待、准备、执行、发布，并允许回看已到达阶段；结果已发布后在同轮结果的“查看本轮检查过程”读取这些事实。提交时间、计划项数、已处理数和发布完整性各自对应已有字段；短阶段可能不被轮询捕获，不能补造逐阶段日志、耗时或安全结论。

## 修改与直接验证

1. 从具体组件及其测试定位；跨页问题再追 `ControlShell`、任务引用和后端 DTO。DTO 修改先核对实际模型、可选字段和错误码，在唯一 API 文件通过统一 request 调用，不保留已退役状态别名。
   每次视觉修改都先按同类元素盘点全部当前页面与状态：布局间距、配色、分隔、状态框、可点击内容、按钮、输入框和各级入口。追公共规则并搜索所有消费者，包含挂载到 body 的 Modal、Drawer 和菜单；修正同根因用法并回报覆盖范围，不只修改截图所在页面。按实际影响选择局部验证，不把横向排查等同于全量测试。页面级标题使用 EditorialHeader；PageTaskHeader 是同一骨架的兼容调用入口，不维护独立样式。
2. 按本次影响核对加载、空、未知、失败、陈旧响应及正常状态；纯样式重点包含选中、禁用、悬停等实际受影响状态。写后回读事实，不能重放写操作。
3. 行为变化运行直接相关的已有组件测试；纯文案或布局通常不新增单元测试，使用真实页面核对。新增回归须有已确认需求或真实故障作为判据。生产构建按指纹复用，不因修改测试内容主动强制重建。

```powershell
.\scripts\dev.ps1 frontend-test src/features/checks/CurrentTestsPage.test.tsx
.\scripts\dev.ps1 verify run --level L2 --ui references
```

命令均从仓库根运行。测试名称替换为实际受影响文件；不把仓库根路径传给 Vitest。测试核对实际点击后的页面与精确引用，不以快照代替行为。

按钮对齐、间距、颜色和局部文案等 UI 小改默认做最相关的 L1–L2 页面检查；只有行为受影响时补组件检查，按需核对主题与窄屏布局；不因此重跑全量回归或 `sample-test`。只有真实交互、生命周期或公共契约变化使原证据失效时，才按影响扩大范围。版本收尾已经通过的技术闭环，可以与后续纯布局修改的局部证据一起复用。

重要视觉变化需要展示验收；只有持续流程或真实运行边界受影响时增加唯一自动 L5 技术闭环。具体顺序依[验证规范](../验证.md#6-自动-l5-与展示验收)及当前任务约定执行。展示检查按影响选择 2560×1440、约 1280px 与 600px、亮暗主题、键盘/焦点、长内容、错误及终态；涉及应用切换、待办、重置和退出时再核对对应流程，不为展示清空用户数据。官方示例自动链见[示例指南](../../能力/应用接入/修改官方示例.md#默认自动验收)。

## 不能改变的语义

- `app` 负责应用壳和页面装配，`features`、`shared` 与 `api` 不反向导入应用壳。共同读取、可见性和编辑保护位于 `shared/runtime`；任务定位只转交后端引用，时间和状态名称只格式化已形成的事实。`RetainedWorkPages` 提供共享可见性上下文，页面不依赖它的容器实现。
- Workspace 是唯一主任务来源，Preparation 是准备事实来源，ResultStory / ProjectRepair 是结论与修复来源。前端不重算 ready、优先级或 Verdict。
- 证明来源页由 `features/preparation/proof-sources/useProofSources.ts` 管理读取、轮询和写回执，`proofSourceOperations.ts` 只保存原项目键下的操作身份；`ProofSourcesPanel` 保留选择、草稿与确认。未知写响应只查原回执，存储定位失败不提交；同类页面的不同操作合同继续各自维护。
- 项目、动作、变化、Run 和原题引用不能在跳转或材料返回时丢失；异步旧响应不得覆盖新对象。普通 PASS 不表示原题已修复。
- 权限只通过 Proposal 与 Human Approval；边界审阅不可原地编辑，返回修改产生新提案。账号或录制缺失不表示权限未确认。
- localStorage 仅存明确允许的轻量偏好；不存草稿、登录内容或秘密。Agent 连接凭据继续遵守受控引用和最小运行时注入边界。
- 自动更新不覆盖输入或抢走焦点；首次读取历史不冒充新完成通知。诊断入口使用后端结构化 route。
- 状态未知不能显示为零或成功；提示出现与消失均保持容器间距。当前交互细节以[交互与视觉](交互规则.md)对应章节为准。
- 官方 Sample 保持普通可访问按钮，不增加测试专用入口、隐藏控制接口或地址栏脚本旁路。

## 依赖与常见故障

依赖视图在 `var/development/frontend/workspace`，静态构建在 `var/runtime/frontend`。源码目录不生成 node_modules、dist、coverage 或 tsbuildinfo；不手写假的第三方类型声明。

编辑器出现 React/Ant/Vitest 类型红线时，核对受控工作区、工作区 TypeScript 插件与 `jiejian.code-workspace`；必要时运行 prepare 后重启 TS Server。解析探针使用 `features/history/CheckHistoryPage.tsx` 及对应测试。

- 没收集到测试：检查参数是否为 `src/...`。
- 页面完成而任务未推进：查服务端 Preparation / Workspace 与项目归属，不以本地 state 强行完成。
- 同页出现多个主操作：将普通操作收敛到 `TaskActionBar`，页头只留状态。
- 窄屏越界：查最小列宽、长 ID、弹层和嵌套容器，不用全局隐藏溢出掩盖。
- 来源管理的局部布局使用 `proof-` 类；证明要求与材料页使用 `evidence-material-` 类。不要让两种工作面重新共享同名局部选择器；共有外观取 shared。
- 结论与证据冲突：回查发布事实，停止在前端拼接判断。
