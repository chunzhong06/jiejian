# 视觉规范

> 状态：CURRENT。维护已接受的视觉规范；功能入口见[产品入口](../../总览/产品入口.md)。

## UI 设计与审阅方式

每次涉及界面设计或重构，先搜索并核验相关成熟产品与获奖作品的一手资料，再说明采用的原则、适用原因和不照搬的部分。获奖事实与界鉴自己的设计判断分开；不能用获奖名称代替具体设计依据。

现有导航、布局、组件和产品文案均可按用户目标重构，不因已经存在而默认保留。重要工作面先提供可操作原型，说明阅读顺序、视觉焦点、尺度、留白、状态和交互为何合适，并覆盖关键失败状态与窄屏。用户已有重构授权，不为普通可逆 UI 决策重复索取许可；原型审阅用于确认体验，不代表真实后端能力完成。

审阅图与原型保存在 `var/design/`，正式实现并经用户确认后清理已无用途的审阅物；不建立定时清理。设计方案与真实实现状态分别记录，原型不冒充产品运行证据。


## 专业工作面的设计依据

主要参考 [Linear 2026 年界面更新](https://linear.app/changelog/2026-03-12-ui-refresh)的一致页头、导航和视图控制，以及 [Sentry 2025 年 Trace Waterfall 改进](https://sentry.io/changelog/trace-waterfall-view-improvements/)中所选对象与对应详情的关联。前者用于减少跨模块切换成本，后者用于让检查事实与证据处于同一阅读工作面。它们支持具体取舍，不代表业界统一偏好或界鉴已经达到同等品质。

获奖案例作为可用性和表现力的补充参照，例如 [Apple Design Awards 2025](https://developer.apple.com/design/awards/2025/) 中 Play 对专业工具复杂度的处理。早期获奖作品只能说明当时的评审，不用作当前趋势的证据；也不把展示站的滚动特效、3D 或玻璃效果移入高频审阅流程。

界鉴的核心视觉关系是“已确认要求 → 接口回应与真实后果 → 本项判断 → 对应证据”。工作台同行比较，窄屏按单项纵向阅读；结果页默认展示整轮结论与全部检查项的分页总览；进入单项后，必要证明直接可见，辅助阶段记录归入证据记录视图。颜色只辅助状态，文字始终说明结果和适用范围。修改与验证页默认展示最近修改，点击后阅读修改内容、检查结果、沿用要求和源码对应；材料入口携带原修改，完成后仍回到同一记录。


## 视觉、布局与响应式约束

全站采用“雾蓝 · 石墨”配色，目标是雅致、从容，略带科技感。灰白或石墨表面承载内容，低饱和雾蓝指向操作；科技感来自细线、准确对齐与证据排版，不增加霓虹装饰。亮暗主题分别定义页面、工作面、辅助区域和浮层，浮层在暗色下适当抬亮；所有具体色值、交互态和阴影只在 `tokens.ts` 维护。

| 颜色用途 | 统一方式 |
| --- | --- |
| 主要操作 | 实心雾蓝，默认、悬停、按下分别定义；文字使用配对的前景色 |
| 次级操作与文字入口 | 次级按钮使用工作面底色与浅蓝边线；文字入口使用独立的蓝色文字令牌和统一下划线交互 |
| 导航与选择 | 侧栏与下拉选中项用浅雾蓝底，平级页签保留下划线；不混用灰色描边卡片选中态 |
| 权限与结果 | 允许/符合要求用柔绿，禁止/发现问题用玫瑰红，待复核/证据不足用琥珀色；规则与结论继续由文案和符号区分 |
| 信息、过程与中性状态 | 信息提示和进行中状态共用蓝灰色；可复用等准备事实使用中性灰，不能因材料齐备显示安全通过 |
| 输入与焦点 | 控件边界与装饰分隔线分开；占位、禁用、错误和键盘焦点各自定义，键盘轮廓保留可辨对比 |
| 来源与证据 | 证据使用中性阅读表面；AI 来源使用柔和紫色，不能代替正式结论色 |

普通文字与实际底色按 4.5:1 核对，输入边界和焦点按 3:1 核对；禁用和装饰元素单独处理。该配色检查不等于整站无障碍认证。组件库显式映射同一令牌，避免暗色算法、默认提示色或局部 CSS 另行生成第二套状态外观。

公共控件外观归 `shared/styles/controls.css`，ProductThemeProvider 在文档根设置产品作用域，使 body 下的浮层与正文使用同一按钮和链接语法。业务页面只安排位置，不重写次级按钮、链接颜色及焦点规则。页面标题由 EditorialHeader 统一；状态外壳 StatusBadge 明确区分规则、准备、生命周期和结论，业务调用者传入事实类别与色调，组件不推断 Verdict。允许/禁止规则不带检查通过勾号；账号和连接已准备使用准备状态，不能冒充权限已验证。

同类问题采用“定位公共规则→核对全部消费者→修改公共真源及必要调用→核对页面与浮层→记录覆盖范围”的处理方式。未挂载的旧组件不因纳入盘点而恢复入口；完整迁移与当前可达状态的检查分别记录，不能以共享组件测试代替全站验收。

内容分隔与卡片边界统一使用可辨的灰蓝细线，Ant Design 的 colorSplit 与普通 CSS 使用同一边界令牌；页面不再通过透明度或混白另行淡化。输入与可交互路径节点保留更强边界，状态底色保持柔和。视觉小改也必须横向检查全站同类布局、配色、状态、可点击入口及控件，包含弹窗、抽屉和菜单；修正所有同根因用法，报告覆盖范围。此项盘点不意味着每次重跑全部后端或整链测试。

检查准备页遇到 `SELECT_ALLOW_CONTROL` 时，展示服务端返回的 DENY 规则和全部同级正常对照；不预选，不按名称或编号打破并列。确认只提交技术绑定与候选指纹，成功后重读准备材料和 Workspace。新演示仅使用主任务指定的操作账号、资源所有者及两个身份槽；页面分别说明“谁执行”和“资源属于谁”，账号不同时要求明确确认测试资源归属。没有当前主任务时不从账号列表猜测组合。

Web V1 使用安静且可核验的原生亮暗双主题。顶部“设置与更多”菜单中的主题入口允许跟随系统、亮色和暗色三种选择；`src/app/theme/ThemeContext.tsx` 只在 `localStorage` 保存这项轻量偏好，并把同一个解析结果同时投影给 Ant Design 和自有 CSS。颜色、间距、字号、圆角、线宽和动画的唯一真源是 `src/shared/ui/tokens.ts`；`app/theme/theme.ts` 映射 Ant Design，ThemeContext 将同一对象投影为 CSS custom properties。全局布局在 styles.css，共享阅读基础在 shared/styles/editorial.css，任务、业务对象与证据工作面的排版分别由 workspace、boundaries、results 的 feature CSS 维护。页面功能 CSS 留在对应 feature 内，不依赖浏览器强制反色。

权限清单的标签、规则首行与操作共用对齐轴，清除标题默认边距；长中文仅在正文列换行，窄屏操作移到正文下方靠右。允许与通过使用同一柔和绿色，禁止与问题使用同一柔和玫瑰红，待复核使用柔和琥珀色。规则、准备、结论标签和提示条共用语义底色与文字色，不增加饱和描边。只有已发布结论保留判断符号；事实类别通过文案和符号区分，不以另一套浓色或外框区分。此处参考 Radix soft badge（https://www.radix-ui.com/themes/docs/components/badge）和 Geist 底色/文字分级（https://vercel.com/geist/colors），具体色值仍由界鉴 tokens 定义。状态标签不可点击；主操作为实心蓝色，次级按钮统一浅蓝描边，正文导航保留蓝色文字。次级按钮外观由公共样式提供，不再把 link 按钮在页面内染成描边按钮。环境下一步卡片的插图独立水平垂直居中，字号、边距和操作尺寸沿用共用令牌；同组次级动作在左、主动作靠右。平级页签统一下划线，不能伪装成提交按钮。普通站内入口不重复附加外链箭头，返回操作可保留方向提示。取舍参考 [Carbon 按钮层级](https://carbondesignsystem.com/components/button/usage/)与 [Atlassian 语义颜色](https://atlassian.design/foundations/color)。

权限提案审阅按“决定摘要 → 权限规则 → 业务定义与来源 → 最终确认”组织。首次新增直接显示拟生效内容，不逐项重复空白基线；UPDATE/RETIRE 保留服务端冻结的前后对照。角色、动作和沿用项可展开完整内容，不能丢弃结果定义、保护字段或来源。原始基线不可用、正式状态漂移、问题未解决或未勾选时仍不能批准；换提案后清除勾选。

权限规则、业务动作、业务角色共用同一搜索槽位：桌面一致宽度，窄屏占满可用行。提案选择操作用统一 gap 分开。蓝色文字链接在 hover/active/focus 时统一下划线、透明背景与透明边框，不出现灰色方块；描边和实心按钮不因此增加下划线。键盘 focus-visible 保留轮廓，鼠标点击不强加键盘焦点框。参考 [Carbon 链接使用规则](https://carbondesignsystem.com/components/link/usage/)。

跨页检查进度和完成提示放在右下角公共通知堆栈，不占正文高度；保留精确结果跳转和完成提示关闭入口，打开结果后收起通知。关闭完成通知后，陈旧 Workspace 不能恢复同一 Run 的执行中提示；新 Run 仍独立跟踪。需要处理的页面错误和阻塞原因继续就地显示。通知不抢焦点，与错误浮层共享容器，窄屏不得超出视口。

Input 与 Select 必须在暗色下使用独立深色底、可见边框和清楚的禁用文字，而不是只依赖浏览器或 Ant Design 默认反色。结果故事与局部 Evidence 区使用同一主题；独立 Report HTML 不属于当前 GUI 入口。

示例入口的按钮紧随说明，使用公共小间距；空间不足时随内容换行，不以自动边距推到整行最右端。多行提示的图标以标题首行居中，页面与浮层共用该对齐规则。

本页维护交互和视觉的唯一人工说明；具体尺寸与色值以 `product/frontend/src/shared/ui/tokens.ts` 为准。

- 核心任务使用完整工作面，以标题、留白、分隔、对照和有限深度组织。容器服务于操作边界，不设置全透明或固定卡片数量的普遍规则，也不把每项事实拆成同级卡片。
- 去掉容器边框后阅读顺序仍须清楚。每个视口最多一个主要深证据区域，普通状态与统计不能强行套证据面。
- 字号按正文、次级、标签、节标题和主标题从 tokens.ts 读取，不在文档维护第二套数值。颜色、尺度和动画从统一 token 获取，feature CSS 不另写十六进制颜色。
- 桌面导航、顶部、窄屏摘要和内容最大宽度共用 tokens.ts 的布局尺度，三视口与亮暗主题保持一致。窄屏结果证据使用同页阅读并恢复焦点；公共操作栏保持正文流与右侧确认位置，不能因包含主按钮就自动吸底遮挡内容。长表单确需固定操作时须单独核对占位与焦点。
- 输入控件在亮暗主题下均保持可辨底色、边框、禁用文字和键盘焦点。长中文、ID 与路径必须换行或进入受控技术区域；不允许意外横向滚动。
- 动效只表达状态，使用统一时长 token 并保持 prefers-reduced-motion 等价。ThemeContext 必须同步关闭 Ant Design motion；仅以 CSS 截断过渡会让加载图标或浮层停留在退出态，污染可访问名称。进度不能提前表达安全成功。

AI 工具连接页也遵循“主结论 + 一个当前任务表面”的层级，不把不同客户端做成并列卡片墙。页面第一屏先说明当前是否真正连接以及下一步，只用一行选择器切换 Codex、DSH、ZCode；下方按当前客户端展示准备连接、添加配置、验证连接三个步骤。每步必须说明打开哪里、复制什么、粘贴到哪里和完成标志，不展示原始配置面板、命令行备选或协议术语。配置创建、配置复制、Bearer 通过和 initialize 完成仍是后端不同事实；普通页面统一翻译为“界鉴已准备、凭据已通过、连接成功”，只有 `connection_state=CONNECTED` 才显示客户端名称、最近活动和逐应用允许范围。连接成功后的日常说明固定为“读取已确认权限 → 完成一批修改后一次登记 → 显式检查并将证据带回原客户端”，不能暗示每次保存或单个文件修改都要调用界鉴。

普通页面不显示 READ、PREPARE、EXECUTE 等内部 level 名称，统一翻译为“只查看、协助整理、执行已确认任务”。调整入口使用“这次允许 AI 工具做到哪一步”，逐项说明能做什么和不能做什么；连接凭据可以长期保留，但超过只查看的范围仅在本次打开界鉴期间有效。需要把 Bearer 写入请求头的客户端仍必须把无秘密配置骨架与凭据复制分开，并明确本地保存风险。

AI 辅助设置只提供一个默认模型连接，普通用户只选择供应商、填写一次性 API Key、读取可用模型并保存。Profile 名称、兼容服务地址、secret reference、预算、超时、字节限制、本机 HTTP 开关和推理强度不进入普通界面；后端 Profile 仍作为持久化和供应商适配边界存在。

新增或重排页面时，不能只看单一截图。先以 2560×1440 分别核对亮色和暗色的现场展示密度，再同时检查约 1280px 和 600px：标题是否换行、双列表单是否变单列、底部动作是否在滚动中持续可触达、弹层焦点是否正确、是否出现横向溢出。


## 已发布路径的版式

结果页只保留一个整体标题；多 Case 保留可辨的选择与结论。业务规则和真实后果优先于实现元数据。路径只画服务端显式父边，线性起始段可以并排，分支与全部事实节点必须保留；画布不能依截图预期删节点。桌面与移动端均在单项调查中切换执行过程和证据，返回恢复原入口焦点。补充来源归入证据记录，原始技术材料按需展开。

权限管理以权限规则、业务动作、业务角色三个平级入口组织内容。搜索与新增位于固定工具栏，编辑属于所选对象；完整草稿统一审阅批准。无修改时只保留紧凑的核对入口，仍允许提交纯实现重绑提案。业务对象默认展示含义、保护结果和引用，完整字段只在编辑时出现。

工作台使用稳定的应用标题、一个当前工作面和业务进展列表。当前任务来自唯一 PrimaryTask；运行进度、正式结论和准备状态分别展示。材料按动作及 revision 匹配 PreparationView，读取失败明确保留上次状态，不从名称或数量猜测准备完成。最近已发布结果标明对应权限版本和历史范围，不冒充整个应用或后续代码的安全结论。导航到业务对象携带精确 action_id。

应用切换菜单只包含已有应用和接入入口。应用与环境提供配置及移除操作；Agent 协作是独立一级入口，承载修复任务与修改、连接与授权。服务端选择 `PREPARE_AGENT_REPAIR` 时，工作台直接定位到精确原题；结果页保留同一入口。复制修复任务不等于已经发送，Agent 登记修改不等于修复成功。常驻子入口通常为两至三个，不在每一区域重复复制模块导航。

决定能否继续的信息直接显示；来源、技术引用等细节采用有名称、有状态的单层展开。权限状态和保护结果不藏在低显著性菜单中。次级入口支持键盘、可见焦点和至少 44px 的触达高度，减少连续折叠与多重抽屉。

活动检查持续只读跟踪，不因固定五分钟预算永久停止；暂时失败退避重试，协议或所属对象错误关闭结果展示。工作台定时回读最新事实，编辑页保留自己的任务上下文。历史列表原位更新已有记录，有新记录时提供提示，不强制重排或跳走；已发布结果正文不被后续检查替换。刷新为备用操作，后台同步不得重放提交、批准或登记请求。


检查材料总览采用一个当前任务工作面和五类材料清单。业务动作只有一个选择器；账号、动作录制、测试资源、结果证明和恢复方式的分组状态来自同一 Preparation 快照。仅全部子项满足时显示“可复用”；已保存但失效的材料显示“已保存，需复核”，不是完成状态。

准备页只在服务端建议对应当前 PrimaryTask 时采用其标题与原因，列出可以沿用的完整材料组。来源页分别显示当前主任务与所选来源的局部处理步骤、处理者和精确入口；它们共用后端只读建议，不在前端猜测失效原因。账号诊断深链只打开管理页，不自动登录。读取失败保留原有任务，陈旧建议不覆盖新任务。

接入前的支持说明使用同一正文、边线与状态样式，提前解释普通完整证明的条件和改造成本。全局资源更新提示复用右下角可关闭通知；只有当前页面内嵌构建标识与已确认服务资源不同时提示更新。缺少身份显示未确认。编辑或检查进行中禁用刷新，始终由用户明确刷新；关闭后同一构建不再提示，新构建可以再次提示。系统页展示页面与服务资源的各自身份；焦点恢复时回读系统状态，不承诺实时推送。

单项材料在独立工作面编辑，桌面左侧选择与比较、右侧显示服务端计算的更新/保留/复核影响；窄屏顺序排列。候选通过来源核对不代表已经保存，须先预览再确认。保存失败或回执不明保留操作标识并回读；返回清单恢复原展开项和焦点。材料选择通过有限草稿恢复，刷新不重复写入或启动检查。

环境页将已确认退出与无法核对所有权分开。确认退出时以“从全新示例开始”说明：旧项目归档、检查与证据保留，新项目使用同步导出的起始实现，权限、账号和材料从零准备。停止页只有一个“启动示例”主入口，不提供恢复旧材料或继续旧源码的选项。未知归属保持阻塞并提供核对说明；重新启动、活动实例重置和移除应用均明确各自影响。

移除官方示例应用使用一次确认，普通项目移除生命周期先停止其拥有的实例，再归档应用并保留历史。前端回读停止后的环境并清除旧提示，不再要求单独停止。普通应用的外部进程不在该操作范围内。环境管理只保留一层标题和紧凑的状态、操作、详情分组。

确认、保存和开始执行使用右对齐的操作区，返回、取消等次要动作在前，最终确认在后；窄屏允许换行，键盘顺序与视觉顺序一致。列表筛选与视图导航不混入确认操作区。结果与证据、源码对应共用页签上方的本轮结论，具体考题的判断在证据内容中单独呈现。

修复流程进入检查和准备材料时持续携带精确 change_id；普通检查入口只可承接服务端明确选定的 VERIFY_REPAIR 主任务，不从最近 PASS 推断修复完成。示例修复阶段顶部入口直达该修复批次，材料返回不得丢弃上下文；已提交后保持本轮上下文，不因工作台更新而退出结果。
