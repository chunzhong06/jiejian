# 界鉴开发文档

> 状态：CURRENT。代码、测试、Schema 与 migration 是实现事实；文档负责解释职责、入口和约束。

第一次开发从[快速开始](开发/快速开始.md)进入。已有具体任务时，直接选[能力指南](开发/能力/)；不知道所有者时查[能力映射](架构/能力映射.md)。Codex 使用同一正文，由 [llms.txt](llms.txt) 选择必要内容。

| 要回答的问题 | 唯一位置 |
| --- | --- |
| 用户怎样完成一次检查与修复 | [工作流](产品/工作流.md) |
| 页面怎样引导操作、表达证据 | [交互与视觉](产品/交互与视觉.md) |
| 系统怎样分工、谁拥有事实 | [系统边界](架构/系统边界.md)、[能力映射](架构/能力映射.md) |
| 一项修改去哪里、怎样验证 | [能力指南](开发/能力/)、[验证](开发/验证.md) |
| 开发工具、启动、打包如何运行 | [环境与脚本](开发/环境与脚本.md)、[便携版](开发/能力/修改发布与便携版.md) |
| 精确格式、失败与兼容语义 | [协议参考](参考/协议/)；字段以 Schema 为准 |
| 找不到公开符号时怎样查 | [生成参考](参考/生成/)，按文件查询，不默认整份阅读 |
| 怎样协作、何时停止 | [工程约束](约束/)；根 [AGENTS.md](../AGENTS.md) 保留行动门禁 |
| 为什么坚持某个边界 | [已接受决策](决策/)，仅在该决策受影响时阅读 |

普通任务通常只需要一篇能力指南和直接代码。跨事务、进程、公共格式或安全语义时，沿指南链接展开相应架构与协议；无需从头读完整文档树。运行证据、设计审阅、临时调查与版本计划放在 `var/` 或用户指定交接包，不作为当前实现说明。

维护人工正文后运行 `dev.ps1 docs`；生成输入变化时先 `dev.ps1 docs -Update` 再只读检查。生成器检查路径和漂移，不能替代事实核对。
