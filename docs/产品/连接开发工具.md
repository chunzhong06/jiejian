# 连接开发工具

开发工具允许外部 Agent 通过本地 MCP 使用明确授予的能力。开始前需要本地服务可用、已选择项目，以及可配置 MCP 的客户端。

## 建立连接与授权

1. 从右上角“开发工具”图标进入，选择客户端并配置连接。连接设置与当前应用授权分区显示。
2. 在客户端配置连接，再回到界鉴核对状态。
3. 查看应用、动作、来源和期限，分别授予读取、准备或执行能力。
4. 先核对当前上下文，再执行被允许的工作。

连接成功只说明传输可达，不代表已经获准执行。不要将密钥复制到普通数据库、源码、日志、截图或报告。

## 使用建议与交付

规则、材料和业务解释建议进入同一人工审阅流程。Agent 不能批准正式权限、改变来源授权或决定安全结论。解释已有结果时引用实际记录，并保留证据范围。

修改交付注明真实范围、关联规则和准确原题。登记、加载与复验各有回执；一个环节成功不代表后续已经完成。请求结果未知时查询原操作，不用另一份交付覆盖不确定性。

## 撤回与排查

暂停或撤权后停止后续受授权操作，已有事实保留供查阅。连接失败时依次检查本地服务、客户端地址、连接状态和能力范围；执行被拒绝时查看具体授权与前置条件，不通过扩大凭据范围绕过拒绝。

## 从报告进入修复协作

报告和规则问题可以生成固定上下文的请求。`jiejian_result_show`返回该轮结果及各修复目标的核验，`jiejian_evidence_show`读取指定用例引用的记录，`jiejian_repair_show`提供原题要求、连续处理历史及复发情况。结果入口始终定位到指定报告，不以“最近一次”替换。

Agent 应先核对事实，再定位实现；修改后以一个稳定操作键登记实际文件变化和多个rule_targets，未知回执先查询原操作。登记、代码加载、材料核对与原题复验分别完成，不用提交说明、人为关闭或版本名称替代修复验收。本流程复用现有MCP授权等级，不新增离线报告或自动发送通道。
