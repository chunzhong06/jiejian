# 排查运行问题

先定位失败阶段，再选择恢复动作。只重做失效的环节，保留已确认的项目、规则、材料和操作标识。

| 现象 | 先看什么 | 如何继续 |
| --- | --- | --- |
| 首次启动长时间准备 | 工具下载、Python、浏览器、构建的当前阶段 | 等待真实就绪或处理该阶段错误，避免反复启动 |
| 页面能打开但不能执行 | 运行状态、目标地址、授权和准备缺口 | 补齐对应条件，不把页面可达当作执行可用 |
| 数据库启动拒绝 | 错误代码、支持修订与原库归属 | 保留原库，按迁移说明处理，不覆盖文件 |
| 登录或录制失效 | 实例是否重启、角色与来源是否变化 | 重核受影响材料，不创建重复主体 |
| 登录过程中服务或窗口中断 | 侧栏“查看登录中断”中的原任务与清理状态 | 清理完成后显式重新打开登录窗口；已保存材料和报告保留 |
| 材料准备内部错误 | 当前批次说明、原操作回执与公开错误代码 | 停止后续准备，保留已有材料；核对原回执及故障原因后再确认剩余计划，不反复提交 |
| 批准或提交超时 | 原操作回执与当前持久状态 | 查询同一次操作，不更换键重试写入 |
| 检查失败或取消 | 生命周期与收尾状态 | 等待停止或修复执行原因，不改成权限通过 |
| 报告证据不足 | 具名缺口、归属、对照和读取闭合 | 补齐后重新检查，保留原报告 |
| 清理条目被跳过 | 文件变化、引用、占用和计划期限 | 按当前事实重新预览，不强行删除 |

需要开发者介入时，提供阶段、公开错误代码、项目或运行标识，以及哪些操作已确认成功。不要提供密码、Cookie、Token、密钥或未经检查的异常正文。

环境、输入和产品行为应分开判断。不能通过放宽授权、覆盖数据库、忽略证据缺口或重放未知写入让流程看起来继续。工程排查和测试失败处理见[执行与排错](../工程/测试/执行与排错.md)。
