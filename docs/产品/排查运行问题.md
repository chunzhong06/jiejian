# 排查运行问题

先定位失败阶段，再选择恢复动作。只重做失效的环节，保留已确认的项目、规则、材料和操作标识。

| 现象 | 先看什么 | 如何继续 |
| --- | --- | --- |
| 首次启动长时间准备 | 工具下载、Python、浏览器、构建的当前阶段 | 等待真实就绪或处理该阶段错误，避免反复启动 |
| 页面能打开但不能执行 | 运行状态、目标地址、授权和准备缺口 | 补齐对应条件，不把页面可达当作执行可用 |
| 数据库启动拒绝 | 错误代码、支持修订与原库归属 | 保留原库，按迁移说明处理，不覆盖文件 |
| 登录或录制失效 | 实例是否重启、角色与来源是否变化 | 重核受影响材料，不创建重复主体 |
| 登录过程中服务或窗口中断 | 侧栏“查看登录中断”中的原任务与清理状态 | 清理完成后显式重新打开登录窗口；已保存材料和报告保留 |
| 材料准备内部错误 | 当前批次说明、原操作回执与公开错误代码 | 停止后续准备，保留已有材料；核对原回执及故障原因后再确认剩余计划，不反复提交 |
| 批准或提交超时 | 原操作回执与当前持久状态 | 查询同一次操作，不更换键重试写入 |
| 检查失败或取消 | 生命周期与收尾状态 | 等待停止或修复执行原因，不改成权限通过 |
| 报告证据不足 | 具名缺口、归属、对照和读取闭合 | 补齐后重新检查，保留原报告 |
| 操作经过没有路径或不完整 | 是否由界鉴受控启动、是否使用支持的 API、请求是否闭合、采集失败或超限原因 | 普通 Node 应用无需补写技术事件；核对运行、采集与发布链后重新检查。权限语义事件与技术调用分开判断 |
| 清理条目被跳过 | 文件变化、引用、占用和计划期限 | 按当前事实重新预览，不强行删除 |
| 清理中断后结果不明 | 存储页中的原计划、逐项回执与未知数量 | 查询结果并核对现状，重新扫描不重放原删除 |
| 更新目录被拒绝 | 完整解压、文件清单、工作区支持范围 | 选择匹配的完整包，不单独替换文件 |
| 更新确认后断连 | 启动器、原更新操作及目标阶段 | 等待新界面或查询原操作，不重复切换 |
| 上次退出需要核对 | 运行诊断中的上次结果、工作区与所属进程 | 确认原实例已停止后继续，不按进程名批量结束程序 |

需要开发者介入时，先在“运行与维护”查看诊断摘要，再提供阶段、公开错误代码、项目或运行标识，以及哪些操作已确认成功。不要提供密码、Cookie、Token、密钥或未经检查的异常正文。诊断摘要不包含原始日志，也不自动发送给第三方。

环境、输入和产品行为应分开判断。不能通过放宽授权、覆盖数据库、忽略证据缺口或重放未知写入让流程看起来继续。工程排查和测试失败处理见[执行与排错](../工程/测试/执行与排错.md)。

## Linux与CI运行

Linux运行包从`./start.sh`启动本机服务；需要独立资料目录时，使用`./start.sh --var-dir /data/jiejian`。自动化命令放在`--cli`之后，例如`./start.sh --cli check --help`；日常执行仍连接显式的本机服务，使用已确认的方案修订、环境绑定和检查指纹。

Linux服务使用显式短期秘密会话。由上游进程创建匿名管道并继承给服务，使用`--session-secrets-fd`指定FD；正文不放入命令参数、普通文件、方案或日志。`--session-seconds`设置有效期，读写不会自动延期；退出或到期后需重新配置会话。历史方案和报告可以保留，旧账号的就绪状态不能替代新会话中的凭据。

当前Linux实测接入方式是独立外部Web。运行地址可达与源码部署匹配分别核对；缺少受控部署对应时，结果比较仍明确限制修复结论。Linux受控Node加载与原生更新不按Windows方式回退，平台与交付边界见[构建与发布验收](../工程/发布.md#linux-x64运行包)。
