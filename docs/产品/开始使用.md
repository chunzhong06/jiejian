# 开始使用界鉴

这份教程使用独立数字展馆完成一次真实检查。完成后，你应能指出一条权限要求、实际结果、判断依据和适用范围，而不只看到一个绿色状态。

## 开始前

在 Windows 本机使用仓库根目录的 `start.cmd`。首次准备需要下载受控工具；无需提供自己的应用、生产账号或付费模型。界面打开后进入“官方示例”。

如果已经使用过示例，继续会沿用当时的源码和规则。要按初始条件学习，在“管理示例”中选择“重新开始示例”，确认建立独立项目；原项目和历史保留。

## 1. 建立运行上下文

1. 在“官方示例”启动数字展馆，等待准备操作完成。
2. 运行后进入示例项目。
3. 核对左侧当前应用为数字展馆项目，右上角本地服务可用。

此时只是应用和环境就绪。运行状态可用不能说明任何权限已经通过检查。若启动结果未知，查询原操作，先不要重复新建。

## 2. 让业务要求成为检查依据

1. 打开“权限规则”，进入待审权限变更。
2. 对照负责人和评审，读清内部完整包、公开预览及公开展示版各自的访问要求。
3. 核对允许或禁止、资源所有者及结果定义，确认提案后选择“批准权限规则”。

批准后，规则表展示正式要求。提案中的规则数量取决于本次选择；不要靠数量判断是否正确。若提示提案已变化，重新读取并审阅。候选和建议未批准前不作为正式依据。

## 3. 准备实际执行与判断材料

1. 打开“检查准备”，选择一个业务动作。
2. 查看所需账号、操作录制、资源、结果证明和恢复要求。
3. 使用“准备示例材料”，核对本次批量准备范围后执行，等待完成回执。
4. 逐项处理仍显示的具名缺口。证明来源需核对读取范围和采用状态。

预期：同一实际账号可供多个动作复用，页面按材料归属展示状态。材料齐备仍不是安全通过。登录失效时重核该账号，证明缺失时处理对应来源，不要从头重复创建所有账号。

## 4. 预览后提交

1. 进入检查预览，查看规则、账号、资源、运行代码和证明范围。
2. 有缺口时返回所属项补齐，再生成预览；不要把未准备动作当作已经检查。
3. 确认范围并提交，等待当前检查形成最终回执。

提交成功产生独立检查记录。断连后先查原记录；未拿到回执不表示没有提交。取消后也需等待实际停止与清理完成。

## 5. 读懂一份报告

1. 从“检查记录”打开本次报告，先读总结果。
2. 选择具体规则，核对业务结果是否满足要求。
3. 按需查看操作经过和证明记录，最后展开本次适用范围。

初始正常示例在材料、身份和证明完整时应得到符合规则的结果。证据不足应指出具体缺口；它不等于暂时安全。报告只覆盖当时冻结的规则、代码、账号、资源和读取范围。
