# 开始使用界鉴

日常工作从“工作台”继续，应用资料、权限覆盖、测试场景和问题各有持续入口。接入自己的应用见[接入应用](接入应用.md)。下面使用独立数字展馆完成一次真实检查。完成后，你应能指出一条权限要求、实际结果、判断依据和适用范围，而不只看到一个绿色状态。

## 开始前

在 Windows 本机使用仓库根目录的 `start.cmd`。首次准备需要下载受控工具；无需提供自己的应用、生产账号或付费模型。空工作区选择“体验官方示例”；已有项目时，从左上角应用切换菜单进入“官方示例”。

入口提出“请求被拒绝，就没有越权吗？”。体验中会把访问要求、实际业务后果和正式判断放在一起阅读；接口响应与检查后的恢复分别列出。

如果已经使用过示例，继续会沿用当时的源码和规则。要按初始条件学习，在“管理示例”中选择“重新开始示例”，确认建立独立项目；原项目和历史保留。

## 1. 建立运行上下文

1. 在“官方示例”选择“开始示例体验”，等待启动操作完成；已有示例则继续上次项目。
2. 在工作台阅读当前任务，选择“确认访问要求”；已有记录则按当前进度接续。
3. 核对左侧当前应用为数字展馆项目，示例状态显示已运行。

此时只是应用和环境就绪。运行状态可用不能说明任何权限已经通过检查。若启动结果未知，查询原操作，先不要重复新建。

## 2. 让业务要求成为检查依据

1. 打开“权限与覆盖”，阅读完整的示例权限要求。
2. 对照负责人和评审，读清内部完整包、公开预览及公开展示版各自的访问要求。
3. 核对允许或禁止、资源所有者及结果定义，选择“批准规则并继续”。已有待审提案则从原记录继续核对。

批准后显示“示例规则已确认”，可以继续准备示例材料，也可以查看已生效的访问规则。若提示提案已变化，先重新核对完整内容。候选和建议未批准前不作为正式依据。

## 3. 准备实际执行与判断材料

1. 从规则确认结果选择“准备示例材料”，或进入当前业务操作的检查准备。
2. 查看所需账号、操作录制、资源、结果证明和恢复要求。
3. 使用“准备示例材料”，核对本次批量准备范围后执行，等待准备结果。
4. 逐项处理仍显示的具名缺口。证明来源需核对读取范围和采用状态。

预期：同一实际账号可供多个动作复用，页面按材料归属展示状态。材料齐备仍不是安全通过。登录失效时重核该账号，证明缺失时处理对应来源，不要从头重复创建所有账号。

## 4. 预览后提交

1. 进入检查预览，查看规则、账号、资源、运行代码和证明范围。
2. 有缺口时返回所属项补齐，再生成预览；不要把未准备动作当作已经检查。
3. 确认范围并提交，从产生的检查记录继续查看执行和报告。

提交成功产生独立检查记录。断连后先查原记录；未拿到回执不表示没有提交。取消后也需等待实际停止与清理完成。

## 5. 读懂一份报告

1. 从“检查记录”打开本次报告，先读总结果。
2. 选择具体规则，核对业务结果是否满足要求。
3. 按需查看操作经过和证明记录，最后展开本次适用范围。

初始正常示例在材料、身份和证明完整时应得到符合规则的结果。证据不足应指出具体缺口；它不等于暂时安全。报告只覆盖当时冻结的规则、代码、账号、资源和读取范围。

## 6. 发现错误修改并验收修复

从正常起点报告选择“查看错误修改”，先核对这份修改影响的访问限制，再明确确认加载。加载后核对受影响材料，生成新预览并检查。报告先回答评审是否取得了内部包，以及正常访问是否仍然可用；接口拒绝或事后恢复不会撤销已经发生的业务后果。

修改页还可选择“查看开放后撤回的修改”，进一步核对请求拒绝、最后恢复时，访问是否曾被开放。打开说明只改变阅读位置，加载源码仍需明确确认；原来的正常起点与错误修改主线继续保留。

从这项权限问题进入“处理与复验”，核对预置修复解决什么、还要保留什么，再确认加载。沿同一任务补齐受影响条件并提交复验。完成后分别核对原问题是否解决、正常功能是否保留，并按需深入证明记录。完整步骤见[复验一次修复](检查与复验.md#复验一次修复)。

复验完成会直接列出评审取得内部包这一原问题，以及负责人访问自身资料、评审访问公开内容等具名正常操作。每项保留实际账号、资源和对应结果；同一事实兼作正常对照与功能回归时合并展示。

离开报告补材料或处理问题后，使用所属任务的返回入口继续原事项。已归档示例从“官方示例”的归档目录查阅，报告和证据保留当时的事实，不在归档阅读中发起新检查或修改。

也可以继续[接入自己的应用](接入应用.md)。
