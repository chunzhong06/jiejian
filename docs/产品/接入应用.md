# 接入应用

接入的目标是把本地源码、业务项目和 Web 运行实例对应起来。开始前准备源码目录、可核对的运行地址，以及允许读取和执行的范围。

## 登记来源

1. 打开“应用连接”，选择源码目录并查看识别结果。
2. 核对已有项目。继续用于沿用规则与历史，独立接入用于建立新的项目记录。
3. 核对运行地址，授权需要的源码读取范围，再执行分析。
4. 查看生成的角色、动作和结果候选，继续[维护权限规则](维护权限规则.md)。

完成后应能同时核对项目、来源目录和实际地址。项目记录不等于运行进程；源码可读也不代表可以自动执行其中程序。语法线索和模型建议仍需人工审阅。

“检查条件”汇总已有的源码分析、地址核验、受控运行和证明来源记录。它只读取已形成事实，不在打开页面时访问目标，也不把当前读取时间冒充目标核验时间。完整执行证明目前支持受控本地 Node ESM 与对应记录来源；外部网站可整理规则和准备材料，单凭能访问或 HTTP 状态码不能确认权限安全。

## 选择应用运行方式

“应用运行”将连接已有程序与启动本地程序放在同一区域，一次只显示所选方式的设置。选择方式只切换表单，不执行程序，也不改变检查地址；地址、入口和端口的未提交输入在本页内保留，切换应用后不沿用另一项目的草稿。

### 连接已有应用

1. 先启动自己的 Web 应用，确认它的实际访问地址。
2. 选择“连接已有应用”，填写“应用地址”。
3. 选择“使用此地址”，将其设为登录、录制和检查的目标。

这条路径不负责启动或停止程序，也不自动取得运行源码的证明。界鉴启动的实例仍在运行时，表单保留“管理运行实例”入口，切回后可以查看或停止它。

### 由界鉴启动

适用于已授权源码读取、满足当前支持条件的本地 Node ESM 应用。官方示例仍在示例页管理；源码尚未授权时也不显示普通应用的启动入口。

1. 选择“由界鉴启动”，填写 Node 入口文件和本地端口，选择“预览启动”。
2. 核对入口、端口和授权文件范围，明确勾选执行授权，再选择“启动应用”。改变入口、端口或源码后应重新预览。
3. 启动成功后，表单替换为实例的实际地址、入口和管理操作。若尚未采用，核对当前检查地址，再选择“使用此应用”。
4. 实例不再需要时，选择“停止应用”。停止只针对本项目拥有的受控实例。

专用 Worker 启动并持有受控进程，预览与加载回执记录源码修订和指纹。旧回执不能证明新代码已加载；启动完成也不自动切换检查对象。运行后再准备真实账号与材料，实例重启后重新核对登录和证明来源。

### 区分设置、运行与检查结果

| 界面状态 | 表示什么 | 不能据此认定什么 |
| --- | --- | --- |
| 检查地址已设置 | 已保存登录、录制和检查的访问目标 | 应用当前在线或运行代码已对应 |
| 正在运行 | 服务已确认界鉴拥有的实例在运行 | 当前检查已采用它或权限安全 |
| 源码已有变化 | 实例与当前源码不再对应 | 新代码已经运行 |
| 已用于检查 | 当前保存的检查地址与该实例地址相同 | 已执行过检查或取得通过结论 |

启动结果尚未确认时查询原操作；仅在页面提供“恢复原启动请求”时明确恢复同一请求。失败或取消后，旧执行确认移除，检查地址保持原设置；再次启动需重新预览授权。

## 无法完成时

| 现象 | 核对内容 | 继续方式 |
| --- | --- | --- |
| 目录不存在或内容不符 | 真实路径、授权读取范围 | 修正后重新预览，不建立空项目 |
| 已有项目与新项目混淆 | 来源与保留历史的需要 | 明确选择继续或独立接入 |
| 运行地址不符 | 实际监听地址与加载回执 | 修正运行上下文后再准备材料 |
| 写入超时 | 原操作标识及持久回执 | 查询原操作，不换键重复提交 |
| 旧实例未确认退出 | 进程归属与原生命周期 | 保留未知状态并核对，不覆盖占用记录 |

接入完成后，规则批准、材料准备和检查结论仍分别需要自己的事实。
