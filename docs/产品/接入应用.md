# 接入应用

应用工作区保存环境、资料、身份、权限要求、测试场景和历史结果。可以从已有 Web 应用开始，源码单独关联和授权。

## 建立与维护工作区

1. 打开“应用与来源”，填写应用名称，建立工作区；已有应用直接在左侧选择。
2. 在“环境”保存明确的 IPv4 HTTP/HTTPS 地址与可选部署说明，选择当前环境，再单独核验地址。当前连接核验支持本机目标；域名和远程目标尚无完整接入链。
3. 在“接口来源”导入 OpenAPI 3.0/3.1 JSON、HAR JSON 或 Postman Collection 2.1 JSON。先查看净化结果与新增、变化、缺失项，再接受修订。
4. 整理请求名称与业务关联。可将请求形成待审业务动作候选，在“业务角色与操作”补充角色及名称；正式访问要求在“权限与覆盖”单独审阅批准。
5. 已关联业务动作的请求可转到“测试”整理场景。后续资料更新沿用当前工作区，人工名称、关联、权限和场景持续保留。

来源只保存请求结构，不保存导入中的参数值、认证值、正文或响应内容。文档内的本地引用有界展开，远程引用和未解析变量拒绝；集合脚本不会执行。来源中的服务器地址不获得执行授权。资源参数和测试数据需要在场景中明确核对，不能把导入成功当作可执行。

保存响应不明确时，页面保留原操作引用，先读取对应修订再恢复。来源变化会提示受影响线索和场景重新审阅，不删除已确认业务要求，也不自动形成权限问题。

## 区分环境、源码和实际效果

环境配置、地址可达、部署声明和代码核验分别保存。地址相同不能证明程序相同；人工部署说明显示“版本未核对”。切换环境后重新核对账号、资源、场景和观察范围，旧材料不会自动获得新环境的有效状态。

无源码应用可通过所有者独立只读查询与实际目标响应，判断已声明 JSON 字段是否披露。资源、所有者、主体或字段不能对应时保留证据不足。该方法不证明写入提交或中间从未改变数据；完整写入证明继续使用相应强来源。

需要本地源码时，在“源码与受控运行”关联准确目录，再独立授权读取和分析。已有规则、来源和报告保留。源码可读不授权执行程序；项目记录也不代表运行进程。

## 选择应用运行方式

“应用运行”将连接已有程序与启动本地程序放在同一区域，一次只显示所选方式的设置。选择方式只切换表单，不执行程序，也不改变检查地址；地址、入口和端口的未提交输入在本页内保留，切换应用后不沿用另一项目的草稿。

### 连接已有应用

1. 先启动自己的 Web 应用，确认它的实际访问地址。
2. 选择“连接已有应用”，填写“应用地址”。
3. 选择“使用此地址”，将其设为登录、录制和检查的目标。

这条路径不负责启动或停止程序，也不自动取得运行源码的证明。界鉴启动的实例仍在运行时，表单保留“管理运行实例”入口，切回后可以查看或停止它。

### 由界鉴启动

适用于已授权源码读取的本地 Node 应用，支持标准 ESM、CommonJS 和锁定的 npm 依赖。Express 可以沿用原来的业务处理器。支持的 HTTP、SQLite 与文件调用会随检查自动记录，不需要手写过程事件；这些技术调用不能代替业务结果证明。官方示例仍在示例页管理。

1. 选择“由界鉴启动”，核对识别到的 npm 锁文件、入口和端口；需要构建时选择已声明的构建脚本，入口填写实际生成的 JavaScript 文件。
2. 使用 SQLite 时，声明数据库相对路径、数据表、唯一资源键、所有者字段和需要观察的业务字段。选择“预览启动”，核对范围后授权“准备并启动”。改变上述设置或源码后重新预览。
3. 启动成功后，表单替换为实例的实际地址、入口和管理操作。若尚未采用，核对当前检查地址，再选择“使用此应用”。
4. 实例不再需要时，选择“停止应用”。停止只针对本项目拥有的受控实例，随后保留启动方式和数据库声明，便于核对后再次运行。

专用 Worker 启动并持有受控进程，预览与加载回执记录源码修订和指纹。旧回执不能证明新代码已加载；启动完成也不自动切换检查对象。运行后再准备真实账号与材料，实例重启后重新核对登录和证明来源。

依赖安装和构建只在运行副本进行。默认不执行依赖安装脚本，确需执行时另行确认；不会读取个人 npm 配置。当前依赖范围是带完整性信息的公共 npm 锁文件。数据库以一致性副本用于测试，原数据库不被检查修改；修复加载沿用所属测试数据。进程及 Node 权限限制不能被理解成对抗恶意依赖的安全沙箱。

普通 SQLite 适配目前实测 Windows x64、Node 24.19.0 和 better-sqlite3 13.0.3。支持单进程、已声明连接、有稳定唯一键的普通表；字段限有限 JSON 标量。外部数据库、后台任务和未声明连接不能自动取得完整业务证明。

### 区分设置、运行与检查结果

| 界面状态 | 表示什么 | 不能据此认定什么 |
| --- | --- | --- |
| 检查地址已设置 | 已保存登录、录制和检查的访问目标 | 应用当前在线或运行代码已对应 |
| 正在运行 | 服务已确认界鉴拥有的实例在运行 | 当前检查已采用它或权限安全 |
| 源码已有变化 | 实例与当前源码不再对应 | 新代码已经运行 |
| 已用于检查 | 当前保存的检查地址与该实例地址相同 | 已执行过检查或取得通过结论 |

启动结果尚未确认时查询原操作；仅在页面提供“恢复原启动请求”时明确恢复同一请求。失败或取消后，旧执行确认移除，检查地址保持原设置；再次启动需重新预览授权。

## 无法完成时

| 现象 | 核对内容 | 继续方式 |
| --- | --- | --- |
| 目录不存在或内容不符 | 真实路径、授权读取范围 | 修正后重新预览，不建立空项目 |
| 已有项目与新项目混淆 | 来源与保留历史的需要 | 明确选择继续或独立接入 |
| 运行地址不符 | 实际监听地址与加载回执 | 修正运行上下文后再准备材料 |
| 写入超时 | 原操作标识及持久回执 | 查询原操作，不换键重复提交 |
| 旧实例未确认退出 | 进程归属与原生命周期 | 保留未知状态并核对，不覆盖占用记录 |

接入完成后，规则批准、材料准备和检查结论仍分别需要自己的事实。
