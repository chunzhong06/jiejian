# Windows 便携版使用说明

## 启动与首次检查

完整解压发布包，将整个文件夹放在有写入权限的位置，双击“界鉴.exe”。便携版使用包内固定组件，不需要预装 Python、Node、Conda 或开发工具；启动时不联网下载、安装依赖或构建前端。

在首页连接自己的应用，或进入官方示例。官方示例使用独立工作副本，保留模板。先审阅访问规则，再准备账号、操作录制、测试资源、结果证明和必要的恢复方式。材料齐备后预览检查范围并提交检查，在检查记录中查看结果和证据。

发现权限问题后，将代码修改关联到对应规则，再沿原问题复验。检查完成与符合规则分别表示不同事实；证据不足时，需要补齐具体缺口后重新检查。

## 目录用途

- app：已构建的产品、前端和发行清单。
- runtime：固定 Python、Node、Chromium 与生产依赖。
- samples：官方示例模板，仅完整版提供。
- docs：使用说明与第三方许可。
- var：本机项目、数据库、证据、日志和运行文件，首次启动时建立。

完整版与不含示例版使用相同的产品程序。运行数据不会写入 app 或 runtime。

## 打开与退出

重复双击“界鉴.exe”会重新打开使用同一工作区的实例。关闭浏览器窗口后，也可以用这个入口恢复。不同发行目录绑定同一工作区时，不会同时启动两套写入服务。

结束工作时，使用左侧“退出界鉴”，等待服务和所属进程停止后再移动目录。终端快捷键可用时，也可以按 Ctrl+C 或 Q 退出，按 G 重新打开界面。

默认地址为 http://127.0.0.1:8765。端口占用时会提示，不会终止其他程序。需要指定端口时，在终端运行 .\界鉴.exe --port 8766；--no-open 用于只启动服务。

## 使用本地新版本

先完整解压新发行包，保留整个 app 和 runtime，不覆盖正在运行的目录，也不混用不同包的组件。点击右上角齿轮进入设置，打开“运行与维护”，选择“版本与更新”。

1. 选择新解压、尚未建立业务工作区的发行目录，预览目标版本与工作区影响。已绑定其他工作区的目录不能用于接续。
2. 产品只读核对完整程序树、清单与当前工作区格式。不支持时拒绝，当前服务和资料保持原状。
3. 确认“停止并切换版本”。当前任务停止，旧启动器等待所属进程和锁释放，再启动新程序。
4. 新程序接续原工作区，并回到原应用。进入“版本与更新”可查询同一操作的就绪或失败结果。

更新不复制、移动或清空业务 var，不自动创建备份。新发行在自己的 var/launcher 中保存工作区位置绑定；以后双击新入口继续使用原工作区。原工作区可能位于旧发行目录中，移动或清除旧目录前须核对“版本与更新”显示的位置，不能连同业务 var 一起删除。

文件摘要只确认本地文件与清单一致，不代表发布者签名。只选择自己信任来源的完整发行包。本版不自动下载更新，也不提供自动降级。

更新支持目标发行明确声明的同代工作区。需要升级结构时，预览会说明影响；确认并停止原服务后才执行事务升级，原应用和报告保留，升级失败回滚。不支持的格式在停止服务前只读拒绝。升级后的结构可能不再被原程序支持，因此不提供自动降级。

只识别旧更新清单的候选程序不能通过原更新页面切换到新清单。先退出旧程序，再用下方命令从新发行入口明确指定原工作区；不覆盖旧程序，不修改清单，不删除原数据。需要全新工作区时，在独立目录启动未绑定的完整发行包。

手工指定工作区可使用 .\界鉴.exe --workspace "D:\界鉴资料" --port 8766。新目录默认为自己的 var，只有明确更新或传入工作区时才接续已有资料。共享工作区的不同入口按同一归属协调，服务锁负责最终写入互斥。

请求后断连时不要重复确认。先等待启动器重新打开，再查询原操作。目标启动失败会保留阶段和工作区；如果原版本仍支持该数据，可由用户明确重新启动原入口，产品不会暗中回退。

换电脑后，Windows 凭据管理器中的登录状态与密钥不会随文件夹复制，需要重新配置。历史资料可读取的范围取决于其格式支持，不能仅根据文件已经复制判断可用。

## 排查问题

缺少组件时，重新解压同一版本的完整发布包。无法写入时，移动整个文件夹到可写位置。启动失败时，查看 var/logs/launcher.log 的阶段信息及产品日志。

登录或证明失效时，按界面提示重新核对对应材料。资料和报告不需要因此删除。开发工具通过受控接口连接界鉴；产品不提供内置模型 API 设置。
