# 在自己的应用中建立可重复的权限检查

> 状态：CURRENT。界鉴保留原 Agent 作为对话与编码入口；这里只介绍普通本地 Web 应用接入。仓库唯一官方示例是协作空间，个人接入应用不随产品发布。

## 先确定要证明的结果

先与 Agent 说清楚“谁对谁的什么资源，可以或不可以做什么”，再选能代表业务结果的具体字段。例如，禁止普通成员把他人的对象状态改为某个受保护状态。界鉴必须同时检查正常允许的操作，不能靠拒绝所有请求得到通过。

只看 HTTP 403 或最终状态不够：应用可能已经发生变化，又把状态恢复了。任意 JSON 日志也可能漏记，不能因为字段齐全就被认定可靠。

## 通用记录方式的接入条件

当前完整证明适用于由界鉴受控启动的本地 Node ESM Web 应用。把需要验证的资源集合接入内建 `jiejian:records` 模块，由记录组件保存这些资源的真实数据和每一步状态变化。应用继续自己实现登录、权限判断和 HTTP 路由；界鉴不替应用批准操作。

这需要修改所选资源的读写方式。它不是给任意现有日志加几个字段，也不是数据库扫描器。没有接入组件的外部数据库、文件、队列和后台任务不在此证明范围内。Node 执行环境用于冻结加载方式和核对运行对应，不是对抗恶意应用代码的安全沙箱。

```javascript
import {openCollection} from 'jiejian:records'
const items = openCollection('work_items')

// 初始化不会覆盖已存在的数据或清空其历史；owner_id 创建后不可转移。
await items.seed('item-1', 'user-a', {phase: 'initial'})

// 在真实 HTTP 请求处理器中，根据已登录账号判断是否允许。
const item = await items.read('item-1')
await items.transact({
  resource_id: item.resource_id,
  subject_id: actualUser.id,
  expected_version: item.version,
  changes: allowed ? [{path: ['phase'], value: 'ready'}] : [],
})
// 必须 await 完成本次写入，再结束 HTTP 响应。
```

`transact` 只接受有限 JSON 字段赋值，不执行 SQL、脚本、回调或外部请求。每次事务至多 8 次赋值，一次请求至多 32 个事务。先改成 `ready` 再改回 `initial` 的两个变化都会被保留。版本不符会拒绝写入，避免把并发变化拼接成同一操作。

宿主把事务关联到真实 HTTP 请求，应用不能自行声明请求已经完成。响应结束后继续写入会被拒绝；没有等待写入、异常关闭或记录不完整时，不能证明“没有发生”。记录的持久日志由 Runtime Worker 独占，损坏或超过 128 MiB 上限会停止提供完整证明，不自动清空或修补。

不要把密码、Cookie、Token 或其他凭据放入资源数据。凭据只通过现有受控账号引用注入。

## 一次完整流程

1. 接入应用源码，在“应用与环境”中预览入口文件、端口和读取范围，然后明确启动受控实例。
2. 在原 Agent 中确定规则，通过 MCP 保存候选；到界鉴核对例子和完整变更，再确认正式权限。
3. 准备实际测试账号，录制业务操作和必要恢复操作，审阅资源与账号的对应关系。
4. Agent 调用 `jiejian_preparation_context`，根据当前动作、账号、资源和输入合同填写证明来源，不猜随机 ID。
5. 在界鉴确认读取范围。预检查由独立 Worker/Runner 核对实际账号、角色、资源所有者、字段与记录组件，不在 API 请求内直接运行目标操作。
6. 预检查可用后，核对资源集合、受保护字段或状态，以及这次采用会替换什么。明确采用后，才能进入正式检查。
7. 查看 PASS、BLOCK 或 INCONCLUSIVE 及证据。继续修改代码时，沿用有效的规则和录制材料，对变化的运行实例、会话和来源重新核对；旧结果保持原样。

## Agent 应填写什么

| 配置 | 含义 |
| --- | --- |
| `source_kind` | `MANAGED_TRANSACTION_RECORDS` |
| `collection` | 应用实际通过 `openCollection` 使用的集合名 |
| `relative_path_template` | `/collections/集合名/{resource_id}`，这是逻辑来源位置，不是应用必须提供的接口 |
| `TRANSACTION_HISTORY_V1` | 核验资源状态变化；`state` 映射到 `data` 下的实际字段 |
| `RESOURCE_FIELDS_V1` | 核验有限 JSON 内容读取；受保护字段必须与已确认业务要求一致 |
| `identity_claims` | 受控账号引用、应用账号 ID、真实身份 GET 路径、账号字段路径和角色字段路径 |
| `target_resource_path` / `target_owner_path` / `target_data_path` | 内容读取时，目标响应中的资源、所有者和业务内容位置 |

资源标识和所有者固定映射为 `resource_id`、`owner_id`。身份接口、角色名、应用入口和业务状态值没有专用白名单。字段能读到只能证明配置可执行；用户还必须确认该字段确实代表要保护的业务结果。

Agent 可以保存候选、修正配置、在既有授权内预检查与正式执行；不能批准规则、采用来源、扩大读取范围或决定安全结论。写请求使用稳定操作标识，响应不明确时查询原回执，不用新键重复提交。

## 旧来源与当前边界

旧 JSON 来源和检查结果保留历史读取。旧应用专用核验不再用于新采用，需要按上述通用方式重新准备。任意 JSON 响应不会自动变成可靠证明；不完整、身份错误、资源不符或没有完成边界时，结果会明确留下缺口。

有限内容读取只核验用户选定的 JSON 字段；额外字段需要独立建立保护要求。金额、时间、唯一性、任意并发业务约束和外部异步后果均不属于此来源的完整证明能力。
