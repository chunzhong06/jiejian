# 知识与文档治理

> 状态：CURRENT。适用于根入口、开发文档、生成参考和人工说明的同步责任。

## 入口与唯一事实

根 `AGENTS.md` 保留行动授权、硬边界、升级和停止条件；`docs/llms.txt` 是 Codex 唯一任务路由；`docs/README.md` 是人类开发入口。两种读者共享正文，不建立第二套 AI 专属知识。

产品文档解释用户流程和交互；架构解释所有者、跨模块事实流和不变量；能力指南回答去哪里修改、怎样验证；协议参考解释格式的目的、消费者、失败和兼容语义；决策按状态保存理由与取舍，提议与历史不冒充当前合同。逐字段类型、函数签名与 import 不在人工正文重复维护。

代码、测试、Schema、migration 与真实运行决定当前实现。文档与它们冲突时先指出并核对，再决定修哪一方，不能用文字补出未实现能力。运行记录、截图、版本计划、执行卡、账本、临时调查留在 `var/` 或用户指定交接载体；版本施工顺序不得写入源码注释或产品文案。产品版本、协议版本和数据库 revision 保留实际兼容语义。

## 按任务阅读

普通修改先读相关能力指南；不知道所有者时才查能力映射。只有改变事务、进程、持久化、公开格式、安全语义或用户流程时，沿链接展开相应架构、协议与约束。已读有效内容不重复加载，生成参考不列为默认必读。路由无入口时先补唯一入口，避免固化全仓扫描习惯。

指南以具体任务组织，给出真实代码入口、关键消费者、直接测试和常见失败；简单工作可以只有几段，不强制标题数量或边界条数。每条详细事实只维护一处，其余页面用一句摘要和链接。当前入口清单归产品导航，视觉行为归交互规范、具体数值归 tokens，材料与复验详细契约归协议参考，迁移历史归数据架构，命令与验证等级归验证规范。能力指南保留操作顺序、实现入口、关键边界和直接测试，不复制完整契约。视觉规范与修改前端的工程步骤分开，数值由 tokens 真源维护。

## 修改与协作

创建文件前确认存在独立读者或稳定职责，已有位置无法清楚承载才新增。代码、协议、模块职责或安全边界变化后同步受影响人工说明；生成部分只经确定性工具更新，不手改生成区掩盖漂移。

文档治理、AGENTS 和工程规则由主线程裁决。执行线程可按已接受设计编写人工文档、同步准确事实；AGENTS 与工程规则只能按合同的准确裁决修改，不自行增加约束。UI、交互和产品文案仍由主线程设计与实现，见[执行线程协作](执行线程协作.md)。

移动或删除前确认有效内容去向、实际消费者和历史可追溯性，更新链接，不留长期转发文档。已退役实现不写成 CURRENT；独立保留的协议或算法必须明确其 reader 和适用范围，不能冒充生产主链。ADR 只用提议、已接受、已取代、已废弃、已拒绝；默认路由仅指向仍有效内容。

## 验证文档

用 `dev.ps1 docs` 检查本地链接及章节锚点、路由状态、数据库 head 和生成漂移；生成输入变化时先 `docs -Update`。确定性路径检查覆盖当前人工正文中的静态路径（不把提议、历史决策和生成符号清单当作当前实现），检查真实静态源文件和测试路径；命令、通配符、动态运行目录和示例值不冒充路径。不要为了通过检查创建空目录。

至少用受影响的实际任务走一遍“路由、指南、实现、直接测试”，确认没有被旧链或重复正文误导。链接存在只证明可达，不证明文字正确。独立执行线程探针只在用户授权委派时使用，不因文档检查自动创建聊天。

正式测试入口和失败后的检查点复用见[验证](../开发/验证.md)；工作区权限与停止边界见[工作区与权限](工作区与权限.md)。
