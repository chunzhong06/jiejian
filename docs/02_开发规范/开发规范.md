# 开发规范

本文是面向日常实现的简版规则。冲突时以根目录 [AGENTS.md](../../AGENTS.md)、[项目设计规范](项目设计规范.md)和已接受 ADR 为准。

## 1. 开始前

- 确认唯一项目根目录是 `D:\常用\BJUT\全国大学生信息安全竞赛\2027\界鉴`。
- 先读与任务相关的项目规范、开发路线图和 ADR；代码不得静默偏离。
- 检查工作树，保留用户已有修改，不用清理命令掩盖差异。
- 首次写入前确认根 ACL 继承开启、属主为 `LHQ\LHQ` 且 FullControl 可继承。

## 2. 分层与安全

- 首版保持模块化单体，不主动拆微服务。
- CLI、未来 GUI/API 和 CI 复用同一应用服务与领域规则。
- 所有主动目标请求只允许 Runner 发出；CLI、API 和 Worker 不具备目标请求能力。
- Domain 不依赖 SQLAlchemy、httpx、Typer、Playwright 或具体 LLM SDK。
- Run lifecycle、Job state 和安全 verdict 分开保存。
- LLM 只能提出候选或解释，不得直接决定漏洞结论。
- 秘密、缓存、数据库和运行工件不得写入源码目录或提交 Git。

## 3. 代码粒度

- 按稳定职责组织模块，不为每个动作创建薄文件。
- 私有辅助函数默认至少需要三个生产调用点；领域不变量、安全边界、框架入口和独立清理职责可以例外。
- 零调用且没有框架发现、当前需求或测试约束的符号应删除或延后。
- 新抽象需要两个真实实现或明确隔离需求。
- 超过约 500 非注释行时检查是否混合多个演进方向；不为凑行数合并无关职责。

## 4. 数据与协议

- 公共数据结构必须带 `schema_version`。
- 不兼容公共接口或文件格式变化必须有迁移说明。
- RunnerInputV1/RunnerResultV1 V1 不得原地改变语义；模型、协议文档和签入 Schema 必须同步。
- 数据库迁移只向前；生产建库使用 Alembic，不用 `create_all` 替代。
- 所有绝对协议/数据库时间使用调用方提供的 UTC Unix 微秒整数。

## 5. 错误和输出

- 使用稳定 `JiejianError` 和错误码，不回显 SQL、路径中的秘密、凭据或原始不受信任值。
- 日志、异常、事件、Evidence 和报告都必须在落盘或输出前脱敏。
- 基础设施错误不能伪装为 `INCONCLUSIVE`；`INCONCLUSIVE` 只表示正常完成但证据不足。

## 6. 验证

- Python 命令同时设置 `PYTHONDONTWRITEBYTECODE=1` 并使用 `python -B`。
- 语法检查使用 `ast.parse`，不用 `py_compile` 或 `compileall`。
- pytest 禁止写缓存，临时目录位于受控 `var/` 并精确清理。
- 完成前检查 `__pycache__`、`.pyc`、`.pytest_cache`、var、工作树范围和秘密泄漏。

测试布局和不变量见[测试规范](测试规范.md)，模块依赖见[代码组织](代码组织.md)。
