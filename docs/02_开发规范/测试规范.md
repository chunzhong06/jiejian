# 测试规范

## 最终目录

```text
tests/
├─ conftest.py
├─ architecture/    # 模块依赖和入口约束
├─ domain/          # 共享生命周期枚举与纯模型基线
├─ runtime/         # 配置、doctor、日志、错误和脱敏
├─ verification/    # 输入、安全范围、计划、HTTP、判定
├─ storage/         # Alembic、SQLite、Repository、UnitOfWork
├─ execution/
│  ├─ protocol/     # Runner V1 与 Schema 漂移
│  ├─ runner/       # 隔离 Runner 进程
│  ├─ worker/       # Job、租约、取消、恢复、发布
│  ├─ recording/    # 浏览器边界、持久 Recording 和 FlowDraft
└─ e2e/             # CLI safe/vulnerable/inconclusive 门禁闭环
```

测试按业务职责归档，不按 `unit/integration` 两个大桶分组。文件内部仍可根据是否使用数据库、进程或网络环回决定 fixture 范围。

测试目录的详细地图、最小定位集合和 Windows 命令见 [`tests/README.md`](../../tests/README.md)。根 `tests/conftest.py` 共享样例服务和项目/请求夹具；`tests/execution/recording/__init__.py` 是 pytest 同名模块收集边界，二者均非生产兼容层。真实边界测试使用显式 `browser`、`process`、`database`、`e2e` 和 `slow` markers，可用 `-m` 组合筛选。

## 必测不变量

- 非法生命周期转换失败，生命周期和 verdict 不混写。
- ACTIVE Contract 不可原地修改。
- 相同输入与 seed 产生相同 MutationPlan。
- 未授权目标不会发出请求，HTTP 重定向继续校验范围。
- 缺少必要观察者不能得到 `PASS`。
- HTTP 拒绝但后端发生越权副作用时得到 `VULNERABLE/BLOCK`。
- 秘密不进入日志、错误、数据库、Runner JSON、Evidence 和报告。
- Runner 输入/结果拒绝未知字段、未知版本、重复键、非有限数和超限字节。
- 签入 JSON Schema 与 Pydantic 生成结果一致。
- 并发幂等提交只创建一个 Run/Job，并发 claim 最多一个 Worker 成功。
- 旧 Fencing Token 不能续租、更新、发布或补写完成态。
- 状态更新和连续 Job Event 同事务提交或回滚。
- 数据库完成态不能先于工件发布。
- 发布后数据库提交失败可幂等恢复，不重复 Evidence 或事件。

## 测试数据与副作用

- 主动网络测试只使用项目内 `127.0.0.1` safe/vulnerable 样例，不访问公网。
- 每项测试使用唯一临时目录和数据库，不写源码树或真实 `var` 数据。
- 不通过删除、跳过或放宽失败断言满足验收。
- 测试结束后不得残留缓存、临时数据库、Runner staging 或样例进程。

## 阶段 5.2 契约分析测试补充

- 相同来源、版本和输入重复分析必须得到相同候选排序、候选 ID、指纹、问题顺序和规范哈希。
- 需求模板、Flow/确认 FlowDraft、OpenAPI 和 FastAPI AST 的正反路径必须覆盖；源码适配器不得 import、执行或越界读取。
- 等价候选必须合并且保留 provenance；冲突、歧义、不可执行、观察器不足和 LLM/显式需求冲突必须阻断 REVIEW/ACTIVE。
- 六类漂移、规则/来源/状态差分和 legacy/治理历史 Contract 解析必须有直接测试；行为漂移不得改写 Run verdict。

## 阶段 5.3 受限 LLM 候选测试补充

- 无 provider 时离线治理、assessment 和激活测试不受影响；provider 调用必须发生在数据库事务之外。
- 送模输入只包含显式授权 Requirement 的脱敏、有界规范 JSON，不得包含 locator、源码、环境变量或秘密；原始 prompt/响应不得落盘。
- 输出必须覆盖严格 schema、未知字段、Markdown、超限、越权 Requirement、非法 Rule、重复候选和 provider 失败路径；错误码稳定且不回显原始异常/响应。
- LLM metadata 必须哈希一致、Repository 往返一致、Candidate ID 可幂等复用；0004→0005 和新库迁移均需验证，旧非 LLM Candidate 保持兼容。

## 阶段 5.4A 治理 Contract 绑定测试补充

- 0005→0006 和旧库升级必须保留既有项目，治理绑定成对字段为空；部分绑定、非正版本和跨项目/非 ACTIVE 版本必须拒绝。
- 激活治理版本与 ProjectRecord 绑定必须同一事务提交；同一或不同 contract 的新版本激活都必须前移绑定，旧执行请求保持不变。
- 未绑定项目的 API Run 使用 YAML Contract；已绑定项目使用精确 ACTIVE 治理快照；治理绑定失效时不得静默回退 YAML。
- 显式 `activate_contract` 清空治理绑定，`revalidate` 保留治理绑定；历史 resolver 继续以经 hash 校验的执行请求为执行时真源。

## 阶段 5.4B 契约工作台与治理 REST 测试补充

- 工作台服务与 REST 必须覆盖 Requirement→确定性 Candidate→DRAFT→REVIEW→ACTIVE、激活绑定、修订、assessment/diff/drift 和历史 Run Contract 查询。
- 派生请求必须覆盖阻断零部分持久化、重复调用 Candidate 幂等复用、跨项目引用拒绝及严格输入；Requirement 来源定位/哈希由服务生成。
- 默认无 provider 时 LLM 端点返回稳定 `LLM_PROVIDER_UNAVAILABLE` 且离线闭环不受影响；注入受控 provider 时只验证结构化 provenance，不落盘原始 prompt/响应。
- OpenAPI/请求模型不得出现任意源码路径、外部 URL、secret、provider 或模型配置字段；旧 `/contracts` 文件接口和 5.4A Run 快照回归必须通过。

## 阶段 5.4C CLI 与 GUI 建约测试补充

- CLI 必须使用同一 var-dir 连续覆盖 workspace、Requirement、Flow-only derive、DRAFT、submit、activate、assessment、drift，并验证非法 transition 与稳定 JSON 错误。
- CLI 每个治理动作必须通过 `ApplicationContext`/`ContractWorkbenchService`，不得调用本地 REST 或复制领域算法；history 使用当前 var-dir 的执行请求解析。
- `frontend/src/features/contracts/` 必须覆盖 workspace 刷新恢复、默认 LLM unavailable、Requirement/derive、阻断未落盘、Candidate 建草稿、submit/activate 和显式 YAML 兼容入口。
- 前端通过 `frontend/src/api/contracts.ts` 等能力叶 API 访问治理 REST；不得在浏览器保存治理正文、实现合并/assessment/状态机或接收 provider/key/prompt 配置。
