# ADR-0033：工件发布、完整性与恢复边界

- 状态：已接受
- 日期：2026-08-19
- 适用范围：Runner staging、manifest、Evidence、Report package 和恢复

## 背景

Runner 产生的文件可能不完整、越界、泄露秘密或与数据库身份不一致。数据库完成态不能只代表进程退出成功，必须代表已校验的事实和工件已经安全发布。

## 决策

Runner 只能写受限 staging。Worker 校验协议、run/job/attempt/fencing 关联、路径、大小、预算、脱敏、内容 hash、语义 hash 和 manifest 后，使用原子 publication 发布不可变工件。数据库完成事务只引用已发布内容。

`Evidence` 和报告包发布后不可变。数据库提交失败而目录已经发布时，由 reconciliation 按 manifest 和 hash 幂等补齐；不完整、篡改、重复或孤儿工件只能拒绝、隔离或进入明确恢复路径。

## 理由与取舍

manifest、hash 和原子替换缩小崩溃窗口并使结果可审计。代价是需要 staging 清理、恢复扫描和有限的磁盘预算。

## 影响

`report.json` 是报告语义真源；HTML、SARIF、JUnit 只能是确定性投影。发布失败、清理失败或完整性不足不能改变 Verification Verdict，也不能伪造 Gate 结果。

## 迁移与兼容

只接受当前 Artifact、Evidence、Report package Schema 和 publication 规则。旧开发工件、旧报告或未知 wire format 不自动兼容。
