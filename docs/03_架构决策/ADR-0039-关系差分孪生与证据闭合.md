# ADR-0039：关系差分孪生与证据闭合

- 状态：已接受
- 日期：2026-08-20
- 适用范围：PermissionContract、DifferentialExperimentPlan、SecurityEffectFact、Verification、行为差分与碰撞实验

## 背景

只看 HTTP 表面或把所有 Observer 失败一律降为 INCONCLUSIVE，会同时产生漏报和假安全。权限验证需要明确预期安全效果、ALLOW 控制、DENY 变体、唯一变化维度、基线一致性和异步闭合；并发碰撞还需要与普通串行 case 分离。

## 决策

Action 使用 `effect_ids` 引用 Contract 内的 Security Effect Manifest，不再保留 `side_effect`。首批效果类型为 STATE_MUTATION、DATA_DISCLOSURE、OBJECT_CREATION、EXTERNAL_DISPATCH、RESTRICTED_FUNCTION_INVOCATION 与 CREDENTIAL_ACCESS。旧 `side_effect: true` 不做静默推断。

Coverage 仍只消费 Contract 并产出 PermissionMutationPlan；其后由 DifferentialExperimentPlan 为每个风险 case 建立 ALLOW 控制与 DENY 变体。孪生对必须冻结 action、workflow、target、非身份输入、逻辑资源、初始业务状态、effect manifest、observer bindings 与 normalization，只允许声明的 subject、relation、context 或显式 workflow state 发生变化。token、Cookie 等秘密字节不参与孪生指纹。

基线只接受 EXACT_RESTORE 或 NORMALIZED_EQUIVALENCE，并绑定逻辑资源句柄、指纹和版本化 normalization。仅调用 reset 不代表基线有效。时间闭合只接受 IMMEDIATE、TERMINAL_STATE、BOUNDED_QUIESCENCE 与 EXCLUSIVE_CHANNEL_WINDOW；任务仍在运行或观察窗口未闭合时不能 PASS。

Observer 原始事实在效果聚合边界形成 `SecurityEffectFact`。任一权威、完整、可靠、相关的通道确认禁止效果即可 CONFIRMED，辅助通道失败不能抹去该事实；只有全部必需通道完整、可靠、相关地证明不存在且时间闭合，才能形成 ABSENT，其余为 UNKNOWN。

唯一 Verification 消费执行事实、效果事实、孪生有效性、基线完整性和时间闭合。DENY 变体出现权威 CONFIRMED 或确定性 ACCEPTED 即 BLOCK；PASS 必须同时满足请求被拒绝、全部效果 ABSENT、闭合 CLOSED、ALLOW 控制有效且基线一致；其余为 INCONCLUSIVE。Finding 身份保持既有稳定规则。

数据披露使用 run-specific HMAC/canary 的版本化投影，只持久化 projection、digest、match 与 correlation，不保存正文、PII 或密钥。行为差分复用现有 Baseline/Gate，只比较规范化的 Contract、workflow、twin、baseline、execution、effect vector、充分性、闭合和 Verdict。

普通 case 继续 `max_parallel_cases=1`。并发验证由独立 `CollisionExperiment` 承担：先顺序验证正常语义，再逐轮恢复并核对同一 baseline fingerprint，按 barrier 同步碰撞组并重复。实验具有独立的 request、repetition、request timeout、experiment timeout 与 synchronization timeout 预算；请求不完整时停止后续轮次，始终执行注入的清理职责。

碰撞结论不根据“看起来同时”或 HTTP 表面状态推断。只有跨至少两轮、且对应请求和业务不变量观察均完整时重复出现的未授权效果、重复副作用、非法状态、额度突破或撤销后访问成功形成 BLOCK；延迟变化、响应顺序变化、偶发 500、一次更快、只出现一次的业务异常或不完整观察只能作为线索并形成 INCONCLUSIVE。顺序语义有效、基线一致、全部轮次与业务不变量观察完整且没有异常或线索时，才允许 PASS。HTTP/2 精确同步若未来加入，也只能留在这一独立边界。

## 理由与取舍

非对称证据规则保留“确认存在”的强证据，同时对“证明不存在”要求完整闭合，避免辅助观察失败覆盖真实漏洞，也避免把缺证据当安全。代价是 PASS 门槛更高，并需要显式效果、孪生、基线和闭合配置。

## 影响

Contract、Profile、Runner/Evidence 与结果解释同步升级；GUI/CLI 以安全效果、控制组、基线、闭合和结论解释结果。行为差分与碰撞实验复用同一事实语言，不创建第二套 Verification。

## 迁移与兼容

仓库 Contract、样例和 fixture 一次性迁移至 Security Effect Manifest。旧 `side_effect`、无孪生/基线/闭合的执行快照和旧 Evidence 不兼容读取。
