# ADR-0028：开发者技术文档体系与真源分层

- 状态：已接受
- 日期：2026-08-19
- 适用范围：开发者技术知识、架构说明和公共边界文档

## 背景

产品入口、开发约束、当前架构、历史决策、机器协议、数据库迁移和研究结论面向不同读者，却曾混在同一目录层级并相互复制。重复内容会让实现、测试和文档出现多个“当前真源”。

## 决策

建立固定的技术文档分层：`AGENTS.md` 负责开发行为，根 `README.md` 负责产品使用，`docs/README.md` 负责技术路由，Architecture 描述当前是什么，ADR 解释为什么，Protocol/Data 和 Schema 定义机器边界，Migration 定义数据库结构，Roadmap 只描述下一步，Experiment 只保留长期研究结论，代码和测试是最终运行事实。

CURRENT 文档必须自包含当前边界；已经被 CURRENT 和长期 ADR 完整吸收的阶段过程正文从当前工作树移除，历史仍由 Git 恢复，不建立默认可见的 archive。ADR 状态只使用“提议、已接受、已取代、已废弃、已拒绝”。

## 理由与取舍

分层降低首次阅读成本并避免 Architecture 复制历史。代价是跨层变化需要同步检查链接和真源；该代价通过 `docs/README.md` 路由和每篇文档的相关真源部分控制。

## 影响

技术文档按 `01_技术规范`、`02_架构设计`、`03_架构决策`、`04_协议与数据`、`05_路线与研究` 组织。删除旧文档时不创建长期 wrapper；被移除的过程历史由 Git 保留，当前决策理由由仍在索引中的 ADR 保留。

## 迁移与兼容

仍约束当前实现的 ADR 保持原编号和文件名；已被完整吸收的过程 ADR 只在完成理由与链接迁移后移除。该决策不改变生产代码、公共 API、Schema、migration 或运行产物。
