# ADR-0035：产品入口与控制面边界

- 状态：已接受
- 日期：2026-08-19
- 适用范围：GUI、CLI、CI、API、ApplicationCore、任务展示和结果读取

## 背景

界鉴需要同时服务普通用户、自动化和 CI，但入口不能各自实现权限治理、执行编排或结果判定。产品展示还必须让用户区分生命周期、证据、结论和门禁。

## 决策

GUI、CLI、API 和 Worker 共享 ApplicationCore。API 是本机 loopback 的薄控制面，只负责严格解析、授权、资源/任务/事件/结果读取和脱敏错误映射，不发目标请求。CLI/CI 复用同一工作流，Human、JSON 和 CI 输出语义分离。

GUI 使用任务型信息架构：`/workspace`、`/apps/access`、`/apps/rules`、`/checks/start`、`/checks/results`、`/checks/history`、`/advanced/recording`、`/advanced/models`、`/advanced/system`。用户术语使用工作台、应用接入、权限规则、开始检查、检查结果、历史变化和高级能力。

结果展示分离生命周期、Evidence 完整性、Verification Verdict 和 GateResult。PASS 表示当前规则覆盖范围内未发现越权，BLOCK 表示发现可能的权限越界，INCONCLUSIVE 表示证据不足，INVALID 表示结果无效；四态不能互相替代。

## 理由与取舍

共享 ApplicationCore 避免 GUI、CLI、CI 形成不同安全语义；任务型页面让用户按目标动作理解产品。代价是人类展示与机器协议必须保持两套明确的表示边界。

## 影响

API/GUI 不直接访问目标；断开控制面不取消任务也不代表任务成功。事件序号支持恢复读取。历史变化只比较完整终态运行，高级能力不改变主执行链。

## 迁移与兼容

当前 API 路径为 `/api`，CLI 命令和输出以实际 help 为准。旧 GUI 页面组织、旧 API 路径和旧内部入口不作为兼容承诺。
