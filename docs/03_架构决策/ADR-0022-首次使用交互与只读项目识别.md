## 背景

首次使用者需要先知道检查对象、读取范围、缺少的信息和下一步；系统不能把内部执行模型、模型服务或未知命令暴露为必填前置条件。浏览器拖入目录在 Windows 上不能可靠提供绝对路径，因此系统目录选择必须由回环后端显式提供真实端口。

## 决定

1. 欢迎页使用标题“检查你的应用有没有权限越界”，主动作是“选择应用文件夹”，次动作是“试用内置演示”；模型服务不是必填。C3 已将该入口落到 React 向导，C4 已验证真实演示提交、后台完成、验证和报告导航。
2. 识别页展示技术、启动候选、配置/API/认证线索和缺项，并说明“我们只读取常见配置，不会运行脚本或安装应用依赖”。补充页固定询问启动方式、测试账号、允许检查的地址和恢复方式；每项说明用途、例子、必填性和安全影响。
3. 文件推断出的命令、地址、私网授权、写操作和重置方式必须由用户确认。系统不得自动执行未知命令、安装目标依赖或扫描公网。“快速检查”使用最小安全默认值；“高级配置”承载多身份、复杂权限、观察器、预算和 CI，不增加业务阶段。
4. 目录选择和识别是独立显式动作。`FolderSelector` 通过 ApplicationContext 注入；Windows 默认实现以固定解释器启动短生命周期 UI 子进程，在子进程主线程延迟导入标准库 `tkinter.filedialog`，为原生对话框提供显式、置顶的透明父窗口。子进程环境只保留 Python/系统必需项和 Windows Known Folder 所需的非敏感桌面变量，不继承秘密，也不得把系统缓存落入仓库。选择器单实例串行，等待预算为 120 秒；超时、并发、非 Windows、headless 或桌面不可用均返回稳定的 `unavailable` 并提示手工绝对路径，取消返回 `cancelled`。前端等待上限为 125 秒，必须显示系统窗口提示并在所有失败路径恢复操作。选择动作只返回目录，不扫描、不执行目标命令。
5. C1 只提供 `/api/v1/onboarding/select-folder` 和 `/api/v1/onboarding/inspect` 所需的应用能力与回环适配；C2a 提供会话、快速 bundle 和排队编排；C2b 提供可信内置演示进程和同一排队链；C3 提供首次使用前端向导、刷新恢复、六阶段指导和可读错误/结果；C4 已完成真实演示提交、发布、浏览器导航、刷新恢复和三种窄屏几何验收。后续 D 由 Sol 另行交接。
6. C1 识别必须使用绝对存在目录的 canonical 路径；拒绝根 symlink/junction/reparse，子项不跟随并给出警告。扫描条目总数最多 256（目录、普通文件、`.env`、非 allowlist 条目各计一次），最多两层；单文件 256 KiB、总读取 1 MiB、候选 32 项，并限制在 allowlist 文件名/后缀。枚举逐项有界，未确认整层条目数前不得无界物化或排序。
7. C1 只读常见配置和公开接口描述结构信号，不读源码正文、数据库、秘密或 `.env` 内容；`.env` 只报告存在。`package.json` 仅暴露脚本名称对应的 `pnpm/npm/yarn run` 候选，候选固定标记需确认且未执行。禁止 shell、包管理器、目标运行时、网络、Git 和外部命令。
8. 结果使用版本化字段 `detected_types`、`start_candidates`、`config_hints`、`interface_hints`、`auth_hints`、`missing_items`、`warnings`。错误使用稳定脱敏代码，映射为输入无效/路径不安全 400、读取预算 413、选择器不可用 503；取消不视为错误。
9. 普通路径不显示 Project bundle、Contract、Flow、Runner、Job、Attempt、fencing、observer、GatePolicy、schema_version。高级诊断出现“租约”时固定解释：“系统给后台检查任务的临时占用凭证，用来避免同一任务被重复执行；通常无需操作。”错误按“发生了什么—可能原因—现在怎么做”展示，内部诊断仅可展开。
10. C2a 快速检查只支持带显式端口的 IPv4 回环 `127.0.0.1`；拒绝 `::1`、`localhost`、其他域名、用户信息、路径、查询、片段、其他私网和公网目标。高级配置保留现有 TargetScope 能力。C2a 会话只持久化非秘密 JSON，两个凭据仅存在当前进程内存；快速 bundle 经现有 loader、项目注册和执行提交服务排队，不执行命令、不探测目标、不发目标请求。
11. C2b 内置演示只能启动固定的 `product.backend.workflows.onboarding.demo_target` vulnerable 变体和随机端口；不接受用户命令、模块、工作目录、地址或环境。ready 只取子进程首行并严格匹配 `http://127.0.0.1:<port>`，超时或格式错误即停止进程。演示子进程只获得最小基础环境和两个固定 sample token；token 只在内存 vault 与子进程环境中存在，不进入会话、bundle、日志、响应或异常。演示服务复用 C2a 的会话、凭据、bundle、注册和提交能力，API 不发送目标请求；`start_worker=False` 时任务仍只进入待处理队列。

## 影响与验证

C1/C2 新增 onboarding 能力区、注入式目录选择器、受限 discovery、可信演示生命周期和回环 API；不改变 Verification、Execution、Worker/Runner、Storage、migration、公共机器 Schema、现有六阶段页面或启动脚本。验证覆盖选择器子进程固定入口、桌面环境白名单与秘密隔离、父窗口、取消/不可用、超时/并发收敛、前端等待恢复，以及绝对路径、链接与 reparse 边界、读取预算、环境文件和脚本正文不泄漏、演示 ready/停止/并发/秘密隔离、API 错误映射及架构依赖。演示 smoke 只验证 ready 信号和清理，不发送目标 HTTP。
