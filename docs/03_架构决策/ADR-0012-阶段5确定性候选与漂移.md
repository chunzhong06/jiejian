# ADR-0012：阶段 5 确定性候选与漂移

- 取代者：ADR-0029、ADR-0030
- 当前阅读提示：本文保留历史决策；当前边界以 ../README.md 和相关 CURRENT 文档为准。

## 状态

已取代

## 背景

阶段 5.1 已提供需求、候选和版本化契约的治理存储，但还不能从来源稳定地产生候选、识别冲突或解释契约与当前能力的差异。阶段 5.2 需要完全离线、可重复的分析闭环，同时保持 `SecurityContract`/`ContractRule` 为唯一执行正文，并让阶段 4 的历史 Run 在不读取当前 YAML 的情况下定位执行时快照。

## 决策

1. 确定性需求解析只支持公开模板 `rule id=<slug> kind=<RuleKind> observers=<csv> severity=<level>`，逐行解析；未知文本、缺字段、动态值和语法错误返回稳定 `AMBIGUOUS_SOURCE`，不猜测、不生成候选。
2. Domain Flow 适配器只消费已编译 `Flow`；`FlowDraftV1` 的确认编译由 Application 调用现有 `FlowDraftReviewer` 后再进入 Domain。GET、非 GET 和敏感字段分别映射现有 `FOREIGN_READ`、`UNAUTHORIZED_SIDE_EFFECT`、`PRIVILEGED_FIELD`，每个候选保留 Flow/step 定位。
3. OpenAPI 适配器只消费受控内存 Mapping；拒绝外部 `$ref`、越界路径和无效操作。FastAPI 的路径解析、根目录边界、大小/后缀/秘密路径分量和读取由 Application 完成；Domain 只接收已授权源码文本或 bytes、规范 locator 与 hash 做 AST 静态分析，不 import、不执行。
4. 候选 ID、规则指纹、合并顺序、问题排序、审阅评估和 Contract Version Diff 均由规范 JSON/SHA-256 确定。等价候选合并并保留全部 provenance；同 Rule ID 不同正文、歧义、不可执行和观察器不足为阻断项。Candidate 不因来源变为可信。
5. `ContractReviewAssessment` 是提交 REVIEW 和激活前的统一确定性门禁。LLM 仅作为 `source_type=LLM` 的离线候选数据表达，若与显式 Requirement/候选冲突则产生 `LLM_REQUIREMENT_CONFLICT`；本子阶段不调用模型。
6. `DriftReport` 只保存六类漂移的结构化条目：需求未覆盖、规则从当前 Flow/路由能力消失、路径/字段能力变化、观察器不足、已验证行为指纹变化、LLM 与显式需求冲突。行为漂移只接受调用方提供的完整性已验证指纹，不建立 RegressionBaseline，也不改变 Run verdict。
7. `ContractVersionDiff` 只比较规则增删改、状态和来源集合，输出规范哈希，不生成自然语言结论。历史解析以经 `request_hash` 校验的持久执行请求为执行时 `SecurityContract` 真源，并附带精确治理版本；有请求时来源枚举为 `EXECUTION_REQUEST`，无请求时才退回治理版本快照。legacy Run 只读持久请求，不读取当前 YAML。

## 影响与迁移

本子阶段不新增数据库表、不改变 Runner/Worker 协议、不接入 API、CLI、GUI 或 LLM SDK。Domain 保持纯模型/函数，文件和 FlowDraft 副作用收敛在 Application；既有 5.1 三表、阶段 4 执行请求和 Run verdict 保持兼容。

## 回滚

停用候选、评估、漂移和历史解析服务即可回到阶段 5.1；不删除 5.1 治理记录、阶段 4 YAML 绑定或历史执行请求。无数据库 downgrade。
