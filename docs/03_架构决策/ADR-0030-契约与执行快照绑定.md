# ADR-0030：契约与执行快照绑定

- 状态：已接受
- 日期：2026-08-19
- 适用范围：ACTIVE Contract、ExecutionProfile、执行计划和冻结请求

## 背景

用户配置、当前治理版本和真正执行的输入具有不同生命周期。执行期间重新读取可变 Profile、Contract 或 Flow，会使历史结果无法解释，也可能让治理变化悄悄改变目标请求。

## 决策

ExecutionProfile 是用户执行配置，当前只允许 WEB target，并显式保存 Contract 引用、身份、action/observer bindings、预算、secret refs 和指纹。登记时检查项目治理绑定、ACTIVE 状态、计划和来源 fingerprint；漂移默认拒绝。

提交时将 ACTIVE Contract、Coverage/PermissionMutationPlan、bindings、目标范围、预算和指纹冻结为 `ExecutionProjectSnapshot`，再写入 `PersistedExecutionRequest`。Worker 和 Runner 只消费冻结请求，不重新读取可变 Profile、Contract 或 Flow。

## 理由与取舍

快照绑定保证结果可复现、可审计并阻止治理漂移影响运行。代价是配置更新必须重新登记或显式接受变化，旧请求不会自动跟随当前配置。

## 影响

执行请求同时保留 `contract_id`、`contract_version`、plan/binding fingerprint 和完整执行快照；旧 Run 的安全语义不因新版本激活而改变。

## 迁移与兼容

缺少绑定、版本不匹配、fingerprint 不一致或未知结构时严格失败。旧开发 Profile、Run 和请求格式不提供兼容读取。
