# ADR-0018：阶段 5-O3A 发布前结构兼容重置

- 取代者：ADR-0027、ADR-0032
- 当前阅读提示：本文保留历史决策；当前边界以 ../README.md 和相关 CURRENT 文档为准。

- 状态：已取代
- 日期：2026-08-12
- 范围：阶段 5-O3A 门禁 B 子批次 1～3，前端/CLI 私有兼容导出、Python facade/聚合根及零调用通用模型清理
- 关系：保留 ADR-0017 历史原文；本决策只记录发布前结构兼容重置，不静默改写既有决策

## 背景

阶段 5-O3 已完成能力实现迁移。用户明确批准在发布前重置阶段 5-O3 以前的旧代码结构 import 兼容，不提供弃用周期，也不因假设的仓库外消费者保留兼容壳。永久稳定产品入口、公共协议、数据库、历史数据以及安全和状态语义继续保持。

## 决策

1. 旧 Python 内部 import 路径立即失效；新能力叶模块是唯一代码真源。
2. `product.backend.cli:main` 及 CLI 命令、参数、输出、脱敏和退出码保持不变；`product.backend.cli` package-root 只导出正式 `main`。
3. 前端旧 `App.tsx`、`ContractPage.tsx`、`api/client.ts` 和兼容测试入口删除，不创建替代 wrapper；生产入口直接使用能力叶模块。
4. 永久产品入口、协议、数据库和历史数据兼容不受本次结构重置影响。
5. ADR-0017 保留历史原文，不因本决策静默改写。

门禁 B 分三个可恢复子批次实施，当前三个子批次均已完成：子批次 1“前端与 CLI 私有兼容导出”、子批次 2“Python facade、聚合根和兼容委托”、子批次 3“通用生命周期模型与 RunService 安全测试迁移”。子批次 2 收缩了 `application`、`domain`、`worker`、`recording`、`api.schemas`、`runner` 与 `recording_runner` 包根；子批次 3 保留七类生命周期枚举和 `DomainModel`，删除零生产调用通用实体、`state_machines.py` 和 `verification/pipeline.py`，并将安全 E2E 迁移到 CLI→Job→Worker→隔离 Runner→publication 链路。

## 验收边界

架构测试保护 CLI 根仅含 `main`、Python facade/聚合根不再重导出、仓库生产/测试从具体叶模块导入、前端兼容文件不存在且 `main.tsx` 直接装配 `app/ControlShell`；同时保护 `domain/lifecycle.py` 仅承载七类共享枚举与 `DomainModel`、不存在 `state_machines.py`/`verification/pipeline.py`，安全 E2E 经过正式 Job/隔离 Runner 并保留历史报告读取 fixture。本决策不修改公共协议、Schema 字段、数据库、历史数据语义、安全断言、Runner 隔离或工件读取兼容。

发布前包验收结论：wheel 通过 Hatchling 构建期映射携带原仓库真源的 Alembic 配置、迁移链和公共 JSON Schema；源码真源路径 `product/backend/alembic.ini`、`product/backend/migrations/**`、`product/protocols/schemas/**` 不移动、不复制，安装态 Storage 通过稳定资源定位使用同一内容。
