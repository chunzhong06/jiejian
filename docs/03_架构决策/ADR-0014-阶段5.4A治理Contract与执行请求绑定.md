# ADR-0014：阶段 5.4A 治理 Contract 与执行请求绑定

- 取代者：ADR-0030
- 当前阅读提示：本文保留历史决策；当前边界以 ../README.md 和相关 CURRENT 文档为准。

## 状态

已取代

## 背景

阶段 5.1–5.3 已能创建、评估、审阅和激活 `ContractVersion`，但阶段 4 的 API Run 仍从项目登记的 YAML 路径加载 Contract。若不绑定，治理 ACTIVE 版本不会进入真实执行主链。

## 决策

1. `projects` 增加可空且成对出现的 `governed_contract_id` 与 `governed_contract_version`。0006 只向前增加列；旧项目迁移后保持未绑定。
2. `ContractGovernance.activate_review` 在同一 `UnitOfWork` 内完成旧 ACTIVE→SUPERSEDED、新版本 ACTIVE 和 ProjectRecord 绑定更新。激活同一或不同 `contract_id` 都将项目绑定前移到被激活版本。
3. `ProjectCatalog.current_bundle` 仍只验证项目、Flow 和 YAML fallback 的来源完整性，不把数据库 Contract 伪装成文件。未绑定项目的执行请求使用该 YAML Contract。
4. API 新 Run 使用统一执行请求入口：先验证 `current_bundle`，再读取完全匹配项目、Contract ID 和版本的治理版本，并要求治理记录与其 `SecurityContract` 快照均为 ACTIVE。治理绑定缺失、跨项目、版本不匹配、缺失或非 ACTIVE 时稳定拒绝，不回退 YAML。
5. 持久执行请求中的 Contract 快照是真实执行时正文；治理版本只提供当前生命周期和 provenance 关联。绑定变化不修改旧 Run 或旧 request。
6. 显式 `activate_contract(path)` 表示切回 YAML Contract，在更新 ProjectRecord 时清空治理绑定；`register`/`revalidate` 保留既有治理绑定。录制仍使用项目/Flow，不因绑定发送目标请求。

## 影响与迁移

新增 `0006_stage5_governed_project_binding`、ProjectRecord/ORM/Repository 字段和统一 API Run 请求解析入口。CLI 显式项目/Contract 文件路径保持原有构建路径；不改变 Runner/Worker/Verification/Verdict 协议。

## 回滚

停止治理 Contract 绑定入口即可继续使用未绑定 YAML 项目；数据库只向前迁移，恢复旧数据库需使用备份或旧版本新库重建。
