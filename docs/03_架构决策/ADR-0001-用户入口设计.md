# ADR-0001：用户入口与启动方式

- 取代者：ADR-0035、ADR-0036
- 当前阅读提示：本文保留历史决策；当前边界以 ../README.md 和相关 CURRENT 文档为准。

- 状态：已取代
- 日期：2026-08-08
- 适用版本：V1

## 背景

界鉴同时包含项目配置、多身份登录、可见浏览器录制、契约确认、后台测试、证据展示和CI门禁。单一入口无法同时兼顾交互体验、自动化、竞赛演示和可测试性。

需要在CLI、GUI、TUI、REST API、原生桌面和容器启动方式之间确定主次，避免首版维护多套重复逻辑。

## 决策

采用以下入口组合：

1. GUI是主要用户界面。
2. CLI是能力基线、首个实现入口和自动化入口。
3. CI模式复用CLI，不另建执行引擎。
4. REST API是GUI和CLI可选远程模式的控制面，不作为普通用户主入口。
5. TUI不进入V1。
6. 原生桌面壳不进入V1。
7. Docker Compose作为团队部署和可复现实验入口，不作为本地录制的唯一方式。

## 各入口定位

### GUI

适合：

- 创建项目和配置目标范围；
- 管理身份、角色和租户；
- 启动可见浏览器录制；
- 确认安全契约；
- 查看实时阶段、证据链和历史差异；
- 竞赛现场演示。

GUI使用React和TypeScript实现，由本地FastAPI服务提供API。默认启动命令为：

~~~
jiejian serve --open
~~~

该命令启动API、单Worker和静态前端，并自动打开系统浏览器。GUI不是独立执行引擎。

### CLI

适合：

- 项目初始化和配置校验；
- 无界面运行；
- 调试和故障恢复；
- 导入、导出和批量测试；
- CI门禁；
- 为领域引擎提供最小可测试入口。

首版核心命令：

~~~
jiejian init
jiejian doctor
jiejian serve
jiejian project validate
jiejian record start
jiejian contract propose
jiejian contract activate
jiejian run
jiejian report
jiejian export
jiejian ci
~~~

CLI默认通过进程内应用服务运行；需要连接已启动服务时，才使用显式的远程API参数。不得维护两套业务逻辑。

### CI

CI调用：

~~~
jiejian ci <project_id>
~~~

CI输出JSON、JUnit XML和SARIF，并使用稳定退出码表达通过、阻断、系统失败、配置不完整和安全停止。

### REST API

REST API承担：

- 命令接收；
- 参数和状态转换校验；
- 任务排队；
- 状态查询；
- SSE事件；
- 报告和证据下载。

API不得直接调用Playwright、攻击变异器或目标应用。

### TUI

V1不实现TUI，原因：

- 多身份配置、契约编辑和证据对比更适合GUI；
- 自动化和运维场景已经由CLI覆盖；
- TUI会形成第三套交互状态和测试负担；
- 对竞赛展示和核心研究贡献帮助有限。

当出现长期无图形环境运维、SSH远程监控等明确需求时，可以增加只读TUI，但不得在TUI内重新实现领域逻辑。

### 原生桌面

首版不使用Electron、Tauri或PyWebView封装。先验证本地Web GUI的稳定性。

满足以下条件后再评估桌面封装：

- 需要面向非开发用户一键安装；
- 浏览器启动和本地服务管理成为主要故障源；
- 需要系统托盘、自动更新或更严格的本地文件权限；
- 核心API和GUI已经稳定。

### Docker

Docker Compose用于：

- 团队共享环境；
- 自动化实验；
- Benchmark复现；
- PostgreSQL部署；
- API、Worker和Web组合部署。

可见浏览器录制优先使用宿主机Playwright，不强制放入容器。

## 结果

优点：

- 首个垂直切片可以CLI优先，开发和测试成本较低；
- GUI仍然是最终产品和竞赛演示中心；
- CI、GUI和CLI复用同一领域引擎；
- 避免首版维护TUI和桌面壳。

代价：

- 本地启动需要管理API、Worker和前端资源；
- 需要为jiejian serve实现统一进程管理；
- Windows、Linux和macOS的浏览器启动行为需要分别测试。

## 重新评估条件

出现以下情况时应修订本决策：

- 本地Web架构无法安全管理浏览器会话；
- 单进程CLI与API模式产生不可接受的行为差异；
- 比赛或交付明确要求单文件桌面程序；
- TUI出现不可替代的真实用户需求；
- Worker隔离需要独立服务部署。
