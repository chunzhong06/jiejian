# ADR-0027：发布前单代产品架构收敛

- 状态：已接受
- 日期：2026-08-19
- 范围：产品目录、公共协议、ApplicationCore、Storage、API/CLI/Runtime、启动与独立交付
- 依据：[工程设计规范](../01_技术规范/工程设计规范.md)、[公共数据与 Schema 版本](../04_协议与数据/公共数据与Schema版本.md)、[Runner 执行协议](../04_协议与数据/Runner执行协议.md)、[开发路线图](../05_路线与研究/开发路线图.md)

## 1. 背景

代码已将 PermissionContract、ExecutionProfile、Runner/Evidence/Result、ExecutionFact/ObservationFact、ExecutionRouter、WEB HttpExecutionAdapter、ApplicationCore、Storage、API、CLI、Runtime、启动脚本、发布协议、migration baseline 和 Wheel 交付链收敛到当前实现。文档和架构门禁仍残留旧目录、旧公共名称、双 API 路径、开发期 migration 和旧协议文档链接，继续保留会使当前真源与代码不一致。

## 2. 决策

1. 当前只保留一套 PermissionContract、ExecutionProfile、Runner、Evidence、Result 和 Results 读取链。Candidate 是非权威建议，只有 ACTIVE ContractVersion 才能进入 Coverage 和冻结执行请求。
2. 当前只实现 `TargetType.WEB` 与 `HttpExecutionAdapter`。ExecutionRouter 是按 TargetType 查找 adapter 的唯一执行边界；HTTP 字段停留在 Web target/binding/adapter，不进入 Permission Core 或共享 Verification。
3. ExecutionFact 和 ObservationFact 是与 Web 技术无关的共享事实。HTTP 状态、请求/响应和具体 Observer envelope 在基础设施边界归约后，Verification 只读取 ExecutionOutcome、ObservedEffect、完整性、可靠性和稳定原因码。
4. GUI、CLI 和未来 MCP 入口共享 ApplicationCore；API 是薄 transport，不执行目标请求；Worker 使用最小组合根，隔离 Runner 承担主动目标流量。
5. Storage 按垂直聚合组织；公共协议位于 `product/protocols`；当前 API 使用 `/api`；启动由 `start.cmd`、`start.ps1` 和四个 startup 职责脚本组成。
6. 当前数据库由唯一 `0001_initial.py` 从空库建立，业务表使用 `execution_profiles`。数据库兼容性必须同时检查 revision、表集合和列集合。
7. 当前产品文件、模块、类、函数和 Schema 文件使用功能名称。wire `schema_version`、外部服务 URL 版本和规则集身份保持真实值，不为视觉一致性修改。

## 3. 安全不变量

- 目标 scope、请求预算、重定向、reset、秘密注入、脱敏和 staging/publication 都在明确边界内校验。
- API、CLI、GUI 不直接向目标发请求；Worker/Runner lease、fencing、取消、超时和清理失败不能被包装成安全 Verdict。
- Evidence 必须精确覆盖 required observation 与 resource；缺失、不完整、不可靠或 UNKNOWN 只能得到 INCONCLUSIVE。
- HTTP 表面拒绝但 ObservationFact 确认副作用时为 VULNERABLE，并可形成 BLOCK；完整事实证明权限正确才为 SAFE/PASS。
- Evidence、Finding、Occurrence、Baseline、GateResult、Report 和 publication manifest 都是可验证的已发布事实，不因读取或格式投影而重判。
- 日志、异常、协议 stdout、请求、工件和报告不得包含真实秘密；日志只写脱敏结构化内容。

## 4. 不兼容处理

旧开发数据库、旧 Profile、旧 Run、旧 Evidence、旧 Artifact/Report 文件和旧公共协议不提供 alias、wrapper、双 reader 或猜测迁移。启动前的数据库探针只读检查 revision、结构身份和列集合；不兼容时明确提示备份后重建 `var`，不删除、不 stamp、不 repair、不原地改写。

旧文件名和历史 ADR 可以作为历史记录保留，但当前产品代码、协议导入、路由和文档真源不再把它们当作可执行入口。新执行只接受当前协议和当前数据库基线。

## 5. 未来 Target 的扩展影响

未来 `CLI_APPLICATION` 或 `MCP_AGENT` 主要增加对应 Target definition、Action binding、ExecutionAdapter、安全 guard、必要 Observer 和样例/测试。它们不得重写 `PermissionContract`、Coverage、ExecutionFact/ObservationFact、Evidence、Verification、Finding、Baseline、GatePolicy 或 Report 的共享安全语义。

本 ADR 不表示 ProcessExecutionAdapter、McpExecutionAdapter、MCP ingress、CLI Target、MCP Target 或对应 Sample 已实现。未来目标必须单独提交公共边界、最小权限、预算、秘密和安全停止决策。

## 6. 边界和不做事项

- 不在本决策中新增目标类型、Runner、Observer、报告能力或产品入口。
- 不重新设计 Contract/Profile 真源、Verification Verdict、Finding identity、GateResult 或 Report 语义。
- 不把 API 文件布局、Storage 目录重排、migration 历史压缩以外的工作混入当前收敛；后续变化必须有独立范围和验收。
- 本 ADR 只同步已落地代码、协议、目录和交付边界，不把路线图中的未来能力写成当前实现。

## 7. 验收依据

- `tests/architecture/test_dependencies.py` 阻止 backend/API/protocol/migration/未实现 adapter 边界回归。
- Runner、Observer、ExecutionProfile、ExecutionRouter、Storage、API、CLI、Runtime 和 onboarding/动态执行直接测试保护当前行为。
- `0001_initial.py` 空库、重复 upgrade、旧 revision、未知 schema 和损坏结构测试保护数据库不兼容拒绝。
- `Runner执行协议.md`、`数据格式.md`、项目设计规范和本 ADR 共同构成当前文档真源；路线图只记录里程碑状态，不替代代码和测试。
