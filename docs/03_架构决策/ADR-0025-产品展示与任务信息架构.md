# ADR-0025：产品展示与任务信息架构

- 取代者：ADR-0035
- 当前阅读提示：本文保留历史决策；当前边界以 ../README.md 和相关 CURRENT 文档为准。

## 状态

已取代

## 决策

界鉴的展示边界分为四类：

1. `start.cmd`/`start.ps1` 负责启动检查、准备和服务启动的终端展示，启动品牌只在此边界出现一次。
2. 人类 CLI 使用统一 presentation 边界，在交互终端提供任务语言；`--json`、非 TTY、CI 和重定向保持机器 JSON 或既有二进制输出。
3. 机器 CLI 和内部进程保持稳定 stdout、退出码和错误结构，不引入 GUI 或人类展示文本。
4. API/Worker/Runner/Observer 的机器协议只传递版本化事实，不承担用户界面语言。

GUI 采用任务信息架构：工作台、应用、检查和高级。稳定路径为 `/workspace`、`/apps/access`、`/apps/rules`、`/checks/start`、`/checks/results`、`/checks/history`、`/advanced/recording`、`/advanced/models` 和 `/advanced/system`。首次使用向导保留局部四步流程，但不再作为全局产品阶段导航。

工作台、权限规则、开始检查、检查结果、历史变化和高级页面只读取服务端真实事实。权限矩阵只展开 Contract 中声明的 subject、action、resource、rule 和 relation；关系图同时提供完整文本关系列表。V1 Contract 没有关系实体时只显示已有规则，不构造矩阵或图数据。复杂权限 Contract 只通过一个只读投影提供给 GUI，不增加协议语义、数据库字段或执行能力。

检查结果页面分开展示 lifecycle、result integrity、Verification Verdict 和 Gate decision。稳定 Finding/Occurrence 只使用服务端身份与状态；Evidence 时间线按 V1/V2 已发布字段展示，没有时间戳或事实时明确写未提供，不以完成状态推断通过。报告导出只链接已存在的格式端点。

历史变化只对按创建时间排序、处于 terminal 且结果完整的检查串行读取 stable Finding。页面展示服务端返回的 `APPEARED`、`PRESENT`、`DISAPPEARED`、`REAPPEARED` 和 `CHANGED`，缺少 occurrence 时不补点、不推断消失。

## 不变量与边界

- API、CLI、GUI 共享 ApplicationContext 和应用能力；GUI 不直接执行目标请求或访问 Runner/Observer。
- 普通用户层不显示 Contract、Runner、Observer、Evidence、Job、Protocol、内部 ID 等实现术语；技术标识只进入高级详情。
- 不新增目标类型、Execution Router、Process/MCP Adapter、协议字段、数据库模型、迁移或报告生成逻辑。
- 窄屏使用局部横向容器或单列详情，矩阵、关系图、时间线不造成页面级横向溢出；键盘操作与减少动画偏好继续有效。
