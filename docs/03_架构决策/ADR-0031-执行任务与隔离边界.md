# ADR-0031：执行任务与隔离边界

- 状态：已接受
- 日期：2026-08-19
- 适用范围：Job、Worker、隔离 Runner、Target Runtime 和高风险目标流量

## 背景

高风险目标请求必须与 API、GUI 和普通应用编排隔离，并且能够在进程退出、重复提交、租约过期和取消时保持安全状态。

## 决策

Job 持有生命周期、尝试、lease、fencing token、取消和重试信息。Worker 负责 claim、lease、fencing、cancel、retry、恢复、结果校验和发布前交接；Runner 是隔离进程，只消费冻结 `PersistedExecutionRequest` 并执行受预算约束的目标流量。

`TargetRuntimeRegistry` 是唯一的 Target Runtime 选择边界。生产只注册 WEB 的 `WebTargetRuntimeFactory`；通用 Case Orchestrator 不依赖 HTTP。HTTP scope、origin、host、port、重定向、私网授权、请求/响应预算、超时、脱敏和清理都在 Web Runtime 边界检查。当前不提供 Process 或 MCP 目标执行入口。

Supervisor 为一个等待态 Job 建立 Worker 启动责任后，claim 前的不可恢复 bootstrap 失败通过窄化的 waiting-fatal 应用边界收口。Storage 只有在目标 Job 仍为 `PENDING/RETRY_WAIT`、没有 lease 且没有并发取消时才原子写入 FAILED；同事务同步 Run/Recording 并追加 `JOB_FAILED / WORKER_FATAL`。该路径不创建 attempt 或 fencing token，条件失配后只接受最新状态；已经 RUNNING 的 Job 仍完全由 lease/fencing/recovery 处理。

Worker claim 前必须持有按 Job 区分的系统文件锁；Serve 必须持有带随机 owner token 的控制面系统锁。锁是否有效只由操作系统句柄决定，PID 和文件内容只供日志诊断。Supervisor 观察到自己启动的 Worker 在可信终态前退出时，只能使用启动时保存的 lease owner 与当前 fence 收口；服务重启处理未知旧 Worker 时，必须同时满足 lease 过期和 Worker 锁可重新获取，才能形成 `EXECUTION_EXITED / PROCESS_EXIT_CONFIRMED` 恢复证明。锁仍被占用或 owner 已变化时不得抢占。

控制面异常消失后，Worker 通过 Serve token 与系统锁探针请求持久取消；正常退出由 API shutdown 先请求取消并等待，超时后只终止已持有句柄的 Worker/Runner 进程树。该设计负责清理该次执行创建的受控浏览器，不扫描或关闭用户自己的浏览器进程。

每个 Worker 使用按 job_id 可定位的独立有界诊断日志，直接承接 stdout/stderr 以覆盖 import 和组合根初始化失败；结构化日志显式包含 job_id，所有 sink 都执行通用与已知秘密脱敏。

Runner 只获得完成请求所需的最小环境和秘密引用；秘密值不进入协议、Evidence、日志、报告或异常。

## 理由与取舍

进程和租约边界降低 API 误发目标流量、旧 Worker 覆盖新结果和秘密扩散的风险。代价是任务恢复、fencing 和 staging 校验比同步调用更复杂。

## 影响

退出、过期 token、未知 TargetType、预算超限、目标范围失败、协议错误或清理失败都不能形成成功安全结论。claim 前退出不会无限保留为可调度 PENDING，claim 后退出必须形成 FAILED、CANCELLED 或受重试上限约束的恢复状态，不能绕过 fence 或永久停留在 RUNNING。观察不足向 Verification 传递 INCONCLUSIVE，而不是伪造通过。

## 迁移与兼容

只接受当前 Runner/Observer Schema 和冻结请求格式；旧开发执行请求、结果和兼容适配不自动读取。publication/storage 细节由 ADR-0033 和数据持久化 Architecture 负责。
