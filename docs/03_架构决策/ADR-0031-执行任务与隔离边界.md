# ADR-0031：执行任务与隔离边界

- 状态：已接受
- 日期：2026-08-19
- 适用范围：Job、Worker、隔离 Runner、ExecutionRouter 和高风险目标流量

## 背景

高风险目标请求必须与 API、GUI 和普通应用编排隔离，并且能够在进程退出、重复提交、租约过期和取消时保持安全状态。

## 决策

Job 持有生命周期、尝试、lease、fencing token、取消和重试信息。Worker 负责 claim、lease、fencing、cancel、retry、恢复、结果校验和发布前交接；Runner 是隔离进程，只消费冻结 `PersistedExecutionRequest` 并执行受预算约束的目标流量。

`ExecutionRouter` 是唯一的目标 adapter 选择边界。当前只注册 WEB 的 `HttpExecutionAdapter`。HTTP scope、origin、host、port、重定向、私网授权、请求/响应预算、超时、脱敏和清理都在 Web adapter 边界检查。当前不提供 Process 或 MCP 目标执行入口。

Runner 只获得完成请求所需的最小环境和秘密引用；秘密值不进入协议、Evidence、日志、报告或异常。

## 理由与取舍

进程和租约边界降低 API 误发目标流量、旧 Worker 覆盖新结果和秘密扩散的风险。代价是任务恢复、fencing 和 staging 校验比同步调用更复杂。

## 影响

退出、过期 token、未知 TargetType、预算超限、目标范围失败、协议错误或清理失败都不能形成成功安全结论。观察不足向 Verification 传递 INCONCLUSIVE，而不是伪造通过。

## 迁移与兼容

只接受当前 Runner/Observer Schema 和冻结请求格式；旧开发执行请求、结果和兼容适配不自动读取。publication/storage 细节由 ADR-0033 和数据持久化 Architecture 负责。
