# ADR-0034：模型服务、候选生成与秘密边界

- 状态：已取代
- 日期：2026-08-19
- 适用范围：LLM Provider、Profile、候选生成和凭据引用
- 取代者：[ADR-0041：确定性引导与受限 AI 辅助边界](ADR-0041-确定性引导与受限AI辅助边界.md)

## 背景

模型服务可以帮助整理权限意图，但模型输出、供应商连接和凭据都不应进入安全结论或目标执行边界。

## 决策

LLM Provider 通过受限服务调用；非秘密 Profile 保存 provider、model、推理强度、预算和版本等配置，凭据只保存受控引用。默认可离线运行，出站访问必须由明确的模型服务边界管理。全局 `AIAssistanceSettings` 只保存启用状态和默认 profile，不进入项目或安全结论。

正式 OpenAI、DeepSeek 和 Gemini 各自使用供应商正式 Models API 与生成接口；OpenAI-compatible 只作为高级兼容能力。模型目录从用户自己的供应商凭据动态发现，未知模型只跟随供应商默认，不根据名称猜测推理档位。正式供应商不能覆盖 Base URL；兼容服务只有在 `/models` 明确不支持时才允许高级用户手工填写模型。

临时模型发现只在一次显式 POST 请求内使用表单 Key，不先持久化 Profile 或秘密；已保存 profile 的刷新从 SecretStore 解析精确引用。传输统一禁用系统代理和自动重定向，并限制超时与响应字节。供应商的 reasoning、reasoning_content、thought 或等价隐藏思考在 adapter 边界丢弃，上层只取得最终答案和安全统计。

输入使用有界、规范化和脱敏 JSON；输出必须严格解析为不可信 Candidate，并继续经过确定性合并、assessment、人工审阅和 Contract 状态机。模型不可用、超时、非法输出或冲突只产生稳定脱敏错误或治理阻断。

秘密值不进入协议、Candidate、ExecutionRequest、Evidence、日志、异常、报告、前端或 Git。LLM 不决定 Verdict、Finding、Gate，不自动激活 PermissionContract。

Windows Credential Manager 适配器和最小 `SecretStore` 端口位于共享 `infra/secrets`，不属于 LLM 私有实现。端口只支持精确 write/read/delete/configured，不提供枚举；`cred:jiejian/llm/<profile>` 保持原语义，测试账号使用隔离的 `cred:jiejian/test-identity/<project>/<identity>/<secret>` 固定深度命名空间。业务服务不能跨命名空间构造或读取引用。

## 理由与取舍

候选和结论分离可以使用模型辅助而不扩大安全信任边界；动态目录和正式 provider 分离避免前端伪造供应商能力。代价是每个 provider 都要维护独立投影与能力映射，所有模型结果仍需要额外校验、审阅和 provenance。

## 影响

模型服务不是运行目标请求的适配器，也不是 Verification 的输入真源。核心权限治理在无模型环境下仍必须可用。共享 SecretStore 只提升平台秘密持久化能力，不允许 LLM 与测试账号互相读取凭据，也不让 Runner 获得 Credential Manager 枚举能力。

## 迁移与兼容

Profile、全局 AI 设置和 provider 输出只接受当前严格模型；它们的关系字段由当前唯一 `0001_web_v1` 数据库基线建立。旧开发配置、秘密存储、开发期 migration 和原始 prompt/response 不兼容读取。
