# ADR-0034：模型服务、候选生成与秘密边界

- 状态：已接受
- 日期：2026-08-19
- 适用范围：LLM Provider、Profile、候选生成和凭据引用

## 背景

模型服务可以帮助整理权限意图，但模型输出、供应商连接和凭据都不应进入安全结论或目标执行边界。

## 决策

LLM Provider 通过受限服务调用；非秘密 Profile 保存 provider、model、adapter、预算和版本等配置，凭据只保存受控引用。默认可离线运行，出站访问必须由明确的模型服务边界管理。

输入使用有界、规范化和脱敏 JSON；输出必须严格解析为不可信 Candidate，并继续经过确定性合并、assessment、人工审阅和 Contract 状态机。模型不可用、超时、非法输出或冲突只产生稳定脱敏错误或治理阻断。

秘密值不进入协议、Candidate、ExecutionRequest、Evidence、日志、异常、报告、前端或 Git。LLM 不决定 Verdict、Finding、Gate，不自动激活 PermissionContract。

## 理由与取舍

候选和结论分离可以使用模型辅助而不扩大安全信任边界。代价是所有模型结果都需要额外校验、审阅和 provenance。

## 影响

模型服务不是运行目标请求的适配器，也不是 Verification 的输入真源。核心权限治理在无模型环境下仍必须可用。

## 迁移与兼容

Profile、Candidate metadata 和 provider 输出只接受当前严格 Schema；旧开发配置、秘密存储和原始 prompt/response 不兼容读取。
