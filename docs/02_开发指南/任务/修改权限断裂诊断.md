# 修改权限断裂诊断

> 状态：CURRENT。适用于当前 CHECK 已发布事实的授权连续性、断裂定位与只读展示。

## 当前 CHECK 诊断链

当前输入为冻结 `PersistedExecutionRequestV3` 的 Case/Twin、`CheckRuntimeBundle` 的独立身份映射以及已发布 `CheckEvidence`。唯一 `core/verification/checks.py` 先形成效果事实与 Verdict；`assess_check_authorization_continuity` 和 `BreakpointLocator.locate_current` 使用这些事实，`CheckStoryBuilder` 将定位写入只读 `ResultStory`。不构造旧 `PermissionContract` 或 `DifferentialExperimentPlan`，不通过 `ResultPresentation` 进入当前结果 API。

Trace 真源是 `infra/observers/check_trace.py` 对本 Case 真实审计窗口的显式投影；缺失父节点、跨 Case 引用、冲突或预算不足必须保留 partial。它只消费显式范围、effect_id、父引用和受控来源，不能从请求结果或计划补证。实际账号映射来自独立身份核验；Trace 主体名不能覆盖已核验身份或替未知身份兜底。

六种断裂类型与 `EXACT / RANGE / VIOLATION_ONLY` 语义保持不变。合法委托必须具有因果祖先 `AUTHORIZATION/ALLOW`、非空显式来源范围、未扩大的委托范围、实际动作和资源被覆盖以及一致凭据来源。缺失/空数组不证明范围；错误授权祖先、跨 Case 引用和无关资源不能证明合法委托。即使委托合法，也不能把独立权威来源已确认的 DENY 禁止效果从 BLOCK 改成 PASS。

修改位置为 `product/backend/core/verification/{continuity,breakpoints,trace}.py`、`product/backend/infra/observers/check_trace.py` 与 `product/backend/workflows/checks/story.py`。诊断只影响解释，不重算发布 Verdict。检查 `test_check_breakpoints.py`、`test_check_continuity.py` 的直接规则及 `test_check_audit_scope_publication.py` 的真实采集发布链；不得仅用手工 Trace 代替后者。当前 GUI 和 MCP 只消费同一 ResultStory；独立报告格式不属于该产品读取链，CLI 不提供结果命令。

## 诊断边界

定位只解释已确认后果，不能因为缺少诊断把 BLOCK 降成 PASS。EXACT、RANGE、VIOLATION_ONLY 必须有相应证据支持；无法证明具体类型时保留 null，不猜文件、函数或行号。主断裂与后续影响分开，影响只沿显式父子因果传播，不按时间、名称或列表顺序补边。

当前执行路径只引用本 Case 真正承载 Trace 的 CheckEvidence。缺失 Trace 时保留事实对照，不能生成示意路径冒充执行证据。实际身份来自独立核验，计划主体、Trace 名称和后端 actor 变化均不能兜底。

独立报告格式仍可由保留的 ResultPresentation/trace/reporting 实现及其直接测试消费；其字段与 canonical 约束见[报告与格式投影协议](../../03_参考手册/协议/报告与格式投影协议.md)，不能据此恢复旧前端或 CLI/MCP 入口。
