# 修改权限断裂诊断

> 状态：CURRENT。适用于权限血缘、被动 Breakpoint 定位、最小见证、已确认影响锥、结果页/CLI/MCP 展示、Report diagnosis 和受限模型解释。

## 这项能力解决什么问题

Verification 已经回答某个 DENY Case 是否存在确认的越权效果；权限断裂诊断继续回答“最早能证明哪里断了、证据能精确到什么程度、确认影响沿哪条已发布路径传播”。它是 publication 后的只读解释层，不执行新请求、不回读目标现场，也不改变 Verdict、Finding、Gate 或报告生命周期。

正式链路是：

```text
冻结 PermissionContract + DifferentialExperimentPlan
→ DENY SecurityEffectFact
→ AuthorizationContinuityAssessment
→ 已发布 ALLOW/DENY ExecutionTrace + Evidence refs
→ BreakpointLocator
→ BreakpointResult
→ ResultPresentation diagnosis
→ GUI / CLI Human / CLI Machine / 现有 MCP 结果工具
→ Base/Gate report.json v5 与 HTML
→ 可选的受限模型解释
```

## 先判断能不能定位

授权连续性先只消费冻结 Differential twin、Contract 和 `SecurityEffectFact`。DENY Case 中任一受保护效果为 `CONFIRMED` 即确认孤儿后果；受保护效果为 `UNKNOWN` 或缺失时连续性为 `UNKNOWN`；只有全部受保护效果都由完整、可靠、相关、时间闭合且基线有效的 `ABSENT` 事实覆盖时才为 `INTACT`。它不读取 Trace，也不形成第四 Verdict。

Locator 只处理已经确认的孤儿后果。Trace 完整时继续定位 `EXACT`；Trace 缺少中间节点时降为 `RANGE`；外部权威 Observer 已确认后果但 Trace 没有稳定事件时仍保留孤儿事实，并以 `VIOLATION_ONLY` 表达“当前无法更细定位”。不能为了让页面有内容而使用当前数据库、Sample runtime、HTTP 重放、任务状态或模型补证据。

当 Trace 连断裂类型都无法可靠支持时，`VIOLATION_ONLY` 的 `breakpoint_type` 保持空值；不得为了满足字段形状伪造 `AUTHORIZATION_MISSING`、`IDENTITY_SUBSTITUTION` 或其他类型。`EXACT` 与 `RANGE` 必须继续携带已证明的类型和对应事件边界。

首批断裂类型固定为：

```text
AUTHORIZATION_MISSING
AUTHORIZATION_LATE
AUTHORIZATION_BYPASS
IDENTITY_SUBSTITUTION
AUTHORITY_EXPANSION
COMPENSATION_MASKING
```

增加或改变类型属于公共安全解释语义变化，需要主线程同时审查 Locator、结果消费者、Report Schema 和完整验收范围。

## 修改事件对齐与因果顺序

ALLOW/DENY 事件只能按下列稳定业务结构对齐：action、逻辑 resource、通用 kind、effect identity、父角色关系，以及同业务 `semantic_key` 辅助项。event/task ID、时间戳、HTTP 状态、列表位置和中文文案都不能成为对齐依据。

每个 Case 只有一个最早可证明 primary。后续异常只有在当前 DENY Trace 中位于 primary 的后代路径上时，才可以成为 amplifier 或 confirmed impact。不能把“时间上更晚”当成“因果下游”，也不能跨 Trace 借用 parent 或 event ID。

## 修改定位精度

精度只允许：

```text
EXACT           首个违规事件可唯一证明
RANGE           只能证明断裂位于稳定前后界之间
VIOLATION_ONLY  违规成立，但没有足够稳定边界继续定位
```

Trace partial、候选并发歧义或缺少稳定前界时必须降级。RANGE 的用户文案保持“断裂发生在 A 与 B 之间”；VIOLATION_ONLY 保持“违规已确认，但当前证据不足以进一步定位”。不提供 confidence 百分比，也不让消费者把降级精度升级成 EXACT。

## 修改最小见证与影响锥

`ResultPresentation` 的问题故事固定为七项并保持顺序：

1. 权限要求；
2. 实际身份；
3. 本不该发生的受保护业务后果；
4. 是否拥有符合原权限要求的合法授权来源；
5. 首个可证明主断裂；
6. 后续扩大影响的行为；
7. 最终业务影响。

实际身份与普通 issue 使用同一只读投影：只有完整 Trace 中可靠且一致的 IDENTITY 事件才能确认；否则显示无法确认，不能使用计划身份代替。

confirmed impacts 只来自 Locator 返回的当前 Trace 下游事件，并保留 event、parent、kind、effect 和 Evidence 引用。完整 Trace 仍可供高级审阅，但默认折叠；页面只读展示后端 `summary` 和 DTO，不解析 `semantic_key` 生成断裂结论。

## 修改 Report、CLI、MCP 或模型解释

Base/Gate `report.json` 使用格式 4，把授权连续性、主断裂、amplifier、固定七项故事和影响锥纳入 presentation 与 canonical。Report package manifest 是独立格式 1，只绑定当前报告及其 hash。Schema 变化先改严格模型和 reader，再用 `schema -Update` 更新签入文件，最后只读 `schema` 证明零漂移。

CLI Human、CLI Machine 和现有 `jiejian_result_presentation` MCP 工具消费同一个 ResultPresentation。不要新增平行 MCP 工具或为某个表面单独重组 diagnosis。

模型解释只允许看到 `breakpoint_type`、`precision`、`minimal_witness`、`confirmed_impacts`。模型可以换一种受限说法解释这些事实，但不能生成新类型、改变定位、提升精度、扩大影响集合或决定安全结论。

## 常见失败怎样定位

- 改随机 ID 或时间后结果变化：对齐泄漏了非语义字段；回查 alignment key。
- 页面与 CLI 显示不同类型或精度：存在第二套投影；统一回到 ResultPresentation。
- partial Trace 仍显示 EXACT：降级门禁缺失，不要由前端隐藏问题。
- 影响锥出现同 Trace 的旁支：检查 child edge 后代遍历和 Locator 返回集合，不能按列表切片。
- 实际身份等于计划身份但没有 IDENTITY 事实：展示层做了不允许的 fallback。
- Report JSON 可读但 canonical 失败：检查 diagnosis 是否完整进入 semantic input、Schema 与 Base/Gate copy。
- 模型输出了新的断裂判断：缩小 surface/template 白名单并拒绝模型覆写字段。

```text
Locator 只消费冻结 twin、已发布 Trace、confirmed effects 和 Evidence refs
六种类型与三种精度保持严格枚举，没有 confidence
primary 是最早可证明因果点，amplifier 和 impacts 只来自后代路径
固定七项故事顺序不变，实际身份没有计划值 fallback
GUI、CLI Human/Machine 和 MCP 使用同一 ResultPresentation

模型只解释四项白名单事实，不决定或改变安全语义
Continuity 只有 INTACT / ORPHAN_EFFECT_CONFIRMED / UNKNOWN，且不能改变 Run Verdict
固定七项故事顺序不变，实际身份没有计划值 fallback，primary 与 amplifier 分开
直接测试、Schema、Docs、注释与 git diff 检查通过
```
