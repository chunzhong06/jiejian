# 修改安全准备

> 状态：CURRENT。适用于权限考题编译、动作技术准备绑定与现场检查。当前后端已装配准备服务，普通检查准备页面尚未开放；正式权限检查不可用。

## 这是什么

准备服务把正式 BusinessAction revision 和 Permission revisions 翻译成真实身份、动作演示、具体资源、业务结果证明和恢复方式。`ActionAssuranceContract` 与身份需求计划都是确定性派生结果，不持久化为另一套权限规则。DENY 没有合法 ALLOW control 时要求回到权限维护，不能猜测允许身份。

`PreparationService` 每次重读业务事实、账号状态和技术绑定，形成 `SATISFIED / NEEDS_USER / STALE / BLOCKED / NOT_REQUIRED`。材料齐备不等于检查可运行，更不等于 PASS。旧 ProjectPreparation、SecuritySetupCompiler 和 CheckPreview 是保留迁移资产，不能作为当前准备入口；ActionSafetySetup 已被四类动作技术绑定取代。

## 正常修改路线

先确定变化属于派生需求、候选提取、技术事实写入还是现场检查。权限与业务结果来自已批准的正式 revision；候选只来自真实脱敏事件、请求模板与 Flow 资源位置。唯一且合法的解释可由确定性程序采用，歧义则保留待审，LLM 只能解释。

TARGET 最终化时发布不可变 Flow，再在同一数据库事务保存 Recording 完成态、ActionExecutionBinding 和当前 owner 的 ActionResourceBinding。一个动作可有多个 owner 的资源；重复最终化不能用旧录制覆盖后来已成立的绑定。Flow 已发布但数据库事务失败时只留下内容寻址的孤立文件，重试必须验证相同 hash。

OBSERVATION 在开始前绑定当前动作已有的 effect_id，只能从明确的观察录制形成 ActionEvidenceBinding。REGISTERED_OBSERVER 是已存在受控 descriptor 的窄引用，普通 UI 不暴露，不接受任意 URL、SQL 或脚本。RECOVERY 只为改变状态的动作形成恢复模板；只读动作的恢复直接为 NOT_REQUIRED，不创建假记录。

## 来源与失效

四类绑定只持久化被确认的技术事实与指纹。现场检查核对业务 revision、语义和实现指纹、真实确认 endpoint、源码来源、账号、来源 Recording/Draft 与 Flow。账号重新登录不抹去技术来源；账号删除保留历史 ID，但旧绑定不能满足当前准备。业务 revision 变化后旧绑定保留历史，不能迁到新 revision 冒充 current。

新写入先验证动作、effect、账号和来源属于同一项目且 revision 精确；补录必须关联同动作、同版本、同账号的已完成 TARGET。确认前源码、目标地址或实现漂移时失败关闭，不根据名称重新匹配。

## 不能破坏

- 前端不重算身份匹配、准备完成、stale 或唯一下一步；Workspace 是任务优先级真源。
- HTTP method、risk_hint、模型建议和页面状态不能创造或改变 BusinessEffect、Permission、Verdict。
- 缺身份、资源、观察或恢复只形成准备缺口，不冒充安全结论。
- 现场检查不连接目标、不恢复浏览器、不读取秘密正文、不写“READY=true”。
- Recovery 不删除历史证据；测试环境全量 reset 是独立设施，不能冒充动作恢复。
- 数据库增量升级保留正式业务数据，旧候选录制或安全数据非空时在 DDL 前拒绝；不猜映射、不重置数据库。

## 怎样验证

需求变化测确定性与身份约束；候选变化测唯一、歧义和无候选；绑定变化测原子写入、幂等、多 owner 和独立来源漂移；持久化变化再补增量升级与失败不变证据。按实际影响选择直接节点，不因局部修改机械重跑全量或真实 L5。
