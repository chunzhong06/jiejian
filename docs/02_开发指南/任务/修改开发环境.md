# 修改开发环境

> 状态：CURRENT。适用于界鉴的 Python/Conda/uv、Node/pnpm、前端构建、开发命令、自动 L5、Windows 启动显示和发行命令总控。

## 这套开发环境解决什么问题

界鉴不依赖开发者当前激活的 Python、全局 Node 或源码目录里的 `node_modules`。仓库根的 `scripts/dev.ps1` 是唯一开发总控入口：它选择并校验受控工具，按命令准备必要环境，把缓存和生成物写入 `var/`，最后恢复调用者原有的环境变量、当前目录和控制台编码。

产品启动仍只有一条路线：

```text
start.cmd
→ scripts/start.ps1
→ scripts/dev.ps1 prepare
→ product.backend.cli serve
```

`dev.ps1 start` 只是把请求交给同一个 `start.ps1`，不会建立第二套启动编排。

Windows 源码启动优先选择 PATH 中的 PowerShell 7；未找到时使用系统目录内的 Windows PowerShell 5.1，经同一个 start.ps1 完成 prepare、serve 和退出。5.1 的本机隔离验证覆盖前端重建、数据库准备、默认浏览器打开与正式 shutdown；这不代表全新机器下载或 Portable 已验收。不要用 PowerShell 7 的模块搜索路径污染 5.1 诊断子进程。

默认本地端口为 `8765`。若 Windows 保留该端口或已有应用占用，可通过 `start.cmd -Mode Gui -Port 18766 -VarDir <运行目录>` 显式选择空闲端口；启动脚本将参数交给同一 serve，浏览器地址与本地控制 Origin 同步使用该端口，不自动换端口或修改系统网络规则。旧 1.x 数据库被拒绝时应保留原目录并明确使用兼容或新的运行目录，`sync` 不会转换旧业务模型。

第一次准备仓库时，在仓库根运行：

```powershell
.\scripts\dev.ps1 bootstrap
.\scripts\dev.ps1 prepare
```

日常修改后只运行与修改范围相符的命令；不需要每次强制重建全部运行时。

## 修改 Python、Conda 或 uv

Python 基线由 `environment.yml` 定义，项目依赖锁由 `uv.lock` 定义，固定 uv 下载信息来自 `product/config/toolchain.json`。`scripts/dev/python.ps1` 负责定位 `jiejian_env`、确认 CPython 3.13、准备固定 uv、同步 editable 项目并验证运行身份；共享状态、prepare lock 和调用者环境恢复属于 `scripts/dev/common.ps1`。

常用路线：

```powershell
# 新机器，或 environment.yml 发生变化
.\scripts\dev.ps1 bootstrap

# 严格按现有 uv.lock 重新同步
.\scripts\dev.ps1 sync

# 明确更新锁文件；后续参数原样交给 uv lock
.\scripts\dev.ps1 update
```

修改时必须保持以下边界：

- 正式开发解释器仍是名为 `jiejian_env` 的 CPython 3.13，不能回退到当前 PATH 中碰巧可用的 Python。
- Python 检查使用受控解释器并带 `-B`；正式 pytest 必须经 `dev.ps1 test`，不能把裸 `python -m pytest` 当作验收入口。
- uv 下载必须校验工具链清单中的固定版本和摘要；缓存、下载和安装目录只能进入 `var/`。
- editable 包目录新增、删除或移动时要进入同步指纹，不能只比较 `pyproject.toml` 和 `uv.lock`。
- 脚本临时设置的 Python、uv、Playwright、JIEJIAN 和 PATH 变量必须在成功或失败后恢复，不能修改用户 PATH 或 PowerShell Profile。

直接验证：

```powershell
.\scripts\dev.ps1 test tests/scripts/test_dev_script.py
.\scripts\dev.ps1 prepare
```

失败时先看错误中的阶段名。`conda` 通常从 Conda 是否可调用、`jiejian_env` 是否存在和 `environment.yml` 开始；`uv` 从 `product/config/toolchain.json`、下载摘要和 `var/runtime/uv` 开始；`python-identity` 从同步是否完整及受控解释器回执开始。不要通过临时激活另一个环境掩盖身份失败。

## 修改 Node、pnpm 或前端构建

`scripts/dev/frontend.ps1` 拥有固定 Node/pnpm、受控依赖工作区、依赖与 build 双摘要、编辑器解析插件和 Vite production build。正式前端源码仍在 `product/frontend/`，依赖视图位于 `var/development/frontend/workspace`，不可变 build 位于 `var/development/frontend/builds/<digest>`，当前产品实例的静态资源副本位于 `<VarDir>/runtime/frontend`。

正常路线：

```powershell
# 强制重建前端依赖和 production build，并完成其他源码启动准备
.\scripts\dev.ps1 prepare -ForcePrepare

# 复用同一受控工作区运行前端测试
.\scripts\dev.ps1 frontend-test
```

前端编辑使用仓库根的 `jiejian.code-workspace`。准备完成后，VS Code 的工作区 TypeScript 插件会只读解析 `var/development/frontend/workspace/node_modules`；首次提示时允许使用工作区 TypeScript，并执行一次“TypeScript: Restart TS Server”。

不能在 `product/frontend` 运行 `pnpm install`，也不能把 `node_modules`、`dist`、Vite cache 或 `*.tsbuildinfo` 放回源码树。Node/pnpm 只属于构建阶段；已有可验证的构建指纹命中时，产品运行不应再次下载或启动它们。

直接验证：

```powershell
.\scripts\dev.ps1 frontend-test
.\scripts\dev.ps1 test tests/scripts/test_dev_script.py
.\scripts\dev.ps1 prepare -ForcePrepare
```

若 VS Code 大量报告 `react`、`antd`、`vitest` 等模块不存在，先确认受控工作区已经准备、使用的是根 `jiejian.code-workspace`，再重启 TypeScript Server。若 `frontend-install` 或 `frontend-build` 失败，从 `var/development/frontend/workspace` 的依赖摘要和完整性、`var/development/frontend/builds` 回执、固定 Node/pnpm 与 Vite 输出开始，不要用手写声明文件消除真实错误。

## 新增或调整开发命令

`scripts/dev.ps1` 只负责公开参数、七个模块的装配顺序、命令合同预检、分派和最终恢复。命令怎样组合已有能力放在 `scripts/dev/commands.ps1`；Python、前端、源码准备、自动 L5 或 Wheel 的具体工作必须留在各自模块，不能重新堆回总入口。

增加命令时按这个顺序处理：

1. 在 `dev.ps1` 的公开命令集合中登记名称，并明确它是否允许 `-Update`、`-ForcePrepare` 或位置参数。
2. 判断命令真正需要 Python、完整依赖同步、Node、前端 build、Chromium、数据库和 prepare lock 中的哪些能力；没有证据时不要擅自缩窄原有准备语义。
3. 在 `commands.ps1` 组合已有能力；新增的领域准备逻辑放入唯一所属模块。
4. 所有非法参数组合必须在取得锁或产生准备副作用前失败，不能静默忽略。
5. 在 `tests/scripts/test_dev_script.py` 中证明分派、参数、环境恢复和副作用边界。

当前硬边界包括：`-Update` 只属于 `schema` 与 `docs`；`-ForcePrepare` 只允许 `prepare`、`start` 和 `package`；位置参数只允许 `update`、`cli`、`test` 与 `frontend-test`。只有顶层 `dev.ps1` 可以 dot-source `scripts/dev/` 模块，子模块之间不能互相加载。

直接验证：

```powershell
.\scripts\dev.ps1 test tests/scripts/test_dev_script.py
.\scripts\dev.ps1 test tests/architecture/test_dependencies.py
```

出现“参数看似接受但没有效果”时，先查 `Test-CommandContract` 和分派路径；出现调用后环境变量、目录或编码变化时，先查 `Save-CallerEnvironment` / `Restore-CallerEnvironment` 及顶层 `finally`；出现并发准备失败时，确认是否确有另一个进程持有 `var/runtime/locks/prepare.lock`，不要删除正在使用的锁文件。

## 修改自动 L5

唯一入口是 `dev.ps1 sample-test`，从真实 start.cmd 启动隔离实例。默认 Official 编排由 `scripts/dev/sample_test/official.py` 和 current_api.py/current_gui.py 调用普通 Proposal、Human Approval、Preparation、CHECK、ResultStory、Evidence 和原题 Repair；Worker 支持 CHECK 与 RECORDING。界面动作和后端成功事实均需成立，API 成功或截图不能替代真实交互。不要恢复旧 Run/Profile、Report/CLI 或竞赛专用结论链。

最终验收与首错恢复边界见[验证与测试](../../04_工程约束/验证与测试.md)和[官方示例与整链验收](修改官方示例与整链验收.md)。普通开发仅运行受影响的直接测试；真实启动、目标与资源清理按当次明确授权执行，不把每次 UI 修改都扩大成 L5。

## 修改 Windows 启动显示

普通用户从 `start.cmd` 进入，`scripts/start.ps1` 负责六阶段总流程。`scripts/startup/` 已按职责分开：

- `presentation.ps1`：Banner、菜单、阶段结果、等待动画和恢复提示；
- `runtime.ps1`：外部命令、prepare marker、服务 ready/failure 状态和启动错误；
- `source.ps1`：调用开发准备并校验源码运行回执；
- `product.ps1`：受控 Python/CLI/serve 调用。

修改展示时不能改变六阶段、`__JIEJIAN_PREPARE_STATUS__` allowlist、source receipt、失败退出码或 `start.cmd → start.ps1 → dev.ps1 prepare → serve` 关系。动画是独立展示资源：父进程通知停止，子进程停止写屏并退出，父进程确认退出后才清行并写永久结果；正常路径不能先强杀动画。动画创建或清理失败只能降级展示，不能改变 prepare/serve 的产品结果。

普通启动不再打印整块 Python/Conda/Node/pnpm/Chromium 路径摘要，但日志、source receipt、`doctor`、GUI 运行环境页、失败诊断和 CLI Welcome 仍需保留这些可排障事实。

直接验证：

```powershell
.\scripts\dev.ps1 test tests/scripts/test_start_script.py
```

启动显示的技术闭环由 `dev.ps1 sample-test` 覆盖；展示验收再肉眼确认温启动和一次 `-ForcePrepare` 长启动中的动态行、GUI 打开体验与失败文案。若自动打开浏览器失败，只要服务已 ready，应显示本地访问地址，不能误报成产品启动失败。

## 修改发行命令

`scripts/dev.ps1 package` 是 Windows x64 Portable 的唯一开发入口。`scripts/dev/package.ps1` 负责准备前端、Chromium、冻结 CPython 与内部 Wheel，并把组装交给 `scripts/build/portable.py`；大段发行逻辑不能回填总控台或 `commands.ps1`。

Portable 的 Base Tree、full/nosamples、相对离线启动、runtime identity、六阶段进度、固定 artifacts 和仓库外验收统一由[修改发布与便携版](修改发布与便携版.md)说明；跨主进程与子进程的正式身份合同见[Portable 运行身份与发行结构](../../03_参考手册/协议/Portable运行身份与发行结构.md)。本文只保留开发命令边界：`package` 仍持有 prepare lock，允许 `-ForcePrepare`，不接受位置参数，所有缓存和发行生成物进入 `var/development`。

## 最终检查清单

开发脚本变化至少确认：

```text
公开命令的参数和副作用没有被静默改变
调用者环境、当前目录、控制台编码和 prepare lock 均被恢复
缓存、依赖、测试临时目录和构建产物只进入 var/
PowerShell 5.1 能解析含中文的启动脚本，项目规定的 UTF-8 BOM 保持
对应 tests/scripts 与必要 architecture 测试通过
docs、schema 或 package 的真实输出按修改范围完成核验
最终验收的 sample-test 从真实 start.cmd 完成，展示验收没有被误称为第二套 L5
```

正式测试入口示例：

```powershell
.\scripts\dev.ps1 test tests/scripts
.\scripts\dev.ps1 test tests/architecture/test_dependencies.py
.\scripts\dev.ps1 schema
.\scripts\dev.ps1 docs
```
