## 固定业务与普通审批

冻结配方位于`product/backend/workflows/business_boundaries/official_recipe.py`：Alice项目负责人可以导出自己的完整交付ZIP；Bob普通协作成员不得导出Alice资源，但可以查看日常协作资料。两个Actor、两个Action、两个Effect和三条Permission保持明确。

只有真实活动 OfficialSampleExperience 且 project_id 精确匹配时，普通权限页才提供“使用已提供的权限提案”。用户显式采用后进入同一待审 Proposal 和普通 LOCAL_GUI Human Approval。启动仍需 consent，不能按项目名称识别 Sample；预置提案只是可选输入，不形成第二套审批或安全判断。未批准或边界不匹配时返回结构化待办，不安装材料或创建检查。

受控验收脚本只可在本轮新实例内核对完整固定配方后自动提交普通批准。未知提案、权限变化或与配方不符的内容必须拒绝；这属于已授权验收数据准备，不证明GUI批准交互已经通过。

## 准备材料

普通 Preparation 当前缺口提供“使用已提供的测试材料”；显式采用后重读 Preparation 和 Workspace，再由普通 `/tests` 的“开始检查”显式提交，材料齐备本身不创建 Run。OfficialScenarioInstaller调用正式Recording提交、JobAttempt、结果消费、Review/finalize和current Preparation绑定。固定无秘密事件不是现场浏览器录制，也不绕过事务写Storage。录制创建、claim、消费与持久完成共用原子事务；同key可读回恢复，不能重复消费已接受结果。普通Recording的Worker/独立进程/headed Chromium能力仍独立保留。

Alice/Bob使用正式TestIdentity与内存SessionSecretOverlay，秘密不落真实CredentialManager或公共工件。导出TARGET与RECOVERY分开录制，日常查看先取得具体资源再执行唯一TARGET，subject/owner/资源注入均精确绑定。源码变化后先读取公开 actor_bindings/action_bindings；存在非 CURRENT 绑定时，先经普通 maintenance 提案核对原有业务语义与权限，再由 Human Approval 复核实现，之后才准备材料。不通过先失败一次 prepare 探测页面流程，也不自动更改权限或 epoch；prepare 返回的结构化 pending 仍按真实失败处理。

## 六来源及真实因果

导出最终ZIP的AZURE_BLOB_OBJECT是唯一VERDICT_REQUIRED；审计是DIAGNOSIS_REQUIRED；Owner API、SQLite、Task和Queue是SUPPORTING。六来源都实际执行，任务完成和消息派发不能冒充ZIP效果。Owner使用Alice合法Cookie读取受保护资源；独立Bearer观察端点保留独立用途。

问题实现先真实enqueue，再authorize；Bob收到403后Worker仍可能形成ZIP。Worker在响应完成后继续，Trace保留派发、后置授权及Worker分支，archive节点才标最终effect_id。通用Locator据此形成AUTHORIZATION_LATE，HTTP拒绝不等于安全。

| 版本 | 真实变化 | 新检查事实 |
| --- | --- | --- |
| VULNERABLE | enqueue在authorize前，决定性ZIP观察可用 | BLOCK / AUTHORIZATION_LATE |
| EVIDENCE_LIMITED | 保持问题，ZIP观察不可用 | NEW Run INCONCLUSIVE |
| FIXED | authorize移至enqueue前，合法导出和日常查看保留 | 原题NEW Run PASS / Repair VERIFIED |

工作台 OfficialSamplePanel 只保留启动、重置、停止以及中性的“问题版 / 证据受限版 / 修复版”环境条件，不带预期 Verdict 色。版本切换只修改真实源码/观察条件并登记SourceChange，不创建Run。FIXED必须携带第一轮已发布BLOCK重建的CurrentRepairReference。三个run_id不同，旧包永久保持；权限、身份、资源及决定性标准不因观察不足而降低。

## 运行与退出

每次体验位于独立`var/runtime/official-samples/<experience-id>`，source/state、端口、进程树、descriptor与秘密均属于该实例。Sample只绑定loopback，不调用真实云或付费接口。停止、替换、项目移除或ApplicationCore关闭先收口自身进程/Registry/会话秘密，再归档项目，历史publication保留。

活动CHECK必须先经正式取消和回收，不能在目标执行中切换版本或删除源码。业务恢复仅撤销本资源当前效果，保留Task/Audit/历史对象；全局reset不作为业务恢复。失败清理不得覆盖第一主错误或终止无关进程。

## 默认自动验收

唯一最终入口为`dev.ps1 sample-test`。非前端编排由`official.py`保留真实start.cmd、新var、source receipt、解释器身份、端口保护、受控浏览器HttpOnly会话、限时等待、failure.json与精确清理；`current_api.py`编排已冻结配方和公开API。

顺序固定为：启动隔离实例、准备官方示例、确认权限与准备材料、问题版检查、观察不足的新检查、原题修复与新检查、结果与历史证据核对、退出与资源清理。

每轮从精确change_id的check-preview取得计划指纹，向schema2 runs提交完整Plan。切换条件后若普通 Preparation 仍完整且 CheckPreview 可执行，则复用已有材料，不为 Sample 安装标记重复准备；未知回执先回读；GUI路径只定位本轮新Run用于收口，不再次POST；API专用编排若重取回执也只使用原idempotency_key，不能生成新key重复检查。仅在result_integrity=VALID后读取ResultStory/Evidence/repair-contracts；当前有界check-history、runs列表及精确run_id回读替代旧History，ProjectRepair替代旧Finding修复投影。普通 ResultStory、Evidence、Changes 和 Repair 是唯一分析路径，不保留 Sample 专用展示页；旧 Report/CLI/ResultPresentation 链不恢复，也不标成已验收。

`current_gui.py` 通过本轮受控浏览器实际操作界面，记录成功动作；`current_api.py` 只核对公开事实。技术 GUI 自动化覆盖：环境启动、普通权限页采用提案和 Human Approval、按 Workspace 精确 task_id 在普通 Preparation 采用材料、普通 `/tests` 提交、三个已发布结果与退出。绑定失效先普通重绑后准备；READY_TO_VERIFY 原题必须实际经 `/changes` 点击“复验原题”，核对精确 change_id 后再开始检查，不重复登记版本切换已经形成的变化。问题结果从本轮 Story 的决定性证明来源真实打开“已发布证据”局部区域（桌面complementary、窄屏dialog），到达证据最多两次操作，核对本次 GET 的 Run/Evidence 引用以及“在哪里看到、看到什么、因此支持什么、不能单独证明什么”四问；无对应来源必须失败，不能补假证据。原题下钻与定位证据同样保留真实操作记录。API核验支撑详细不变量，不能替代这些交互；截图也不是交互证据。driver的GUI接入点未全部通过时不报告最终验收成功。视觉验收另覆盖三视口、亮暗主题、焦点、遮挡和菜单。


真实 GUI 还核对问题版执行路径：按同 Case Story 选择路径并点击节点，DOM 父边逐项等于已发布 parent_event_ids；完整性、精度和证据文档归属保持。没有对应路径时失败，不补图。原题定位证据提前注册全部 GET，再点击一次并逐项核对 Run/Case/Evidence。历史页实际搜索问题 run_id、打开精确记录，返回保留输入和筛选。截图只记录实际准备、提交后可观察状态、三种结果、历史、证据与修复，不制造运行占位。

### 同实例 MCP 责任场景

正常 Official 流程在三版本与历史验收后、退出前运行 `current_mcp.py`；没有第二入口，stop_after_setup 跳过完整检查与此场景。受控 SDK 客户端名为“界鉴验收客户端”，不调用用户 Coding Agent 或付费模型，不声称编写过修复代码。

先读取 MCP paired。已有用户级配对只经当前控制会话 reveal 后在内存复用，不重新 pair/rotate/forget；此前未配对才通过 `/tools` 的真实按钮创建，成功或失败后清理自己新建的配对并回读。凭据是 Windows 用户级资源，不随 var 隔离；token、headers、完整 SDK 异常和凭据响应不得进入日志、截图、报告、配置、剪贴板或持久环境。凭据/账户权限阻塞即停止，不替换 SecretStore 或切换身份重试。

通过 GUI 对唯一 Sample 项目选择并核对 READ/PREPARE/EXECUTE 回执。READ 登记变化与 PREPARE 提交检查各拒绝一次，以前后公开列表证明没有新增状态。PREPARE 只登记一次“受控验收核对当前修复源码，未修改文件”的声明，claimed_paths 为空，实际变化必须为零，来源包含本客户端；GUI 展示记录，人工表单保持折叠。EXECUTE 只提交一次关联该 change_id 的完整普通检查，不携带原题修复引用，不用 HTTP 再提交，也不重发未知 SDK 回执；只回读新增 Run 供失败清理。

新增检查沿既有发布读取核对 PASS、两动作三 Case 与六来源。它是第四个普通 Run，不能标 VERIFIED，也不能混进原三版本列表；原三轮及原题 VERIFIED 关系保持，summary 单列 MCP 证据及实际总数 4。用户仍在筛选历史页时，后台完成不改变 URL 或输入；实际点击完成提示后进入该精确新 Run，返回仍保留原筛选。确认无活动 Run 后恢复 READ、清理自建配对，再沿既有退出与资源清理。GUI、历史、路径或 MCP 必需记录缺失不能报告验收通过。

validation/competition/all及Portable是保留工具，不属于当前默认闭环，不为默认验收失败追加另一套技术L5。局部开发只跑直接测试/stub；最终前端与公开能力就绪后才运行唯一完整sample-test。

## 环境操作回执与历史

start/stop 接受可选 UUID operation_id；显式 ID 持久绑定一次操作，重复 ID 只回读，不再启停。已有活动实例上的新 start 保持既有空闲与替换语义，回执操作为 reset；省略 ID 仍表示一次显式新操作。版本切换接口不增加新执行行为，未知回执不得重发来探测。

体验状态区分 NOT_STARTED、STARTING、RUNNING、STOPPING、STOPPED、FAILED 和 UNKNOWN，并给出 history_project_id、last_error_code、operation_id、operation_state。安装 available 与生命周期分开。服务重启不复活进程，旧 PENDING 只读投影 UNKNOWN；停止与归档全部确认才是 STOPPED。连接部分提交失败保留已创建项目索引，清理错误不覆盖首个错误码。

`GET /api/experience/official-sample/history` 从独立持久操作表列出真实记录，默认25、最多100条并返回 has_more；不扫描日志猜历史。测试 `tests/backend/workflows/test_environment_receipts.py` 使用 stub 进程所有者验证重放、重启与局部失败，不替代真实环境验收。
