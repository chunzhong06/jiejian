# 修改官方示例与整链验收

本文说明如何修改界鉴内置的官方 Web Sample、固定样例合同与唯一自动 L5。官方样例面向首次体验和竞赛展示，必须让用户先看懂矛盾，再通过真实检查形成结论；它不是预制 Verdict 的动画，也不是普通应用接入流程的替代品。

## 体验合同

仓库只维护一个官方 Web Sample：“协作空间——项目资料管理应用”。固定业务事实是：

- Alice 是项目负责人，可以生成完整项目交付包；
- Bob 是普通成员，可以查看日常协作资料；
- Bob 不得生成包含申报书、预算、成员信息和评审材料的完整项目交付包。

问题来自一次可复验的 Vibe Coding 变化：Agent 为缩短导出等待，把后台任务创建提前到权限判断之前。Bob 在页面收到 403，但任务、消息和 ZIP 仍可能已经产生。界鉴必须把页面响应与真实业务后果放在同一条证据链中判断。

对外只能说“依据多项公开研究机制构造的可复验案例”，不能声称某篇论文出现过完全相同的人名、ZIP 和代码故事。

## 三个版本

三个版本共享同一应用、角色、业务动作、权限规则和检查计划，只改变真实代码或可观察条件：

| 版本 | 真实变化 | 预期检查结果 |
| --- | --- | --- |
| 问题版 `VULNERABLE` | 先创建后台任务，再判断 Bob 是否有导出权限；只读业务状态与 ZIP 两条关键结果观察可用 | `BLOCK` |
| 修复版 `FIXED` | 先判断权限，再创建任务；两条关键结果观察可用 | `PASS` |
| 证据受限版 `EVIDENCE_LIMITED` | 恢复问题代码，同时让只读业务状态与最终 ZIP 两条关键结果观察对 Bob 当前实验不可用 | `INCONCLUSIVE` |

版本切换只改变样例源码和观察能力，不得创建 Run、Evidence、Finding 或 Verdict。服务端同时记录本次版本切换时间，供所有界面拒绝复用切换前的旧结果；每次结论都必须由用户重新发起正式检查。

样例 Project 只承担一次体验会话：用户结束示例、重新启动另一轮示例或 ApplicationCore 正常关闭时，必须先回收运行目录和进程，再经正式 Project 生命周期归档该 Project。历史 Run、Evidence 和报告继续保留，但失效源码目录对应的“协作空间”不能继续出现在普通应用列表中。

## 首次体验顺序

未接入工作台先展示项目背景和核心矛盾。用户点击“启动官方示例”后：

1. 弹窗解释 Bob 的既有权限边界、Agent 的局部修改和本次体验不会预先生成结论；
2. 用户确认“启动问题版”，系统复制安全源码基线并让运行实例进入问题实现；
3. 工作台提供“一键应用样例配置”，不要求用户逐项填写固定故事中的角色、流程、账号和权限表；
4. 一键动作完成后，用户发起问题版检查并得到真实 `BLOCK`；
5. 用户点击“交给 Agent 修复”，先查看界鉴发布给 Agent 的修复合同，再确认生成修改；
6. 变化模块显示 `authorization_policy.py` 的真实差异，用户独立复验并得到 `PASS`；
7. 用户可以切换证据受限版；页面回到工作台并显示“当前版本还没有可信结论”，用户重新检查后得到 `INCONCLUSIVE`。

工作台是主控入口，变化、权限、测试是辅助模块。样例不建立线性步骤条：用户可以随时查看代码变化、公开权限合同、测试范围、结果和证据。

## 一键配置的安全边界

“一键应用样例配置”只是替用户执行固定样例中没有判断价值的重复操作，必须继续调用正式产品服务：

- 确认 ApplicationUnderstanding 中的 Alice、Bob、导出和查看动作；
- 准备受控测试身份，秘密只进入 SecretStore；
- 经 `ProjectRecordingService` 提交正式 Recording，由 `JobAttempts` 建立真实 attempt，再由 `RecordingSubmission.consume_result`、`RecordingLifecycle.review/finalize` 形成两条已审阅业务流程；
- 经 ActionSafetySetup 确认资源、独立观察和恢复方式；
- 经 PermissionIntentService 提交三条公开权限规则；
- 经 SourceChangeService 读取真实磁盘差异并登记问题变化；
- 只连续执行后端标为 `AUTO` 的安全准备动作，遇到任何用户判断立即停止。

一键配置不得：

- 直接写数据库拼装已完成状态；
- 绕过 Recording 提交、Job attempt、结果消费或生命周期服务直接构造 Recording、Job、FlowDraft 存储记录；
- 预制 Run、Evidence、Finding、Report 或 Verdict；
- 绕过 Human Approval 服务写权限结论；
- 把密码、Cookie、Token 或 owner token 写入源码、日志或公共协议；
- 为了演示恢复已经删除的 `/mode`、`/identities`、`/behavior` 等样例专用接口。

普通应用仍通过权限模块管理测试账号和业务流程。官方样例的一键配置不能改变普通应用的操作合同。

## Agent 与 MCP 的展示语义

启动弹窗说明问题变化来自 Vibe Coding Agent。修复弹窗必须完整展示：

- 来源：Codex 通过 MCP 读取界鉴基于先前 `BLOCK` 检查形成的修复合同；
- 必须消失：Bob 的导出任务、队列消息和 ZIP 文件；
- 必须保留：Alice 仍能生成完整项目交付包；
- 不能改变：Bob 仍可查看日常协作资料，原权限规则和观察标准保持不变；
- 代码动作：修改 `authorization_policy.py`，把权限判断移动到后台任务创建之前；
- 验收边界：切换完成不代表修复成立，必须按原考题重新检查。

`jiejian_official_sample_apply_fix` 是 Agent 可用的正式 MCP 入口；GUI 按钮模拟同一合同被 Agent 获取并执行。两者都只能形成源码变化，不能替 Verification 决定结论。

## 运行与存储边界

- 源码、公开 OpenAPI 和 Bundle 描述留在 `samples/web/collaboration_space/`；
- 每次体验复制到当前实例 `var/runtime/official-samples/<experience-id>/source`；
- 数据库、Task、Audit、Queue、Blob、ZIP 和环境描述符进入同体验 `state`；
- 日志进入 `var/logs/official-samples`，不写入 `var/data`；
- Sample 只绑定 loopback，不扫描公网，不调用真实云服务或付费接口；
- 正常停止、移除应用和 ApplicationCore 关闭必须回收进程树、观察环境、内存秘密和本次 source/state；
- `/reset` 只属于 loopback、显式测试模式下的 fixture 基线，不等同于业务撤销。

业务撤销保留 Job、Task、Audit、Queue 和 artifact 历史；重复撤销幂等。测试 `/reset` 可以恢复空白基线，但不能被产品页面当作普通业务操作。

## 前端展示要求

- 产品默认进入正式工作台；只有用户主动点击“进入完整展示”才进入四幕展示模式；
- 四幕按“发现矛盾—回看变化—展开证据—验证修复”重排当前真实事实，不生成新事实；
- 未接入工作台要交代背景、规则和三个版本；应用接入页可以调用同一个由界鉴管理的官方示例启动动作，普通未知应用仍需用户显式启动并确认地址；
- 版本按钮必须先弹出说明，再执行切换；问题版、证据受限版、修复版使用可区分的状态色；
- 活动样例只在工作台显示一个统一控制器；版本切换后返回工作台，切换前的结果不能显示为当前版本结论；
- 测试、运行、结果、现场验证和展示模式都只读取当前版本切换时间之后形成的 Run；切换前结果只留在历史和修复来源中，不能阻止当前版本再次发起检查；
- 现场验证首屏只呈现“表面看到—独立观察到—因此得出”，随后是去重后的关键执行链和“在哪里看到、看到什么、因此支持”的事实依据；完整权限考题、全部路径与主张边界按需展开；
- 业务正文使用专业、直白、证据导向的语言；协议名、ID 和机器字段只进入详情；
- 2560×1440 是主展示视口，同时检查原生亮暗主题并保持 1280 和 600 像素入口可用；测试长页面的底部操作栏必须随滚动保持可见，页面不得出现横向溢出、同层卡片堆叠或把辅助模块伪装成线性步骤。

## 自动 L5 的正式入口

唯一入口仍是：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 sample-test
```

独立验证集仍通过同一命令选择：

```powershell
.\scripts\dev.ps1 sample-test validation
.\scripts\dev.ps1 sample-test competition
.\scripts\dev.ps1 sample-test all
```

调用链固定为：

```text
dev.ps1 sample-test
→ scripts/dev/sample-test.ps1
→ scripts/dev/sample_test/driver.py
→ start.cmd -Mode Gui -VarDir var/test/sample-test/<uuid>
→ scripts/start.ps1
→ 正式控制面、Worker、Runner 与官方样例
```

自动 L5 的十个阶段是：

| 阶段 | 必须证明的事实 |
| --- | --- |
| 1 界鉴真实启动 | `start.cmd`、prepare、receipt、GUI ready、Worker running |
| 2 进入 Agent 写错的问题版 | 启动弹窗、Sample 运行、工作台问题版状态，不生成结论 |
| 3 一键应用公开样例合同 | 角色、动作、身份、流程、权限和问题源码变化均由正式服务形成 |
| 4 三条权限路径与检查准备 | Alice 导出、Bob 禁止导出、Bob 查看资料和一组导出差分均可运行 |
| 5 问题版真实检查 | 正式 Runner 和六面观察得到 `BLOCK` |
| 6 Agent 获取修复合同并修改代码 | 修复弹窗、来源 Run、合同文本和真实源码变化一致 |
| 7 修复版独立复验 | 原考题重新执行，三条回归路径得到 `PASS` |
| 8 证据受限版检查 | 同一问题实验因关键证据不可用得到 `INCONCLUSIVE` |
| 9 GUI / CLI / JSON 等价 | 同一权威事实没有用户可见语义分叉；核对 2560、1280、600 视口 |
| 10 报告、历史、证据与资源回收 | Report、History、Evidence 合同和受控资源安全退出 |

`validation` 对公开 registry 执行一次，`competition` 独立执行三次。private oracle 不进入产品输入、MCP 输出或产品 Verdict；展示模式不读取逐 Case oracle 结果。

## Playwright 与 Recording 能力的关系

官方样例页面和版本弹窗由 Playwright 按真实用户入口验收。`scripts/dev/sample_test/windows.py` 与对应 UIA 测试仍用于证明普通应用的 headed Recording 能力，但它们不再参与官方样例的一键配置，也不能恢复旧的逐项 Recording 导览。

普通应用 Recording 仍必须经过 Worker、独立 Recording Process、headed Chromium、capture 协议、FlowDraft、Review 和 SafetySetup。官方样例的固定故事不冒充一次现场浏览器录制：它把仓库内受控、无秘密的确定性操作轨迹依次送入正式 Recording 提交、Job attempt、结果消费、审阅和最终化服务，用于替用户完成没有判断价值的重复配置；不得直接写 Storage，也不能据此删减普通产品能力。

## 失败保真和资源收口

任何阶段失败时先保存 `primary_failure`，再按公开 API 重置已准备身份、停止官方 Sample、请求系统关闭，并等待本轮 `start.cmd` 退出。只有控制面不可访问时，才允许终止本轮 Harness 自己拥有的进程树。

失败证据写入本轮隔离目录的 `audit/sample-test/failure.json`，可以包含阶段、稳定错误码、活动 Run/Job、清理动作、端口与进程树状态和相对日志/截图路径；不得包含密码、Cookie、Bearer、owner token、完整环境或浏览器 profile。

同一根因首次有效失败后，先建立低成本直接复现。修复后只重跑失败项和直接邻域；完整 `sample-test` 只在阶段收口运行一次，不能作为日常 Debugger。
