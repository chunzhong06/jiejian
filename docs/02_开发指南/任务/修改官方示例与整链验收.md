# 修改官方示例与整链验收

本文说明如何修改界鉴内置的官方 Web Sample，以及如何用唯一自动 L5 入口验证从真实启动、Recording 到三态结果和安全退出的完整产品链。它面向会同时触及 `samples/web`、官方示例管理、Sample 接线、Windows UI Automation 或 `sample-test` Harness 的任务。

官方 Sample 不是预制结论的演示 fixture，自动 L5 也不是把多个局部测试串在一起。两者共同证明普通用户实际使用的产品入口能够在真实 Windows 环境下形成可复核事实。

## 快速找到修改位置

开始前先把需求归入以下职责之一：

| 变化 | 主要位置 | 不应顺手修改 |
| --- | --- | --- |
| 协作空间的业务页面、会话、导出生命周期 | `samples/web/collaboration_space/source/` | Verification、Verdict、正式 Observer |
| Sample Bundle、启动与停止 | `samples/web/collaboration_space/sample.json`、官方示例工作流 | Runner 或 tests-only 生产开关 |
| Sample 到权限检查的正式接线 | `product/backend/workflows/security_setup/` | Sample 源码中的预设 Contract/Profile |
| 自动 L5 总编排和失败证据 | `scripts/dev/sample_test/official.py` | CLI/API 的既有产品合同 |
| Windows Recording 窗口与按钮操作 | `scripts/dev/sample_test/windows.py` | SendInput、CDP、浏览器调试端口 |
| `sample-test` 命令路由 | `scripts/dev/sample-test.ps1`、`scripts/dev/commands.ps1` | 把长篇实现堆进 `dev.ps1` |

如果失败只来自 Harness 把两种正式表示比较错了，应修 Harness；不能为了让验收通过而改产品协议。例如 Evidence 列表端点返回发布索引，单条 Evidence 端点返回完整文档。自动 L5 应分别验证“索引可读”和“文档内容”，不能要求两者逐字相等，也不为此恢复已删除的 CLI Evidence 命令。

## 官方 Sample 的长期边界

仓库只维护一个 Web Sample：“协作空间——项目资料管理应用”。固定业务主体是项目负责人 Alice 与普通成员 Bob，固定高价值动作是生成完整项目资料包。不同安全结果来自同一动作在不同授权顺序和观察条件下的真实行为，不来自三份不同应用或预制 Verdict。

Sample 必须保持以下边界：

- 源码、公开 OpenAPI 和 Bundle 描述留在 `samples/web/collaboration_space/`；每次体验复制到当前实例 `var/runtime/official-samples/<experience-id>/source`，数据库、Task、Audit、Queue、Blob、ZIP 和环境描述符进入同体验 `state`，日志进入 `var/logs/official-samples`，不写入 `var/data`。
- 正常停止、移除应用和 ApplicationCore 安全退出必须停止进程树、注销本地观察环境、清空内存秘密并删除本次 source/state；异常遗留由 LocalMaintenance 的临时文件边界回收。
- 普通业务只表达项目、成员、导出和撤销。权限契约、观察角色、Verdict、Evidence 和 Report 由界鉴正式产品形成。
- 测试身份通过正式控制面准备，Sample 只消费真实会话；密码、Cookie、Token 和 owner token 不进入源码、日志、Evidence 或 failure artifact。
- Sample 只绑定 loopback，不扫描公网，不调用真实云服务或付费接口。
- 官方示例的启动、停止和导览由 ApplicationCore 的正式工作流负责，测试不得直接调用内部 manager 伪造完成状态。

修改 Bundle 或运行描述符时，同时核对 `sample.json`、公开 OpenAPI、官方示例 API、权限设置接线和对应的架构测试。不要在 Sample 中引入第二套正式模型或未来 Target 设计。

## 业务撤销与测试重置必须分开

“撤销本次导出”是正常业务动作，`/reset` 是测试基础设施动作。两者不能共享物理清场实现。

正常导出与撤销的状态关系是：

```text
NOT_CREATED
→ PROCESSING
→ READY / SUCCESS
→ REVOKED
```

撤销以后：

- Project 的 `export_state` 为 `REVOKED`，当前 task、artifact 和 case 指针清空；
- 对应 export job 仍存在并从 `SUCCESS` 进入 `REVOKED`；
- Task 仍存在并表达撤销终态；
- 原 Audit 与 Queue 历史保留，并各追加一次 `EXPORT_REVOKED`；
- 历史 Blob 文件可以保留，但 compatibility listing 和 object fetch 不再把它作为当前有效对象暴露；
- OWNER_API 与 AZURE_BLOB_OBJECT 都投影当前资源不存在，不修改 Verification 来解释撤销；
- 重复撤销幂等，不产生无限重复事件；正在生成的导出返回稳定冲突，不在本任务中偷偷实现“取消生成”。

撤销后的页面应显示“已撤销”和“重新生成资料包”，而不是回到“尚未创建”。重新生成必须产生新的 marker、job 和 artifact，旧 REVOKED 历史不能被复活或覆盖。

`/reset` 只允许在 loopback 和显式测试模式下使用。它可以停止 Sample Worker、清空测试 runtime 并恢复 `NOT_CREATED`，因为它表达的是测试基线重建，不是用户业务历史。业务测试调用 revoke，fixture 生命周期调用 reset；不要为旧测试保留语义错误的 compatibility wrapper。

## 自动 L5 的正式入口

`sample-test` 是唯一的 Sample 与验证总入口。无参数仍是原有 Official Sample 完整 L5：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 sample-test
```

同一入口还承载只属于 tests / competition validation 的独立验证集：

```powershell
.\scripts\dev.ps1 sample-test validation
.\scripts\dev.ps1 sample-test competition
.\scripts\dev.ps1 sample-test all
```

`validation` 对完整公开 registry 执行一次，`competition` 对同一 registry 独立执行三次，`all` 只组合 official 与 validation，不隐式执行三轮竞赛统计。仓库不提供 `competition-test`、`benchmark-test` 或第二套 L5 命令。

`validation` 和 `competition` 只证明当次公开 registry 与外层 oracle 汇总；不得从一次命令成功、单个 Case 或历史汇总推导更大的产品能力。面向 PPT、演示视频和答辩的主张材料在仓库外单独维护，不能反向成为工程真源。

调用链固定为：

```text
dev.ps1 sample-test
→ scripts/dev/sample-test.ps1
→ scripts/dev/sample_test/driver.py
→ start.cmd -Mode Gui -VarDir var/test/sample-test/<uuid>
→ scripts/start.ps1
→ 正式 prepare、GUI serve 和 LocalWorkerSupervisor
```

`dev.ps1` 只做总控台职责：解析参数、加载职责模块、准备共享上下文、分派命令并恢复调用者环境。`sample-test.ps1` 只负责 PowerShell 入口和 Harness 调用，`sample_test/driver.py` 只解析并分派 suite。十阶段编排放在 `sample_test/official.py`，Windows UIA 放在 `sample_test/windows.py`；validation、adapter、registry、oracle 各自保持单一职责。不要留下旧 flat 文件兼容壳，也不要再建立第二套装配体系。

validation 的公开清单位于 `tests/validation/public_registry.json`。第二应用源码只位于 `tests/validation/apps/tenant_records/source`，运行时复制到本轮 `var/test/sample-test/<uuid>`，不进入 `/workspace`、评委导览或普通产品导航。private oracle 不进入 target source root、产品输入、MCP 输出或产品 Verdict，只由 `scripts/dev/sample_test/oracle.py` 外层验收器读取并比较实际结果；公开摘要只包含 public registry 对应的实际结果和聚合计数。这一边界不等同于 Coding Agent 在物理上无法读取整个开发仓库。

validation 的完整方法直接复用生产 `evaluate_permission_case()`、`assess_authorization_continuity()` 和 `BreakpointLocator.locate()`。`scripts/dev/sample_test/adapter.py` 只把公开 fixture 事件构造成正式 Contract、Twin、EffectFact 与 ExecutionTrace，不判断 Continuity state、Breakpoint type 或 precision。

每轮自动 L5 使用全新 `var/test/sample-test/<uuid>/`。Harness 可以复用受控开发工具缓存，但不能替 `start.cmd` 提前完成前端构建、数据库迁移、Source Receipt 或 GUI Serve 准备。默认控制端口被占用时应报告 `L5_CONTROL_PORT_OCCUPIED`，不能杀用户进程或偷偷换端口。

## Recording 为什么必须走真实链

阶段 4 必须通过公开 Recording API 创建任务，随后经过：

```text
LocalWorkerSupervisor
→ WorkerDispatcher
→ 独立 Worker Process
→ RecordingJobHandler
→ 独立 Recording Process
→ BrowserRecordingAdapter
→ headed Playwright Chromium
```

自动 L5 不注入 `controlled_runner`，不伪造 RecordingEvent，不预制 FlowDraft，也不向生产 Worker 增加测试开关。`controlled_runner` 只保留为 L1-L4 的便宜测试缝隙。

capture 协议必须完整经过：

```text
capture.ready
→ POST capture/start
→ capture.start
→ capture.started
→ CAPTURING
→ UIA 执行业务动作
→ POST capture/stop
→ capture.stop
→ Job SUCCEEDED
→ Recording PENDING_REVIEW
→ FlowDraft
```

任何业务按钮都只能在 `capture.started` 以后调用。最终 FlowDraft 必须由 RecordingSubmission 和 FlowDraftProcessor 正常形成，Review 与 SafetySetup 继续走正式应用服务。

## Windows UI Automation 的选择与操作

Recording Chromium 只能用 `pywinauto` 的 UIA backend 操作。该依赖只进入 dev dependency，`product/**` 不得 import `pywinauto`。

窗口选择需要联合证明：

1. Recording 提交前记录可见顶层窗口快照；
2. 候选窗口是提交后新出现的可见窗口；
3. 标题符合官方 Sample 的稳定标题；
4. 进程映像属于本轮受控 Playwright Chromium；
5. UIA tree 中存在稳定业务 Button。

零候选、多候选和可访问性树未就绪应分别给出稳定错误，不能选择第一个同标题窗口。操作按钮使用 `invoke()` 或等价 InvokePattern，并读取可访问性文本等待状态。禁止 `click_input()` 作为主路径、鼠标坐标、键盘扫描码、前台激活、地址栏 JavaScript、CDP、remote debugging、Selenium 或第二套浏览器。

正常业务序列固定为：

```text
进入项目
→ 生成完整资料包
→ 等待“完整项目资料包已生成。”
→ 撤销本次导出
→ 确认撤销
→ 等待“已撤销”
→ 确认“重新生成资料包”可用
```

POST 导出和 DELETE 撤销必须由 Recording 页面自己的业务 JavaScript 产生。Harness 不得直接向 Sample 发送这两个请求来代替用户操作。

## 十阶段输出与每阶段证明的事实

自动 L5 对外只显示十个稳定阶段：

| 阶段 | 必须证明的事实 |
| --- | --- |
| 1 界鉴真实启动 | `start.cmd`、正式 prepare、receipt、GUI ready、Worker running |
| 2 官方示例与应用理解 | 评委导览创建 Sample，App connect、理解、角色与 Action 走正式控制面 |
| 3 测试身份 | Alice/Bob 经正式 Credential Manager 与 SecretStore 边界准备 |
| 4 真实 Recording 与安全恢复 | 独立 Worker/Recording/Chromium、UIA、capture 全链、FlowDraft、Review、SafetySetup |
| 5 权限要求与检查准备 | 正式 Permission Intent、Security Setup 与 CheckPreview |
| 6 漏洞行为检查 | 正式 Runner、六面观察和发布路径得到 BLOCK |
| 7 修复行为检查 | 同一正式路径得到 PASS |
| 8 观察受限检查 | 使用既有受控机制得到 INCONCLUSIVE，不删除 supporting Evidence 造结果 |
| 9 GUI / CLI / JSON 等价 | 同一产品事实没有用户可见语义分叉 |
| 10 报告、历史、证据与资源回收 | Report/History/Evidence 合同和所有受控资源安全退出 |

GUI、CLI Human 和 CLI JSON 不要求内部表示完全相同，只要求对相同权威事实没有语义分叉。比较前先区分列表索引、详情文档和展示投影。例如：

```text
API Evidence detail
→ 验证六来源、角色和状态内容

API Evidence index
→ 验证发布索引可读且能定位完整文档
```

不要把 EvidenceIndexRecord 与完整 Evidence Document 做逐字比较，也不要为了 Harness 断言修改正式 CLI 输出合同。

## 失败保真和资源收口

任何阶段失败时先保存 `primary_failure`，再进行清理。若 Recording 已进入 CAPTURING，先走公开 capture/stop；Job 未终态时走公开 cancel；随后停止 Official Sample，请求 `/api/system/shutdown` 并等待 `start.cmd` 正常返回。只有控制面不可访问时，才允许终止本轮 Harness 自己拥有的进程树。

禁止通过直接写数据库把 Job 或 Recording 改成终态。最终不允许出现：

```text
执行进程已退出 + Job 仍 RUNNING
Job 已终态 + Recording 仍 STARTING / RECORDING
```

失败证据写入本轮隔离目录的 `audit/sample-test/failure.json`。它可以包含阶段、稳定错误码、Recording/Job ID、清理动作、清理前后公开状态、资源退出事实和相对日志/截图路径；不得包含密码、Cookie、Bearer、owner token、完整环境或浏览器 profile。

同一根因首次有效失败后，先从最小模块内事实开始分析，再沿真实调用链扩大。完成修复后，同一错误最多允许两次验证重试；若命令推进到另一个稳定错误码，则它是新的首错，重试计数重新计算。完整 `sample-test` 不是日常 Debugger：出现新的完整 L5 首错后应停止，保存证据并建立低成本直接复现，不能连续盲跑。

## 直接测试与完整 L5 的门禁

优先扩充现有职责文件：

- `tests/scripts/test_sample_test.py`：Harness、UIA 边界、窗口选择、失败清理、索引/详情分层；
- `tests/scripts/test_dev_script.py`：总控台、命令路由、PowerShell 入口；
- `tests/samples/web/test_collaboration_space.py`：导出、撤销、历史保留、权限与 reset；
- `tests/architecture/test_dependencies.py`：产品不依赖 UIA 测试工具；
- `tests/e2e/test_collaboration_space_golden.py`：公开边界上的三态整链。

普通修改先按影响范围选择最小直接测试。涉及真实 Windows UIA 时，在明确授权的交互用户环境运行受门禁探针；不要在多层 PowerShell 双引号中设置 `$env:`，应先在当前 PowerShell 设置变量，再用 `-File` 进入正式入口。

只有低成本直接测试已经证明 UIA capability、Sample UI、Recording 局部闭环、失败收口和生产依赖隔离后，阶段收口才运行一次完整 `sample-test`。完整 L5 通过后不重复运行，展示验收只检查视觉、窗口体验、文案、焦点和比赛演示节奏。

## 常见失败怎样定位

- `=1 is not recognized`：父 PowerShell 提前展开了双引号中的 `$env:`；这是调用错误，不是实现错误。
- fresh runtime 重复下载工具：共享了工具路径却没有共享“已准备”状态；检查共享工具 receipt 与 fresh 产品 receipt 的职责分离。
- Recording 窗口找不到：先核对新窗口、进程映像和 accessibility tree，不要恢复前台激活或物理输入。
- 页面动作成功但没有 Recording Event：核对 capture.started 时序和页面是否真的通过 UI 触发请求，不要由 Harness 补事件。
- Recovery 后 OWNER_API 与 Blob 分叉：修 Sample 的当前状态投影或 Blob 可见性，不修改 Verification。
- Runner 出现值提取失败：沿 Action/Response/Extraction 的正式图检查，不改浏览器或安全结论掩盖编译问题。
- GUI 结果停留在旧 Run：进入结果/历史页时重新读取后端权威运行状态，不用本地完成态冒充服务事实。
- Evidence 索引与详情“不一致”：先确认比较的是索引还是完整文档；不同层级本来不应逐字相等。
- cleanup failure 覆盖主错：检查 `primary_failure` 保存时点和 finally 汇总，清理错误只能作为附加事实。

## 最终检查清单

修改官方 Sample 或自动 L5 后至少确认：

```text
Sample 仍是普通 Web 业务应用，不包含预设 Verdict 或测试 secret
业务撤销保留 Job、Task、Audit、Queue 和 artifact 历史，reset 才物理清场
OWNER_API 与 Blob 对 REVOKED 一致投影当前资源 ABSENT
dev.ps1 仍只是总控台，Harness 与 UIA 实现只位于 scripts/dev/
sample-test 从真实 start.cmd 启动 fresh VarDir
Recording 经过独立 Worker、Recording Process 和 headed Chromium
UIA 只使用可访问性树与 InvokePattern，不使用前台、物理输入或 CDP
capture.ready/start/started/stop、FlowDraft、Review 和 SafetySetup 全链成立
BLOCK / PASS / INCONCLUSIVE 由正式 Verification 和六面 Evidence 形成
GUI、CLI Human、CLI JSON 按各自正式表示保持语义等价
Evidence 索引与完整文档通过 API 分层验证，没有拿不同层级逐字比较
失败保留第一主错，Job/Recording 终态合法，受控资源和锁全部退出
完整 sample-test 每个代码状态只在阶段收口运行一次
展示验收不再称为第二套 L5
```

结果语义同时遵循[修改结果与报告](修改结果与报告.md)，页面交互遵循[修改前端](修改前端.md)，命令与运行环境遵循[修改开发环境](修改开发环境.md)，测试层级与停止规则遵循[验证与测试](../../04_工程约束/验证与测试.md)。
