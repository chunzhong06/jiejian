# 竞赛理解验收脚本

> 状态：CURRENT。用于人工检查讲解者是否理解界鉴的证据边界；本文只给出问题和判定标准，不记录参与者、通过率或未实际发生的测试结果。

## 使用条件

在正式界鉴 GUI 中启动唯一的官方“协作空间”评委导览，至少准备一条 `BLOCK` 结果。需要讨论修复或证据不足时，再使用页面上的“使用原考题复验”和“验证关键结果不可读取时会怎样”，让正式流程产生新的 Run。

回答时允许打开工作台、权限与检查、检查结果、现场验证、证据说明和历史变化。不能用源码中预先知道的答案替代产品证据。

## 问题与判定标准

| 问题 | 回答至少应包含 | 不通过的典型表现 |
| --- | --- | --- |
| Bob 本来能不能导出完整资料包？ | 指出 P-编号、当前 revision、`DENY` 与完整业务权限句子。 | 只说“系统不允许”，没有找到人确认的权限要求。 |
| 表面发生了什么？ | 说明页面或接口是否接受、拒绝或失败。 | 把 `403` 直接说成最终安全。 |
| 真实后果是什么？ | 打开现场验证或证据说明，说明最终资料包或数据是否真实发生。 | 只复述页面提示，不检查业务后果。 |
| 为什么这个后果属于本轮？ | 指出当前 Run 的 Evidence、请求关联或 Trace，并打开“为什么属于本轮”。 | 用时间相邻或文件名相似来猜。 |
| 断裂能定位到哪一级？ | 区分 `EXACT`、`RANGE`、`VIOLATION_ONLY`，只说当前最大可支持精度。 | 在 RANGE 或证据不足时声称唯一断点。 |
| Agent 为什么不能改考题？ | 说明 Agent 可准备或执行，但 ALLOW/DENY 和正式映射需要 Human Approval。 | 把“Agent 没有产品审批入口”说成“Agent 物理上看不到仓库”。 |
| 修复后为什么不是整个功能被关闭？ | 同时核对必须消失、必须保持、不能改变和 ALLOW 对照。 | 只看到 Bob 不再成功，就宣布修复完成。 |
| 证据不足时怎么办？ | 说明应产生新的真实 Run，并接受 `INCONCLUSIVE`，不能把没看见当 `PASS`。 | 在已发布页面上隐藏节点或要求前端改结论。 |

## 通过条件

八个问题都能在产品中找到对应事实；回答明确区分表面响应、实际身份、业务后果、断裂精度和修复复验；没有把 AI 建议、private oracle、页面动画或中间消息当成安全结论。

若某个问题只能靠开发文档回答，记录为产品解释缺口，不把它算作已通过。理解验收结果由实际主持人另行记录，不能回填虚构数据。
