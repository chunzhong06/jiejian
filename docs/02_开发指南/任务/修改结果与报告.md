# 修改结果与报告

> 状态：CURRENT。适用于当前 CHECK 结果读取、历史、原题修复与独立报告格式维护。

## 当前 CHECK 结果入口

当前链为 `PersistedExecutionRequestV3 + CheckRuntimeBundle → CHECK Worker/Check Runner → CheckEvidence + CheckRunnerResult → CheckPublisher → CheckResultReader → ResultStory`。唯一判定入口为 `product/backend/core/verification/checks.py`；发布器重验冻结事实与判定后执行受租约/fencing 保护的文件提升和 SQLite 收据事务。读取只能使用同 Run 的不可变文件、hash 和收据，不重放目标、不调用 Observer、不重算 Verdict。

`product/backend/workflows/checks/results.py` 提供严格 Reader，`story.py` 提供逐 Case 的权限要求、计划身份、独立核验实际身份、HTTP 表面、效果、ALLOW 对照、定位及 Evidence 引用。UNKNOWN/MISMATCH 的实际身份 ID、标签和 actor 保持空值；不得从计划或 Trace 兜底。辅助来源保留 `SUPPORTING / DIAGNOSIS_REQUIRED`，不替代 `VERDICT_REQUIRED`。失效或篡改发布包隐藏安全结论并拒绝详情；进度只是 staging 外非权威旁路。

当前 API 为 `/api/runs/{run_id}`、其 `/result-story`、`/evidence`、`/evidence/{evidence_id}` 与 `/repair-contracts`；项目 `/runs` 提供历史列表，`/repair` 提供只读原题状态。确定性 Story 与受限 AI 解释分开，禁用 AI 不影响读取。Trace 和 Breakpoint 只解释已确认后果，显式合法委托或缺失诊断不能抹去已确认 BLOCK。

修改公共 Check 根需同步 Python、严格解析、canonical/hash、Schema 和真实发布读取测试。使用 `tests/backend/infra/runtime/jobs/test_check_publication*.py`、`test_check_result_reader.py`、`test_check_published_api.py` 与 `test_check_audit_scope_publication.py` 按受影响范围验证。当前BLOCK Case的 `repair_requirement` 从已发布原题重建，`repair_verification` 由精确关联NEW Run派生，ProjectRepair是唯一项目修复投影；保留的 `ResultPresentation`、报告、Finding/Gate 与修复实现不是当前 CHECK 已完成能力的证明，不把旧路由直接接回当前执行链。

`FactComparison.planned_resource_owner` 单独复制同 Run 冻结 bundle 中的资源所有者，verification_status 固定为 PLANNED；`resource_id` 只是冻结 Case 的技术引用，不发明资源实例名称。计划操作人与计划所有者都不能补填 UNKNOWN/MISMATCH 的实际身份。

`CheckProgressView.current_case` 只在有效 EXECUTING 进度、未完成计数与冻结 Case 总数一致时提供计划考题。Reader 使用 CheckRequestStore 按 request/config hash 读取 staging 外的不可变资产，执行纯输入关联校验，并核对 project、source、plan、policy_epoch、engine_version 和 Job/Run 关联。按执行器的 ALLOW 优先、action_id、case_id 串行顺序定位 completed_cases 所指题目；标签只取冻结 action、身份和 proof。该说明不证明请求已发出、实际身份已验证或效果已出现。说明缺失或资产失效时仅 current_case 为空，原有效阶段/计数保留；原进度 fencing/格式校验失败仍无进度。发布后 current_case 为空，安全结论继续只来自完整性校验后的结果。

Story 的 `repair_comparison` 与 ProjectRepair task 的 `comparison` 复用只读 RepairComparisonRow，分别保留 DENY、SELECTED_ALLOW 与全部 REGRESSION 义务。前后只复制对应已发布 CaseVerdict 和 Evidence 引用；缺失、歧义或上下文不符不猜 after 结果。单行 SAFE 不证明原证据标准仍成立，是否完成原题修复始终读取权威 Repair status。

## 修改当前只读投影

`ActionResultStory.proof_coverage` 对应同一已发布 Case 的冻结证明要求与实际证据，界面在“每项要求，由什么证据支持”中展示必要证明、辅助材料、观察状态及限制。投影只读取已校验的同 Run request、bundle 和 Evidence；当前注册来源或配置变化不影响历史解释，也不回写发布文件或重新判断 Verdict。没有对应观察时保持 UNKNOWN，未闭合的 ABSENT 不显示为已经确认不存在。引用按 observation 的等级分别收集；一份文档含多种观察时，可以同时出现在必要与辅助引用中，但不能因此提升证明等级。

点击对应记录复用现有 Evidence 浮层，重新核验 Run、Action、Case 归属，并只在摘要中显示与所选 effect 和 proof 指纹对应的观察；完整文档仍在技术引用内。辅助材料不能替代必要证明，单项观察状态不能当作整轮安全结论。

先确认请求的 project、Run、Case 和 Evidence 引用，再沿发布收据、不可变文件及 hash 回读。同 Run 的索引和完整 Evidence 是不同资源；缺失、篡改、关联不符时拒绝详情并隐藏可见安全结论，不能使用数据库旧 Verdict 或前端缓存兜底。生命周期、结果完整性和 PASS/BLOCK/INCONCLUSIVE 分别表达。

检查历史来自 CheckResultReader 的有界查询。默认 limit 25、最大 50，过滤与成对 cursor 语义见[控制面协议](../../03_参考手册/协议/控制面与Machine输出协议.md#当前-check-历史与执行路径)。不能把历史列表为空解释为问题已修复。

ResultStory 只复制已发布事实，使用冻结业务标签解释权限、计划身份、独立核验身份、HTTP、真实效果、合法对照、诊断精度及证据边界。HTTP 拒绝保持中性，缺 Trace 不补图，partial 保持 partial；前端不按文本、数量或颜色重判。Evidence 完整性失败时页面撤下该 Run 的安全结论。受限 AI 解释与确定性故事分离，GET 不调用模型，显式 POST 也不能改变结论、证据、断点或修复要求。

ProjectRepair 从最早已发布 BLOCK 建立问题族，只接受精确原题、源 Run、变化和新 Run 的关联。必须消失的效果、应保留的合法控制、全部历史 SAFE 回归与原证据标准不能被弱化。普通 PASS 不等于原题 VERIFIED；Agent 自述、界面状态和 Sample 条件都不是修复事实。旧发布结果永不回填，新条件通过显式提交形成新 Run。

## 独立报告格式维护

Report 是独立格式边界，不是当前 GUI、CLI、MCP 或 sample-test 的结果路径。保留的 `workflows/results/reporting.py`、`published.py`、`findings.py`、`gating.py`、`finalizer.py` 与 presentation/repair/trace 内部及测试消费者仍存在，但当前 ApplicationCore/WorkerContainer 不装配旧结果服务链。

`product/protocols/schema.py` 登记 Report 与 package manifest；`ReportStore` 有独立严格 reader，`core/reporting.py` 将同一 report.json 投影为 HTML、SARIF 和 JUnit。Base/Gate Report 根为格式 5，package manifest 为独立格式 1。修改字段必须同步 parser、canonical/hash、Schema、独立 reader 和格式投影测试，不因页面展示需求机械扩展公共格式。

报告只能引用已发布事实；Finding/Occurrence 与 Gate 的既有语义不由格式投影重算。报告派生失败与 Run 生命周期、安全结论分开，不能修改 Evidence 或 Verdict。完整合同见[报告与格式投影协议](../../03_参考手册/协议/报告与格式投影协议.md)。

## 必须保持的边界

- Verification 只依据已形成事实给三态；Reader、Story、GUI、MCP 和模型不重判。
- 当前读取不执行目标、Observer、修复或隐式检查提交。
- 必需证明与支持/诊断来源分开；支持材料不能升级为必需安全事实。
- 独立根版本、嵌套 DTO、数据库 revision 和产品版本各有边界。
- 秘密、原始敏感业务数据和无依据的代码位置不进入结果投影。
- 独立报告消费者存在不证明当前产品已提供报告下载或交付检查。
