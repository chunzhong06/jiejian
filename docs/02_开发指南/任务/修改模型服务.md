# 修改模型服务

> 状态：CURRENT。用于修改 Provider adapter、模型目录、Profile、临时 API Key、确定性 Guidance/ErrorDiagnosis 和受限 AI 辅助。

## 这是什么

模型服务是可选控制面能力，不是界鉴安全执行链的依赖。确定性 `GuidanceSnapshot` 根据 ProjectReadiness、CheckPreview、活动任务和可信结果给出下一步；`ErrorDiagnosis` 根据稳定错误码、Runner 阶段和 cleanup 事实给出恢复入口。它们在没有模型时也必须完整工作。

AI 只接收系统已经形成的有限事实、稳定 option ID 和短标签，用于排序或解释。所有 AI 内容明确标记 `[AI辅助]`，放在“界鉴确定”的事实之后。模型不能生成 PermissionIntent、Contract、Observer、Recovery、目标请求或安全结论。

## 正常修改路线

先判断变化属于供应商传输、Profile 配置、确定性事实还是 AI 展示。Provider adapter 只处理各供应商正式 API、模型目录、推理参数和有界响应；Profile service 拥有启用状态、默认供应商、SecretStore 引用和连接测试；assistant workflow 先生成稳定 Guidance/Diagnosis，再按明确 POST 决定是否调用模型。

GET、页面读取和服务启动不连接供应商。前端收到 `REFRESH_NEEDED` 后才能发出显式生成请求；同一项目、模板和事实指纹只允许一个任务。模型输出必须整体通过模板版本、数量、长度、去重和 option ID 白名单，任何越界都拒绝，不做猜测式修正。缓存只保存已验证的受限结果或短期退避，事实变化后重新计算。

API Key 只在当前设置/测试请求短驻留，保存时写入共享 SecretStore，页面无论成功失败都清空输入。Provider 原始响应、隐藏推理、prompt、Evidence 原文、源码和秘密不得写缓存或普通日志。

## 不能破坏

- 模型关闭、缺密钥、超时、限流或非法输出时，接入、权限准备、执行、Observer 和 Verification 仍可正常工作。
- AI 不能决定 ALLOW/DENY、候选确认、Profile 选择、Verdict、Finding、Gate 或 Recovery 命令。
- 不把 Key 写入环境快照、SQLite、协议、日志、异常正文、报告、前端状态持久化或 Git。
- 不用一个 OpenAI-compatible 猜测层替代供应商正式语义；未知模型不推断能力或 reasoning 档位。
- GET 不产生付费调用；真实付费探针必须由用户明确授权，fake transport 是普通开发默认。
- assistant cache 是可删除缓存，不能成为产品进度或历史结果真源。

## 怎么验证

Provider 变化用 fake transport 固定请求、响应、超时、限长和错误映射；模型目录/Profile 变化测刷新、SecretStore 和默认选择；Guidance/Diagnosis 变化测事实指纹、稳定 option、路由和无模型降级；前端变化再跑对应 settings/workspace 测试。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 test tests/backend/infra/llm tests/backend/workflows/assistant tests/backend/api/test_llm_profile_api.py
```

未经授权不要追加真实供应商调用。真实 API 只在明确需要验证供应商当前合同且用户批准费用/联网后单独执行。

## 失败先查哪里

Guidance 错误先核对 ProductReadiness/CheckPreview 输入和事实指纹，不先查模型。AI 长期停在 REFRESH_NEEDED/GENERATING 时查显式 POST、单飞任务和 cache 状态；不要让 GET 偷跑生成。Provider 错误先按目录、认证、请求格式、响应字节和本地白名单逐层定位。结果解释偏离事实时直接拒绝模型输出，不能扩大模板选项去容纳幻觉。
