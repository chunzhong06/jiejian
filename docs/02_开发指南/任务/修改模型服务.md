# 修改模型服务

> 状态：CURRENT。用于修改 Provider adapter、模型目录、Profile、临时 API Key、权限自然语言草稿、CURRENT 三类受限 AI 辅助，以及与模型设置并列展示的 AI 工具连接边界。

## 这是什么

模型服务是可选控制面能力。当前确定性下一步由 `WorkspaceService` 生成，动作材料由 `PreparationService` 现场检查；两者都不依赖模型。旧 `GuidanceSnapshot`、`ErrorDiagnosis` 和八类旧 surface 保留为 dormant 算法，未装配为当前 Assistant API，不可据此恢复 ProjectReadiness 或 CheckPreview 链。

普通产品只提供一个“AI 辅助”设置抽屉，用于启用辅助并管理默认 Provider、API Key 与模型。模型服务不是独立产品模块，不进入普通导航；`/settings/models` 只作为模型错误的恢复深链，进入后直接打开同一抽屉并回到工作台，不展示中间概览页。

AI 只接收服务端形成的有限事实、请求内 opaque option ID、当前实体 ID 和短标签。权限草稿可以把人主动输入的短文本整理成待审 ALLOW/DENY 建议，但不能形成 PermissionIntent；其他 AI 只用于排序或解释。所有 AI 内容明确标记 `[AI辅助]`，放在“界鉴确定”的事实之后。模型不能批准权限、生成 Contract、Observer、Recovery、目标请求或安全结论。

“AI 工具连接（MCP）”是供本机外部工具调用现有 ApplicationCore 的控制入口，不是模型 Provider，也不调用供应商。它与 Provider Profile、API Key、assistant enable 状态分别管理；页面打开、状态读取或启用 MCP 都不能触发 AI 调用。MCP 的 transport、工具和授权真源见[修改 API 与控制面](修改API与控制面.md)。

## 正常修改路线

先判断变化属于供应商传输、Profile 配置、权限草稿、确定性事实还是 AI 展示。Provider adapter 只处理各供应商正式 API、模型目录、推理参数和有界响应；Profile service 拥有启用状态、默认供应商、SecretStore 引用和连接测试，但普通 GUI 只管理一个默认连接，不提供 Profile 列表、兼容地址或运行预算等开发者字段；权限草稿由显式 POST 临时建立 option universe 并在当前响应内完成；assistant workflow 先从正式 View 生成带稳定指纹的 surface input，再按明确 POST 决定是否调用模型。

当前 GET/POST `/api/projects/{project_id}/assistant/{surface}` 只接受 `implementation-mapping`、`recording-review`、`preparation-explanation`。映射解释恰好指定一个正式 actor 或 action；录制解释必须指定 recording；准备解释必须指定 action。服务端核验当前项目、正式 revision 与来源，不能以最新记录猜焦点。旧 result/error 路由不注册；客户端不能提交任意 prompt、facts、候选结果或 Verdict。

映射输入限当前 BusinessActor/Action 与有限有效 Candidate；录制输入限明确 Recording 的步骤和资源候选，资源 ID 保留所属步骤关联，去除 query/body 等正文；准备输入限当前 ActionPreparationView 的短业务事实。输出最多三条短建议，kind 必须匹配当前实体类型，观察/恢复解释还须匹配相应准备类别。确定性解释已唯一时 `can_generate=False`，即使显式 POST 也不调用 provider 或缓存。

权限草稿不属于 Assistant surface，由独立 POST `/api/projects/{project_id}/permission-drafts` 接收严格格式 1 和 1..2000 字原文。服务端从当前 ACTIVE Actor、Action 与 Effect catalog 枚举合法原子选项，不要求已有 Permission。同 actor 只允许 OWNS/SAME_ROLE_OTHER_ACCOUNT，不同 actor 只允许 OTHER_ROLE；每项固定单个 effect。模型只见 opaque ID 与短业务名，返回 option ID、ALLOW/DENY、原文连续引文；本地拒绝未知项、伪引文与同原子冲突，按相同 subject/action/owner/relation/expectation 合并多 effect，并保留未覆盖实质原文。超过 128 项直接返回 PARTIAL，不调用模型或静默截断。

草稿返回 `READY_FOR_REVIEW / PARTIAL / UNAVAILABLE` 和 `boundary_fingerprint`。模型返回后复读正式 Boundary，漂移时返回空建议与 BOUNDARY_CHANGED。草稿不写数据库、AssistantCache、Proposal 或 Approval；形成正式权限仍须完整 Boundary maintenance Proposal 与 LOCAL_GUI Human Approval。界面先显示原文引文和未确认项，用户选中建议后显式填入浏览器本地草稿，再手动生成 Proposal 并批准；不会自动提交或审批。项目、边界指纹、草稿或输入文本在异步返回期间变化时，旧建议被丢弃。

GET、页面读取和服务启动不连接供应商。页面只做冷读取；只有用户点击带 `[AI辅助]` 标记的按钮才发出显式 POST。同一 subject、模板和事实指纹只允许一个任务。模型输出必须整体通过模板版本、最多三条、短纯文本、kind 和当前实体 ID 白名单，任何未知字段、未知实体、越界或额外 Verdict 都拒绝，不做猜测式修正。缓存只保存已验证的受限结果或短期退避，事实变化后重新计算。

API Key 只在当前设置/测试请求短驻留，保存时写入共享 SecretStore，页面无论成功失败都清空输入。Provider 原始响应、隐藏推理、prompt、Evidence 原文、源码和秘密不得写缓存或普通日志。

## 不能破坏

- 模型关闭、缺密钥、超时、限流或非法输出时，已开放的接入、业务边界维护、身份登录和动作准备仍可正常工作；不因此宣称 CHECK、Observer 执行或 Verification 已开放。
- AI 可以提出不生效的 ALLOW/DENY 草稿，但不能批准、激活或修改正式 PermissionIntent，也不能决定候选确认、Profile 选择、Verdict、Finding、Gate 或 Recovery 命令。
- 不把 Key 写入环境快照、SQLite、协议、日志、异常正文、报告、前端状态持久化或 Git。
- 不用一个 OpenAI-compatible 猜测层替代供应商正式语义；未知模型不推断能力或 reasoning 档位。
- GET 不产生付费调用；真实付费探针必须由用户明确授权，fake transport 是普通开发默认。
- assistant cache 是可删除缓存，不能成为产品进度或历史结果真源；权限草稿连该缓存也不使用。
- MCP Bearer 不能复用 Provider API Key、SecretStore 引用或浏览器 Cookie；启用连接也不能隐式启用 AI 辅助。

## 怎么验证

Provider 变化用 fake transport 固定请求、响应、超时、限长和错误映射；模型目录/Profile 变化测刷新、SecretStore 和默认选择；权限草稿测 option 白名单、精确引文、冲突、非法输出、Oracle 不变量和无持久化；Guidance/Diagnosis 变化测确定性事实和路由；surface 变化逐类测试事实指纹、实体白名单、提示注入与无模型降级；前端变化测试冷读取不触发供应商 POST、显式按钮和确定性主流程不受影响。MCP 面板变化还要证明它与 Provider Key 分离、默认关闭、显式启用和提权、轮换/关闭撤销，且全程没有 AI 调用。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 test tests/backend/workflows/assistant/test_current_surfaces.py tests/backend/api/test_current_assistant.py tests/backend/api/test_permission_drafts.py
```

未经授权不要追加真实供应商调用。真实 API 只在明确需要验证供应商当前合同且用户批准费用/联网后单独执行。

## 失败先查哪里

Workspace 下一步错误先核对正式 Boundary、implementation inspection 和 PreparationView，不先查模型。surface 事实错误先核对对应正式 View、实体 ID 和事实指纹。AI 长期停在 REFRESH_NEEDED/GENERATING 时查用户显式 POST、单飞任务和 cache 状态；不要让 GET 或页面挂载偷跑生成。Provider 错误先按目录、认证、请求格式、响应字节和本地白名单逐层定位。结果解释偏离事实时直接拒绝模型输出，不能扩大模板选项去容纳幻觉。
