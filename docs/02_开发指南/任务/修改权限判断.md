# 修改权限判断

> 状态：CURRENT。用于修改权限意图、Contract/Coverage、差分用例、效果事实、Verification、Finding、Baseline 或 Gate。

## 这是什么

权限判断回答三个不同问题：用户要求什么、系统实际观察到什么、这些事实是否足以给出安全结论。`PermissionIntentRevision` 是 Human GUI 追加批准的权限需求，独立 binding 表达当前实现映射，`PermissionContract` 是唯一可执行安全意图，`Evidence` 保存不可变执行与观察事实，`Verification` 只据这些事实给出 PASS、BLOCK 或 INCONCLUSIVE。Finding、Baseline、Gate 和 Report 都在已发布结果之上工作，不能反向改写 Verdict。

HTTP 403 只是一条 `ExecutionFact`。如果 Owner API 表面拒绝而 Blob 或其他可信关键来源确认副作用存在，结果仍应 BLOCK；如果关键观察失败或“未发现对象”的闭合条件不足，只能 INCONCLUSIVE。PASS 是对当前已执行范围的全称证明，不是“没有报错”。

## 正常修改路线

先定位语义层。用户矩阵、执行代表或 coverage gap 属于意图/编译；ALLOW control、DENY variant 和唯一变化维度属于 Differential；HTTP 分类属于 ExecutionFact；来源状态、可靠性、完整性和闭合属于 Observation/SecurityEffectFact；三态规则才属于 Verification。不要为了修展示直接改 Verdict，也不要为了让 Verdict 通过去弱化 Observer。

改变权限合同前先写清效果 manifest、主体关系、允许与拒绝预期、必需观察和恢复。Coverage 只消费 Contract；差分计划冻结 action、workflow、target、资源、非身份输入、Observer 和 normalization，只允许声明的身份/关系等维度变化。基线必须由 EXACT_RESTORE 或版本化等价证明，reset 调用本身不等于基线成立。

BLOCK 使用可靠存在性证据：DENY 变体产生确定性 ACCEPTED 或关键效果 CONFIRMED。PASS 必须同时满足请求被拒绝、全部禁止效果 ABSENT、闭合 CLOSED、ALLOW control 有效且基线一致。其他组合进入 INCONCLUSIVE，并保留具体限制原因。模型、页面和报告都只能解释这套规则。

## 不能破坏

- Human GUI 是 revision 语义和正式 binding 的唯一批准入口；CLI、MCP、Machine、AI、Compiler、Check Prepare、Run 与 Recording 不推进 epoch，不把 proposal 冒充当前规则。
- PermissionIntent revision、implementation binding、Contract、Plan、运行策略快照、Evidence、Verdict、Finding 和 Gate 不合并，不建立“快速判断”旁路。
- Verification 不导入 HTTP/数据库/Observer adapter，不执行 I/O，不让 LLM 决定结论。
- Supporting/corroborating 观察会实际运行并发布 Evidence，但不进入 baseline fingerprint、twin gate 或 PASS 必需闭合；不能借删除它制造 INCONCLUSIVE。
- 关键来源确认效果后，辅助来源失败不能抹去 BLOCK；关键来源失败或不存在证明不完整时不能 PASS。
- Finding 稳定身份、canonical/hash 输入和排序是长期合同；重命名或格式化不能改变既有语义身份。
- 生命周期失败、结果完整性失败和安全三态分开，Job 成功不代表 PASS。

## 怎么验证

只改纯规则时先跑对应 core 单测，再补 workflow projection；改公共模型或 Schema 时按协议门禁同步模型、严格 reader、Schema、消费者和测试。至少为涉及的规则保留 ALLOW control、403 但副作用存在、关键 Observer 不完整、baseline/closure 不成立等对照。Runner 进程、真实六面观察和 L5 只在跨边界或阶段收口时运行。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 test tests/backend/core/verification tests/backend/workflows/results
```

这是上限示例；局部修改优先选择一个测试文件和直接邻域。

## 失败先查哪里

三态不符先打印/读取已形成的 ExecutionFact、SecurityEffectFact、closure 和 baseline，不从 HTTP 响应猜。BLOCK 消失先查关键效果是否仍 CONFIRMED；PASS 变 INCONCLUSIVE 先找哪个必需通道、control、baseline 或 closure 不完整。Finding/History 不一致先核对 publication 与 ResultFinalizer，不重新执行 Verification。测试 fixture 与正式绑定不同要修 fixture 事实，不能放宽生产规则。
