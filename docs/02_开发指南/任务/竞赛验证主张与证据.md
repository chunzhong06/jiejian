# 竞赛验证主张与证据

> 状态：CURRENT。本页只记录现有 competition validation 能直接支持的主张、证据和限制；代码、公开清单、private oracle 与每次实际运行汇总仍是机器真源。

## 当前验证矩阵

当前矩阵由两个真实 Web 应用、五种权限断裂模式和三种状态组成，共 30 个 Case。每个 Case 都运行独立的 ALLOW 对照，再运行 DENY 变体：

| 维度 | 当前取值 |
| --- | --- |
| 应用 | 官方协作空间、tests-only 多租户记录应用 |
| 权限断裂 | 对象/租户检查缺失、新入口未继承权限、新功能绕过、委派或服务身份扩权、拒绝后的异步后果 |
| 状态 | 断裂存在且证据可用、保护有效且证据可用、保护有效但关键效果观察不可用 |
| 结果语义 | `BLOCK`、`PASS`、`INCONCLUSIVE` |

公开业务输入位于 `tests/validation/public_registry.json`；private oracle 位于授权源码根之外的 `tests/validation/private_oracle.json`。被测应用、产品、MCP、Agent 输入和公开逐 Case 结果都不能读取期望 Verdict、断点答案或 golden answer。

## 主张—证据矩阵

2026-08-30 在正式入口执行一次：

```powershell
.\scripts\dev.ps1 sample-test validation
```

该次公开汇总为 `accepted`，覆盖 30 Case × 1。以下数字只适用于当前固定矩阵。

| 可支持的主张 | 直接证据 | 当前结果 |
| --- | --- | --- |
| 完整方法区分三态，不把证据不足判成安全 | private oracle 外层计数与完整方法 Verdict | 30/30 匹配；漏洞错判 `PASS` 为 0，证据缺口错判 `PASS` 为 0 |
| 每个 Case 都有可用的正常业务对照 | 同 Case 的 ALLOW control 与真实受保护效果 | 30/30 有效 |
| 判定使用真实业务效果，而不只看 HTTP 状态 | `ObservedEffect` 与权限判定输入 | 30/30 效果判断匹配 |
| 执行归因到实际测试身份 | 真实会话或请求身份与执行事实 | 30/30 完成身份归因 |
| 拒绝后的后果能按授权连续性或孤儿后果解释 | 效果状态与公开 Trace 断裂分类 | 30/30 与矩阵状态一致 |
| 对漏洞给出当前矩阵允许的断裂类型和最大精度 | 公开 Trace 因果顺序与外层 oracle 计数 | 类型 30/30、精度 30/30 匹配；无断点的安全态和证据缺口态计入不适用 |
| 同一应用和模式的保护版本保留合法功能并消除断裂 | 正确态、ALLOW control 与授权连续性 | 10/10 适用修复对照通过 |
| 每个 Case 恢复独立基线并回收受控运行资源 | reset、进程或线程退出检查 | 30/30 完成 |
| 只看 HTTP 拒绝不足以覆盖权限断裂 | HTTP-only 基线 | 14/30 匹配；6 个漏洞和 10 个证据缺口被错判为 `PASS` |
| 只比较授权接口回归不足以覆盖拒绝后的真实后果 | authorization-regression 基线 | 14/30 匹配；6 个漏洞和 10 个证据缺口被错判为 `PASS` |
| 在这组已构造效果观察中，单状态效果能区分三态 | single-state 基线 | 30/30 匹配；它没有证明身份、因果断点、跨状态连续性或恢复能力 |

安全地板是硬门禁：完整方法一旦出现“漏洞判 `PASS`”或“证据缺口判 `PASS`”，validation 必须失败，即使其他汇总指标仍然通过。

## 不能据此宣称的内容

当前证据不支持以下说法：

- 已实现任意复杂主动诊断探针；
- 已实现可测试的 CLI Target 或 MCP Target；
- 能对任意应用自动推导完整权限要求和实现映射；
- 能自动完成所有权限缺陷修复；
- 在所有应用、所有权限缺陷或所有运行环境中都能“首次命中”或“零漏报”；
- Trace 本身就是不可伪造、无需其他观察面交叉核对的强证明。

`validation` 只运行一轮，因此不能把本页的单轮一致计数解释为重复稳定性证明。三轮独立执行只由 `sample-test competition` 形成，其结果必须以当次公开汇总为准。

维护或扩展矩阵时，先按[修改官方示例与整链验收](修改官方示例与整链验收.md)核对唯一入口、公开/私有隔离、真实应用和资源收口，再按[修改权限判断](修改权限判断.md)核对三态语义。
