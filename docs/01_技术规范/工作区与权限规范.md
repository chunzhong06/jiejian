# 工作区与权限规范

> 状态：CURRENT。适用范围：界鉴在 Codex、Windows、沙箱和 Git 中的工作区与权限操作。

## 1. 工作区与权限基线

- 唯一有效工作区是当前 Git 仓库根。新建任务或执行线程前，保存的项目路径必须解析到该根目录，不得使用上级目录、旧副本或同名目录。
- 新执行线程使用能说明自然子阶段职责的名称；是否复用按协作规范的生命周期证据判断，不按历史名称或阶段编号固定绑定。
- 项目根目录保持继承开启，由当前交互用户所有，并为该用户保留可向子目录和文件继承的完全控制权限。新增文件必须继承该权限，不得创建受保护的独立 ACL。

## 2. 沙箱与首次探针

- 普通代码修改使用工作区沙箱。只有 ACL 调整、用户级依赖缓存、系统临时目录或其他明确超出工作区的必要操作，才申请范围明确的提升权限。
- 新执行线程第一次写入前只进行一次低成本环境探针：确认准确工作区、沙箱身份、根目录 ACL、Git 状态和本阶段实际运行时。
- 如需验证写入，只能在 `var/` 创建唯一命名的临时探针，读回后立即删除并确认目录恢复原状。
- 涉及 Node 子进程、浏览器或 pytest 临时目录时，分别增加一个最小定向探针；通过后不重复。

## 3. 权限失败交接

任务所必需的命令若因权限、沙箱、用户级缓存、系统临时目录或用户上下文差异失败，先进行一次证据核对，确认它不是代码或测试断言失败。确认后停止无增量重试，交给用户执行。交接必须包含：工作目录、可复制的精确命令、用途与安全影响、预期结果，以及需要用户回传的输出。

用户返回结果后，从该恢复点继续。

## 4. ACL 与安全主体诊断

- 会话不得自行执行 `takeown`、递归 `icacls /reset`、关闭继承或删除未知 SID。发现异常时，先报告当前身份、目标路径、所有者、继承状态和失败命令，由主线程决定修复范围。
- 无法解析的 SID 不等于陈旧账户。Windows elevated 沙箱会对当前写入根授予稳定的 `CodexSandboxUsers` 权限和可能无法解析为普通账户的 capability SID，并对 `.git` 等受保护路径设置对应 DENY。
- capability SID 是任务或写入根的授权主体，不是必须能在“本地用户和组”中解析的普通账户。新任务仍可能为新写入根增加该 SID，不能因已有 `CodexSandboxUsers` 或换任务而假设它不会出现。
- 判断 capability SID 前，必须核对最新 sandbox 日志、当前写入根和该 SID 是否被本次 setup 重新授予；当前会话仍使用的 SID 不得清理。
- 只有关闭使用相关父目录的全部会话后，SID 不再被最新 setup 日志引用或重新创建，且已定位显式 ACL 来源时，才能作为历史残留处理。
- 清理前备份相关路径 SDDL，只移除已确认的显式 ACE，不递归、不修改继承项；工具无法匹配孤立 SID 时不得继续猜测命令变体。
- `apply deny-read ACLs` 优先核对 `%USERPROFILE%\.codex\.sandbox\deny_read_acl_state.json` 是否为无效 JSON 或 NUL 内容。
- `CreateProcessAsUserW failed: 5` 优先核对实际 shell 可执行文件及父目录的读取执行权限。
- 上述两类错误均不得通过重置项目 ACL 处理。

## 5. Git 保护

- `.git` 的沙箱写入拒绝默认视为预期保护。
- `git add`、`git commit`、`git merge` 等操作按批准规则申请沙箱外执行。
- 申请因环境权限失败并完成一次证据核对后，按“权限失败交接”交给用户，不通过放宽 `.git` ACL 绕过。
- 完整 Git SHA 只能直接取自 `git rev-parse` 等 Git 实际输出，不得根据短 SHA 推测、补齐或人工扩写；现有证据只有短 SHA 时只能记录短 SHA。
- rebase、filter、批量重建提交、`update-ref` 等历史改写前必须建立名称明确的 recovery/backup ref。每个目标提交的消息、父关系、tree 及本轮关注事实必须显式给值并可验证，不得用 `null`、空字符串或隐式哨兵表示“沿用提交消息”。
- 正式移动 branch/ref 前必须校验候选历史；recovery ref 在全部验证完成前不得删除。改写失败后优先从恢复点恢复，不继续对正式引用反复试错。
