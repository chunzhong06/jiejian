# 协作与阶段执行规范

> 状态：CURRENT。适用范围：完整阶段提示词、PRO 分析规划、主线程执行、Luna 委派、阶段恢复与验收。

## 1. 完整阶段提示词与角色

一个阶段继续使用一份完整的大阶段提示词，统一描述产品目标、设计意图、禁令、阶段边界和最终验收。中间分析、规划、分批交接和上下文压缩不得把它替换为若干互相独立的局部提示词。

- **PRO**：负责完整提示词下的中间调查、方案比较、架构分析、详细规划与设计。输出应包含需求映射、已冻结决策、受影响边界、自然子阶段、验证合同、停止/升级条件和遗留风险。
- **主线程（Sol）**：负责核对 PRO 方案未偏离完整提示词，依据冻结方案实施、集成、异常决策和最终验收。方案和边界已明确时，优先执行，不重复同一轮开放式设计。
- **Luna 执行线程**：只承接主线程已冻结的机械边界，完成实现、定向测试和本次变更直接引入的局部修复；关键假设失效或重新出现架构选择时返回主线程。

PRO 方案是执行设计，不是新的范围真源。若方案遗漏、缩减、扩大或冲突，以用户当前指令和完整阶段提示词为准，由 PRO 或用户修订后再执行。

架构与公共语义、README 与 docs、AGENTS、注释与 Skill、测试或 fixture 组织、用户可见交互、前端视觉与复杂可视化、用户文案和最终产品验收属于主线程的高判断职责。Luna 只承接后端工作流、Runner/Worker/运行时、确定性 API/DTO、启动脚本底层控制、有界重构和直接相关测试等已冻结机械边界。

## 2. 单写入者、接管与线程定义

- 同一工作树同一时间只保留一个主要写入者。需要并行时使用独立工作树，并明确互不重叠的 Git 和文件边界。
- 是否使用执行线程由任务边界、实现复杂度和预期质量决定，不作为固定步骤。
- 若主线程验收发现系统性偏差、提示词保真不足、重复返工或继续委派的收敛收益明显偏低，可接管有界实现；接管前停止或等待执行线程空闲，记录依据。接管只改变执行者，不扩大范围或免除验证与恢复点。
- 本文 Luna 只指 Codex 应用中用户可见、可单独进入和归档的任务线程。内部 sub-agent 不得创建、冒充或代替指定执行线程；找不到、无法唤醒或无法交接给既有 Luna 时，主线程停止调度并请用户提供或创建对应任务。

## 3. 模型、粒度与生命周期

- 主线程创建用户可见执行线程时，显式指定 `gpt-5.6-luna` 与 `high` reasoning effort；只有用户当次明确指定其他配置时覆盖。
- 一个 Luna 默认连续负责同一完整阶段或若干高度相关阶段；子阶段/批次边界不等于线程边界。每批形成恢复点并验收后，默认继续复用。
- 每次只交接一个边界完整、可独立验收的自然子阶段；存储、公共 API、GUI 和动态集成等不同验证闭环分批交接。
- 子阶段以清晰提交为优先恢复点；暂不提交时必须明确当前提交、未提交范围、验证结果和下一批可依赖接口。
- 进入不同能力域、前后端切换或目录变化本身不是新建线程理由。

新建 Luna 只能由以下证据之一触发：

- 现有上下文已实际造成遗漏、误解或返工；
- 收到一次明确固定运行时纠正后仍重复使用错误环境；
- 执行质量或指令遵循出现可观察下降；
- 预计剩余单个自然子阶段已无法在当前上下文可靠完成；
- 下一个任务是可独立验收的不同结果，且确有并行或隔离价值。

换线程前记录具体触发证据，并从当前提交、完成报告和冻结约束生成精炼交接。系统中断后从仓库、权威文档和最近完成报告恢复，不依赖重放完整聊天历史。

## 4. 运行时固定与首次探针

- 主线程在阶段首次探针确认实际运行时后，后续交接写明解释器、Node、npm 等工具的绝对路径和版本。
- Luna 必须使用指定绝对路径，不得自行改用 PATH 默认环境、安装或升级依赖，亦不得 fallback；路径缺失或版本不符时立即升级，不反复尝试。
- 同一线程且环境未变化时复用首次探针，不机械重复完整环境检查。
- 完成报告写明实际运行时绝对路径、版本和完整验证命令。

## 5. 任务交接与范围

初次交接固定包含：背景、目标、已确定决策、可以修改、不可以修改、验收标准、测试模块、验证程度上限、是否需要 L5 和升级条件。后续交接以当前恢复点和增量约束为主，但验收与升级条件不能省略。

- 交接描述结果与边界，不默认展开逐行操作；只有关键假设失效时重开方案讨论。
- 不因顺手优化扩大任务，不修改无关模块、依赖、公共接口、稳定格式、用户自己的改动或其他阶段代码。
- 每个自然子阶段开始前明确“本批必须完成、明确不做、停止条件”；验收条件不能隐式授权新增子阶段。
- 阶段验收发现范围外缺口时只记录缺口、影响和后续建议；若缺口直接否定当前阶段成立，停止并重新划分边界。
- 长期事实沉淀到代码、测试、ADR、规范和 Git，不依赖完整聊天历史。

## 6. 升级条件

出现以下任一情况，Luna 停止重复试错并返回主线程；主线程若受同类条件阻塞，则返回 PRO 或用户决策：

- 实际代码与关键假设冲突，或验收必须修改范围外重要模块；
- 需要改变架构、安全边界、公共 API、公共 Schema、持久格式或核心状态机语义；
- 同一问题经过若干合理方案仍失败，开始重复尝试或无法解释环境差异；
- 需要人工权限、安装软件、外部账号、改写 Git 历史或其他高风险操作。

升级报告说明：问题、已尝试内容、失败原因、最可能根因、1～3 个下一步方案，以及分别需要谁决定。

## 7. 验证与失败处理

- 开发子阶段遵守冻结的验证合同，以直接相关测试和一个代表性闭环为默认上限；只有合同中的升级证据才扩大模块或验证程度。
- Luna 不得因“保险”超过交接上限或自行运行 L4；共享边界扩大时停止并交回证据与建议等级。
- 主线程决定测试模块、验证程度、升级条件和最终充分性；真实终端、浏览器、GUI 及最终产品体验的 L5 由主线程验收。
- 主线程默认复用可信定向结果，仅在风险、报告或环境证据要求时补最小验证。L4 的重复限制与失败处理见 [验证与提交规范](验证与提交规范.md)。
- 失败方案记录方法、原因、根因和错误假设；可复用模式转化为规则、测试、ADR、校验项或交接检查项。

## 8. 技术实验与返工收敛

- 动态实验前，主线程一次性核对运行时、协议/API 版本、连接方式、最小权限、预算和成功判据；Luna 按固定组合执行，不自行更换环境、依赖或协议方案。
- 实验按“准备、观察、断言、清理”形成可诊断闭环；失败时保存脱敏证据，只改变一个已定位变量，临时脚本、数据和日志只进入 `var/`。
- 默认产物是“可行、不可行或延后”的证据结论；除非当前子阶段明确授权产品化，实验通过后停止，不自动继续生产适配器、公共协议、GUI 或总闭环。
- 实验结束后只长期保留问题、思路与设计、固定条件、观察、结果、结论、限制和可迁移影响；未产品化代码、测试、数据和日志删除，不建立长期 `experiments/` 源码目录。
- 同一子阶段第二次非偶发返工，或一次明确纠正后再次偏离时，Luna 停止探索；主线程收敛根因和唯一方案后再恢复。
- 生成文件按真实模型依赖自然更新，兼容由协议、canonical 和回归测试保护，不为维持生成文件字节不变添加投影或特例。新入口或 wrapper 只有在稳定 public import、框架发现、独立安全/进程边界或真实生产调用者存在时保留。

## 9. 汇报与上下文控制

- 交接后没有新决策事项时，不持续轮询执行线程，不重复读取相同代码、重做既定分析或进行无新信息推理。
- 同一 Luna 后续交接只发送当前恢复点和增量约束，不重复稳定背景；完整阶段提示词由固定路径或原始任务保持为统一真源，不在每次消息中整篇重贴。
- `rg`、diff、日志和测试输出限定到受影响路径与必要上下文；输出过大或截断时缩小范围，不重复全仓读取补偿。
- 主线程只在架构、公共接口、多方案权衡、复杂调查和失败重规划时提高推理投入。Luna 默认 `high`；仅对边界明确的复杂实现或局部疑难使用 `xhigh`，架构不确定时返回主线程。
- Luna 完成报告固定为“变更摘要、修改文件、验证结果、偏离原方案、待确认问题”；后两项没有内容时明确写“无”。

## 10. 范围熔断与阶段验收

- 阶段验收只验证完整提示词和已接受任务明确列出的能力，不把“阶段完成”解释为补齐所有相关可能性。
- 若继续需要新增独立公共协议、数据库迁移、Runner/Worker 执行链、外部实验、API/CLI/GUI 产品入口或其他可独立验收能力，先判断是否在当前范围；不在则停止并列入后续。
- 一个自然子阶段默认一次主要实现和必要局部修订；第二次非偶发返工触发升级，不用新增微批次、重复测试或扩大上下文继续消耗。
- 最终验收发现非阻塞缺口时写入“遗留事项”并结束；只有缺口直接否定核心能力时才重新规划，不在验收阶段扩项。
- 阶段报告明确区分“本阶段已实现”“验收发现但留待后续”“明确不属于本阶段”。
