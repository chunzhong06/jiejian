# 工程设计规范

> 状态：CURRENT。适用范围：界鉴当前模块化单体的代码组织、公共边界、安全工程和验证方式。

## 1. 系统形态与依赖方向

界鉴是模块化单体。GUI、CLI、API 和 Worker 共享 `ApplicationCore` 与应用工作流；高风险目标执行只能经持久 Job、Worker 和隔离 Runner。

当前主要目录职责如下：

| 目录 | 职责 |
| --- | --- |
| `product/backend/core` | 领域模型、纯规则、Verification、权限和结果语义 |
| `product/backend/workflows` | ApplicationCore 使用的应用编排和跨模块工作流 |
| `product/backend/infra` | Storage、Repository、事务、队列、发布和外部基础设施 |
| `product/backend/api` | FastAPI transport、资源、任务、事件和结果读取 |
| `product/backend/cli` | CLI 参数、调用共享工作流、等待、取消和展示 |
| `product/backend/migrations` | Alembic 数据库结构与迁移真源 |
| `product/protocols` | 跨进程公共模型、canonical、hash、解析和 JSON Schema |
| `product/frontend` | Web GUI 展示和用户交互，不直接访问目标 |
| `scripts` | Windows 启动、准备和运行环境编排 |

`ApplicationContainer` 是 GUI、CLI、API 的完整组合根，`ApplicationCore` 是其能力门面；Worker 使用独立完整的 `WorkerContainer`，禁止通过继承或提前返回形成部分初始化对象。领域纯逻辑不得依赖 FastAPI、SQLAlchemy、Playwright 或具体 LLM SDK；协议模型不得反向依赖具体 transport。

## 2. 当前执行边界

当前唯一可执行目标是 `TargetType.WEB` 与 Web Target Runtime。生产协议不保留 `CLI_APPLICATION`、`MCP_AGENT` 等未实现枚举或空模型；未来 Target 以不兼容 Schema 加入 TargetRuntimeRegistry。当前没有 Process execution adapter、MCP execution adapter 或 MCP ingress。

安全主链为：

`安全意图 → PermissionContract → Coverage/PermissionMutationPlan → TargetRuntimeRegistry → Web Target Runtime → ExecutionFact + ObservationFact + SecurityEffectFact → Evidence → Verification → Run publication → Finding/Occurrence → 基础 Report → 可选 Baseline/Gate/Gate Report`

具体边界和数据流分别见五篇 Architecture；代码负责实现，测试负责证明，不在本规范复制实现步骤。

`ActionDefinition` 只表达业务动作、Security Effect、batch 和 workflow transition；HTTP method、relative path、status、身份和资源注入属于 Web workflow binding。`PermissionMutationPlan` 只表达覆盖用例和 required observations，不把具体 Observer 类型塞入权限动作。通用 Orchestrator 与 Verification 不导入 Web 协议。

## 3. 公共格式与兼容

- `product/protocols/schemas` 是机器字段约束真源。
- 公共数据必须明确 `schema_version`；canonical 序列化和 hash 输入必须稳定、可复现。
- 跨进程请求、结果、证据、报告和工件必须严格解析、校验身份关联、大小、预算、秘密和完整性。
- 错误结构必须稳定、脱敏，并区分输入无效、执行失败、证据不足、发布失败和内部故障。
- 当前不提供旧开发数据库、旧 Profile/Run/Evidence/Artifact/Report 或旧 wire format 的兼容读取。数据库 revision、结构签名或公共格式不匹配时 fail closed，要求重建 `var`，不猜测迁移。
- migration 由 `product/backend/migrations` 管理；代码不得静默修改数据库结构或绕过迁移边界。

## 4. 安全工程边界

- LLM 只能产生待审阅候选，不能决定 Verification Verdict、Finding、Gate 或自动激活 PermissionContract。
- 秘密只通过受控引用和最小 Runner 环境注入；秘密值不得进入协议、Evidence、日志、异常、报告、源码或 Git。
- API/GUI 不直接向目标发高风险请求；目标范围、重定向、私网授权、请求/响应预算、超时、脱敏和清理必须在执行边界检查。
- 已发布 Evidence 不可变；生命周期状态、Verification Verdict 和 GateResult 分离保存，后者不得反改前者。
- `INCONCLUSIVE` 表示证据不足或观察不完整，不能解释为安全或未发现问题。
- `var` 保存运行数据库、日志、缓存、临时 staging 和工件，不属于源码或提交内容。

协议族的当前机器格式版本以代码和 Schema 为准：Runner、Observer、Execution facts 使用 2，Recording、FlowDraft、Artifact 使用 1，Report 使用 2。该数值只表示 wire/schema 格式，不表示产品代际。

## 5. 模块、抽象和文件内聚

模块按真实业务、安全、协议、事务或进程边界组织。新增抽象必须有多个真实实现、稳定公共边界、框架发现或隔离价值；不为未来可能性建立空壳 adapter、wrapper 或目录。

文件保持单一职责和内聚。跨模块不变量放在领域或应用边界，transport 只做适配，基础设施只负责资源和事务。低成本局部细节留给代码，不用文档或抽象增加间接层。

- 私有辅助函数默认至少有三个生产代码调用点，测试调用不计入生产复用证据。
- 框架入口、领域不变量、安全边界、独立失败或清理职责，以及能够阻止主流程膨胀的独立检查，可以低于三个调用点，但必须能说明边界价值。
- 零调用且没有框架发现机制、当前需求或测试约束的符号应删除或延后，不以未来可能使用为由保留。
- 新增抽象前证明存在两个以上真实实现或明确隔离需求。
- 三百至五百非注释代码行只是职责审查提醒，不是文件最低行数；超过约五百行时审查是否混合多个演进方向。小文件仅在缺乏独立业务、框架或安全边界时合并。
- `__init__`、程序入口、配置、Schema 和测试文件不要求承担三百行以上业务逻辑。

## 6. 测试与注释

测试优先覆盖安全边界和可观察契约：Contract 治理、Profile 漂移、Target/Router、Worker lease/fencing/recovery、staging/publication、migration，以及 GUI/CLI/API 共享语义。业务闭环测试应验证真实事实链，而不是只断言中间状态。

Python 检查设置 `PYTHONDONTWRITEBYTECODE=1` 并使用 `python -B`；语法检查优先 `ast.parse`。pytest 使用 `-p no:cacheprovider` 和 `var/` 下唯一 basetemp，并在结束后精确清理临时目录。

Windows 启动脚本兼容默认区域设置：`scripts/start.ps1` 与 `scripts/startup/*.ps1` 保存为带 BOM 的 UTF-8，使 Windows PowerShell 5.1 在系统 UTF-8 Beta 关闭时仍能解析中文；`.cmd/.bat` 保持无 BOM 且仅含 ASCII，代码页 65001 只用于后续控制台输入输出。字节级测试保护该约束。

修改生产源码时，在最终验证前使用仓库 Skill `.agents/skills/jiejian-comments/SKILL.md` 校准三层注释；文档、纯数据、生成文件、普通 migration、包标记和测试 fixture 不适用。独立业务、安全、协议、事务和编排文件保留简短信息卡。公共边界、关键不变量、危险副作用、失败/清理和返回契约保留必要说明。Pydantic 模型类 docstring 会进入生成 Schema，注释专门优化不得新增或改写，应使用类定义前的 `#` 并运行 Schema 漂移测试。行内注释解释原因和反直觉边界，不复述代码动作。

不建立注释指标、覆盖率扫描、逐文件教程或长模板 docstring；自动生成文件、migration、纯常量、包标记和测试 fixture 可例外。

## 7. 用户可见术语

用户可见名称使用稳定、直接的产品术语：工作台、应用接入、权限规则、开始检查、检查结果、历史变化，以及高级中的流程录制、模型服务、运行环境。内部类名、状态机、Runner、Observer、Schema 和 GatePolicy 不作为首页能力名称。
