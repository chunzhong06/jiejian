# 技术文档规范

> 状态：CURRENT。适用范围：`docs/` 技术知识、架构、协议、决策、路线和研究文档。

## 1. 真源层级

文档按回答的问题分层，不在多个文件维护同一份当前事实：

1. `AGENTS.md` 是开发行为入口，只保留全局硬约束并路由到工程、验证、权限和协作专题规范。
2. 根 `README.md` 是普通用户的产品入口。
3. `docs/README.md` 是技术知识路由。
4. Architecture 描述系统当前是什么、边界在哪里。
5. ADR 解释为什么形成某项长期决策，并保留历史过程。
6. Protocol/Schema 定义跨进程机器边界；JSON Schema 是字段约束真源，Protocol Markdown 解释语义、生命周期和失败边界。
7. Migration 是数据库结构和迁移真源。
8. Roadmap 只说明下一步方向和完成摘要。
9. Experiment 只保留问题、思路与设计、固定条件、观察、结果、结论、限制和可迁移影响。
10. 代码与测试是最终运行事实。

## 2. 文档职责与去重复规则

- Architecture 不复制 ADR 历史，不把每次开发过程写成当前架构。
- ADR 不复制 Architecture 当前事实，只记录决策、理由、取舍、影响和状态。
- Protocol Markdown 不复制完整 JSON Schema 字段表；字段、类型和 required 约束以 Schema 为准。
- Roadmap 不承担永久当前架构，不作为普通任务的默认技术入口。
- 廉价的局部实现细节不写文档；只有跨模块不变量、安全边界、公共契约、失败语义或长期取舍才进入文档。

同一事实需要在多个入口出现时，入口只保留一句摘要和链接，详细内容只保留在一个真源中。

## 3. CURRENT 与历史

ADR 状态只使用以下五种值：`提议`、`已接受`、`已取代`、`已废弃`、`已拒绝`。

CURRENT 文档必须描述当前实现或仍然约束当前实现的边界。已取代、已废弃和已拒绝的 ADR 保留原编号与正文，用于追溯，但不进入默认必读集合。历史文档可以包含旧阶段、旧路径或旧格式，不能被路由文字误标为当前产品事实。

Architecture 只有在其正文、代码真源和相关测试一致时才标记 CURRENT。发现冲突时，先标明冲突范围和代码真源，不用猜测补齐架构。

## 4. 创建、更新、拆分与删除

创建文档前必须确认：已有文档无法清楚承载该长期边界，且新文件有独立读者、真源或演进理由。只有把多个主题混在一起并造成误读时才拆分。

更新文档必须同步检查相对链接、状态、相关真源、代码路径和测试引用。公共协议、Schema、migration、入口、安全或持久化语义发生变化时，文档和实现必须在同一变更范围内重新核对。

删除文档只在内容已完整迁移、历史仍由 Git 或 ADR 保存、没有必要的路径消费者后进行。不要创建只转发到新路径的长期 wrapper。

## 5. 相对链接、标题与状态

- 技术文档只使用相对链接，链接到仓库内真实路径或本批明确会创建的目标路径。
- 链接文字使用目标文档的正式标题，不把阶段编号当作长期能力名称。
- 文档顶部说明 `状态`、`适用范围` 和必要的真源；CURRENT 文档不得把历史方案写成当前实现。
- Architecture 标题使用能力和边界，不使用开发阶段、版本代际或一次性任务名称。
- 删除或移动文件后，必须搜索旧路径消费者；不能用死链掩盖未迁移的入口。

## 6. Architecture 最小模板

每篇 CURRENT Architecture 至少包含：

1. 状态与当前适用范围；
2. 职责；
3. 非职责；
4. 真源；
5. 目的；
6. 组件与边界；
7. 关键数据流；
8. 关键不变量；
9. 失败语义；
10. 安全约束；
11. 兼容与版本；
12. 相关真源。

“非职责”是强制项，用来防止 Architecture 越界描述尚未实现的能力或吞并其他文档的语义。

## 7. 其他文档最小模板

- ADR：状态、背景、决策、理由、取舍、影响、迁移/兼容、相关真源。
- Protocol/Data：目的、消费者、边界、生命周期、失败/安全语义、版本规则、Schema 真源、相关代码。
- Roadmap：已完成摘要、当前可验证事实、下一步目标、验收边界和明确不做事项。
- Experiment：问题、思路与设计、固定条件、观察、结果、结论、限制、可迁移影响；不得把实验结果写成已实现产品能力。实验代码、测试、数据和日志只在实验期间进入 `var/`，文档沉淀后删除；转为正式能力的内容按实际生产或测试职责归位。

读者应先从 `docs/README.md` 按任务进入，再只读取必要的 Architecture 和深入真源，不要求先读完整 Roadmap 或全部 ADR。

## 8. 变化责任

代码、测试、Schema、migration、协议或安全边界改变时，变更者负责检查直接相关 Architecture、ADR、Protocol/Data 和链接。架构决策改变时，必须同步说明旧决策是保留、局部取代还是完整取代。文档改动不得反向创造不存在的代码能力。
