# 权限契约与执行计划

> 状态：CURRENT。本文解释权限数据族之间的安全边界，不复制 JSON Schema 字段表。

## 目的与消费者

本协议族连接 Contract Governance、Coverage 编译、WebExecutionProfile、Verification 和 GUI/CLI 展示。消费者需要区分用户意图、候选建议、可执行契约、覆盖用例和观察要求。

## 协议边界

- `Requirement` 是待验证意图。
- `ContractCandidate` 是确定性或 LLM 建议，始终不可信。
- `PermissionContract`/`ContractVersion` 是唯一可执行安全意图，包含 Security Effect Manifest；Action 只通过 `effect_ids` 引用效果，不包含 transport 细节。
- `NormalizedPermissionPlan` 是规范化计划。
- `PermissionMutationPlan` 是带 fingerprint、seed、预算、cases、coverage、gaps 和 required observations 的 Contract-only 覆盖计划。
- `DifferentialExperimentPlan` 在 Coverage 之后为风险 case 冻结 ALLOW 控制、DENY 变体、允许变化维度和必须相同的不变量。
- `Coverage` 说明规则、subject、action、resource、relation 和覆盖范围；不包含 HTTP transport 细节。

## 生命周期与数据流

```text
Requirement → Candidate → 人工治理
  → PermissionContract/ContractVersion ACTIVE
  → NormalizedPermissionPlan
  → PermissionMutationPlan/Coverage
  → DifferentialExperimentPlan
  → WebExecutionSnapshot
```

确定性 canonical、ID、排序、指纹和 drift 结果必须稳定。LLM 候选必须经过同一 assessment、审阅和激活门禁。

## 失败与安全语义

空规则、重复 ID、跨项目引用、冲突候选、观察器不足、规则漂移、非法状态转换和 canonical/hash 不一致均阻止进入执行。Candidate 不能决定 Verdict、Finding、Gate 或自动激活 Contract。

## 版本规则与 Schema 真源

Security Effect Manifest 与差分计划引入不兼容结构后，当前 contracts Schema 升级为单一新版本；版本号只表示机器格式。完整字段、required、枚举和严格解析以：

- `product/backend/core/`
- `product/protocols/schemas/contracts/`
- `product/protocols` 中对应模型

为准。本文只说明边界，不复制完整 Schema。
