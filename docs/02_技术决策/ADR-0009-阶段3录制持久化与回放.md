# ADR-0009：阶段 3 录制持久化与回放

## 状态

已采纳（2026-08-11）。

## 背景

阶段 3 需要把浏览器交互转换为可审阅的 Flow，并在不让 CLI 直接接触目标流量的前提下持久化、审阅、发布和回放。录制数据可能包含 Cookie、Authorization、表单字段、响应体和动态资源标识，必须在任何文件、数据库或日志边界前完成脱敏。

## 决策

1. **进程边界**：CLI 只校验、提交 Job 和展示状态；Worker 负责租约、取消、结果校验和发布；Recording Runner 一个进程只执行一次 Recording 或一次回放。目标请求只能由 Runner 发出。
2. **身份隔离**：每个 identity 使用独立的非持久 `BrowserContext`。不写入原始 `storage_state`，不跨 identity 共享 Cookie、localStorage 或 sessionStorage。
3. **传输与脱敏**：浏览器适配器在请求发出前检查 TargetScope、协议、主机、端口和私网边界；有界 HTTP 传输单跳读取响应，先校验 `Location` 再交付 3xx，SSE、下载和长连接进入显式不支持/安全停止。请求、响应、WebSocket 和错误数据先限长、脱敏，再交给工件接口。
4. **Trace**：原生 Playwright trace 默认禁用，因为无法保证写盘前脱敏；事件采集使用 `RecordingEventV1`，只保存稳定序号、关联标识和脱敏摘要。
5. **草稿审阅**：事件处理器按因果标识关联 UI 动作和请求，提取动态变量候选并生成无环 `FlowDraftV1`。删除、相邻合并、重命名和变量来源确认均产生新 revision；只有 identity、资源和变量来源全部确认后才可编译现有 Flow。
6. **持久化与发布**：`recordings` 保存 Recording 生命周期，`flow_draft_revisions` 保存不可变草稿版本；Job 对旧 Run 或 Recording 恰好一种关联。脱敏事件和草稿先原子写入，最终 Flow 以临时文件、哈希校验和 `os.replace` 发布，随后在同一 UnitOfWork 推进 `Recording=COMPLETED`。数据库不得引用未发布工件，也不保存 trace、storage state 或秘密。
7. **回放**：`recording replay` 复用现有 Worker/Runner 和 Verification 核心，每次创建新 Job 与新浏览器会话，默认连续三次；任一失败即停止并返回稳定错误，不把失败伪装为三次成功。

## 影响与边界

该决策保持阶段 2 的 Job、fencing、工件校验和事务顺序，不新增第二套调度器或最终 Flow 模型。当前 V1 不提供 API/GUI、开放式代理、原始 trace、长期密钥传递或完整多格式报告；动态变量只能使用显式确认的来源。未来阶段如扩展能力，必须保留上述进程、脱敏和发布边界并新增验证证据。

## 回滚

若阶段 3 功能需要回滚，停用 `recording` CLI 命令和 Recording Job 提交入口，保留已发布只读 Flow 与历史 revision；不得删除数据库记录、运行工件或通过旧 fencing token 重放。数据库迁移只向前，结构回滚需另行提出 ADR。
