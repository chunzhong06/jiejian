# ADR-0016：阶段 5.4C CLI 与 GUI 建约接入

- 状态：已接受
- 日期：2026-08-11
- 范围：Contract 治理的 CLI 与 GUI 用户入口

## 背景

阶段 5.4B 已提供 ContractWorkbenchService 和治理 REST，但 CLI 仍只有显式文件校验，GUI 建约页也只展示/激活 YAML。需要形成用户可操作的 Requirement→Candidate→Contract Version 治理闭环，同时保持阶段 4 的显式 YAML 入口。

## 决策

1. CLI 在现有 `contract` Typer 组增加 workspace、requirement-add、derive、draft、revise、transition、assessment、diff、drift 和 history。CLI 直接创建并关闭 `ApplicationContext`，显式 project.yaml 通过统一共享边界 `register(..., revalidate=True)`；不调用本地 REST，不复制领域算法。
2. GUI 建约页迁移到单个 `frontend/src/ContractPage.tsx`，只调用 `frontend/src/api/client.ts` 的精确治理方法。页面展示工作台快照、阻断 issue、版本动作、assessment/diff/drift、项目绑定和 `llm_available`，不在浏览器实现候选合并、评估、状态机或 verdict。
3. GUI 保留显式 YAML Contract 兼容区；LLM 默认离线，页面不接受 provider、key、prompt 或模型配置。actor 使用可见输入，默认 `local-user`。

## 后果

- CLI 与 GUI 共享同一治理语义，激活后的项目绑定和新 Run 快照继续由 5.4A/5.4B 负责。
- 用户可从空 var-dir 通过 CLI 完成建约生命周期，GUI 刷新后从服务端恢复治理数据，不依赖 localStorage 保存契约正文。
- CLI/GUI 接入不改变 API Schema、Runner、Worker、Verification/Verdict 或其他用户阶段。

## 验证

`tests/e2e/test_cli_contract_workbench.py` 覆盖 CLI 连续生命周期和非法转换；`frontend/src/ContractPage.test.tsx` 覆盖工作台恢复、离线 LLM、阻断未落盘、候选建草稿、提交审阅和 YAML 兼容入口。前端 Vitest 与 TypeScript/Vite 构建通过。
