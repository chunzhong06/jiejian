# ADR-0035：产品入口与控制面边界

- 状态：已接受
- 日期：2026-08-19
- 适用范围：GUI、CLI、CI、API、ApplicationCore、任务展示和结果读取

## 背景

界鉴需要同时服务普通用户、自动化和 CI，但入口不能各自实现权限治理、执行编排或结果判定。产品展示还必须让用户区分生命周期、证据、结论和门禁。

## 决策

GUI、CLI 和 API 共享 ApplicationCore。Worker 使用独立组合并复用同一应用服务语义；当前仅装配 RECORDING，控制面报告真实线程与能力，CHECK 不可用。API 是固定 `127.0.0.1` 的薄控制面，只负责严格解析、授权、资源读取和脱敏错误映射，不发目标请求。服务启动时生成只驻留内存的 256-bit control session，GUI 根页面通过 HttpOnly、SameSite=Strict Cookie 取得；所有请求匹配实际 `Host`，全部 `/api` 验证当前会话，写请求再验证精确同源 `Origin`，且不信任代理头。CLI/CI 直接复用 ApplicationCore，不绕 HTTP，也不受浏览器会话影响。Human、JSON 和 CI 输出语义分离。

GUI 使用任务型信息架构：工作台是唯一主控入口，变化与修复、权限边界、检查与结果是三个辅助模块；应用接入、业务流程、测试准备、验证运行、结果和历史保留任务路由。顶部只保留应用切换、AI 工具与低频设置；AI 辅助通过单一设置抽屉管理，`/settings/models` 仅作为错误恢复深链打开该抽屉，不形成独立模型服务页面。旧 `/advanced/...` 路由不作为兼容入口。用户术语以业务任务为主，内部 Recording、Profile、resource id 和 reason code 不进入普通导航。

普通应用接入先建立不要求完整 `WebExecutionProfile` 的 DRAFT Project 与项目级 ApplicationUnderstanding。当前 Web 执行只自动探测并确认 `127.0.0.1`；`localhost` 规范为可用的 IPv4 loopback，`::1` 留待未来完整 Target 支持。基础目录识别与普通源码分析分开授权。确定性分析只提出带证据的角色和业务动作候选，候选及风险提示不构成权限关系、漏洞严重度或 Verification 结论。

工作台和导航共同消费只读 ProjectReadiness。该投影只从 Project、ApplicationUnderstanding、Profile、Flow、Contract、Run 和 Recording 计算，不持久化 CheckPlan；旧 Profile 项目可直接从既有权威事实推导等价 readiness。

结果展示分离生命周期、Evidence 完整性、Verification Verdict 和 GateResult。PASS 表示当前规则覆盖范围内未发现越权，BLOCK 表示发现可能的权限越界，INCONCLUSIVE 表示证据不足；结果完整性无效或执行失败单独展示，不能冒充第四种 Verdict，也不能与三种安全结论互相替代。

## 理由与取舍

共享 ApplicationCore 避免 GUI、CLI、CI 形成不同安全语义；任务型页面让用户按目标动作理解产品。代价是人类展示与机器协议必须保持两套明确的表示边界。

## 影响

API/GUI 不直接访问目标；断开控制面不取消任务也不代表任务成功。事件序号支持恢复读取。历史变化只比较完整终态运行，高级能力不改变主执行链。

## 迁移与兼容

当前 API 路径为 `/api`，CLI 命令和输出以实际 help 为准。旧 GUI 页面组织、旧 API 路径和旧内部入口不作为兼容承诺。
