# ADR-0043：Codex 开发知识与冷启动路由

- 状态：已接受
- 日期：2026-08-26
- 适用范围：Codex 开工门禁、开发知识结构、任务路由、生成参考与冷启动验收

## 背景

旧技术文档体系能够区分 Architecture、ADR、Protocol 和 Roadmap，却默认要求从 Architecture 开始阅读。10.7D 的真实协作表明，新 Codex 可能先加载大量系统知识，却没有先确认用户是否真的要求行动、当前线程角色、恢复点、停止条件和执行线程接受边界；目录 README、源码长注释和 Architecture 又重复承担代码导航，导致上下文偏大并容易漂移。

## 决策

根 `AGENTS.md` 改为紧凑的 Codex 启动协议，先执行用户意图门和恢复门，再按任务分类加载强制知识。Codex 固定沿 `AGENTS.md → docs/llms.txt → 当前任务指南 / 模块参考 / 必要工程约束` 进入；普通任务第一轮默认只选择一篇任务指南、一篇模块参考和一篇确有需要的约束。阶段任务还必须取得用户指定的完整阶段提示词、当前账本和恢复点。

人类开发者沿 `README.md → docs/README.md` 进入，与 Codex 读取同一正文知识。CURRENT Docs 固定为五层：系统地图、开发指南、参考手册、工程约束、设计依据。阶段计划和未来路线保存在仓库外用户指定载体，不进入普通开发知识树。

公开符号、签名、import 和协议字段等“代码现在是什么”由确定性生成参考维护；任务入口、模块职责、安全理由和工程取舍由人工文档维护。目录导航型 README 在内容迁移后删除，不保留转发 wrapper；源码注释只保留职责头、公共契约和靠近实现的原因。

知识库是否可用必须通过无历史上下文的一次性 Codex 冷启动探针验证；只看链接存在或文档数量不能替代真实阅读轨迹。

本决策取代 ADR-0028 的默认 Architecture-first 路由和旧五类目录形态，但保留其“入口分责、CURRENT 与历史分离、代码和测试是最终事实”的原则。

## 理由与取舍

任务式路由先解决“能否开始、必须读什么”，再加载系统细节，能够减少上下文并降低角色和范围错误。五层正文同时服务人类与 Codex，避免维护两套知识。代价是代码变化需要稳定生成器，模块或任务职责变化需要同步唯一人工文档；`dev.ps1 docs` 的漂移和死链检查承担这部分成本。

## 影响

- `docs/llms.txt` 成为 Codex 的低成本路由入口，`docs/README.md` 继续作为人类入口。
- 旧 `01_技术规范`、`02_架构设计`、`03_架构决策`、`04_协议与数据`、`05_路线与研究` 按冻结治理 map 迁入五层结构，不长期并存。
- 执行线程状态、等待、返回和接受进入工程约束；停止或完成事件不能替代主线程审计。
- 自动参考签入 Git，但生成器不能 import 并执行生产代码来理解源码。

## 迁移与兼容

迁移只改变开发知识路径和生成参考，不改变产品代码、公共 API、Schema、migration 或安全结论。旧路径在内容和链接完成迁移后直接删除，不建立长期兼容 README。历史正文继续由 Git 恢复。
