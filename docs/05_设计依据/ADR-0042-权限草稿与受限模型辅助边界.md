# ADR-0042：权限草稿与受限模型辅助边界

- 状态：已接受
- 日期：2026-08-31
- 适用范围：权限自然语言草稿、CURRENT 三类 AI surface、确定性准备投影、模型出站、缓存与界面标识

## 背景

普通用户需要用业务语言批量表达权限要求，但正式权限仍必须由 Human GUI 逐项确认。模型适合把人主动输入的短文本整理成候选草稿，不适合发现权限真源、批准 ALLOW/DENY、决定实现映射或替代当前正式业务边界。

## 决策

`PermissionDraftService` 只在用户明确提交文本时调用默认模型。服务端从当前 ACTIVE BusinessActor、BusinessAction 与 Effect catalog 建立完整的有限原子 option universe；每项固定 subject/action/owner 的正式 revision、合法 relation、单个 effect 与已有 current expectation。同 actor 只枚举 OWNS/SAME_ROLE_OTHER_ACCOUNT，不同 actor 只枚举 OTHER_ROLE，没有既有 Permission 也能形成选项。模型只见 opaque `option_id`、短业务显示名、关系和当前期望，不见业务 ID、源码、Evidence、秘密、HTTP、Observer、Recovery 或执行配置。超过 128 项时直接 PARTIAL 并引导手工维护，不静默截断或调用模型。

模型输出只能包含 `suggestions[].option_id/expectation/source_quote` 和 `unresolved_quotes[]`。本地验证本次 option、ALLOW/DENY、原文连续非空引文、字段与预算；未知项、伪引文和同原子冲突全部拒绝，相同 subject/action/owner/relation/expectation 的多 effect 才合并。未覆盖的实质原文由本地保留为待确认事项，不依赖模型自报完整。模型返回后复读正式 Boundary fingerprint，变化时拒绝全部陈旧建议。

草稿状态只表达 `READY_FOR_REVIEW`、`PARTIAL` 或 `UNAVAILABLE`。独立 permission-drafts API 只返回待审建议与正式 Boundary fingerprint，不持久化、不进入 AssistantCache、不推进 `policy_epoch`，没有 Proposal/Approval 或 binding 写能力。正式权限必须由完整 Boundary maintenance Proposal 和固定 LOCAL_GUI 的 Human Approval 事务形成，不能沿旧矩阵 cell target 审批。

模型关闭、默认 profile 缺失、秘密未配置、超时、限流、provider 错误或非法输出都只让本次草稿降级，现有业务边界与确定性主流程保持可用。页面读取、GET、服务启动和普通业务边界操作不触发模型调用。

当前 Assistant 只注册 `implementation-mapping`、`recording-review`、`preparation-explanation`，分别使用 `jiejian.implementation_mapping`、`jiejian.business_recording_review`、`jiejian.preparation_explanation` 模板。它们只解释当前正式业务对象、明确定向的录制步骤/资源候选或准备缺口，不写 binding、TARGET、requirement 或安全结论。旧八模板及 Guidance/ErrorDiagnosis 仅为 dormant 算法，不注册旧 result/error API。

确定性下一步与准备事实由 WorkspaceService 和 PreparationService 提供。Assistant GET 只重算服务端短事实并读缓存，显式 POST 才允许生成；唯一确定时连 POST 也跳过 provider/cache。每项输出都按版本、数量、长度、当前 entity ID、kind 与实体/准备类别重验，缓存回读同样验证。缓存只保存受限结果或短期退避，不保存 prompt、供应商原始响应、隐藏推理、秘密、源码或 Evidence 正文。

## 理由与取舍

先由服务端建立有限 option universe，再让模型只引用 opaque ID，可以提供自然语言整理能力，同时把正式权限审批、实现映射和执行范围留在确定性边界内。代价是模型不能自由补充看似合理的新单元，部分原文会返回未映射项，用户仍需逐条核对并确认。

权限草稿不复用 AssistantCache。草稿包含本次人主动输入的原文片段，且只有当前响应需要；不落盘可以避免把权限文本变成新的历史真源，也避免旧草稿在业务边界变化后被误用。

## 影响

模型 Provider、Profile、模型目录、推理强度、连接测试和共享 SecretStore 继续作为全局可选控制面。PermissionIntent、ContractVersion、Verification、Finding、Gate、Report、Observer、Runner 和 WebExecutionProfile 均不消费模型建议。产品必须把草稿明确显示为“待你确认”，模型失败时继续显示并允许维护现有业务边界。
