# ADR-0042：权限草稿与受限模型辅助边界

- 状态：已接受
- 日期：2026-08-31
- 适用范围：权限自然语言草稿、八类 AI surface、确定性引导、错误诊断、模型出站、缓存与界面标识

## 背景

普通用户需要用业务语言批量表达权限要求，但正式权限仍必须由 Human GUI 逐项确认。模型适合把人主动输入的短文本整理成候选草稿，不适合发现权限真源、批准 ALLOW/DENY、决定实现映射或替代当前权限矩阵。

## 决策

`PermissionDraftService` 只在用户明确提交文本时调用默认模型。服务端先从当前 `PermissionIntent` 矩阵建立本次请求内的有限 option universe，每个 option 只暴露 opaque `option_id`、短业务显示名、关系和当前期望；candidate ID、源码、Evidence、秘密、HTTP、Observer、Recovery 与执行配置都不发送给模型。

模型输出只能包含 `suggestions[].option_id/expectation/source_quote` 和可选 `unresolved_quotes[]`。服务端重新验证 option 属于本次 universe、期望只为 ALLOW/DENY、引文是人类原文的精确子串、同一 option 不冲突、字段和条数均未越界。无法通过的内容被拒绝，不猜测、不补全，也不创建角色、动作或权限单元。

草稿状态只表达 `READY_FOR_REVIEW`、`PARTIAL` 或 `UNAVAILABLE`。草稿不持久化、不进入 AssistantCache、不推进 `policy_epoch`，也不调用 `confirm`、`approve_proposal` 或 `rebind`。用户确认某条草稿时仍通过现有 Human Approval API 提交精确 cell target；只有该服务端事务可以形成正式 revision 或 binding。

模型关闭、默认 profile 缺失、秘密未配置、超时、限流、provider 错误或非法输出都只让本次草稿降级，现有权限矩阵与确定性主流程保持可用。页面读取、GET、服务启动和普通矩阵操作不触发模型调用。

其余 AI 辅助固定为 `jiejian.next_step`、`jiejian.candidate_review`、`jiejian.identity_preparation`、`jiejian.recording_review`、`jiejian.observation_recovery`、`jiejian.check_preview_explanation`、`jiejian.result_explanation` 和 `jiejian.error_explanation` 八个版本 1 模板。它们只排序或解释服务端从正式 View 构造的有限事实，不生成权限草稿，也不改变候选、TARGET、权限预期、scope、恢复入口或安全结论。

`GuidanceSnapshot` 与 `ErrorDiagnosis` 继续是确定性只读投影。八类 surface 的 GET 只重算事实并读取可删除缓存；只有用户显式 POST 才能调用模型。缓存只保存已经通过本地白名单验证的短结果或短期退避，不保存 prompt、供应商原始响应、隐藏思考、秘密、源码、Evidence 原文、数据库内容或日志。

## 理由与取舍

先由服务端建立有限 option universe，再让模型只引用 opaque ID，可以提供自然语言整理能力，同时把正式权限审批、实现映射和执行范围留在确定性边界内。代价是模型不能自由补充看似合理的新单元，部分原文会返回未映射项，用户仍需逐条核对并确认。

权限草稿不复用 AssistantCache。草稿包含本次人主动输入的原文片段，且只有当前响应需要；不落盘可以避免把权限文本变成新的历史真源，也避免旧草稿在矩阵变化后被误用。

## 影响

模型 Provider、Profile、模型目录、推理强度、连接测试和共享 SecretStore 继续作为全局可选控制面。PermissionIntent、ContractVersion、Verification、Finding、Gate、Report、Observer、Runner 和 WebExecutionProfile 均不消费模型建议。产品必须把草稿明确显示为“待你确认”，模型失败时继续显示并允许操作现有矩阵。
