# 界鉴项目总览

## 一句话定位

界鉴是一个面向 Vibe Coding Web 应用的安全意图差分验证与交付门禁系统：它检查开发者想要的安全规则，是否真的落实到了应用运行行为中。

## 它解决什么问题

AI 可以很快生成一个“看起来能用”的 Web 应用，但页面提示、HTTP 状态和后端真实行为可能并不一致。例如，接口返回了 `403 Forbidden`，数据库里的资源却已经被越权修改。如果只看 HTTP 状态，就会把这个缺陷误判成安全。

界鉴因此不把 `200`、`403` 或其他单个状态码直接当作安全结论。它会同时观察请求结果和资源所有者视角的后端副作用，再用安全契约判断行为是否符合预期。

## 核心链路

```text
安全意图 → 安全契约 → 关系变异 → 多观察者验证 → 证据 → 门禁
```

| 环节 | 做什么 |
| --- | --- |
| 安全意图 | 说明谁能对什么资源执行什么操作。 |
| 安全契约 | 把意图变成可执行、可审查的规则。 |
| 关系变异 | 保持业务动作基本不变，只交换身份、资源或敏感字段。 |
| 多观察者验证 | 同时比较 HTTP 表象和资源所有者看到的真实状态。 |
| 证据 | 保存输入、变异、观察、原因码和内容哈希。 |
| 门禁 | 聚合为 `PASS`、`BLOCK` 或 `INCONCLUSIVE`，供本地或 CI 使用。 |

最终结论必须能沿这条链回溯，不能只依赖模型判断或一句“可能有风险”。

## 当前已经能做什么

项目当前完成了阶段 0–2.4，真实产品入口是 CLI `jiejian`。现有能力包括：

- 校验严格的项目、Flow 和 ACTIVE Contract 输入；
- 对所有权场景生成确定性的身份交换、资源交换和敏感字段变异；
- 在授权的本机目标上执行 HTTP 验证，并比较 HTTP 与 owner API 观察；
- 输出带哈希的 JSON Evidence 和 `PASS`、`BLOCK`、`INCONCLUSIVE` 门禁结论；
- 将 Job 持久化到 SQLite，由 Worker 调度隔离 Runner；
- 使用 RunnerInputV1/RunnerResultV1 固定进程协议，真实秘密只通过最小子进程环境传递；
- 校验 staging 后原子发布工件，再通过 UnitOfWork 写入数据库完成态；
- 在发布后数据库提交失败时通过 reconciliation 幂等恢复；
- 用 `report <run_id>` 读取并校验已发布的 JSON 报告。
- 通过 `recording start/status/review/finalize/replay` 完成脱敏录制、FlowDraft 审阅、Flow 发布和三次隔离回放。

安全与缺陷配对样例位于 [fixed ownership](../samples/fixed_apps/ownership/) 和 [vulnerable ownership](../samples/vulnerable_apps/ownership/)。

## 当前还不能做什么

以下能力仍属于后续阶段，当前仓库没有可用入口：

- Web GUI 和 REST API；
- LLM 契约候选和漂移分析；
- 插件系统；
- HTML、SARIF、JUnit 等完整多格式报告；
- 未经授权的公网扫描或不可逆破坏性测试。

## 第一次从哪里开始

1. 按 [README](../README.md) 创建并激活 `jiejian_env`。
2. 运行 `jiejian --help` 和 `jiejian doctor --json`，确认本机环境。
3. 阅读安全样例的 [project.yaml](../samples/fixed_apps/ownership/project.yaml)、[flow.yaml](../samples/fixed_apps/ownership/flow.yaml) 和 [contract.yaml](../samples/fixed_apps/ownership/contract.yaml)。
4. 运行输入校验：

   ```powershell
   jiejian project validate .\samples\fixed_apps\ownership\project.yaml
   jiejian contract validate .\samples\fixed_apps\ownership\contract.yaml
   ```

5. 按 [架构说明](架构说明.md) 启动本机样例并比较 safe 与 vulnerable 的门禁结果。
6. 需要深入设计时，再读 [项目设计规范](02_开发规范/项目设计规范.md)、[开发路线图](05_开发记录/开发路线图.md) 和 [详细模块地图](01_架构设计/模块地图.md)。
