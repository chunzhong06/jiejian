## 后续阶段顺序与验收

## 阶段 6：复杂权限关系与多观察者

### 6.1 权限意图与兼容适配

已完成：实现 subject/action/resource/relation/context/expected result 的 V2 权限意图和规范化用例中间表示；显式声明角色并严格校验角色/动作/状态引用、连续关系路径、上下文一致性、冲突和观察器要求；以确定性适配器读取现有 RuleKind/FlowStep 所有权 V1，不修改历史快照或 Runner V1。已签入独立 V2 Contract/计划 Schema、严格漂移与兼容测试。复杂权限计划仍不作为 V1 输入；Runner V2 执行使用独立快照和工件边界。

### 6.2 关系覆盖与约简

已完成：支持角色、部门、租户、所有权、资源/管理层级、工作流状态、有限批量操作和有界间接继承。使用合法基线、最近禁止邻居、显式覆盖维度和稳定消除规则生成覆盖，不穷举全组合；计划记录来源、关系路径、seed、预算、约简理由、gap 和稳定 finding 前置身份。fixed/vulnerable/inconclusive 三套同 Contract 的 loopback 样例资产与动态测试已加入，并由正式 Profile→Worker→Runner→publication 闭环得到 PASS/BLOCK/INCONCLUSIVE；V1 ownership 输入不变。

### 6.3 Observer V2 与隔离执行

6.3 已完成：建立严格 Observer V2 spec/invocation/envelope/outcome 公共协议、规范 JSON/hash、窗口/因果/完整性语义和 owner_api V2→V1 兼容投影；在 Runner 隔离域新增固定 `resource-state` 只读 SQLite 子进程、最小 `env:` secret 选择、父墙钟/SQLite progress/行数/字节预算及失败矩阵，并用 fixed/vulnerable 同 HTTP 403 的真实 SQLite BEFORE/AFTER 配对证明拒绝后的无副作用与部分副作用。V1 Observation、Evidence、工件和 Verdict 不变；Runner V2 执行/工件阶段另有独立边界，Profile 后端入口已在阶段 6 后续批次接线。

验收：V1 黄金样例和历史 Run 读取不变；V2 用例生成可重复且预算不足不会 PASS；观察器无明文秘密、无隐式降级、无越界查询；Runner V2 输入、Evidence V2、Runner Result V2 具有独立 Schema/协议及执行编排测试，Job/lease/fencing/recovery/publication 语义不变。

### 阶段 6：Runner V2 与 Evidence V2 公共协议

已完成：冻结独立 `RunnerInputV2`、`EvidenceV2` 和 `RunnerResultV2` DTO、strict parser/canonical/hash、三份 Runner Schema 及跨引用、预算、显式 requirement→observer binding、OWNER_API 非秘密 credential ref、仅 BEFORE/AFTER/EVENTUAL 执行阶段、逐资源 resource×phase 覆盖、请求失败和 Evidence 内容寻址完整性测试；并接入稳定 `python -m jiejian.runner` 的 schema_version 分派、串行 case 时序、观察器调度、Verification V2 投影和 Evidence/Result staging 工件生产。现有 Worker 生命周期已接入持久请求、staging 校验、原子 publication 和 V2 基础结果读取；本批新增无秘密 Permission Execution Profile 源治理、0008 摘要表、共享 Application 服务、显式 `/api/v2` 路由和 `permission-run` CLI，完整 Profile/计划/快照仍在源文件/request/publication 链，不新增 jobs/runs 字段。测试页高级复杂权限入口和验证页 V2 Evidence 展示已接线；无秘密样例正式入口与动态闭环已接线，7.1 Finding 和 7.2 Baseline/Gate 已通过稳定 Results v2、v2 API 与新 CLI 接入，阶段 8 统一报告仍未实现，V1 输入/结果/工件/结论保持不变。

阶段 6 Verification V2 纯判定叶已实现：内部事实模型和确定性矩阵覆盖单资源、批量原子语义及 owner/sqlite/audit/async/Queue/Blob 观察归约；由 Runner V2 通过显式事实投影调用，Worker 只监督生命周期和 publication，不解释判定。

### 6.4 最小因果关联技术实验

技术实验已完成：测试侧确定性 harness 证明显式 case tag 可闭合请求、唯一任务终态和最终副作用，并对缺失/冲突 tag、重复/交错、轮转/部分尾行和预算不足返回不可确认；该实验结论记录见[阶段 6.4 因果关联技术实验](阶段6.4-因果关联技术实验.md)。生产审计日志、异步任务状态观察器和三类本机异步因果样例已完成并接入 Runner V2、Worker/publication、Profile/API/CLI 和验证页。0008 只保存非秘密 Profile 摘要，observation 事实继续保存在不可变工件；7.1 Finding 已另行完成，阶段 8 统一报告尚未实现。

当前批次完成：实现 `STRUCTURED_AUDIT_LOG` 与 `ASYNC_TASK_STATUS` Runner-side 隔离观察器，分别支持固定 JSONL 顶层轮转族和固定 IPv4 只读任务状态 API；增加 fixed/vulnerable/inconclusive 三类本机异步因果样例，测试侧分开验证 HTTP、审计日志、异步任务和最终副作用四面事实。两类观察器均使用显式 case correlation、独立 invocation、有限字段/状态、预算和严格完整性/冲突语义，且区分目标任务 `TIMED_OUT` 与观察窗口超时。旧 6.3 Observer DTO/canonical 不变。Runner V2 执行编排已能调用这些观察器、投影纯判定事实并生成 V2 Evidence/Result staging 工件；Worker/publication bridge 已复用既有生命周期接收 V2 结果；Profile 后端入口、无秘密样例正式入口与动态闭环已在本阶段后续批次接线；消息队列与对象存储适配器已在阶段 6.5 完成。

### 6.5 消息队列与对象存储技术实验

消息队列与对象存储最小只读实验均已完成并通过：Queue 验证了 Queue SAS `r`、Peek 不改变 dequeueCount、显式 `case_tag` 关联和 32 条无 continuation 的负观察边界；Blob 验证了 Container SAS `r+l`、固定 prefix 的分页 list/head/get、创建/覆盖/metadata-only/删除事实和预算不足时的 INCONCLUSIVE 边界。Queue Peek 与 Blob Object 生产适配器均已完成并通过本机 Azurite 动态验证；Profile 后端入口和无秘密样例正式入口已接入统一服务。结论记录见[阶段 6.5 消息队列与对象存储技术实验](阶段6.5-消息队列与对象存储技术实验.md)。

阶段 6.5A 协议与 Schema 已冻结：新增 `AZURE_QUEUE_PEEK`/`AZURE_BLOB_OBJECT` locator、provenance、独立测试命名空间、严格 endpoint/secret/allowlist/prefix/预算/阶段校验，并签入六份由模型原生 Schema 生成的 Observer Schema。共享 spec 定义扩展使 audit/async invocation Schema 发生机械变化；旧实例 canonical/hash、V1 行为和旧 invocation 运行语义不变。Queue Peek 与 Blob Object 已完成 Runner 隔离 REST 适配器和 Azurite 动态验证；Runner V2 执行编排现可调度各 Observer 并由既有 Worker/publication bridge 接收 V2 工件；Profile 后端入口和无秘密样例正式入口已接线。

### 阶段 6 里程碑验收

已完成：复杂权限覆盖多角色、部门/租户、资源层级、状态、批量操作和间接继承；owner_api、只读 SQLite、结构化审计与异步任务使用同一 Observer V2/Runner V2 事实链；Queue Peek 与 Blob Object 满足只读、显式关联、预算、规范化和 INCONCLUSIVE 边界。相同 Contract/Profile/seed 的计划、Evidence ID 和工件 hash 由 canonical 与回归测试保护，required 观察缺失不会 PASS。阶段 6 已验收；7.1 与 7.2 已分别验收，阶段 8 尚未开始。

## 阶段 7：稳定 Finding、回归基线与 CI 门禁

### 7.1 Finding 与 Occurrence

已完成：将单次不可变 Evidence、跨 Run 稳定 Finding 和每次运行的 FindingOccurrence 分开持久化；稳定 key 排除 run/case/时间、实际对象值和秘密，并覆盖项目、权限意图/规则、subject 类、action、resource 类/关系与问题类别。`0009_stage7_findings` 只向前新增两张索引表，旧 V1 Evidence 投影继续只作为历史读取结果；`/api/v2/runs/{run_id}/findings` 只从 PublishedResultReader 已验证的 V1/V2 publication 事实生成稳定查询结果。已覆盖 V1/V2 分派、Evidence 引用、旧库升级、稳定 ID 不误合并和两 Run 出现/消失闭环。

### 7.2 Baseline、GatePolicy 与 CI

已完成：RegressionBaseline 只能由操作者通过明确 actor、非空 reason 接受已发布 COMPLETED Run，并冻结 Finding/Occurrence/Evidence 引用、覆盖清单和执行/协议/engine 版本；基线创建后不可自动漂移。GatePolicy 生成独立、可重放的 GateResult；新漏洞、重现、覆盖退化、INCONCLUSIVE 和 required observer 缺失为 BLOCK，执行/发布错误为 ERROR。v2 API 与 `baseline accept`、`gate evaluate`、`gate result` CLI 共用同一应用服务，旧 `ci` 退出语义保持不变。

验收：7.1 已满足同一问题跨 Run ID 稳定、不同问题不误合并、Evidence 不可变引用、迁移与历史 V1 读取兼容；7.2 已满足 vulnerable→fixed→vulnerable 重现阻断、observer/覆盖退化阻断、publication/执行 ERROR、基线不可漂移、API/CLI 共用 GateResult 和旧 `ci` 兼容。阶段 8 尚未实现。

## 阶段 8：受控产物检查与统一报告

### 8.1 产物检查边界

新增独立、预算化的产物检查 JobHandler/隔离进程，只读取显式 staging 工件和 manifest。首版覆盖秘密、调试配置、Source Map、禁止文件及固定本地规则集的依赖版本；拒绝链接、路径逃逸、无界遍历、工件执行和在线规则更新。

### 8.2 报告真源与格式渲染

版本化 `report.json` 作为新 Run 的唯一语义报告真源；HTML、SARIF、JUnit 只从校验后的同一 JSON 确定性生成。历史 V1 报告原样读取，现有 API/CLI 稳定字段和退出语义通过显式版本 reader/投影保持。

验收：产物检查与运行时 Evidence 来源和进程边界分离；所有格式的 Finding、Gate、脱敏和 evidence 引用一致；修改派生格式不能改变结论；原子 publication、hash/manifest、历史 `report.json` 和当前报告入口兼容。

## 阶段 9：评测、量化实验与作品化

### 9.1 有真值评测集与实验

建立版本化 safe/vulnerable/inconclusive 配对集和保留集，覆盖 ownership、tenant、department、hierarchy、workflow、bulk、异步观察、观察器不可用、产物问题与修复回归。报告 Finding 级 precision/recall/F1、误报、INCONCLUSIVE 原因、覆盖率、观察可用率、预算、耗时和重放一致性。

### 9.2 比赛交付

冻结离线环境、规则/engine/protocol/schema 版本、黄金演示、安装包、报告、限制、指标和答辩材料。LLM 只评估候选接受率和人工成本，不进入 Verdict 真值；不得修改评测真值迁就实现。

验收：干净环境可按根 README 启动；固定环境和 seed 可重复得到预期 PASS/BLOCK/INCONCLUSIVE；实验数据不含秘密或未授权目标；报告、截图、指标、Schema、迁移和当前实现一致，不把规划写成已实现。

## 阶段通用完成定义

- 功能、关键不变量和失败恢复路径通过与风险相称的测试。
- 文档、实际行为、Schema、API 客户端和迁移保持一致。
- 无明文秘密进入源码、日志、证据、报告或提交。
- 运行态数据只进入 `var/` 或测试临时根；验证结束后清理本批临时目录和缓存。
- CLI 无交互路径、退出码和公共协议稳定；GUI 与 CLI 对同一 Run 读取同一事实。
- 已知限制、兼容面、外部依赖和未实现边界明确记录。
