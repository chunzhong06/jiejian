# 阶段 6.4：最小因果关联技术实验

状态：技术实验完成；生产观察器、公共协议扩展和样例产品化未实现。

## 实验范围

`tests/experiments/test_causal_correlation.py` 使用标准库和 pytest 临时目录构造确定性目标端 harness。实验只使用显式逻辑步进，不使用 sleep、墙钟接近判断、真实网络、真实数据库或外部服务。两个 case 可以交错推进，审计、任务和最终副作用分别写入有界 JSONL；测试同时覆盖重复事件、无关事件、日志轮转、部分尾行、任务排队→执行中→成功/失败和扫描预算。

## 已证明的假设

- 请求中的 opaque `case_tag` 被目标端逐条回显到审计事件、任务状态和最终副作用记录时，可以沿 `case_tag → task_id → sequence/terminal state → resource_id` 建立唯一闭环。
- 同一事件 ID 的完全重复记录可以去重；同 ID 不同正文、多个 task ID、非法序列、缺失终态、缺失副作用和超出扫描预算都会明确返回 INCONCLUSIVE 或缺口原因。
- fixed（拒绝且没有任务/副作用）、vulnerable（拒绝但同 tag 任务成功并改变资源）和 inconclusive（只有时间/资源相似但 tag 缺失或不匹配）三类事实可在无墙钟等待的情况下重复得到稳定结果。
- 轮转文件、交错 case、无关记录和部分尾行不会让扫描器把相似记录错误归因；部分尾行只作为显式不完整事实，不被当作成功证据。

## 未由实验回答的事项

实验没有证明真实目标框架是否会可靠传播 tag、生产日志轮转是否原子、多个进程的竞争读取是否无竞态、目标端访问控制是否允许最小读取，也没有验证真实 audit/task 数据源的 schema 漂移。确定性调度只证明关联规则本身，不等同于生产并发安全性。

时间接近不能成为因果证据：相同资源和相邻逻辑时间可以同时属于其他请求；没有 tag 时，关联器只能报告无法确认，不能用资源 ID、状态值或时间窗口补齐链路。

## 后续生产实现的最小结论

后续固定 observer 至少需要受限 locator、`case_tag`/request correlation、稳定 task identity、单调 sequence、明确终态、逐资源副作用记录、来源 hash/provenance、完整性和冲突 reason code。预算至少需要文件数、字节数、行数、轮询次数、状态数和有界 eventual window；缺 tag、冲突、部分读取、超时或 required observer 不可用都只能进入 INCONCLUSIVE，不能隐式降级到 HTTP 或时间邻近推断。

本实验不创建公共 Schema、Runner 输入、Evidence、migration 或正式 observer type。实验 harness 保持在测试目录，不复制进 `backend/src/jiejian` 生产实现；如果目标不能明确回显/记录 tag，正确结论只能是 INCONCLUSIVE。
