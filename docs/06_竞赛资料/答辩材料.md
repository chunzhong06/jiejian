# 答辩材料

## 问题

Vibe Coding 生成的 Web 应用可能只在前端或 HTTP 表象上拒绝越权操作，后端副作用却已发生。只看状态码、页面提示或 LLM 文本判断，无法证明安全意图真的落实。

## 核心创新

1. **安全意图到可执行 Contract**：把角色、资源和动作关系转成可版本化规则。
2. **关系变异**：在正常 Flow 上只交换身份、资源或敏感字段，保持差分可解释。
3. **多观察者副作用判定**：同时比较 HTTP 与 owner API 前后状态，识别“拒绝后仍生效”。
4. **Evidence 门禁**：结论带规则、观察、原因码和内容哈希，可回溯、可回归。
5. **可恢复隔离执行**：Job、租约、Fencing Token、Runner、staging、原子发布和 reconciliation 阻止旧进程与半写工件污染结果。

## 架构

当前入口是 CLI。CLI 提交持久 Job，Worker claim 并启动隔离 Runner；Runner 复用 Verification 发送目标请求并生成 Evidence；Worker 校验后原子发布，再用 UnitOfWork 写 SQLite 完成态；CLI/report 展示唯一结果。

## 当前能力

- 阶段 0–2.4 已完成。
- safe/vulnerable 所有权样例形成相反门禁结论。
- 缺少必要观察者时明确输出 `INCONCLUSIVE`。
- Runner V1、SQLite 五表、Job 控制、进程隔离、发布恢复均有自动化测试。
- 真实秘密不进入协议、数据库、日志或 Evidence。

## 当前限制

- 只有 CLI，没有 GUI 和 REST API。
- 浏览器录制和 Playwright 执行尚未实现。
- Contract 与 Flow 当前由人工提供。
- LLM、插件、HTML/SARIF/JUnit 报告尚未实现。
- 当前验证重点是本机授权样例，不代表已经得到大规模准确率或召回率结论。
