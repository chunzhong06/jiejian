# 实验结果

## 当前可证明结果

以下结果来自阶段 2.4 完成时的本地自动化验收，不外推为公开数据集指标：

| 项目 | 结果 |
| --- | --- |
| 全量基础回归 | 404/404 通过 |
| fixed ownership 样例 | `PASS`，CI 退出码 0 |
| vulnerable ownership 样例 | `BLOCK`，CI 退出码 1 |
| 缺少必要 owner observer | `INCONCLUSIVE`，CI 退出码 2 |
| Runner V1 | 模型、严格解析与签入 Schema 漂移测试通过 |
| 阶段 2 持久执行 | 幂等、并发 claim、租约、旧 token、取消、恢复和发布测试通过 |
| 工件发布 | 合法发布、旧 Fencing Token 拒绝、哈希篡改拒绝、发布后提交失败幂等恢复通过 |

## 结果说明

vulnerable 样例的价值不在于“能看到 403”，而在于系统能同时看到 owner 资源已被修改，并把这个副作用与当前变异请求关联，形成 `UNAUTHORIZED_SIDE_EFFECT` Evidence 和 `BLOCK` 门禁。

`INCONCLUSIVE` 用于执行正常完成但证据不足的情况；启动、协议、租约、工件或数据库错误不会被包装为 `INCONCLUSIVE`。

## 尚未得到的指标

当前没有足够正式评测集，因此不报告准确率、召回率、F1、跨框架覆盖率或性能对比。阶段 7 只有在真值样例稳定后才开展这些实验，不能用当前 404 项工程测试代替安全检测统计。
